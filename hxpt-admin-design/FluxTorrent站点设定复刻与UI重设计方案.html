FluxTorrent 站点设定
功能复刻 + UI 重设计方案

以好学站（hxpt.org）settings.php 十二分区为功能基线，在 FluxTorrent（Rust API + Next.js 15）复刻全部站点配置能力，并按 v44.0 设计稿 Token 全新设计管理界面。英文键名不再裸奔，字段类型化渲染、校验、审计、权限一次到位。

01现状诊断：键值表的问题与复刻差距

FluxTorrent 当前「站点设定」位于 /admin 的 settings 页签：从 /api/v1/admin/settings 拉取 site_settings 全表，按 grp 分组渲染成「键值表 + 保存按钮」。0034 迁移已把字段口径对齐 hxpt，但展示与交互停留在原型阶段。

🇬🇧
英文键名直接裸露
设定项列用 font-mono 原样展示 SITENAME / authority_staffmem / randomfree 等键名，管理组看到的是开发者视角而非产品视角。
🧱
全部渲染成文本框
开关（yes/no）、枚举（verification、largepro）、百分比、秒数、颜色全部是一个 text input，无类型化、无枚举下拉、无单位。
🕳️
无校验无反馈
输入非法值（负数概率、>100 百分比、非 URL）直接入库；保存成功只有一行 msg，无校验错误、无影响提示（如「保存后需刷新缓存」）。
🧩
元数据混入
settings_group_order（分组排序的元数据键）也作为设定项显示在「其他设定」里，管理组可直接改坏分组顺序。
🔒
权限只有一档
sysop 可编辑 / administrator 只读，其余 staff 完全不可见；hxpt 的分区级权限（如附件/广告仅站务可配）无法表达。
📉
功能缺口
与 hxpt 基线相比：缺类型元数据、缺枚举/开关渲染、缺分区级权限、缺审计展示、缺修改历史、缺导出/导入、缺「敏感字段」遮蔽。

03数据模型：类型化 settings 元数据

在现有 site_settings 表之上叠加一张类型元数据表（或 JSON 列），用「配置声明」驱动渲染、校验、权限三件事——后端与前端共享同一份 schema，杜绝英文键名直出。

3.1 表结构：settings_meta（新增，幂等迁移）

CREATE TABLE IF NOT EXISTS settings_meta ( name text PRIMARY KEY REFERENCES site_settings(name) ON DELETE CASCADE, type text NOT NULL DEFAULT 'text', -- text|number|yesno|enum|password|textarea|color|classlevel|pair label_zh text, -- 中文名（如「站点名称」），不再用英文键名 label_en text, -- 英文名（en/zh-TW 语言包覆盖） hint text, -- 帮助说明（可含枚举解释，如「verification: none/email/img/emailimg」） unit text, -- 单位：字节 / 秒 / % / 天 / 火花 min double precision, -- 数值下限 max double precision, -- 数值上限 step double precision DEFAULT 1, -- 数值步长 options jsonb, -- enum 选项：[{v:'none',l:'关闭'},...] 或 classlevel 标记 secret boolean DEFAULT false, -- 密文字段（SMTP 密码/统计代码）：回显掩码 readonly boolean DEFAULT false, -- 只读信息（版本号等） group_key text, -- 覆盖 site_settings.grp（分区内卡片分组） card_order int, -- 卡片内排序 updated_at timestamptz DEFAULT now() );

04后端 API：schema / 分组保存 / 校验 / 审计

在现有 GET/PUT /api/v1/admin/settings 之上升级为「声明 + 分组批量 + 校验 + 审计」协议。所有校验在后端权威执行，前端只做即时反馈。

4.1 接口设计

接口说明
GET /api/v1/admin/settings/schema返回分组结构 + 每组字段声明（name/type/options/unit/min/max/secret/readonly/label/hint）+ 当前值（secret 字段只回掩码）＋权限掩码。前端据此渲染整页。
GET /api/v1/admin/settings?group=bonus单分区值（兼容现前端，可下线）
PUT /api/v1/admin/settings/groups按分区批量保存 {"group":"bonus","values":{...}}；服务端逐字段校验（类型/范围/枚举/URL），任一失败整体回滚并返回字段级错误。
POST /api/v1/admin/settings/validate预校验（失焦/提交前调用），返回 {"field":"randomfree","error":"概率须在 0–1 之间"}
GET /api/v1/admin/settings/history?name=&page=单项修改历史（来自 audit 表）
POST /api/v1/admin/settings/export · /import导出全量配置（JSON，secret 掩码可勾选明文）；导入仅 sysop，导入后强制 diff 确认。

4.2 保存管线（示意）

PUT /admin/settings/groups └─ auth：class_id ≥ 90 且 group 不在其只读掩码内 └─ 逐字段 validate(meta)：type / range / enum / url / required └─ 批量 UPDATE site_settings（事务，失败回滚） └─ 逐条 INSERT audit(user_id, 'setting:update', {name, old, new}) └─ 返回 { saved: n, cache: 'FLUSHALL', effects: [...] } -- effects 提示：如改动 announce_url → 「Tracker 地址变更，旧种子文件需重新下载」 -- 改动 SITENAME/BASEURL → 「全站文案与 RSS 链接将更新」
安全注意：SMTP 密码 / 统计代码等 secret 字段：GET 只回掩码（•••••• + 长度提示）；保存时留空 = 保持不变，输入新值才覆盖；audit 日志中 secret 字段 new 值仅记「已更新」不记明文。

6.2 交互规则

  • 即时校验：数字/枚举失焦即调 POST /validate，错误内联展示（红描边 + 红字），不打断填写；保存时再次全量校验。
  • 未保存标记：修改过的字段左侧显示 sky 圆点 + 分区名旁计数；「保存全部修改」按钮常驻。
  • 影响提示：关键字段（announce_url / SITENAME / BASEURL / 促销概率）旁显示小字影响说明；保存后返回 effects 列表逐一提示。
  • 危险操作：删号天数改小、destroy_disabled 打开等用 coral 色值 + 确认弹窗（复用 ConfirmDialog）。
  • 密文显隐：password 控件带显隐切换；显示明文时二次确认（与登录态同源弹窗）。
  • 键盘可达：全字段 Tab 焦点环、Enter 提交、Esc 关闭弹窗；reduced-motion 下无位移动效。

07权限 / 缓存 / 审计策略

7.1 权限矩阵（分区级掩码，扩展现有 class 判定）

角色站点设定可写分区敏感字段
sysop（99）全读写12 分区全部可见明文（显隐需确认）
administrator（90）只读—只见掩码
其他 staff（<90）不可见——
扩展位：meta 表预留 min_class 列（本方案默认全表 99 可写），后续若需「广告/附件交运营配置」只需改该列，不触代码。

7.2 缓存策略

  • 站点设定读取走 Redis 缓存（settings:{grp}），保存成功即失效对应分组缓存，不整库 FLUSHALL；
  • 影响全局行为的三类键（SITENAME / BASEURL / announce_url / 促销概率）保存后额外广播 settings:changed 事件，worker 消费后刷新内存态；
  • 前端保存成功 toast 附「立即刷新缓存」按钮（sysop 可见），对应现有运维习惯的 FLUSHALL 动作。

7.3 审计

  • 复用现有 audit 表：action=setting:update，payload 记 {name, old, new}；secret 字段 new 记「已更新」；
  • 管理组可在「审计」页签按 setting: 前缀过滤；单项修改历史在站点设定内弹抽屉查看（含操作人、时间、旧值→新值高亮 diff）。
