11 封邮件，一套骨架

全部按真实邮件约束制作：600px 表格布局、内联样式、系统字体栈、无外部 CSS / JS / Web 字体、无追踪像素。 所有邮件共用同一个母版——玄墨装饰带（零文字）、宣纸卡面、同一套正文层级、信息块、金线、按钮与页脚； 差异只体现在装饰带高度与结论语义色。纹理全部由纯 CSS 生成，不加载任何背景图片。

统一前后：上一轮只有邀请与找回密码是山海经风，其余 9 封是中性的潮汐风——深蓝 / 浅蓝 / 红 / 琥珀四套底图、四套按钮色， 收件人一眼能看出「不是同一套东西」。本轮取消风格分栏，11 封全部并入玄墨 + 宣纸 + 金线这一套母版， 层级改由装饰带高度（96 / 56 / 64px）区分，颜色只用来表达结果。
三条不可协商的底线：① 装饰带内零文字、零图片，只有 CSS 纹理； ② 正文永远落在纸色卡面（#faf6ec，并用 bgcolor 兜底），任何回退下都不会出现白底白字； ③ 语义色只出现在三处——装饰带底边线、印章式结论标签、主 CTA（本轮统一为金底玄字，不参与语义）。
为什么每封开头句式一样都用「你收到这封邮件，是因为……」开头，收件人第一句就知道为什么收到、要不要处理。
层级靠尺寸，不靠换色标题 26px / 正文 15px / 信息块 14px / 标签 12px 在 11 封里完全一致；三档只改装饰带高度。
语义色只表结果通过=石绿、未通过=朱砂、警示=琥珀、待办=石青。正文一律墨色层级，不用语义色写句子。
暗色不换肤暗色媒体查询把纸色钉住——避免「深色页面 + 客户端剥背景」组合出现浅字白底，因此暗色态与浅色态共用同一份实测值。

纯文本 part 表现

每封邮件都是 multipart/alternative：text/plain 在前、text/html 在后。客户端按自身能力取最后一个能显示的 part；下表说明谁会看到纯文本。

客户端 / 场景纯文本何时被显示纯文本里的链接形态
Gmail 网页 / 移动用户开启「纯文本模式」或邮件被安全策略剥掉 HTML 时完整绝对 URL，自动识别为可点链接
Apple Mail默认按 HTML；可手动「以纯文本显示」或由系统隐私代理剥离完整绝对 URL
Outlook 桌面版启用「以纯文本读取所有标准邮件」时；此外高对比模式下也只保留文本完整绝对 URL
Outlook 网页默认 HTML；企业租户的内容策略可能强制纯文本完整绝对 URL
QQ 邮箱 / 网易邮箱默认 HTML；企业网关或安全扫描会转为纯文本摘要完整绝对 URL
纯文本客户端 / 脚本收信Mutt、Alpine、mail(1)、IMAP 抓取脚本只取 text/plain完整绝对 URL，逐行不折叠
其他 / 通用遵守 RFC 2046：取「最后一个能支持」的 part，因此正常客户端显示 HTML—

规则：纯文本按 68–72 列折行（URL 整行不折，URL-only 行 ≤120 列属明确例外）；不使用 Markdown 符号与 emoji； 所有链接写成 {{base}} 拼出的完整绝对 URL，不依赖「点这里」；纯文本不做 HTML 转义，&、引号按原样呈现。
