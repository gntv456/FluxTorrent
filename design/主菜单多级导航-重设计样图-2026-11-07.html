01

现状诊断

依据 apps/web/components/main-menu.tsx、main-menu-edu.tsx、app/styles/layout.css、app/base.css
A · 宽度写死

深度靠加列来堆

教育级联 .mainmenu-edu{min-width:460px}、每列 150px；「更多」min-width:680px。第 4 级 chips、第 5 级只能继续往里塞，列被压窄、文字截断、整块 max-height:480px 内滚动。

B · 无路径感

hover 切列，状态易丢

学段 hover 即重置年级、鼠标横移经过空隙面板就收起（现有 10px 悬停桥补丁）。没有面包屑、没有返回上级，用户不知道「我从哪进来的」，只能重新展开一遍。

C · 心智分裂

一个顶栏三套模型

「更多」= 分组网格墙；资源库 = 3 组 × 14 分类 + 科目 chips；教育资源 = 三列级联。同一位置三种交互，移动端又统一塌成 fixed 两列，四级结构基本不可用。

02

方案取舍

主导航只保留一套模型，命令面板作为补充入口而非替代
方案结论4~5 级表现代价 / 适用
A 点击逐级展开（本次采纳）
一级 → 二级 → 三级 → 四级，列依次出现		 采用 点一级出二级列、点二级出三级列、点三级出四级列，已展开的列并列可见、选中项逐级高亮；面板固定 1100px，第 5 列起列窗横向滚动并自动滚到最新列，面包屑保留完整路径。 点击而非 hover，状态不丢；桌面/移动共用同一份树与 path 状态。
B 纯钻取（一次一层）移动端采用 深度完全无感，但每次只看一层，跨层比较与「相邻年级」跳转变慢。 实现最简，适合窄屏；作为 A 的 <1024px 降级形态。
C Mega Menu 全平铺否决 2 级很爽，4 级必然变成链接墙；宽屏尚且拥挤，平板直接溢出。 现有「更多」网格就是它的退化版，问题源头。
D ⌘K 命令面板补充 搜索直达任意深度，绕开层级；但不能替代「浏览式」导航（用户常不知道要找什么）。 作为面板内搜索 + 全站快捷键并行存在，不做主导航。

04

窄屏形态 · 全屏钻取（<1024px）

同一份树与 path 状态，只换渲染壳：一次一层、顶部面包屑 + 返回，不再 fixed 两列
与现状的差别：现在 <1024px 把所有一级项塞进「更多」，下拉仍是 position:fixed 两列网格；四级树在手机上没有层级概念。新形态把「深度」变成「步骤」，每步一屏、可回退，搜索框常驻顶部。
05

交互与视觉规格

供实现阶段直接对齐，非最终视觉稿

布局 / 尺寸

面板min(1100px, 100vw - 36px)，距顶栏 4px，圆角 20px，阴影 --sh-2
列每列固定 232px（窄屏 190px），已展开的列并列保留；列头显示层级序号与父级名
溢出超过 4 列时列窗横向滚动、自动滚到最新列；「‹ / ›」可回看，面包屑保留全部层级
高度min(56vh, 430px)，每列独立纵向滚动；禁止整块面板滚动条
断点≥1024 逐级展开列；<1024 全屏钻取一次一层；<640 顶部搜索收成图标
动效新列 160ms 横向滑入 + 淡入；prefers-reduced-motion 下关闭

状态 / 无障碍

触发点击展开，不用 hover：点带 › 的项追加下一列并截断该项之后的旧列；点叶子才导航
路径面包屑记录完整 path，任一段可点击截断回退；进入新层级不丢历史
选中态每一列各有一个蓝底选中项，逐级连成路径；绿字 = 叶子；沿用现有 queryActive 键值全等口径
搜索跨全部层级过滤，结果展示完整路径 + 层级数 + 关键词高亮；空态给「清空」
键盘↑↓ 移动 / → 进入 / ← 返回 / Enter 直达 / Esc 关闭 / 斜杠聚焦搜索
ARIArole="menu" + aria-expanded + aria-current；焦点陷阱、关闭后归还触发按钮
