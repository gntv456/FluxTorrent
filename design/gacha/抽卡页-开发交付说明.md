# 抽卡页（/gacha）开发交付说明

## 一、交付内容

设计稿已落到真实代码库，路由 `apps/web/app/(main)/gacha`（Next.js 15 App Router，登录 + `gacha` 模块闸门）。

| 视图 | 已实现内容 |
| --- | --- |
| 卡池 | 卡池切换、当前期别、本期收录（点亮/未点亮）、星盘保底环（硬保底计数 + 剩余抽数）、右侧「我的进度 / 本期收获 / 获取抽卡券」三栏、单抽 / 十连 |
| 我的卡册 | 合成目标进度条、稀有度筛选、卡名搜索、持有/等级/重复碎片、分解 / 兑换 / 升级、未点亮卡锁定态 |
| 概率公示 | 五档概率表、金色（UR/LR）概率、保底阶梯（软保底/硬保底）、碎片与合成成本、期望值列 |
| 抽卡记录 | 真实抽取流水（时间、结果、保底计数、碎片收益、自然/软保底/硬保底标记） |
| 演出 | 单抽 / 十连结果页，卡面逐张翻出、跳过演出、再抽十连、查看卡册 |

交互附件：HUD（抽卡券 / 碎片 / 记录 / 更多）、更多抽屉（公告、规则、券来源、导出）、七类弹窗（卡面详情、卡池规则、概率详情、券来源、导出记录、进度、确认）、Toast 反馈。整页在 1440 / 1024 / 680 / 390 四端均「一屏装下」，窄屏改为内区滚动 + 底部双卡，不出现整页长滚。

## 二、代码改动

前端：

- 新增 `apps/web/components/gacha/`：`gacha-stage.tsx`（主页面组件）、`gacha-card.tsx`（卡面与纹章符号）、`stage-types.ts`、`stage-copy.ts`（zh-CN / zh-TW / en / ja）
- 新增 `apps/web/app/styles/gacha-stage.css`（全部选择器收在 `.gx` 作用域内，避免污染站点样式）
- 改写 `apps/web/app/(main)/gacha/_inner.tsx`（并发拉取卡池/概率/卡册/我的数据后交给 `GachaStage`）、`layout.tsx`（引入新样式）
- 旧组件（`gacha-draw.tsx` / `gacha-album.tsx` 等）保留未删，`tests/gacha-draw.test.tsx` 仍可用

后端（`apps/api`）：

- `gacha_http/rates.rs`：`banners` 增补 `tenCost`、`startsAt`、`endsAt`、`pitySoft`、`pityHard`
- `gacha_http/me.rs`：`recent` 增补 `drawnAt`、`pityAt`、`isNew`、`bannerId`、`cardId`

数据处理遵循真实接口：`kind=standard` 显示「常驻卡池 / STANDARD / 常驻」，不再展示无数据支撑的 UP 标记；概率、碎片、合成成本、保底计数均来自 `/rates`、`/cards`、`/me`，不写死。

## 三、验证情况

- `tsc --noEmit` 通过；`next build` 编译成功、61/61 静态页生成。
- 生产构建（`next start -p 3000`）+ 真实登录态，四端实测整页滚动高度等于视口：1440 为 900/900、1024 为 902/900、680 与 390 均为 844/844。
- 真实交互：单抽成功（抽卡券 65 → 40、碎片 +N、记录新增、保底 +1、演出页统计为「本次结果」而非全量流水）；分解（碎片 45 → 53）；升级（Lv.1 → 2）；卡面详情 / 券来源 / 规则 / 导出弹窗均正常；券不足十连返回明确提示「抽卡券不足：本次需要 250 券」。
- 已修正：弹窗类名冲突导致常显、单抽结果统计串用全量流水、卡册按钮被裁、概率页碎片列空白、保底阶梯溢出视口、卡池文案失真。

## 四、已知限制

1. 样例账号抽卡券不足以支付十连（250 券），十连扣券仅验证了「不足 → 提示」路径；兑换需碎片 ≥ 目标卡 3200，未真实点通。
2. 导出记录仅打开弹窗，未核对 CSV 下载内容。
3. `public/fonts` 缺少 NotoSerifSC 分片，页面仍有字体 404，属仓库既有问题，首页同样存在，未在本次修改。
4. 构建末尾 standalone 目录符号链接复制报 ENOENT（Windows 环境问题），不影响 `next start`；如需 standalone 部署需单独处理。
5. 本地验证服务为 `next start`（端口 3000）+ `flux-api.exe`（端口 8080），未做容器内回归。
