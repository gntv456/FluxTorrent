01

定位与坐标

为什么不是又一套「甜梦换皮」

娱乐屋已有九款游戏共用糖果色换皮。抽卡页若继续沿用，会和「概率公示」这种法务属性很强的页面气质冲突：玩家在这里需要的是可信、可核对，而不是可爱。因此抽卡页升格为模块级深色展厅——同品牌，不同展区。

Reference A

卡牌图鉴型

以卡面墙为主体，抽卡入口退到角落。收藏感强，但首屏没有「现在该做什么」。

Reference B

扭蛋机台型

大机器 + 大按钮，转化直接。代价是概率与保底被藏进二级页，玩家不信任。

本方案

观测台型

舞台讲「这一期是什么」，星盘讲「我还差多少」，抽屉讲「现在就能抽」。三层各司其职。

取舍：不做全屏弹窗抽卡，不做中奖跑马灯（PT 站无实时全服频道），不做隐藏概率的盲盒叙事。

02

设计原则与令牌

一条纪律：金色是动词，蓝色是名词

金只出现在行动与 SSR

抽卡、兑换、硬保底旗标、SSR 边框与箔光。其余装饰一律冷调星蓝，避免「满屏发光等于没有重点」。

每个数字都有出处

累计 82/90（距硬保底 8）、券 320、碎片 520 全部来自接口字段，不写死；样图用演示值并在页脚标注。

色板

#05080F夜空底
#0B1322面板
#8FC0FF星蓝 · 装饰 / R
#E0BD86金 · 行动 / SSR
#F2E7D3象牙 · 铭牌

稀有度四色不写死：读取后端 /gacha/rarities 的 bg1 / bg2 / frame / ink / foil。稿中 SSR #E0BD86、SR #A89CF0、R #8FC0FF、N #9FB0C6 仅为本期演示值。

字体与数字

层级字体用法
展示层Noto Serif SC 900卡池名、章节标题、卡面卡名、进度数字；字距 .03–.06em
UI 层Noto Sans SC导航、按钮、说明、表格；正文 11.5–13px
数字层同上 · tabular-nums券 / 碎片 / 保底计数 / 概率，等宽对齐防跳动

圆角

面板 14px · 卡片 10px · 按钮 10px · 标签 4–6px。大面板更圆，小控件更方。

描边

统一 1px 半透明发丝线 rgba(150,180,230,.14)，不用纯黑分割，避免深色下出现裂缝感。

动效

交互 160–200ms；翻牌 620ms；错峰 85ms；箔光 1.1s 循环；金弧生长 1.1s。

03

信息架构

L0 一句话 · L1 三个问题 · L2 全部明细

L0

这一期是什么

卡池名、UP 卡、剩余时间。3 秒内决定「要不要抽」。

L1

我还差多少

软 / 硬保底、图鉴进度、券与碎片。决定「现在抽还是再攒」。

L2

钱花在哪

概率表、保底规则、碎片兑换、逐抽留痕。决定「信不信这个池」。

四个 Tab 与真实三 Tab 的差异

Tab承接内容实现状态
卡池L0 + L1：舞台、UP 卡、进度侧栏、底部抽屉已有（gacha-tabbed 第一页）
我的卡册L1 收藏与养成：点亮、分解、兑换、升级已有（gacha-album）
概率公示L2 表定 / 综合双列、保底阶梯、数据口径已有（gacha-rates）
抽卡记录L2 逐抽留痕、30 抽色带、导出新增；后端已有 recent 字段，前端补一页即可

新增理由：现有「近 30 抽」只在卡池页底部露一条摘要，玩家无法核对「第 82 抽出了什么」。记录页把 rows[].seq / r / wasPity / isNew 原样摊开，是概率公示的可验证下游，不新增接口。

05

星盘保底环

把一根进度条，做成这台机器唯一的仪表

保底是本页唯一「有方向」的数据。环形刻度天然表达「越接近越密」，比线性进度条更有压迫感，也避免与页面里其他进度条同质。

外环 90硬保底刻度，每 3 抽一格共 30 格，已过刻度点亮
内环 60软保底起点，60 格细划，起保后转冷蓝
进度弧r=96 处 2.5px 金弧，弧度 = 已抽 / 90
环心当期 UP SSR 卡，3:4 缩至 118×157，可点进卡册
环底累计 x/90 · 距硬保底 (90−x)，与侧栏同源

字段映射：外环 = pityAt / pityHard，内环 = pitySoft，进度弧 = pityAt，环心 = 当期 UP。抽卡成功后环重绘并播一次 1.1s 金弧生长，不做数字滚动。

06

抽卡演出

先给结果，再给仪式；随时可跳过

结算先于演出：点击十连的瞬间即发出 POST /gacha/draw，拿回 rows 后才切到演出视图。演出只是播放器，永不影响余额与保底——跳过、刷新、断网都不会吞掉结果。

0 ms
点击十连 → 按钮转「抽取中…」并禁用 （防重复扣券）
返回
写入余额与保底，进入演出视图；10 张卡背，5×2（移动 2×5）
70 + n×85
逐张 rotateY 180°，perspective 900px；SSR/SR 翻面同时亮 conic 光芒
翻面
SSR 顶部居中「硬保底」旗标（仅 wasPity）；NEW 仅 isNew
翻完
汇总条淡入：各档计数 + 保底是否重置 + 图鉴新增 + 「再抽十连 / 查看卡册」
任意时刻
「跳过演出」= 全部立即翻面，不播动画但保留汇总条

为什么不做逐张点击翻牌

十连点十次对移动端是负担，且延长「结果未知」的时间。自动翻转 + 可跳过，兼顾仪式与效率。

价格呈现

单抽 25、十连 220（较单抽省 30）。抽屉常显「本次消耗」，不做倒计时折扣，避免焦虑营销。

08

卡册 · 概率 · 记录

三个子页，各有唯一主角

我的卡册

主角是合成进度：312/520 横条 + 兑换置顶；24 张按 8 列（1440）铺开，已点亮常显三动作，未点亮只留一句「本季抽卡可解锁」。网格一屏铺 16 张，其余 8 张在网格内滚动，右下角常驻「滚动查看其余 8 张 · 共 24 张」。

概率公示

主角是双列概率：综合 vs 表定并排，每行一条比例条；下方补「保底阶梯」与「兑换分解」。数据口径 / 实测对照 / 公示承诺三块内容移入「口径与复核」弹窗，主视图只留一行摘要与入口。

抽卡记录

主角是 30 抽色带：一格一抽，按稀有度着色，硬保底带金点；下表逐条时间 / 类型 / 结果 / 保底 / 余额，一屏 11 行、超出内部滚动，底部固定「累计 128 抽 · 本页 30 抽」。

09

状态与容错

抽卡页最贵的错误是「扣了券却没结果」

状态触发界面表现
券不足tickets < 25 / 220不切视图；toast「抽卡券不足 · 还差 N 张」并给三条获取路径
结果未知网络中断 / 超时toast「结果未知，请以同一请求重试」；保留同一幂等键
幂等重放replayed = true正常展示，标注「已重放 · 不重复扣券」，不弹二次确认
未登录401卡池与概率只读可见；按钮变「登录后抽取」并回跳本页
空图鉴litCount = 024 张封印卡 + 一句「首抽即点亮」，不做空白页
卡池结束remaining ≤ 0舞台转灰调；抽屉仅留「查看卡册 / 往期归档」

幂等键沿用现有格式 ui-gacha-<timestamp>-<rand>；重试必须复用同一个 key，这是「不重复扣券」的唯一保证。

11

验收清单

逐条可检查，不靠「感觉对了」

视觉

全页无粉色；金色只在主行动、SSR 边框箔光、硬保底旗标
四档稀有度色全部来自 /gacha/rarities，前端无硬编码色表
卡面统一 3:4，铭牌 22%，未点亮有独立封印纹章
无 emoji；图标全部为 1.5px 线性 SVG

结构与交互

1440 / 1024 / 680 / 390 四端无横向溢出、无内容被裁
每个按钮都有真实动作；不可用态有原因，无僵尸按钮
券不足不切视图；结果未知保留同一幂等键
跳过演出后汇总条仍在；刷新后余额与保底不回退

数据一致

页面内所有券 / 碎片 / 保底数字同源，跨 Tab 不出现两个版本
概率页「综合 + 表定」两列同时存在，并注明口径与刷新节奏
记录页条数与 me.recent 一致，序号可追溯
样图演示数据在页脚标注「演示值 · 不扣券」

配套文件 抽卡页-高保真样图.html：五视图 × 四端，可切换、可交互。本册定义「为什么这样做」，样图负责「做出来是什么样」。
