FluxTorrent 全站页面设计审查与优化建议

以「种子详情页」确立的设计标准为锚，对全站前台页面做设计级体检：布局体系、视觉一致性、响应式覆盖、语义与可访问性。结论基于本地真实代码量化扫描，非主观观感。

审查范围：60 前台路由 627 组件/页面文件 13 个样式文件 · 约 420KB CSS 2026-10-15
总体结论：底子好，问题在「多体系并存」。 全站已具备完善的设计令牌（112 个 CSS 变量）、统一布局壳（完整断点体系）、通用页面头（pghd ×19 页）、统一空态/错误组件与模块开关； 核心页面（首页 / 列表 / 详情 / 用户主页 / 论坛）均有体系化设计与响应式。真正需要动的是「收敛」—— 当前至少 7 套独立视觉体系并存（td / up / pting / tsb / request-center / ntf / task + brand 面板 + Tailwind 直写）， 同类元素（页面头、表格、卡片、徽章）在不同页面形态不一；另有语义（一页多 h1）、图标双体系、游戏模块硬编码色等问题。 建议以详情页 L0/L1/L2 与 8 组件规范为锚，抽象「页面模板」逐体系收敛，而非逐页返工。

问题清单（按优先级）

P1 页面头 / 表格 / 徽章三类元素存在 4+ 种实现

元素现存实现建议
页面头① pghd（19 页）② pting-board__head（论坛）③ up-hero（用户主页）④ 列表页搜索盒内建头升级 pghd 为规范组件，其余逐步迁移

P1 一页多 h1 与裸 h1（语义断层）

  • components/home-sections.tsx：首页每个区块头都是 h1（新闻/数据/资源墙……一页最多 6+ 个 h1），应改 h2
  • components/usercp.tsx：侧边导航标题用 h1，应改 h2 或 span
  • components/task-board.tsx / components/contact-staff.tsx：区块头 h1 依赖父级 CSS
  • forums/page.tsx：页面主 h1 无样式类，全靠 pting-board__head 撑
影响：SEO 标题结构与读屏器导航错乱；后续做「页面模板」时标题级将作为硬校验。

P2 响应式覆盖不均衡：14 路由缺 loading，部分体系移动端薄弱

  • 缺 loading.tsx 的路由（14 个，均有真实数据页）：avatar-frames / classes / collections / donate / dressup / farm / gacha / gomoku / jixiao / me / my-spark / offers / users（用户列表）
  • 体系内 @media 缺失：upx-*（上传）、rssx-*（RSS）、funx-*、pghd 头部——移动端布局依赖页面级断点，参差
  • 双缺失高风险页（体系无 @media 且页面无断点前缀）：donate / dressup / gacha / jixiao / farm / collections / avatar-frames 等，需逐个实测 390px

P3 图标双体系：SVG Icon 组件 vs 字符符号（313 文件）

  • 项目已有 components/icons.tsx（SVG 图标库），但 313 个文件直接用字符符号（· → ⚠️ 📣 ♥ ● ◷ ⬇ ★ ✦ ✎ ☰）
  • 同一页面混用：profile-center.tsx 用 ★☰✎✦，其他处用 Icon；usercp.tsx 用 ⚙☆♧
  • 字符符号在不同平台渲染差异大（Windows 缺字形会变豆腐块），无法着色、无法适配主题
建议：新建「符号→Icon」映射表，分两批把高频符号（→ · ✓ ★ ✎ ⚙ ◷ ⬇）替换为 Icon 组件；界面 emoji（152 文件，如上传说明 21 个、商店 18 个、排行 🏆🥈🥉）属品牌资产可保留，但建议统一样式封装。

P3 硬编码色集中在游戏模块（114 处 / 23 文件）

  • fishing-pond.tsx ×33、lucky-wheel.tsx ×24、capsule-machine.tsx ×16、sw-enrich.tsx ×8——游戏组件用 hex 直写（含渐变/发光色），未走令牌
  • 主站核心页面硬编码色极少（torrent-related ×3、upload-form-descr ×2）——健康
  • 建议：游戏模块若保持「街机风」视觉，将专用色收进 arcade.css 的局部令牌（--arcade-*），至少不再散落 tsx

P4 局部细节

  • rounded-full 370 处 / 173 文件：多数是正常的 chip/头像/胶囊按钮（新体系标配），无需全量动；仅需确认「旧式 pill 按钮」场景已随 tsb- 表格换代完成
  • 内联 style={{...}} 70 处 / 44 文件：可接受，多为动态值（分类色、进度条）
  • 游戏体系（arcade.css + arcade-sweet.css ≈ 130KB）与主站视觉差异大：功能上自成模块合理，但「进入游戏区」的过渡观感可加统一入口壳

第五章

统一化路线图：三层推进，不逐页返工

以详情页已确立的「L0/L1/L2 层级 + 8 组件状态机 + 4 断点规范 + 开发落地映射」为全站标准。

S1 快速修（低风险，2-3 天）

  • 语义修复：home-sections / usercp / task-board / contact-staff 的 h1 → h2/span，forums 页 h1 补类
  • 补 14 个路由 loading.tsx
  • 新建「符号→Icon」映射表，替换 10 个高频字符符号

S2 模板化（中工作量，核心收益）

  • 抽象 4 个页面模板：列表页模板（以 tsb- 为准）→ requests/users 列表/收藏收敛；详情页模板（td 已立）→ collections / subtitles / wiki 详情收敛；表单页模板（upx 立标）→ upload / offers / reports 收敛；主页模板（pghd + up 合并）→ 19 页页头统一
  • 统一数据表格组件（列设置 / 排序 / 翻页 / 空态内建），替换 nexus-table / profile-tabs 表格
  • 统一 Badge 组件（sticker 升级为 tone 体系），替换 request-status / pting-card__count 等

S3 收敛与治理（长期）

  • 游戏模块硬编码色 → --arcade-* 局部令牌；emoji 视觉资产统一封装
  • 「页面模板」加机器校验：标题级唯一、体系前缀白名单、硬编码色门禁（可并入现有 lint）
  • 响应式门禁：新页面必须过 4 断点（1440/1024/768/390）截图比对（沿用详情页验收口径）
路线图原则：站型包可以不同，组件语言必须同构。先统一「页面模板」与「三类通用组件」（页头/表格/徽章）， 收益覆盖 80% 页面的观感断层；之后再处理游戏/街机这类刻意差异化的模块。
