第一章

现状诊断：为什么「太散」

详情页目前由 17 个模块按页面顺序纵向堆叠，每个模块信息完整但彼此孤立。散，不是内容缺，而是没有给信息分级、没有把导航性信息提到该在的位置。

模块承载内容当前问题
1 面包屑资源库 / 分类 / #ID正常，但样式弱、无分类色
2 海报头海报 + 名称 + 副题 + 徽章 + 标签 + 发布元信息徽章与规格信息挤在头部，层级靠字号硬撑
3 状态卡做种 / 下载 / 完成 / 感谢 / 健康度位于头部右侧，窄屏被折叠成一行，数据被弱化
4 规格网格大小 / 文件数 / 分类 / 维度 / 评分紧贴头部之后，挤占「决策动线」位置
5-7 折叠块简介 / MediaInfo / NFO默认收起，用户不知道里面有什么
8 抓轨日志碟片抓轨分数与问题有则渲染，位置在简介之后，无固定语义位
9 当前在线做种/下载者明细（脱敏）埋在页面中段，需滚动多次才能看到
10 分组版本同资源多版本切换与头部割裂，用户可能没发现存在
11 试读试听试读 / 试听预览内容层的核心，但被折叠块淹没
12 合集所属合集 / 系列仅文字 sticker，无卡片聚合
13 文件列表文件树（数量最多模块）PT 用户最高频信息，被埋在页面 60% 位置
14 字幕字幕面板折叠块，入口弱
15 下载记录SnatchList 下载用户折叠块，社交佐证信息被弱化
16 感谢 / 评论感谢者 + 评论区交互核心，但在最底部
17 相关种子相似资源推荐页面最底，几乎无曝光

信息没有分级

做种人数、健康度、文件结构、相关种子……全部同权平铺。用户为「要不要下」做的每项决策，都要在长页面里重新找一遍。

关键决策难找

健康度、H&R 义务、价格、文件格式这些「决策数据」散在头部、折叠块和页面中部，第一屏看不到完整决策信息。

文件结构太深

PT 用户最高频查看的「里面有什么文件」，被放在第 13 位、需要滚过一半页面才看到，与决策动线割裂。

桌面宽屏浪费

全文单栏约 900px，左右留白；评论、相关种子、文件列表等天然适合侧栏的信息被纵向拉长。

第二章

设计目标与原则

L0 · 决策层

一屏完成决策

用户进入详情页后，不滚动即可判断「值不值得下」

  • 海报 + 标题 + 副题 + 关键徽章
  • 做种 / 下载 / 健康度大数字
  • 核心规格（大小 / 文件数 / 格式）
  • 下载 / 收藏 / 分享操作常驻
L1 · 内容层

阅读与了解

想深入了解资源的用户，在这里读完内容

  • 简介（课程大纲 / 适用对象）
  • 试读 / 试听预览
  • MediaInfo / NFO / 抓轨日志（折叠）
  • 感谢者与评论区
L2 · 导航层

延伸与佐证

横向跳转：看文件、看相关、看同系列

  • 文件结构（桌面常驻侧栏）
  • 合集 / 字幕 / 下载记录入口
  • 相关种子推荐
  • 分组版本切换
设计原则：决策先于阅读、导航跟随内容、窄屏折叠不丢弃——移动端不删模块，只改变呈现层级（折叠 / 锚点 / 常驻）。
第三章

信息架构重组

把 17 个模块按「决策 → 内容 → 导航」三级重新归位。桌面端拆成主栏 + 常驻侧栏，移动端拆成头部 + 折叠卡 + 锚点条，任何端都不丢模块。

第四章

桌面端 · 双栏布局（≥1024px）

左主栏承载决策 + 内容，右侧 320px 信息栏 sticky 常驻：状态、文件、元信息、相关种子一屏可达。这是「散」的直接解法——把导航性信息从长页面里提出来钉在侧栏。

布局决策理由
右栏 sticky（top: 72px）状态 / 文件 / 相关种子在滚动全程可达，决策信息不再「滚丢」
文件列表提升到侧栏PT 用户「看文件 → 决定下」是主决策路径，从第 13 位提前到第一屏
规格从网格改为徽章条网格 6-8 格占满一整行太占地；徽章条可横向折行，一屏装下全部决策规格
折叠块统一样式 + 内容角标用户未点开也知道「这里有 MediaInfo / 有 NFO」，减少盲猜
主操作在 hero、副操作在侧栏下载 / 收藏常驻视觉层；补种 / 分享 / 管理下沉侧栏不抢主操作
