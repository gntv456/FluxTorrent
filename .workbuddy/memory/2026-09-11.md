### 关键坑与约定
- **语言码口径是 `en|chs|cht`（NexusPHP 风格），不是 web 路由 locale 的 `zh-CN/zh-TW/en`**。0024 `users.site_language DEFAULT 'chs'`、0025 `default_language='chs'`、`components/usercp.tsx` 的 `<option value="chs|cht">` 三处一致。0039 初版误用 locale 码导致既有值不在枚举内（下拉静默落首项 → 保存即篡改），0040 修正。
- **禁止修改已应用的迁移文件**：sqlx 校验 SHA-384，就地改会触发 `migration N was previously applied but has been modified` 而**阻断 API 启动**。修正必须追加新迁移。开发库曾因 0037 的历史 checksum 漂移（19fe1456 ≠ 当前 c5b77a8c）崩溃循环。
- `require_auth` 以库中 `status/class_id` 为准，token 里的 class 不可信（伪造 token 提权无效）。
- 运行时写 `site_settings` 的键（如 `module_textbooks`/`module_showcase` 由站点类型切换写入）必须在新库迁移里补种，否则 `settings_meta` 的 FK 会失败。
- 迁移里的多条语句写在同一个 `psql -c` 会构成隐式事务，一条失败整批回滚。

### 环境要点（本机）
- **bash 工具不可用**（PortableGit shim 报 `dirname: command not found`），全部改用 PowerShell。
- PowerShell 工具**不回显 stdout**：需 `... | Set-Content -Encoding UTF8 file` 后用 Read 读文件；`psql` 输出直接重定向会变二进制，需经 `Out-String`。
- `Invoke-RestMethod` 遇无 charset 的 `application/json` 会按 Latin-1 解码 → 中文乱码；须取 `RawContentStream` 字节再 `[Text.Encoding]::UTF8.GetString`。
- HTTP 错误响应体用 `$_.Exception.Response.GetResponseStream()` 读到空，须用 `$_.ErrorDetails.Message`。
- 镜像 `docker-api`/`docker-web` 由工作树重建；改 `apps/**` 后需 `docker compose build` + `up -d`（web 无 bind mount，不重建则新路由不生效）。
- **compose 文件在 `D:\FluxTorrent\docker\docker-compose.yml`（project=`docker`，service=`web`/`api`），不在仓库根目录**；在根目录跑 `docker compose build` 会报 `no configuration file provided`。用 `docker inspect <ctr> --format '{{json .Config.Labels}}'` 可查回 compose 工作目录。
- **同一文件的多个 Edit 不能并发**：并行发两个 Edit 到同一文件时，其中一个会被另一个的写入覆盖（实测结构体新增字段丢失，编译报 `no field`，需重发）。改动同一文件请串行。
- 改 `apps/api/src/**` 后重编译前必须先 `Stop-Process` 掉正在运行的 `target/debug/flux-api.exe`，否则 `link.exe` 报 exit code 1104（文件被占用）。
- PowerShell 5.1 读取**无 BOM 的 UTF-8 `.ps1`** 会按 GBK 解析，脚本内的中文字面量会变乱码（数据来自 JSON 响应的中文则正常）。

## tracker 高频请求防护审查（代码审计，只读未改）

## tracker 高频防护修复（已实施，cargo test 6/6 通过）

## 保种影响评估（用户问"会不会影响保种"）

- **结论：正常用户不受影响，被限只延迟不丢失**。关键依据（`apps/worker/src/jobs.rs`）：
  - 计费是累计量差值口径（process_event :218-232，`last_up/last_down` vs 客户端累计上报）→ 被拒 announce 的增量合并进下次成功 announce，**流量不丢**。
  - `snatches.seeding` 是粘性 OR（:245 `seeding = EXCLUDED.seeding OR snatches.seeding`）→ 被拒不会摘做种标记，保种区统计（seeders 由 snatches 回填 :184-188）与 hr_snapshots 口径不受限流影响。
  - 数学边界：interval 1800s → 每分钟 announce ≈ 挂种数/30；600/min 用户阈值覆盖 1.8 万挂种。
- **据此上调默认阈值（两轮，用户反馈 1.8 万不够 → 终值）**：user **1800/min**（覆盖 5.4 万挂种）、IP **3600/min**（60r/s/IP，main.rs + compose）；Nginx **60r/s、burst 120、conn 120**（生产部署指南 §4；边缘必须 ≥ 应用层每用户速率，否则先卡住鲸鱼）。垃圾洪水仍有界，分布式洪水属网关/WAF 职责。
- **发现既有严重缺陷（与防护无关）→ 已修复**：`snatches.seeded_seconds` 全仓无写入点。修法（用户确认"需要"后实施）：
  - 迁移 `0043_snatches_last_seen.sql`：snatches 加 `last_seen_at TIMESTAMPTZ DEFAULT now()`。
  - worker `process_event` upsert 内累计：本次 left=0（EXCLUDED.seeding）且 `last_seen_at` 在容忍窗内 → `seeded_seconds += now() - last_seen_at`（LEAST/GREATEST 夹取）；`last_seen_at = now()` 每次刷新。容忍窗 = 2×announce_interval（consume_announce 每轮从 site_settings 读，clamp [3600,172800]）。以本次事件 left 为准，规避 seeding 粘性 OR 的挂机伪造口子。
  - `hr_flag` 运行时刷新补进 hr_enforce 第 5 步（0029 只迁移置过一次；14 天且 <120h → TRUE，NOT hr_flag 幂等守卫）。
  - 生效闭环：H&R（hr_snapshots 同步）、等级做种小时、保种认领 seed_time_delta、/me/hr 全部拿到真实数据。
  - 验证：cargo check/test -p flux-worker 通过（3/3）。坑：worker 里 `v.parse().ok()` 推断不出类型需 `parse::<i64>()`（tracker 同款代码带 turbofish，抄漏了）。
  - 部署提醒：需 `docker compose build worker api && up -d`；老行 last_seen_at 默认迁移时刻，时长从部署后起算，不回溯。
