### 实测基线（2026-09-11 快照）
- FT：后端 175 个去重路由 / 前端 36 个页面 / 前端仅调用 117 个 API / 82 张表 / 后端 33 单测 / 前端 0 测试
- NP：158 个 public/*.php 页面 + 53 个 Filament Resource；`routes/web.php` 仅 13 条，legacy 页面仍是主力入口（不可当废弃页剔除）

### 核心结论
**后端覆盖约 80%，用户端到端可用率仅约 67%** —— 175 路由中 58 个（33%）无任何前端调用。
最大风险是「API 完成 ≠ 功能可用」。

### 实锤缺陷（均已代码验证）
- P1：`/users/{id}` 用户主页无路由无接口（usercp.tsx 有死链）；无 PUT/DELETE /torrents/{id}（发布者不能编辑删种）；无 peer/snatches/NFO 接口；`/admin/hr/pardon` 无 UI；`/admin/appeals/handle` 无 UI（申诉断链）；`/magic-pool/donate` 无 UI（页面纯展示）；`/jixiao/*` 全栈无 UI
- P2：2FA 无法自助开启（usercp.tsx:1296「启用」链接自指当前页）；`/me/tokens`、`/push/*` 无 UI；`tags` 表全栈零引用但文档声称标签筛选；勋章赠送/求种候选投票/求种达成/课本关联无 UI
- P3：死代码组件 5 个（economy-actions / my-profile / my-torrentlist / passkey-card / task-actions，功能已被 usercp.tsx 内联重写）
