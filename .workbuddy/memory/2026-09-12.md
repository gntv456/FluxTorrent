## 签到失败修复（500 → 正常）

- 根因：`economy_http.rs` checkin 的连签查询 `(count(*) OVER ())::int` 返回 INT4，但 Rust 元组按 i64 解码 → sqlx 解码类型不匹配 → 500「内部错误」。签到状态接口不受影响。
- 修复：`::int` 改 `::bigint`（保留 Rust i64）。全库 grep 无同款问题。
- 部署：重建 flux-api 镜像（Rust 构建约 7 分钟）并重启容器。
- 验证：签到成功（+5 火花、streak 逻辑正确）、状态接口 checked_today=true、重复签到幂等返回「今天已经签到过啦」而非 500。

## 主流 PT 架构横向对比（GZ / NP / UNIT3D / 老派 / 新一代）
产出文档：`_doc/主流PT架构横向对比与借鉴.md`（含谱系表、结构性差异表、借鉴清单、避坑清单、P0-P3 落地优先级）。
核心结论（供后续决策引用）：
- 真正的代差在 announce 计费链路：GZ=Ocelot 内存累计+定时 flush、NP=同步写库+队列、UNIT3D=队列+定时任务、我们=Redis Stream→worker 异步增量（流水为事实源）。我们领先，不要为"实时"把计费放回同步路径。
- 我们最大风险是**生态不兼容**（ptool/IYUU/PT Mate 默认适配 NP 字段口径）与**教育网 IPv6 缺失**（`apps/tracker/src/peers.rs` 明确 IPv6 不进 compact 列表，纯 v6 用户拿不到 peer）。两者定 P0。
- 值得抄：GZ 的 Torrent Group 聚合（→ 教材/课程聚合层，我们扁平种子最大产品结构缺口）、对象级读缓存、FL Token、Ratio Watch 柔性观察期；NP 的第三方工具适配层、做种收益饱和封顶公式、盒子规则；UNIT3D 的聊天盒/成就/一键升级。
- 不要抄：GZ 的 PHP+MySQL 债与站点↔tracker 共享表耦合、NP 的双轨 PHP 与同步写库、UNIT3D 的 Livewire 全栈耦合与组件膨胀。
- 上游事实核验（2026-09）：Gazelle 官方正从 MySQL 迁 PostgreSQL（印证我们选 PG）；Ocelot 为 C++、仅 TCP、仅 IPv4（所以我们缺 UDP 不算落后于 GZ，但 IPv6 要补）；UNIT3D v9.2.0 = Laravel+Livewire+Alpine+Meilisearch+Reverb，AGPL-3.0。
- 环境：本会话 bash 缺 coreutils（ls/dirname 不可用），改用 Glob/Grep/Read；WebSearch 可用。
