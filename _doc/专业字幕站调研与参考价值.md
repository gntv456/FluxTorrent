# 专业字幕站调研与参考价值评估

> 调研日期：2026-09-21
> 范围：独立字幕站（OpenSubtitles / SubHD / 字幕库 / 伪射手 / addic7ed / podnapisi / SubDL / Subscene / Bazarr 生态等）
> 目的：判断这些站的哪些机制能搬进 FluxTorrent 的字幕区

---

## 0. 结论：有参考价值，但要分三类搬

**一句话：专业字幕站解决的是「怎么让用户在海量字幕里找到能用的那条」，PT 站字幕区解决的是「怎么让社区愿意贡献字幕」。两者目标不同，能搬的是前者的元数据规范与质量机制，搬不了的是它的匹配前提（它拿得到视频文件，我们拿不到）。**

| 档位 | 内容 | 判断 |
|---|---|---|
| **直接搬** | 字幕元数据规范（FPS / 机翻标记 / 听障 / 仅外语部分 / 字幕来源 / 制作人-校订人-上载人三元署名）、md5 查重、体积上限 + 压缩包白名单、修订版、评分与坏字幕标记、按上传者等级排序 | 成本低、收益高，建议做 |
| **改造后搬** | 求字幕请求（OpenSubtitles `AddRequest` / podnapisi request）→ 结合 KG 的 pots 做成**魔力悬赏**；贡献者主页（SubtitleCenter「This is me」）→ 挂到现有用户主页 | 中等成本，差异化 |
| **搬不了 / 不划算** | moviehash 精确匹配（需要视频文件首尾 64KB，PT 站没有文件本体）、下载配额与 VIP、AI 翻译、整季包 | 但**可以用 release name 近似替代**（见 §4） |

### 顺手挖到的本仓库问题

`site_settings` 里早就有 **`maxsubsize = 1048576`（1MB 字幕体积上限）**（`0034_settings_np_align.sql:29`，并在 `0039_settings_meta.sql:357` 配了后台元信息「字幕体积上限（字节）」），
但**全仓库没有任何代码读它**——`apps/` 下 grep `maxsubsize` 只命中这两处迁移定义。
也就是说：**配置项躺在库里，上传链路完全没接线**，现在传 500MB 的字幕也能过。
这正是专业字幕站最基础的一条（伪射手 8M、字幕库 30M、OpenSubtitles 走 subhash 校验）。**接线成本不到 20 行。**

## 2. 专业站有、PT 站字幕区普遍没有的机制（清单）

按「对 FluxTorrent 的可用性」排序：

| # | 机制 | 出处 | FluxTorrent 现状 | 可用性 |
|---|---|---|---|---|
| 1 | **release name / VERSION NAME 精确匹配** | addic7ed、Bazarr、SubDL | 只有 `ILIKE '%关键词%'` | ★★★ 可替代 hash |
| 2 | **字幕文件 md5 查重**（上传前先查是否已存在） | OpenSubtitles `TryUploadSubtitles` | 已有 `attachments.sha256`！只差一步查询 | ★★★ 天然具备 |
| 3 | **体积上限 + 压缩包白名单** | 伪射手 .rar/.zip/.7z ≤8M；字幕库 ≤30M | `maxsubsize` 有配置**未接线** | ★★★ 改 20 行 |
| 4 | **机翻标记**（automatictranslation） | OpenSubtitles；伪射手明文"请勿上传机器翻译的字幕" | 无 | ★★★ 加字段 |
| 5 | **听障字幕 HI / 仅外语部分** | OpenSubtitles（hearingimpaired / foreignpartsonly）、addic7ed（HI 勾选） | 无 | ★★★ 加字段 |
| 6 | **FPS 字段** | 伪射手、OpenSubtitles、podnapisi 筛选 | 无 | ★★ 加字段（对特效字幕很关键） |
| 7 | **三元署名：制作人 / 校订人 / 上载人 + 字幕来源 + 字幕组** | 伪射手 | 只有 user_id | ★★★ 加字段（呼应 KG 的 "for KG" 署名） |
| 8 | **修订版**（对已有字幕传改进版） | 伪射手、字幕库（3 个月内可改） | 无 | ★★ 加 `parent_id` |
| 9 | **评分 + 坏字幕标记 + 评论** | OpenSubtitles（1-10 分、badsubtitles）、Subscene（good/bad） | 只有"举报"按钮且无闭环 | ★★★ 替代/补充举报 |
| 10 | **按上传者等级加权排序** | OpenSubtitles（trusted/platinum/gold/user/anon 各档不同分） | 固定 `id DESC` | ★★ 复用现有 class 体系 |
| 11 | **求字幕请求** | OpenSubtitles `AddRequest`、podnapisi request | 有求种（requests.bounty），**无求字幕** | ★★★ 结合 KG pots 做悬赏 |
| 12 | **贡献者主页 / 信用认领** | SubtitleCenter「This is me」、podnapisi 贡献追踪 | 用户主页无字幕作品区 | ★★ 挂现有 medals |
| 13 | **排版规则**（行宽 ≤40 字符、proper case、禁广告） | addic7ed、伪射手明文禁广告 | 无 | ★ 写进规则文案即可 |
| 14 | **禁广告**（字幕里塞"本字幕由 XX 上传"会被删） | OpenSubtitles、伪射手 | 无 | ★ 写进规则文案 |
| 15 | **程序化 API + 工具生态** | OpenSubtitles REST、SubDL API、Bazarr 集成 | 有 `/api/v1/subtitles` 但无公开文档 | ★★ 长期 |
| 16 | **整季包 full_season + 自动展开单集** | SubDL | 无 | ☆ 剧集站才需要 |
| 17 | **每日下载配额 / VIP 额度** | OpenSubtitles VIP、SubHD（第三方侧 20 条/天） | 无（用魔力体系即可） | ☆ 不划算 |
| 18 | **AI 翻译 / Whisper 生成** | SubDL、Bazarr | 无 | ☆ 不建议（质量风险） |

## 3. 伪射手上传表单（国内站的字段天花板，可直接抄）

四段式，摘自 `https://2.assrt.net/sub/upload.html`：

**① 影片信息**：匹配版本 / 影片原名 / 中文译名 / 香港译名 / 台湾译名 / 英文片名 / 别名或简写 / IMDB ID / 豆瓣ID / **字幕说明、简介与译者附言**
（登录后可在「我的字幕」中选择**上传已有字幕的修订版本**）

**② 字幕信息**：字幕格式（VobSub .idx+.sub / Subrip .srt / SSA-ASS / MacroDVD .sub / SUP / 其他）、**桢率 FPS**、字幕语种（英/简中/繁中/法/西/日/韩/双语/其他）

**③ 字幕文件**：有效扩展名 `.rar .zip .7z .tar.gz .tar.bz2`，**最大 8M**
规则原文：*「请勿上传任何影片下载信息或广告，请勿上传机器翻译的字幕。建议将字体包上传到网盘。」*

**④ 制作发行信息**：**制作人 / 校订人 / 上载人** / 字幕来源（原创翻译 / 校订翻译 / 市售DVD / 官方译本 / 其他）/ 字幕组（快选列表几百家）/ 版本 / 发行网站 / Email（同一 Email 可发修订版）+ 验证码

→ **对比 FluxTorrent 的上传表单（file / torrent_id / title / lang 四项）**：少了 FPS、格式、来源、署名、修订版、体积校验这六项。前四项是"让字幕可被正确使用"的关键元数据。

## 4. 匹配机制：hash 用不了，但 release name 可以

**OpenSubtitles 的 moviehash**：读视频文件首尾各 64KB + 文件大小算 64bit checksum。
→ PT 站**没有视频文件本体**（只有种子元数据），算不出 moviehash，这条路走不通。

**但 FluxTorrent 有两样别人没有的东西，可以做近似匹配**：

1. `torrents.name` —— 华语 PT 站的种子名基本就是 **scene release name**（`Movie.2024.1080p.BluRay.x265-GROUP`），
   正好等价于 **addic7ed 的 VERSION NAME 匹配**。addic7ed 靠这个成为美剧字幕第一站，说明 release name 匹配在 PT 语境下**够用**。
2. `torrents.media_info JSONB`（`0020_gap_features.sql:92`，含 `imdb_id`）+ `metadata_sources`（imdb/douban/bangumi，0088）
   → 可做 **IMDB/豆瓣 ID 级匹配**（OpenSubtitles `AddRequest`、podnapisi 就是按 IMDB+语言求字幕）。

**建议的匹配优先级**（照抄 OpenSubtitles 的加权思路，换成我们有的字段）：

```
1. torrent_id 精确命中（用户手动挂载）           → 最高分
2. release name 归一化后相等（去 ._-+、大小写）   → 次高
3. media_info->>'imdb_id' 相同 + 语言相同        → 中
4. 文件名/标题 ILIKE 模糊                        → 低
5. 每条再叠加：上传者等级加权 + FPS 匹配加分 + 下载数/评分兜底   （照抄 OS 的排序公式）
```

## 5. 落地建议（合并到一条迁移 + 一次后端改造）

```sql
-- 1) 字幕元数据规范（对齐专业站）
ALTER TABLE subtitles
  ADD COLUMN IF NOT EXISTS size BIGINT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS ext TEXT,                       -- srt/ass/ssa/sup/idx/sub/zip...
  ADD COLUMN IF NOT EXISTS fps NUMERIC(6,3),               -- 桢率，特效字幕关键
  ADD COLUMN IF NOT EXISTS machine_translated BOOLEAN NOT NULL DEFAULT false,  -- 机翻标记
  ADD COLUMN IF NOT EXISTS hearing_impaired BOOLEAN NOT NULL DEFAULT false,    -- 听障
  ADD COLUMN IF NOT EXISTS foreign_parts_only BOOLEAN NOT NULL DEFAULT false,  -- 仅外语部分
  ADD COLUMN IF NOT EXISTS source TEXT,                    -- 原创翻译/校订翻译/市售DVD/官方译本/其他
  ADD COLUMN IF NOT EXISTS producer TEXT,                  -- 制作人
  ADD COLUMN IF NOT EXISTS proofreader TEXT,               -- 校订人
  ADD COLUMN IF NOT EXISTS author_name TEXT,               -- 译者/字幕组署名（KG "for KG" 同款）
  ADD COLUMN IF NOT EXISTS parent_id BIGINT REFERENCES subtitles(id),  -- 修订版
  ADD COLUMN IF NOT EXISTS release_name TEXT,              -- 归一化后的 scene release name，用于匹配
  ADD COLUMN IF NOT EXISTS rating_sum INT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS rating_count INT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS bad_reports INT NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS anon BOOLEAN NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS status SMALLINT NOT NULL DEFAULT 1,
  ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ;

-- 2) 求字幕悬赏（KG pots + OpenSubtitles AddRequest 合体）
CREATE TABLE IF NOT EXISTS subtitle_requests (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id),
  torrent_id BIGINT REFERENCES torrents(id),
  lang TEXT NOT NULL,
  descr TEXT,
  bounty BIGINT NOT NULL DEFAULT 0,
  contributors JSONB NOT NULL DEFAULT '[]',
  status SMALLINT NOT NULL DEFAULT 0,
  fulfilled_subtitle_id BIGINT REFERENCES subtitles(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 3) 种子体积回填（从 attachments 反查）
UPDATE subtitles s SET size = a.size
FROM attachments a
WHERE s.file_ref = 'attach://' || a.sha256 AND s.size = 0;
```

**后端改造清单**（`apps/api/src/content_http/subtitles.rs`）：

| 动作 | 说明 |
|---|---|
| 接线 `maxsubsize` | 上传时 `size > maxsubsize` → 400（默认 1048576，后台可配） |
| 扩展名白名单 | `srt/ass/ssa/sup/idx/sub/zip/rar/7z`（zip/rar 内须含字幕文件，可后置解包校验） |
| **sha256 查重** | 已有 `attachments.sha256`：同一 sha 已挂在某字幕下 → 拒绝重复上传（防刷 +5 火花） |
| release_name 归一化 | 存种子名归一化值，列表/种子页按 §4 的优先级排序 |
| 评分与坏字幕 | `POST /subtitles/{id}/vote`（1-10）、`POST /subtitles/{id}/report`（bad_reports++，达阈值自动隐藏） |
| 上传者等级加权 | 复用 `users.class`，排序时按档加分 |
| 求字幕 | `POST /subtitle-requests`（bounty）+ `POST /subtitle-requests/{id}/contribute`（凑钱）+ 交付后整池结算（抄 `community_http/bounty.rs` 的 CAS + 幂等键） |
