## 二、P0 详述与复现

### P0-1 VIP/去广告全线 500（扣款成功、效果丢失）

- 复现：`POST /shop/buy {"item_id":8}`（贵宾待遇 80000）→ `code:1000 内部错误`。
- 根因：`shop_effects.rs` 中
  `vip_until = GREATEST(...) + make_interval(days => $2)`，
  `$2` 由 sqlx 绑定为 i64/bigint，PostgreSQL `make_interval(days => double precision)`
  只接受 double/int4，bigint 无隐式转换 → `function make_interval(days => bigint) does not exist`。
  ad_free 分支同款。容器日志有完整报错。
- 后果链：spend_spark 已提交 → 订单行已插（effect_applied 由 CAS 先置 true
  再执行效果，失败后无回滚）→ 用户余额少了 8 万、vip_until 为空。重试同键
  返回「重放」，效果永久丢失。这是**扣了钱什么都没拿到**的资损。
- 备注：同类坑在仓库记忆里出现过（sqlx ::int 三连），promo 购买侧用的
  `make_interval(hours => $1)` 与 bind(body.hours) 是 i32 所以没事——days 分支
  绑的是 config.days 的 i64，独踩。
- 修法：`make_interval(days => $2::int)` 或 `($2 || ' days')::interval`，
  同时给整个 buy 流程补「效果失败 → 回滚订单行+退款」或至少告警工单。

### P0-2 负价商品 = 印钞机

- 复现：root 调 `POST /admin/shop-items {"name":"neg","kind":"upload_credit","price":-100}`
  → 201 成功；用户购买 → 响应 ok，`spark_ledger` 落 `+100`，余额上涨。
- 根因链：管理端只校验 name/kind 非空，price 无 `>=0`（或 `>=1`）校验；
  `spend_spark` 的 `balance < amount` 对负数永假，`-(-100)` 直接入账。
- 加重项：后台 UI 类型下拉虽是白名单，但 API 层 kind 无白名单（实测
  `kind:"free_money_forever"` 建成并上架成功，用户可买、无任何效果——
  「花钱买空气」死灰复燃的入口）。price 也不设上限（1e15 也建得成）。

## 三、P1 详述

### P1-1 库存编辑实际失效

- 复现：`PUT /admin/shop-items/19 {"stock_quota":5,"stock_used":3,...}` →
  返回 ok，DB 两字段纹丝不动。UPDATE 语句根本没 SET 这两列（0287 只改了
  POST 分支）。前端 admin-props.tsx 表单把 stockQuota 塞进 payload 也白塞。
- 后果：限量商品配额写死后无法纠错/补货，只能进库手改。

### P1-2 重放多计库存

- 复现：quota=3 买 1（成功，used=1→实为 3 状态见下）→ 网络重试同键 →
  返回 replayed 但 `stock_used` 又 +1。玩家拿脚本对同键狂重放可把库存计数
  顶到售罄（DoS 限量商品），虽然券不多发。
- 修法：库存占位移到 spend_spark 判重放之后（或占位改条件 `NOT EXISTS(spark_ledger...)`）。

### P1-4 种子数据三坑（用户视角可直接感知）

- 自定义头衔 8 万：买完 title 仍为空（config 无 title 键，效果分支静默跳过）。
- 赠送魔力 10,000 → 只得 1,000：这是把「10 张 1000 面额」错标成单价。
  商品语义应为「购买 1000 魔力面额」（名字里也没写面额），负期望商品必改。
- APP VIP(30天)/贵宾待遇/15 天去广告的 days 全靠代码缺省 30/15，name 里的
  30 天与 config 脱节——改 days 必须同步改名，运营易踩。

## 四、验收通过项（此前修复回归）

- 幂等：同键自然重放不双扣；跨用户同键不互串（uid 前缀）；卡片类 `:N`
  后缀行不会被 LIKE 撞（`shop:4167:t17-a:2` 不匹配 `t17-a` 前缀的 `%` ——
  实测 `t17-a` 与 `t17-a:2` 分行无串行）。
- 库存：quota 原子占位无超发（3 张券实测精确 3 张）。
- 装扮唯一性：已拥有再买被拒；未拥有不能佩戴。
- 券：使用/重复使用/跨用户盗用全部正确拒绝；免费券正确入库 user_vouchers。
- 补签卡：购买 qty=5 落 5 订单行，补签消耗 1 行（cards_left 正确）。
- 勋章：买/重买拒/赠送（5% 费率）/送自己拒/余额不足拒全对。
- 促销（置顶/限时免费）：购买/重放闸门/时长落库全对，价格表合理。
- 反通胀阀门 buffer_cap_check、余额不足、未登录、qty 边界 0/101/-5 全拒。
- 审计链 audit_log 防删改（清理测试数据时被正确拦截）。
