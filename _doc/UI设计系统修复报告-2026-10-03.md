## 一、四个 P0：用户操作了但系统没响应

### P0-1 深色模式完全失效 ✅

**根因**：`theme-tide.css` 有**两处** `:root,` 前缀（子报告只发现了一处）：

| 位置 | 内容 | 影响 |
|---|---|---|
| 24 行 | `:root, [data-theme="baozi"]` | 109 个色彩令牌全部覆盖夜间 |
| 674 行 | `:root, [data-theme="baozi"]` | **字体栈被强灌给夜间用户** |

`:root` 会同时匹配 `<html data-theme="baozi-night">`，把 `base.css:126` 定义正确的夜间令牌全覆盖。该文件 21 行注释写着「绝不触碰 baozi-night」，而全文件 `baozi-night` 只出现 1 次（就是那句注释）——**注释与代码行为相反**。

**修法**：
1. 摘掉两处 `:root,`（`<html data-theme>` 由 `app/layout.tsx` 的 `ThemeNoFlash` 首绘前必赋值，无回退风险）
2. 文件末尾加 `[data-theme="baozi-night"]` 回填块：显式给尺寸类（`--r-*`）、`--tide-*` 专有令牌、`--baozi-*` 兼容层、**以及三个字体栈变量**（摘掉 `:root` 后不声明会掉回 base.css 旧栈）
3. 色彩类**不重复声明**，沿用 base.css:126 夜间值——避免两处真源

### P0-2 移动端种子列表每行露出砖红色块 ✅

`.trow-swipe__acts`（滑动操作层）缺初始位移，直接压在卡片右缘；而 `.trow-swipe__front` 没有背景色，砖红从内层透出。

```css
.trow-swipe__acts  { transform: translateX(100%); }   /* 新增：藏到前层之外 */
.trow-swipe__front { background: var(--surface-card); }  /* 新增：兜底不透明 */
```

### P0-3 `/login` 底部提示永久丢失 ✅

`max-height: 563px` 写死，900px 视口下画布顶着溢出，`documentElement.scrollHeight === 900` 不产生滚动条——用户看不到"连续 5 次登录失败将限流"等安全告知。且提示框 `font-size: 9px` 是全站最小字号。

| 位置 | 原值 | 新值 |
|---|---|---|
| `.bz-login-card` max-height | `563px` | `calc(100vh - 180px)` |
| `.bz-login-canvas` min-height | `615px` | `min(615px, calc(100vh - 80px))` |
| `.bz-login-notice` font-size | `9px` | `12px` |

### P0-4 CSS 语法错 + 9 个悬挂变量 ✅

`pages.css:1924/1928/1936` 写的是 `var(--baozi-orang e-dark)`——**变量名中间带空格**，浏览器把后半段当 fallback，**整条 `color` 声明失效**（趣味盒「好笑/爆笑」与链接「待审」标签掉回继承色）。

另发现 9 个变量被 `var()` 引用却从未定义（浏览器静默回退到消费点写的旧 Aurora 硬编码色）。在 `base.css` 加「旧名别名层」，全部指向语义变量，浅色夜间自动跟随：

```css
--muted: var(--text-muted);    --card: var(--surface-card);
--panel: var(--surface-card);  --fill-2: var(--surface-sunken);
--accent-soft: var(--sky-soft);
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);
```

**9 → 3**：剩下 3 个（`--trow-cat` `--tone` `--marquee-duration`）是 TSX 内联注入的动态变量，有真实消费方，保留正确。

### P0-5 控制面板侧栏字形缺失 ✅

`USERCP_NAV` 用 `⌂♙✎⚙♧⌾☆` 七个键盘符号当图标，其中 `✎`(U+270E) 缺字形——控制面板第 4 项只剩一个孤立「、」。改用 `components/icons.tsx` 的语义 SVG（该文件已有 100+ 图标，继承 `currentColor`）：

`gauge` / `user` / `edit` / `settings` / `forums` / `shield` / `star`

## 二、第二层：补齐尺度令牌层

问题的根源不是审美，是**令牌层只覆盖了色彩，尺度层全靠硬编码**。

### 新增令牌（`base.css` 的 `@theme`）

| 类别 | 档位 | 治理目标 |
|---|---|---|
| 语义断点 | `--bp-sm/md/lg/xl/folded` | 47 个裸像素断点收敛到 4 档 |
| 间距 | `--sp-1..7`（4/8/12/16/24/32/48） | 438 处声明里 59.4% 非 4 倍数 |
| 圆角补充 | `--r-2xs/xs/pill/circle` | 19 种圆角，最高频的 8px 与 999px 原本无令牌 |
| 字号 | `--fs-2xs..3xl`（9 档） | 34 种字号、20.6% 是半像素 |
| 层级 | `--z-base..toast`（9 档） | 18 个裸 z-index，`90` 曾承担 4 种语义 |
| 触控 | `--tap-min: 44px` | 346 处 < 44px |

### 合并 8 组同义变量

`--ink`≡`--text-strong`、`--sub`≡`--text-muted`、`--line`≡`--border-soft`、`--cream`≡`--surface-cream`、`--surface-cream`≡`--surface-raised`、`--accent-purple`≡`--indigo` 等，原先各自独立声明同值，换肤时改一处漏一处就脱节。全部改为别名，建立单一真源（CSS 变量解析不受声明顺序约束，前向引用安全）。

## 五、可访问性

### pages.css 补动效降级

全站最大文件（553 个选择器）此前 **0 处** `prefers-reduced-motion`——而 `motion-tide.css` 有 22 处、`base.css` 有 2 处。补降级块，口径与 motion-tide 一致：**位移与循环动画全关，颜色/边框过渡保留**（避免界面生硬跳变）。

### 焦点环：改用 CSS 兜底而非逐个改 TSX

全站 55 处 `outline-none` 关掉了 `base.css:376` 的全局焦点环，改用 `focus:border-sky`（仅边框变色）——对键盘用户定位帮助远弱于 2px 描边。

**没有逐个改**：补 56 字符的 `focus-visible:outline-*` 会把原本 40~60 字符的 className 串顶到 **98~130 字符**，触发行宽门禁（80 列）；批量折行实测两次生成了 `"";` 语法错误。

改用 `base.css` 末尾的 CSS 兜底，零 TSX 改动、零行宽风险：

```css
input:focus-visible, textarea:focus-visible, select:focus-visible {
  outline: 2px solid var(--baozi-orange);
  outline-offset: 1px;
}
```

同时修了 `usercp-nav` 两处：`flex-direction` 重复声明（column 被 row 覆盖）、`a` 触控高度 40px → 44px。

## 八、本轮踩的坑

### `git checkout --` 批量回滚误伤

为修脚本生成的 `"";` 语法错误，批量回滚 43 个 web 文件——但 `pages.css` / `theme-tide.css` / `layout.css` / `usercp.tsx` 不在保留白名单里，**全部改动被一起撤掉**，得逐个精确 Edit 重施。

工作区有另一个会话在改 Rust 文件（`rss_http.rs` / `openapi.rs` / `compat_http.rs` 等），`git diff --name-only` 会看到它们的改动——未触碰。

## 九、补修（第二轮审计后追加）

第一轮修完后自查，发现 4 处遗漏与 1 处硬约束。

### 9.1 深色模式有第二处 `:root,`（子报告漏了）

`theme-tide.css` **两处**选择器带 `:root,`：

| 位置 | 内容 | 影响 |
|---|---|---|
| 24 行 | `:root, [data-theme="baozi"]` | 109 个色彩令牌覆盖夜间 |
| **674 行** | `:root, [data-theme="baozi"]` | **字体栈被强灌给夜间用户** |

第一轮只修了 24 行那处。674 行的字体块（`--font-display` / `--font-serif` / `--font-mono`）同样在污染夜间。

**修法**：两处都摘掉；且**夜间块必须显式声明三个字体栈变量**——摘掉 `:root` 后若不声明，夜间会掉回 `base.css` 的旧字体栈（这是本轮差点漏掉的一环）。

### 9.2 硬约束：`pages.css` 只能变瘦

`pages.css` 早已在行宽基线外（基线 3760，本轮开始时 3765）——**只许瘦不许胖**。而本轮要往里加：语法错修复、滑动层修复、降级块、forums 钩子、首页标签样式，合计 +63 行，直接触发门禁。

**解法**：把「Bottom Sheet 抽屉 + 筛选 FAB/Sheet」整块（105 行）从 `pages.css` 搬到新建的 `ui.css`。

这个搬迁是**顺理成章的**而非凑数：`components/bottom-sheet.tsx` 是通用浮层组件，它的样式本就不属 pages 域。且 `ui.css` 在 `globals.css` 里排在 `pages.css` **之后**加载——被搬的浮层（`z-index: 95` 的抽屉、45 的 FAB）优先级更高，正是想要的结果。

`pages.css`：3789 → **3675 行**（低于基线 3760，门禁 PASS）

### 9.3 上传页：5 种控件高度 + 必填选填无区分

实测高度分布：`28px` ×2 / `38px` ×5 / `44px` / `48px` / `64px`——五种高度混排。

| 类别 | 修法 |
|---|---|
| 输入框 / 按钮（28/38px） | 统一 `min-h-10`（40px，Tailwind 标度） |
| 拖拽区（44/48/64px） | 统一 64px |
| 必填 vs 选填 | 三处拖拽区 className **完全重复**，抽成 `.uf-drop` 基类 + `.uf-drop--required`（实线边框+强调底）/ `.uf-drop--optional`（虚线+降饱和）变体 |

抽基类一举两得：既统一了视觉，又让「必填/选填有视觉区分」从不可能变成可能。文件 289 → 290 行，仍在 300 限内。

### 9.4 种子列表表头：裸 emoji → 图标 + 可见文字

表头是 `💾` `🌱` `⬇️` `✅`，列名只藏在 `title` 属性里。而 i18n 字典里 `colSize`「大小」、`colSeeders`「种子」**早就存在**——只是没被用上。

改为「Icon + 可见文字」，窄屏（≤1024px）用 `clip-path: inset(50%)` 只留图标（文字仍在 DOM 与 `title` 里，屏幕阅读器可读）。

### 9.5 首页问候条：4 个数据格只有符号

`<md` 的问候条数据格只有 `↑ ↓ ∑ ★`，新用户判断不出 `∑` 是分享率、`★` 是魔力余额。改 `<dl>/<dt>/<dd>` 带标签（新增字典键 `mhome.up/down/ratio/spark`），三语同步。

### 9.6 门禁抓到了我自己

写 `ui.css` 时用了 `900px` 和 `1023px` 两个野断点，`ui_design_guard` 立刻 FAIL。**这正是建门禁的意义**——不是写完就信，是写完立刻被拦。

## 十一、根因级发现：娱乐屋夜间主题从未生效过

这一节是整轮修复里最重要的发现——**不是颜色写错，是整块规则从未匹配过**。

### 11.1 症状

令牌层修好后实测（无头浏览器逐元素量 computed background 亮度）：

| 页面 | 首轮发白元素 | 说明 |
|---|---|---|
| 首页 / 种子列表 / 论坛 / 我的 / 管理端 | 1 个（顶栏） | 顶栏 `rgba(255,255,255,.9)` 硬编码 |
| 娱乐屋 `/games` | **38 个** | 面积最大 17.3 万 px² |
| 种子详情 | 2 个 | body 报 200 万 px²（误判，实际是全屏白容器） |

把顶栏改成 `var(--chip-veil)` 后复扫：**5 个页面全部归零**，但娱乐屋仍有 28 个。

### 11.2 真因

`arcade-sweet.css` 里 32 条夜间覆盖写成：

```css
[data-arcade="sweet"][data-theme="baozi-night"] .gc-card { … }
```

**双属性选择器要求同一元素同时具备两个属性。** 但：

| 属性 | 挂载位置 | 出处 |
|---|---|---|
| `data-arcade="sweet"` | 内层 `<div>` | `(main)/games/layout.tsx:21` |
| `data-theme="baozi-night"` | `<html>` | `app/layout.tsx:125`（`ThemeNoFlash`） |

两者是**祖先-后代关系，永不相交**。这 32 条规则从写下那天起就从未匹配过。

而该文件头部注释还写着：

> 做法：① 用**双属性选择器**（特异性更高）把局部令牌换回深色；
> ② 皮肤里另有 13 处硬编码浅色…逐条兜底。

**兜底机制本身是失效的**——它以为自己生效了。

### 11.3 修法

全部改成后代选择器（中间有空格）：

```css
[data-theme="baozi-night"] [data-arcade="sweet"] .gc-card { … }
```

`arcade-gacha.css` 拆分时复制了同样的 bug（12 处），一并修正；另有 16 行是娱乐屋专属选择器（`.gc-*` `.sw-ten-*`）被误抽进 gacha 文件——`/gacha` 页面没有 `data-arcade` 属性，是死代码，已删除。

### 11.4 为什么静态检查抓不到

选择器写错**不报错、不告警、构建正常、运行时静默失效**。这类 bug 只能靠：
1. **实测**（量 computed style）发现；
2. **门禁**防止复发。

已给 `ui_design_guard.mjs` 加第 7 条规则：任何**相邻**双属性选择器（`[a="b"][c="d"]`，中间无空格）一律 FAIL。已做负向测试（注入后 FAIL、恢复后 PASS）。

> 第一版正则写成 `\]\s*\[`，把正确的后代选择器也误报了，收紧为 `\]\[`。

### 11.5 附带清理

顺带把 `arcade-sweet.css` 里 10 处 `background: #fff`（纯白底）换成 `var(--surface-card)`，硬编码色值 1180 → 1170。

## 十三、第二个根因级坑：CSS 注释里的 `/*`

### 13.1 症状

`docker compose build web` 失败：

```
Error: Unexpected '/'. Escaping special characters with \ may help.
    at /build/apps/web/static/css/4cfa5f31309245f1.css:1837:28
```

**但三道常规检查全绿**：

| 检查 | 结果 |
|---|---|
| `npx tsc --noEmit` | 0 错误 |
| `npx eslint`（我改的全部文件） | 0 错误 |
| 括号配平扫描 | 全部平衡 |

### 13.2 真因

注释文本里写了含 `/*` 的串，CSS 把它当作**新的注释开启符**：

```css
/* …但只服务 /games/*。/gacha 是独立抽卡模块… */
     ↑        ↑ 这个 /* 又开了一次
```

后续所有内容被吃掉，直到遇见下一个 `*/`。**三处踩到**：

| 文件 | 注释里的串 | 是谁写的 |
|---|---|---|
| `arcade-gacha.css` 文件头 | `/games/*` | 我（拆分脚本生成） |
| `arcade-sweet.css:4` | `/games/*` | 存量 |
| `globals.css:29` | `/games/*` | 我（注释娱乐屋搬移） |
| `arcade.css` | `.gc-*/.arc-*` | 我（夜间兜底注释） |

### 13.3 修法

注释里不写含 `/*` 的串，改用文字：

- `/games/* 路由` → `games 路由`
- `.gc-*/.arc-*` → `gc- 与 arc- 前缀`

### 13.4 门禁第 8 条

栈式扫描每个 CSS 文件的 `/*` 与 `*/` 配平，未闭合或多余即 FAIL。已做负向测试（注入 `/games/*` 注释后 FAIL、恢复后 PASS）。

**这是本轮第三次「静态全绿但运行时炸」**：

| # | 缺陷 | 为什么静态查不出 | 怎么发现的 |
|---|---|---|---|
| 1 | 双属性选择器不匹配 | 选择器语法合法，只是不匹配 | 无头浏览器量 computed style |
| 2 | 硬编码浅色不走令牌 | 语法完全合法 | 无头浏览器量背景亮度 |
| 3 | 注释里的 `/*` | 语法合法但语义错 | 真构建 |

**唯一可靠的验证是「真构建 + 真浏览器量 computed style」**，静态检查只能覆盖一部分。
