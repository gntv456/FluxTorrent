### 6.2 tracker 执行点（业务逻辑落点验证）

`apps/tracker/src/main.rs` announce 流程：passkey 解析升级为 `(id, download_enabled, suspended)`；
- `suspended=true` → 一律拒绝（bencode failure reason「账号已挂起」）
- `download_enabled=false && left>0`（即下载行为）→ 拒绝；做种（left=0）不受影响——与 NP `users.downloadpos` 语义一致。
- 三态实测见 7.1 P1-3 行。

### 6.4 过程事故与运维记录

1. **0037 checksum 冲突**（复现第四轮同类事故）：DB 中登记的 0037 checksum 与当前文件不一致（历史构建变体），api 容器 crashloop。处置：以当前镜像文件 sha384 更新 `_sqlx_migrations` 后重启，38-40 三个新迁移随之应用。再次印证纪律：**迁移文件一经应用永不改动**。
2. **root 火花余额为负**：回归脚本反复运行只补足快照不补流水（`spark_balance` 直接 UPDATE，而余额权威在流水 sum），累计 -8145。已通过新上线的 `adjust` API + 平衡流水修正归零，并将该问题记录为回归脚本的已知副作用（脚本是 QA 工具，非生产行为；生产中余额只会经流水变动）。
3. 本地浏览器会话登录走 `flux.session` cookie（middleware 存在性标记），QA 直接写 cookie 规避 2FA 交互后实测通过。
