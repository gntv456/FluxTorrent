## 1. 实测通过项

### 1.1 审核工作流
- 普通用户（新芽）发种 → `approval_status=0` 待审；管理 `/admin/reviews` 列表可见
- `decide(approve=false, reason)` → 种子被拒 + 发种人 `deny_count` +1
- `decide(approve=true)` → 种子过审 + `approve_streak` +1（连击免审的计数基础正确）

### 1.2 求种悬赏闭环（逐笔流水核对）
- 发单 bounty=300 → `spend_spark` 即时冻结 -300（幂等键 `req-bounty:{uid}:{rid}`）
- 应种人（须为种子发布者）fulfill → `task_reward` +300；求种单 `status=1` + `fulfilled_torrent_id`
- **自应自**：冻结 -100 → 退还 +100，完结后余额 == 发单前（净零，语义正确）
- 重放应种 →「该求种已处理」拒；**非发布者**拿别人 torrent_id 应种 → 拒（防悬赏盗领在位）

### 1.3 日常互动
- 评论 `POST /torrents/{id}/comments {body}`、点赞、感谢（`thanked:true`）
- 收藏 `PUT /torrents/{id}/bookmark {on}` 落库/取消对称
- 签到 +15（连续天数加成）、重复签到拒绝
- 个人对账：`sum(spark_ledger) == users.spark_balance` 成立

## 2. 发现的问题与修复

### 2.1 【P0-A】注册初始等级断链 —— 新用户「冷启动 5 分钟无权限」

**取证**：`repo/auth.rs register_user` 的 INSERT 不写 `class_id` → 落 DB 缺省 **0**（「种子」档，`role_permissions` 对 class 0 **零授权**）。`torrent.upload` 只授 class≥1 → 新用户注册后发种 403。数据库里存量用户全是 class 1，是因为 worker `class_auto_adjust`（300s 慢道）按 class_rules 把满足条件的 0 档提到 1——**新用户要等最长 5 分钟才获得基础权限**，且这期间站内欢迎 PM 还在引导「上传你的第一颗种子吧」。

**修复**：注册事务内读 `initial_class` 设定（缺省 1，clamp 0..89 防误配直通 staff），INSERT 显式写入；0272 迁移补设定键 + `settings_meta` 登记（后台「用户」组可改）。

**验证**：注册 → 立即查 `class_id=1` → 立即发种成功（无需等 worker）。

### 2.2 【P0-B】0266 orphan_offset 对冲行污染 root 余额

**取证链**（root 余额 -50599 的完整还原）：
1. 0266 迁移为对冲历史孤儿流水，在 root 名下插入 `kind='orphan_offset', amount=-52374`（注释明确「只作全站合计对账，不改个人余额」）
2. 但 `seeding.rs` 的个人余额重算公式是 `spark_balance = baseline + sum(该用户全部流水)`，**不区分对冲行**
3. root 当晚有游戏流水（2h 重算窗命中）→ 快照被重算为 365-52374 ≈ **-52009**
4. 之后游戏/签到在负数上继续滚动 → 深测时读到 **-50599**，悬赏/免罪等一切消费全部 409

**修复**：① 重算公式排除 `kind='orphan_offset'`（对冲行只参与全站合计对账，不进个人余额）；② 0272 按账本纪律（只追加）补 `+52374` 反向修正行，使 root「快照==流水」重新成立（无法删历史行）。

**验证**：`root.spark_balance == sum(流水 WHERE kind<>'orphan_offset')`；修正行幂等键在位。

### 2.3 【P2】自助免罪定价硬编码

`/me/hr/pardon` 的 `SELF_PARDON_PRICE=20_000` 常量与站点设定 `cancel_hr`（0266 前就存在、后台商店价格组可改、PM 文案里也写着 20000）脱节——后台调价不生效。改为读设定（坏值/缺省回落 20000）。

**验证**：`cancel_hr=100` 时免罪扣 100；恢复 20000。

### 2.4 【P2】批量促销非法值静默回落

`POST /admin/torrents/batch action=promo` 的 `promo_kind` 拼错（如 `2xfree`）会被 `unwrap_or("free")` 静默挂成 **free**——管理端无感知（三轮深测时实测踩中：x2free 挂成 free 导致计费首跑误判）。改为未知值 400 并列出合法值；未给值仍缺省 free（兼容）。
