# FluxTorrent 论坛视频内嵌策划案

> 版本：v1.2 · 日期：2026-09-25
> **实施状态：V1 + V1.5 + V2 全部落地并验收通过（18/18），未提交。**迁移 0189/0190 已在本地库应用；验收脚本 `_v_forum_video.py` 可重复跑。文件地图见 §11。
> **v1.2 增补：首页公告视频内嵌**（§12）——announcements 富文本链路经 ammonia 自定义配置放行白名单 iframe/video，域集合动态取 `video_embed_rules`，验收 10/10（`_v_news_video.py`），已随本次提交。
> 背景：论坛骨架（forums→topics→posts、三层权限、匿名、精华、已读、搜索、admin 管理、悬赏/投票/抽奖形态）已由 M15 + 论坛四期全部落地。本方案只补一件事：**帖子内嵌视频播放**。
> 结论先行：市面论坛三条路线——①外链白名单 embed（Discourse Onebox / Discuz `[media]` / phpBB s9e）、②本站上传 mp4 直映 `<video>`（Discourse 默认）、③FFmpeg 转码 HLS（Reddit 级大厂专属）。**本方案做 ①②，明确不做 ③**；①为先（成本低、零新依赖），②复用附件基建补三块短板（Range/独立配额/魔数校验）。

## 0. 一页结论

| 项 | 决策 |
|---|---|
| 内容格式 | 不新增格式。帖子正文已是安全 Markdown 子集（`forum-markdown.tsx` 零依赖 React 渲染器），视频用两个新语法接进去：显式 `!video(URL)` + 独立行白名单 URL 自动转换（Onebox 风格） |
| V1（P0） | 外链白名单 embed：`video_embed_rules` 表（正则→iframe 模板，后台可管、站型可配），前端渲染层 fail-closed（未命中白名单只出链接，永远不出 iframe） |
| V2（P1） | 本站上传视频：mp4/webm 直映原生 `<video>`，**不转码**。复用 attachments sha256 基建，补 Range/206、独立视频配额、mp4 魔数校验、前端抽时长+封面 |
| V3（不做） | 自建 FFmpeg 转码 HLS/DRM。预留 `provider='external'` 字段，真有需求接 Cloudflare Stream / 阿里云 VOD 托管 |
| 模块开关 | **不新增 modules 键**（0178 中立矩阵 29 键不动），用 `site_settings` 两开关：`forum_video_embed` / `forum_video_upload`，随站型包走 |
| 生态商店 | V1.5 里程碑：`content_packs.kind` 扩 `'embed'`，视频 embed 规则成为可上架规则包品类（国内站型带 B 站、海外站型带 YouTube），口径同 0173 assets 包 |
| 迁移编号 | V1 = `0189_video_embed.sql`，V2 = `0190_video_attachments.sql`（0188 category_tree 之后顺延） |
| 安全红线 | 用户永远不能直接产出 iframe/任意 src；iframe 只能由"URL 正则匹配白名单→固定模板"生成，生成后再验一次 embed 源域；上传走魔数+独立配额+频率限制 |

## 1. 现状盘点（证据）

### 1.1 发帖链路（已存在，本方案不改）

- 表：`forums` → `topics` → `posts`（0001，posts 按 created_at RANGE 分区，主楼=首帖，回帖 `reply_to` 楼中楼 0163）。
- 写入：`community_http/topic_create.rs`（发主题）、`post_write.rs`（回复）、`post_edit.rs`（编辑）。正文存 Markdown 原文，`strip_markdown()` 压纯文本进 `posts.body_text` 供搜索/列表预览——`!video()` 语法需要在 `strip_markdown` 里当链接处理（见 §3.6）。
- 前端：`forum-composer.tsx`（TopicComposer，含标签/悬赏/投票/抽奖形态）、`forum-reply-box.tsx`。
- 权限：`forum_access()` 三档 + `forum_mods` + `postmanage(90)/forummanage(93)`，视频能力全部挂在这套权限之下，不另起。

### 1.2 渲染层（本方案主战场）

- `apps/web/components/forum-markdown.tsx`（267 行）：行级 block 解析（fence/标题/引用/列表/hr）+ `INLINE_RE` 行内（粗斜删码/链接/@提及）。**全 React 元素输出，无 dangerouslySetInnerHTML，天然防 XSS**；`SAFE_URL` 只放行 http(s)/mailto/站内绝对路径。
- 视频能力 = 在此加两类 block：`!video(URL)` 显式语法 + "整段恰为一个白名单视频 URL"自动转换。渲染为 React `<iframe>` / `<video>`，同样不碰 innerHTML。
- 行数门禁：新渲染逻辑拆独立组件 `forum-video-embed.tsx`（300 行内），markdown 主文件只加识别分支。

### 1.3 附件基建（V2 复用 + 补短板）

- `attachment_http.rs`：sha256 内容寻址、全站去重、`attach_quota_mib` 配额（默认 512MiB）、storage 本地/S3 双后端。
- **三个短板**（V2 必须补）：
  1. `ATTACH_MAX_BYTES = 8MiB` 全局单文件上限——视频需独立上限；
  2. `GET /attachments/{sha}` 全量 `body(bytes)` 读内存返回——**无 Range/206**，`<video>` 拖进度条会整文件重下；
  3. mime 白名单在字幕端把关，通用附件侧无视频格式魔数校验。

### 1.4 模块与站型接缝

- 模块网关 `modules/gateway.rs`：`/api/v1/forums` → `key::FORUMS`；0178 中立缺省矩阵 29 键 forums=true。视频端点若挂在 `/api/v1/forums` 前缀下自动继承门控，无需动注册表。
- 生态商店：`content_packs.kind ∈ (taxonomy, theme, rules, assets)`，纯覆盖 + payload.tables 键白名单（0173 口径）。
- 后台设置：`site_settings` + `settings_meta` + `/admin/settings` GET/PUT + settings_http 分域（history/export/import）。

## 2. 三路线取舍（为什么是 ①+②）

| 路线 | 成本 | 代表 | 取舍 |
|---|---|---|---|
| ① 外链白名单 embed | 低：一张规则表 + 渲染分支，零服务器开销（流量在视频平台） | Discourse Onebox、Discuz `[media]`、NodeBB ns-embed、phpBB s9e | **V1 做**。PT 站帖子里 90% 的视频是 B 站/YouTube 链接，这条覆盖绝大部分需求 |
| ② 本站上传直映 | 中：Range 流式 + 独立配额 + 魔数校验 + 前端抽元数据；**不引 FFmpeg** | Discourse 默认（上传 mp4 原生播放器）、Flarum fof-upload | **V2 做**。少量站内自制内容（教程、发布会录屏）需要；存储/流量站点自扛，靠配额+频率限制兜住 |
| ③ 上传+转码 HLS | 高：FFmpeg 集群、多码率切片、AES-128 防盗链、hls.js | Reddit v.redd.it、X | **不做**。独立论坛没人自建这层；真到那量级直接接 Cloudflare Stream / Mux / 阿里云 VOD，V3 预留字段即可 |

依据：论坛四期策划案（`_doc/论坛版块完善策划案.md` §4 Phase 0 已定 Markdown 基座）+ 本次对 attachment/markdown/gateway 的代码盘点（§1）。

## 3. V1：外链白名单 embed（P0）

### 3.1 数据模型 —— `0189_video_embed.sql`

```sql
CREATE TABLE IF NOT EXISTS video_embed_rules (
  id           BIGSERIAL PRIMARY KEY,
  provider     TEXT NOT NULL,              -- 'bilibili' / 'youtube' / 'self' ...
  name_zh      TEXT NOT NULL,              -- 后台展示名
  url_pattern  TEXT NOT NULL,              -- 正则（源串匹配），必须 ^https?:// 域名字面量开头
  embed_template TEXT NOT NULL,            -- iframe src 模板，$1..$9 引用捕获组
  embed_origin TEXT NOT NULL,              -- 生成 src 的合法前缀（二次校验）
  render_kind  TEXT NOT NULL DEFAULT 'iframe' CHECK (render_kind IN ('iframe','video')),
  aspect       TEXT NOT NULL DEFAULT '16:9' CHECK (aspect IN ('16:9','4:3','1:1')),
  extra_params TEXT,                       -- 追加到 src 的固定 query（如 &autoplay=0）
  builtin      BOOLEAN NOT NULL DEFAULT FALSE,  -- 内置规则可停用不可删（同 0176 builtin_assets 口径）
  enabled      BOOLEAN NOT NULL DEFAULT TRUE,
  sort         INT NOT NULL DEFAULT 100,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

内置种子（builtin=true）：B 站（`^https?://(www\.)?bilibili\.com/video/(BV[0-9A-Za-z]+)` → `https://player.bilibili.com/player.html?bvid=$1`）、YouTube（`watch?v=|youtu\.be/` → `https://www.youtube-nocookie.com/embed/$1`）、Vimeo。`render_kind='video'` 预留给直链 mp4 站点与 V2 站内附件。

设置行（`site_settings`）：`forum_video_embed = 'yes'`（总开关，缺省 yes）。

### 3.2 渲染链（核心安全设计）

```
用户正文（Markdown 原文，DB 不动）
  ↓ forum-markdown.tsx 识别：!video(URL) 显式语法 / 整段恰为 URL 的段落
  ↓ 与 GET /api/v1/forums/embed-rules 返回的启用规则逐条 url_pattern 匹配
  ↓ 命中 → 捕获组代入 embed_template 生成 src
  ↓ 二次校验：src 必须以该规则 embed_origin 开头（防正则/模板组合出逃逸）
  ↓ render_kind=iframe → <iframe sandbox="allow-scripts allow-same-origin allow-presentation"
  ↓                      loading="lazy" referrerPolicy="strict-origin-when-cross-origin">
  ↓ render_kind=video  → <video controls playsinline preload="metadata">
  未命中任何规则 → 渲染为普通 <a> 链接（fail-open 链接 / fail-closed iframe，二者必居其一）
```

要点：

1. **iframe 永远是数据驱动生成的，用户产不出任意 src**。React 元素输出，无 innerHTML。
2. 二次校验是纵深防御：即使管理员配了坏正则，src 也被 embed_origin 前缀兜住。
3. **懒加载两段式**：首屏只渲染封面占位（16:9 容器 + provider 图标 + 播放钮），点击才挂 iframe——一页多视频不被平台 JS 拖慢（Discourse 同款策略）。
4. `sandbox` 不加 `allow-top-navigation`/`allow-popups`；CSP 建议在反代层加 `frame-src` 白名单（见 §6.4）。

### 3.3 API

| 端点 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/api/v1/forums/embed-rules` | GET | 启用规则的公开只读列表（前端渲染用，可缓存） | 登录（forums 前缀自动过模块网关） |
| `/api/v1/admin/embed-rules` | GET/POST | 列全量 / 新建（保存时服务端编译正则、校验 `^https?://` 域名字面量开头、模板 $n 引用数 ≤ 捕获组数） | forummanage(93) |
| `/api/v1/admin/embed-rules/{id}` | PUT/DELETE | 改/删（builtin 只许 PUT 停用，DELETE 拒） | forummanage(93) |

后端新文件 `community_http/embed_rules.rs`（用户侧）+ `staff_http/embed_rules.rs`（管理侧），沿用 `staff_http/custom_pages.rs`（0187）刚趟过的拆分模式。

### 3.4 Composer 插入体验

- 工具栏加"视频"按钮：弹层贴 URL → 前端拿 embed-rules 试匹配 → 命中出 16:9 预览缩略 + 「插入」；未命中提示"该站点不在支持列表，将作为普通链接"。
- 插入产物即 `!video(URL)` 独立行。自动转换（裸链接整段）作为兜底共存，两者渲染结果一致。
- i18n：文案进 `dict.forums.*`（i18n 门禁纪律）。

### 3.5 站型与生态商店（V1.5 里程碑）

- `content_packs.kind` 扩 `'embed'`（一条 ALTER，同 0173 先例），`payload.tables` 键白名单放行 `video_embed_rules`，apply 走既有纯覆盖路径。
- 站型货架：国内教育/影视站型包默认带 B 站/腾讯视频规则，海外站型带 YouTube/Vimeo，general 中立包只带 builtin 三条且可整体停用——与 0178 缺省翻转纪律一致（中立站不偏向任何平台生态）。

### 3.6 周边适配

- `strip_markdown()`（forum_perm.rs）：`!video(URL)` 压成 `URL` 纯文本，搜索/列表预览不丢信息也不出乱码标记。
- RSS（rss_http/forum.rs）、feed、搜索快照消费 `body_text`，天然不受影响。
- 帖子编辑重渲染：正文存原文，规则后续增删 → 旧帖重渲染自动按最新规则走，无迁移。

## 4. V2：本站上传视频直映（P1）

### 4.1 上传链路（复用 attachments）

```
composer 上传按钮 → POST /api/v1/attachments/video (multipart)
  ① 独立单文件上限 site_settings.video_max_mib（缺省 200，0=禁用）
  ② 独立配额 video_quota_mib（缺省 2 GiB/人，与 attach_quota_mib 分账，防一个视频吃光图片配额）
  ③ 魔数校验：mp4 必须在 offset 4 处命中 'ftyp' box；webm 验 EBML 头 0x1A45DFA3
     （扩展名/mime 声明均不可信；沿用字幕附件三层校验纪律）
  ④ 频率限制：每人每日 N 条（缺省 5，复用 forum_flood 思路或 redis 计数）
  ⑤ sha256 入库 attachments（mime='video/mp4'），metadata jsonb 记 duration/width/height/poster_sha
  → 返回 sha → composer 插入 !video(/api/v1/attachments/{sha})
```

元数据**不引服务端 FFmpeg**：上传前浏览器端用 `<video>` + `canvas` 抽 duration/分辨率/首帧（首帧转 blob 走既有图片附件路径存 poster_sha），随表单一并提交；服务端魔数校验兜底真伪。后续若需要服务端强校验（时长上限防刷），再评估引 ffprobe（单二进制、只读元数、不转码，成本可控，列为可选加固项不阻塞 V2）。

### 4.2 服务端 Range 支持（`<video>` 可拖进度条的硬前提）

`GET /attachments/{sha}` 增强：

- 支持 `HEAD`；
- 支持 `Range: bytes=start-[end]` → `206 Partial Content` + `Content-Range` + `Accept-Ranges: bytes`；无 Range 时维持 200 全量（兼容现图片路径）；
- 本地后端：按 `storage::local_path` 打开文件流式读区间（`futures::stream` 分块，不整读内存）；S3 后端：GetObject 带 Range 参数；
- ETag 用 sha（内容寻址天然正确），`Cache-Control` 维持 immutable；
- 认证维持 require_auth（flux_token cookie 根路径，`<video src>` 同源请求自动携带，架构已支持）；视频文件名对无权限用户 404。

实现落点：`attachment_http.rs` 拆 `serve.rs`（行数门禁），路由不变。

### 4.3 渲染

- 内置 `self` 规则（0189 一并种子）：`url_pattern = '^/api/v1/attachments/([0-9a-f]{64})$'`，`render_kind='video'`，`embed_origin='/api/v1/attachments/'` → 走 §3.2 同一条管线出 `<video controls playsinline poster="{poster_url}" preload="metadata">`。
- 站内相对路径本就被 `SAFE_URL` 放行，无 CORS/域问题。
- 每帖视频数上限（缺省 3，前端 composer 计数 + 后端 `!video` 出现次数校验），防一帖塞十几条视频拖垮移动端。

### 4.4 设置与开关

`site_settings`：`forum_video_upload`（缺省 **no**，中立缺省纪律：重资源能力默认关，站型包显式开）、`video_max_mib=200`、`video_quota_mib=2048`、`video_daily_limit=5`、`post_video_max=3`，均登记 `settings_meta`（forum 组卡片），后台 `/admin/settings` 直接可调。

## 5. V3：托管点播预留（不做自建转码）

- `video_embed_rules.provider` 允许 `external:*` 前缀 + `render_kind='iframe'` 已能表达 Cloudflare Stream/Mux 的 embed 语法——接入时只是"多一条规则 + 上传侧多一个外部回链表单"，无架构改动。
- 明确不做：FFmpeg 转码集群、多码率 HLS 切片、AES-128 分片加密、DRM。判定依据：独立 PT 站的视频内容量撑不起转码集群的固定成本，且流量峰值在 BT 生态自身。

## 6. 安全红线清单（评审逐条过）

1. **用户不能产出任意 iframe/video src**：iframe 只能由白名单规则模板生成，`!video(未命中URL)` 降级为链接。
2. **模板代入后二次校验 embed_origin 前缀**：坏正则/坏模板组合无法逃逸到任意域。
3. iframe 属性固定：`sandbox="allow-scripts allow-same-origin allow-presentation"` + `loading="lazy"` + `referrerPolicy`；不加 allow-top-navigation/allow-popups。
4. **CSP**：反代（或 next 端）加 `Content-Security-Policy: frame-src https://player.bilibili.com https://www.youtube-nocookie.com https://player.vimeo.com 'self'`——与 embed_origin 白名单互为冗余；规则表新增 provider 时后台提示同步 CSP（文档化运维项，写进建站运维手册）。
5. 上传魔数校验（ftyp/EBML），扩展名与声明 mime 仅作展示；视频 mime 白名单只有 `video/mp4`、`video/webm`。
6. 独立配额 + 每日频率 + 每帖条数三层限额，防存储/流量滥用。
7. `<video>` 自动播放一律 `muted` + `playsinline`（移动端合规）。
8. 附件服务维持登录态（无匿名视频直链）；`poster` 走既有图片附件同权限路径。
9. embed-rules 管理侧写操作全部进 audit_log（站型派生值架构的排查纪律：先看 audit_log 写入路径）。
10. 服务端保存规则时正则编译校验 + 限长 + 必须域名字面量锚定，防 ReDoS。

## 8. 验收清单（摘）

**V1 功能**：A1 发主题贴 B 站链接自动出播放器；A2 `!video()` 显式语法；A3 未命中白名单降级链接；A4 一帖多视频懒加载（首屏无 iframe 请求）；A5 builtin 规则停用生效；A6 后台新建规则（含坏正则被拒）；A7 编辑旧帖重渲染跟随新规则；A8 `forum_video_embed=no` 时全站降级链接；A9 搜索预览 body_text 不含 `!video` 标记。
**V1 安全**：A10 `!video(javascript:alert(1))` 无效化；A11 恶意规则模板（外域 src）被 embed_origin 拦截；A12 iframe sandbox 属性存在性断言。
**V2 功能**：B1 上传 200MiB 内 mp4 成功、超限拒；B2 伪 mp4（改扩展名的文本）魔数拒绝；B3 `<video>` 拖动进度条仅请求对应 Range（断言 206 与 Content-Range）；B4 配额分账（视频不吃图片配额）；B5 每日频率限制；B6 poster 与时长正确展示；B7 未登录直拉附件 401。
**V2 安全**：B8 webm 头校验；B9 每帖第 4 条视频被拒；B10 `forum_video_upload=no` 时上传端点 403。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 平台 embed 改版（B 站换 player 参数） | 规则表后台可热改，不动代码；builtin 规则跟随版本升级种子 |
| 移动端 iframe 兼容（微信内置浏览器拦截外域 iframe） | 两段式点击加载天然规避批量加载问题；真拦截时用户仍可点"原链接观看"（占位卡保留原文链接出口） |
| 大视频流量滥用 | 三层限额 + 缺省关（forum_video_upload=no）+ 中立站型不带开箱即用 |
| ReDoS / 坏正则 | 保存时编译校验 + 域名字面量锚定 + 限长（§6.10） |
| attachments Range 改造影响现图片路径 | 无 Range 头维持 200 全量语义不变；契约测试补 HEAD/Range/无 Range 三例 |

## 10. 结论

- V1（外链 embed）零新依赖、1.5 天可上线，覆盖 90% 场景，且把"规则表 + 渲染管线 + 安全二次校验"的地基一次打好；
- V2（站内上传）是对既有附件基建的三处精准补强（Range/配额/魔数），不引 FFmpeg，浏览器端抽元数据；
- 转码路线明确不做，托管点播以规则表形态天然预留；
- 与站型/生态商店/模块网关/中立缺省四条既有架构纪律全部对齐，无新增模块键、无矩阵改动。

**实现期三个坑（后续维护须知）**：
1. `setting_i64` 读开关：site_settings 里开关值是 'yes'/'no' 而非数字，直接 `::bigint` 会 SQL 报错（表现为 500/403 摇摆）——已改为 CASE 翻译后转换；

## 12. v1.2 增补：首页公告视频内嵌

**现状**：announcements 是管理员写富文本 HTML → ammonia 白名单消毒 → 首页弹窗 `dangerouslySetInnerHTML` 渲染，默认白名单无 iframe/video，视频贴了也剥。

**改法**（新文件 `http/home_news.rs`，home.rs 308→283 瘦身符合"只许瘦不许胖"）：

- `announcement_clean()`：ammonia 默认配置 + 放行 `iframe`/`video`/`source` 标签及各自属性（src/allow/sandbox/loading/frameborder/controls/poster 等；srcdoc 不在白名单天然被剥）；
- `attribute_filter` 按 `video_embed_rules.enabled` 的 **embed_origin 集合**校验 iframe/video/source 的 src 与 video 的 poster：绝对 URL 比对 **authority 整段 host**（防 `player.bilibili.com@evil.com` 前缀伪装逃逸），站内相对路径比对 origin 前缀；规则集为空 → src 全剥（fail-closed）；
- **不用 ammonia 的 `allowed_domains`**：它是全局 URL 域限制，会把公告里的普通外链/外域图片一并剥掉；
- embed 规则写路径（后台 CRUD + embed 包 import）接 `invalidate_home_cache`——公告白名单随规则即时生效（写失效式，Gazelle 范式）；
- 前端弹窗加 Tailwind 任意子代选择器（`[&_iframe]:aspect-video [&_iframe]:w-full`）做全宽 16:9 响应式，不动已超限的 pages.css；
- 公告编辑器（content-manage）加提示文案：可贴白名单平台 `<iframe>` 或站内附件视频 URL。

**安全模型**：消毒 + 域白名单双保险（比论坛 React 管线多一层服务端消毒）；`javascript:` 由 ammonia 默认 scheme 检查剥离；测试证明普通外链/外域图片不受牵连。

**验收**（`_v_news_video.py` 10/10，8090 实例）：白名单 iframe 过、前缀伪装域剥、javascript: 剥、外链/外图不受牵连、停用规则后已缓存公告 src 即时消失（缓存失效验证）、恢复即时回来。
