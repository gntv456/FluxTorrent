## 一、一句话结论

三处 FAIL 同一根因，**是测试不自洽，不是产品 bug**：脚本要求「两个字节完全相同的请求」
一个被拒、一个成功，而服务端没有区分依据。

## 二、根因（`scripts/e2e_arcade_farm_land.py`）

第 **180 / 188 / 191** 行发的是**完全相同**的请求：`POST /farm/land/upgrade {"slot": 3}`，
且都不带幂等键。却要求：

| 行 | 请求 | 期望 | 实际 |
|---|---|---|---|
| 180 | `{slot:3}` | 200，level=2（Lv.1→2） | 200 level=2 ✓ |
| 188 | `{slot:3}`（同一字节） | **400（当成重放拒掉）** | **200 level=3**（当成新升级扣了 1600） |
| 191 | `{slot:3}`（同一字节） | 200，level=3，cost=1600 | 200 level=4，cost=2560 |

服务端面对第 188 行时看到的是「当前 Lv.2、请求升级 slot 3」——
它没有任何依据把这次调用和「上一次 Lv.1→2 的重试」区分开。
**要区分只能由客户端传幂等键**，而脚本没传。

### 第 3 处 FAIL 是连带，不是独立问题

`(400, 240, {})`：因为第 188 行多升了一级，root 的余额被多扣一笔，
紧接着的 `/farm/plant` 因**余额不足**返回 400 —— 断言拿到的 `minutes` 自然是空。

## 三、确属加固缺口的一处（你们的 handler）

`apps/api/src/games_http/farm_land_write.rs`：

```rust
let from = land.level(body.slot);                        // 读的是服务端当前等级
let idem = format!("farm-up:{}:{}:{}", auth.id, body.slot, from);
```

- **并发双击能挡住**（两个请求都读到 `from=1` → 同键 → 第二个 Replayed）。
- **顺序重试挡不住**：第一次成功后等级已变，重试再算出的键**不同** → 当成新的一次升级
  再扣一笔。即「响应丢失后客户端重试」会导致**多升一级且多扣一次钱**。
- 目前不是活跃 bug（客户端 `api.post` 不自动重试），但**客户端没有重试安全的手段**。

**对照**：同域其它端点（`scratch`/`casino`/`capsule`/`wheel`/`pets`/`fishing`/`item_use`…
见 `grep -rln "idempotency_key" apps/api/src/games_http/*.rs`）都收客户端键。
`farm_land_write.rs` 是**唯一**不收的那个文件。
注意同批里买地那条**碰巧是对的**（`farm-land:{uid}:{slot}` 绑的是稳定字段槽位），
只有升级绑了会变的等级才暴露 —— 别因为一半对就以为整批没问题。

## 四、脚本自身 bug（阻断了最后三条断言）

`scripts/e2e_arcade_farm_land.py` 第 **211-215** 行：

```python
psql("INSERT INTO farm_plots (user_id, slot, crop_id, planted_at, "
     "ready_at, watered) VALUES (%d, %d, %d, now() - interval '2 "
     "hour', now() - interval '5 minute', FALSE) ON CONFLICT "
     "(user_id, slot) DO UPDATE SET crop_id = %d"
     % (uid, slot, cid, uid, slot, cid))          # ← 4 个 %d，却给了 6 个实参
```

→ `TypeError: not all arguments converted during string formatting`，脚本当场退出。

**修法**：`% (uid, slot, cid, cid)`（占位符只有 4 个：INSERT 三个 + `SET crop_id` 一个）。
