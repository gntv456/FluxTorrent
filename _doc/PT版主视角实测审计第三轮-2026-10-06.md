# PT 版主视角实测审计 · 第三轮（2026-10-06）

轴：H&R 与作弊判定的**质量**、日常运营链闭环、生产运维（备份/升级/多副本/可观测）。
前两轮见 `_doc/PT版主视角实测审计-2026-10-05.md`、`_doc/PT版主视角实测审计第二轮-2026-10-06.md`。

标注：**【实测】**＝我读了落地 SQL/代码并确认成立；**【线报】**＝并行排查得出、我未逐条复验。

本轮的判据不是「功能有没有」，而是版主要敢信这个判定：
**误判会把无辜会员推向封禁，漏判会让白嫖者白拿激励。**

## 一、H&R：三处会直接伤会员，一处会放过白嫖

### P0-1 版主手动冻结的下载权限，5 分钟内被作业自动放开【实测 → 已修】

`apps/worker/src/jobs/hr.rs` 的恢复段（旧注释自己写着「不区分当初被禁原因……
极小概率把其他原因禁用的账号一并恢复」）：只要 `hr_violations` 未解决数低于阈值，
就把 `download_enabled` 一律置 TRUE。而版主冻结作弊嫌疑账号写的**是同一列**
（`admin_http/user_status.rs` 的 flags），该作业 5 分钟一跳
⇒ **版主的冻结形同无效**，且放开时不发任何通知、不留任何痕迹。

修法：`users.download_locked_by`（0286）记下锁来源，`staff` / `hr` / `ratio_watch`
三类各自只解自己下的锁；管理组手动锁的必须人工解。
Ratio Watch 侧同步补上「自己锁的自己收尾」——否则我改完 hr.rs 之后，
被观察期停下载的人将永远无人放开（这条连带回归是我自己差点制造的）。

### P0-2 违规通知承诺「持续做种自动消除」，但代码里没有这条路径【实测 → 已修】

`hr_violations.resolved_at` 只有人工 Pardon 才写；`hr.rs` 达标只把
`hr_snapshots.status` 推到 `satisfied`，**已落的违规记录永远挂着**。
而违规 PM 与封禁 PM 都向会员写着「①持续做种达标后违规自动消除」
⇒ 承诺是假的：逾期后才补够做种的人，背着旧违规往 3 次阈值累计，最终被停下载。
修法：新增 `hr_resolve::resolve_met_violations`——按 snatch 现值回判，
达标即消除违规、把 violated 快照改回 satisfied，并回签一条「违规已消除」站内信。

### P0-3 `enable_hr` 是假开关【实测 → 已修】

后台 `yesno` 控件能改，`hr.rs` 从不读它 ⇒ 站长关掉「启用 H&R」，
作业照样建快照、照样判违规、照样停下载。按项目口径「要么真生效要么删」，
本次接真：`no` 时整段跳过（不建快照、不判违规、也不自动恢复）。

### P1-4 新鲜度窗口硬编码 6h，长 announce 间隔站点人人误判【实测 → 已修】

刷新 `seeded_seconds` 的条件是 `s.last_seen_at > now() - interval '6 hours'`，
而 `announce_interval` 允许配到 86400s（站点统一的僵尸判定函数
`sweep::stale_peer_threshold_secs = max(2h, 2×interval)` 就摆在旁边没人用）。
⇒ 间隔 > 6h 的站点，认真做种的人秒数永远刷不进去，到期一律判违规。
修法：改用统一函数。

### P1-5 H&R 对未过审/回收中的种子照样记责任【实测 → 已修】

建快照的 SQL 只 join `torrents` 不过滤 `approval_status`
⇒ 待审、被拒、回收站里的种子同样给会员记义务；
反过来删种子会级联掉证据与违规（`0020_gap_features.sql` 的 ON DELETE CASCADE），
所以「回收」等于悄悄免单。修法：建快照只认 `approval_status = 1`。

### P0-6 幽灵做种的守卫是「两个否定条件都要成立」【实测 → 未修，需口径】

`seeding.rs:60` 的守卫是 `NOT (connectable = 0 AND uploaded = 0)`，
而 `connectable` 缺省按「可达」入库（未探测 = 1）⇒
只要客户端自报 `uploaded ≥ 1`（BEP3 里这就是个自报数），
挂 `left=0` 不动也能拿全额时魔；`class_adj.rs` 的晋升又按**终身**
`sum(seeded_seconds)` 计 ⇒ 幽灵时长能买等级，且降级永不触发
（四个指标全是单调不减的终身量，`class_adj.rs:158-187` 的降级分支实际不可达）。
这一条与第一轮记过的「`left` 完全由客户端自报」同根。
**为什么不一行改掉**：把守卫改成「必须有正证据」会误伤 NAT 后的大多数正常做种者
（探测覆盖率见下），需要先定「什么算证据」的口径。

### P1-7 探测覆盖率是个误差项【线报，量化待复验】

每 300s 抽 50 个 peer、串行 3s 超时 ⇒ 约 14400 次/天；
2 万常驻做种者扫完要 ~33h > 24h，且 `sample_probes` 按 DashMap 顺序在配额处 break
⇒ 后面的 swarm 可能长期轮不到，探测预算还花在已死 peer 上（无 GC）。
结论：`connectable` 目前不能作为「真在做种」的证据，只能作为反证。

### P1-8 作弊事件是只读清单，没有裁决工作台【实测（消费面）】

`cheat_events` 有 5 个生产者（超速/黑名单/回连/间隔异常/登录 IP 跳变），
唯一消费者是 `GET /admin/cheat-events`——无筛选、无状态位、无处置动作、
会员也看不到自己被调查。我上一批新增的 `over_ceiling`（超物理上限被扣量）
**同样没有任何接口去复核并发还**，而代码注释写着「供管理组复核后用补量接口发还」。
⇒ 需要一张「待核 → 放行/扣回/免罪」的队列表，否则扣量等于误伤无申诉。

### P1-9 赦免不可审计、不可撤销【线报】

三处 Pardon 路由都要求填 `note`，然后把它丢掉（审计只写 actor+torrent_id，
批量 500 条那条连 target 都是 `None`）；且建快照条件是
`NOT EXISTS hr_snapshots(user,torrent)` ⇒ 赦免过的 (人,种) 永不重新追责。

## 二、运营链：三处「钱/荣誉」对不上账

### P0-10 捐赠档位按**单**发放，而档位按**累计**判定【实测 → 已修】

`payment/tiers.rs` 的 CAS 键是 `payment_orders.tier_granted`（每单一个），
`match_tier` 取的却是累计实付的最高档
⇒ 跨过 $10 之后**每一单都再发一遍同档奖励**（魔力 + 上传量 + 邀请码 + 勋章）。
小额多次捐赠＝无限复领，且邀请码可用来开小号。
修法：新增 `user_donation_tiers(user_id, min_usd)` 主键台账，按 (人, 档) 只发一次。
顺带修掉同一函数里 `traffic_ledger.torrent_id` 用 `0` 当哨兵的写法（0285 起该列可空）。

### P1-11 促销倍率无法事后追溯【实测 → 已修】

`traffic_ledger.promotion_kind` 自 0001 建表就是死列（`SMALLINT DEFAULT 0`，无人写）。
⇒ 免费/双倍活动到底给谁记了多少，没有任何依据可查；
会员投诉「我下载时明明是免费时段」只能靠人肉比对时间。
修法：`jobs/promo_audit.rs` 按 `promotion_kind_enum` 标签序写入，
并把「种子级 + 全局」两条同时生效时的出处一起记进 `reason`。

### P1-12 其余运营链缺口【线报，逐条待复验】

- 官种撤销漏收尾：批量 `clear_tags` 只删 `tags` 行、不调 `sync_official_tag`
  ⇒ 被摘官种的种子仍享受 `scope='official'` 免费与自动置顶。
- 竞赛是死链：`contest_entries.score` 无任何写入方，无后台 CRUD、无结算作业
  ⇒ 榜永远 0 分，版主只能进库改。
- 字幕：`subtitle_requests.status=2（已撤销）` 无人可置 ⇒ 冻结的赏金永不退回；
  worker 自动验收路径漏发 `offer_free` 促销且不写审计；
  自评无作者校验（自己给自己打 10 分同时喂奖励分与自动认证）；
  认证撤销会被下一轮小时级自动作业 `revoked_at = NULL` 覆盖回去。
- 促销：无预算上限、删除/清空活动不退款、`promo_purchases` 只被一个删除守卫读过
  （用户端与后台都看不到自己的购买史）。
- 复活：奖励硬编码 5000、`torrent_id` UNIQUE ⇒ 同一死种一生只能复活一次，
  单人任务无过期路径（认领人消失即永久锁死），原上传者既不受理也不计分，
  `rescue_honor` 写了没人读。
- 群发：只按 `status<2` 全量发，不看 `notice_prefs`、不看模块开关、不可撤回，
  列表查询不返回 body ⇒ 事后说不清自己发过什么。
- 求种：后台看不到「哪个分类积压多少未满足需求」（这是站方最该看的采购信号），
  发布者拿到命中也没有结算与关闭动作（唯一「完成」手段是删除）。
- 死表/单向表：`seed_milestones`、`rescue_honor`、`promo_purchases` 只写不读；
  `auto_promo_rules` 只读不写（且没有任何入口能写它 ⇒「过审自动挂免费」永不生效）。

## 三、运维：备份按钮是坏的，恢复只有一半

### P0-13 后台「立即备份」在出厂镜像里必然失败【线报，代码事实清楚】

`admin_p3_http/ops.rs` 默认命令是 `docker exec flux-postgres pg_dump …`，
而 api 运行镜像只装了 `ca-certificates wget`（`docker/api.Dockerfile`）
——没有 docker CLI，也没有 pg_dump ⇒ 点按钮 500。
唯一可用路径是宿主 cron 跑 `scripts/backup.sh`。

### P0-14 恢复只覆盖数据库，附件与 Redis 无处可回【线报】

`backup.sh` 产三样（pg_dump / 附件卷 / redis），`restore.sh` 只吃第一个；
`--force` 恢复后附件卷是空的（所有种子文件/NFO/头像 404），
未消费的 `flux:announce`/DLQ 也丢了（备份脚本自己的注释说这些必须备）。
手工塞 `dump.rdb` 也不行：redis 开了 `appendonly yes`，7 版优先读 appendonlydir。

### P1-15 其余运维要点【线报】

- 备份无调度、无演练：worker 任务目录里没有 backup 任务 ⇒ 漏跑一夜没有
  `job_status`、没有 `runtime_logs`、没有告警；`backup_drill.py` 存在但没人跑。
- 回滚＝「恢复旧 dump」＝数据丢回上一次备份点；0266 的审计链触发器
  禁止任何 `audit_log` UPDATE/DELETE ⇒ 旧镜像跑在新 dump 上，任何审计写入即炸。
- 计费链路 fail-open 且**无计数**：tracker `xadd` 失败只 warn 就丢事件，
  消费者 `XTRIM Approx(10000)` ⇒ worker 一慢，未计费的尾部被直接删掉；
  而告警阈值设的是 100000，数学上永远不触发。同期 api 限流是 fail-close，
   polarity 相反：整站在 5xx，tracker 还在静静吞计费事件。
- DLQ 无界：全仓只有 `RPUSH` 没有 `LTRIM`（本轮已修，保留最近 5000），
  配上 `maxmemory 512mb + noeviction` ⇒ 死信堆满后**所有** Redis 写失败。
- 多副本：`cfgver` 只传播 terms/modules，`user_status_cache` 是进程内 ⇒
  A 副本封禁、B 副本 5s 内不认；tracker 默认内存态且每 60s 全量覆盖同一个键
  ⇒ 两个 tracker 互相抹掉对方的 swarm（文档只有一篇 `_doc/G30-*` 提过一句）。
- worker 没有 healthcheck（compose 里显式 disable），卡住对编排器不可见。
- 装机闸门只断言「存在」不断言「能用」：SMTP 测只判非 404、announce 只判字符串入库，
  VAPID/S3/GeoIP 零覆盖（GeoIP 是结构性为关：镜像里恒建空目录）。

## 五、需要站长定口径的四件事

1. **幽灵做种**：什么算「真在做种」的正证据？（回连探测覆盖率太低不能当证据；
   要求 `uploaded>0` 又是自报数。可选：跨 peer 传输互证 / 只给已探测可达者全额时魔 /
   等级晋升改用近 N 天窗口而非终身累计）
2. **降级必须可达**：现在四个晋升指标都是终身单调量，降级分支实际跑不到；
   `inactivity_policy='demote'` 置 class_id=1 后会在 ≤5 分钟内被自动晋升回去。
3. **作弊待核队列**：`over_ceiling` 扣下的量要有人复核、有按钮发还/坐实，
   否则「扣量」就是无申诉的误伤；Pardon 也要能撤销并留住理由。
4. **备份/恢复**：后台按钮要么改成容器内 `pg_dump`（镜像装 client）要么删；
   `restore.sh` 必须覆盖附件卷与 Redis，且要有演练任务与告警。
