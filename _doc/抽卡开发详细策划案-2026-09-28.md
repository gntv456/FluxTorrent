## 1. 领域模型（As-Built）

### 1.1 三层货币/资产

| 层 | 载体 | 规则 |
|---|---|---|
| 抽取券 | `gacha_ticket_balance/ledger`（0231） | **不可购买、不可转让**；只有 grant/draw/daily_free 三出口；行锁 + idempotency_key + balance_after 逐条可核（spark_ledger 同形状） |
| 碎片 | `gacha_shard_balance/ledger`（0231） | 产出=抽取/分解/兑换找零；消耗=兑换/升级/合成；双重身份（奖池产出+消费货币）⇒ 价值由「能换到的最好东西」倒推，不由站长直配 |
| 卡牌 | `gacha_user_cards`（0232） | held（持有数）与 lit_at（图鉴点亮）**解耦**——分解只减 held 不灭灯；lv 只改卡面与图鉴权重，**不给站点经济加成** |


**种子池**（`demo-standard`，与向量逐位同源）：MISS 10 / SHARD 12(+15) / R 50 / SR 22 / SSR 2.0 / UR 0.4 / LR 0.1，票价 25，保底 soft=50/hard=65/ramp=5。LR: value=3000/synth=3200 ⇒ 碎片单价 0.9375。

### 1.3 流水与限次（0232/0234）

- `gacha_draws`：UNIQUE(idempotency_key, seq)——一次请求 N 行共用 key，**数据库级兜底「同 key 只出一批」**；pity_at/was_pity/is_new/seed 落库可复核

## 2. 数学层（双语言镜像，全系统唯一算术源）

### 2.1 文件与镜像关系

```
.workbuddy/gacha-shared.js          ← 样张 oracle（gitignored，判定档案）
packages/gacha-math/src/index.ts    ← TS 镜像（前端公示用）
apps/api/src/gacha_math/            ← Rust 镜像（守卫+抽取预检用）
  composite.rs                        保底 DP：q(s) 与 comp(i) 精确解
  economics.rs                        碎片单价倒推 + 新手/毕业双口径 EV
  simulate.rs                         蒙特卡洛（与 DP 互验）
  tests.rs                            7 用例（向量逐条镜像）
  gacha_math_vectors.json             共享向量 8 用例（TS/Rust 共用）
apps/api/src/gacha_http/roll.rs     ← 抽取 roll（与 simulate 同式）+ 3 crate 内测试
```

### 2.2 核心公式（改任何一行 → 双镜像同步 → 重生成向量）

- **q(s)**（第 s 抽出金概率）：`s≥hard ? 1 : min(1, gs + boost(s))`，`boost = (s-soft)*ramp/100` 封顶 `1-gs`——从非金档按比例搬
- **comp(i)**（含保底综合概率）：`Σ_s h(s)·P(i|s) / Σ h(s)`，h(s)=期望经过 s 的次数；**质量守恒 Σ comp == 1（1e-9）**
- **economics**：`shardValue = max(value/synth, value·lvGain/(lvStep×(lvMax-1)))` 逐卡取最优 ⇒ `evNew`（新卡全价）/`evEnd`（重复按最优兑换）/`ratioWorst = max(两者)/cost` —— **守卫卡 max 而非任一口径**（合成价后门已在样张复现：压低 synth ⇒ sv 0.938→3.750，返还率 96.8%→202.8%）
- **rng**：mulberry32（纯整数流跨语言逐位同谱）；行种子 = 批种子（纳秒^user_id）+ seq，落库可复核

### 2.3 镜像纪律（不可协商）

```
改任何一行算术
  → 同步 TS 与 Rust 两侧
  → node packages/gacha-math/scripts/gen-vectors.cjs 重生成向量
    （内置与样张逐位比对，不一致拒绝写）
  → vitest 29 用例 + cargo 7+3 用例全绿
```

### 2.4 运行时经济守卫（PoolGuard）

每请求现算 `ratioWorst`（不受任何缓存影响，**站长直连改库也拦**）：>100% → 409/4102 + tracing::error 告警。e2e 实证：裸 UPDATE 抬 LR prize_value → 409。

## 4. 抽取算法与保底状态机（roll.rs，与 simulate 同式）

```
每抽：since += 1
  since >= hard            → 硬保底：金档内按权重选（was_pity=true）
  else                     → 软爬坡：金档 pi×(1+b/gs)，非金档 pi×(1-b/nonGS)
    b = (since-soft)×ramp/100 封顶 1-gs（since>soft 才生效）
  出金 → since 归零（pity_at 落 0，非金落 since）
UP 选择：一期未实现（种子池无 up_card_id）——见 §6.1
```

关键不变量（e2e 已证）：
- 20 并发同用户抽取恰扣 20×cost，零超发零双扣（行锁序列化）
- 账本 `balance_after − LAG − delta` 三段查零断行
- 10 万抽出金率 3.3560% vs 公示 3.3875%（偏差 −0.0315pp，抽样误差内）
- pity 状态跨请求续接：最后一批末抽金档 ⇒ since=0，否则续 since

## 5. 工程纪律（本系统的门禁面）

1. **行数/宽度**：gacha_http/gacha_math 全部文件 ≤300 行（craft 287/draw 287/rates 227/roll 214 最大），按域拆分是纪律不是偏好
2. **i18n**：组件硬编码中文须 touch 基线（`node scripts/i18n_baseline_touch.mjs <相对 apps/web 路径>`），**禁用 --update**
3. **守卫脚本**：`gacha_math_guard.mjs`（向量重算 1e-9 + 自证会红 + 真库快照逐池）与 `gacha_pack_guard.mjs`（树解析：颜色只许 rarities 段/卡键白名单/载荷经济断言）已挂 ci_local 链
4. **sqlx 类型纪律**：INT2 列（lv_max/lv）SQL 侧一律 `::int` + 元组 i32；bind 顺序错会把幂等键写成 NULL——e2e 必须断言 key 落库
5. **迁移**：回滚事务法先行（`BEGIN; … ROLLBACK` 对真 schema 验证）；文件永远 LF（CRLF 会破 checksum 拒启，瞬时态重试即可）

## 6. 二期路线（按序，每批独立可验收）

### 6.1 UP 卡选择（纯代码，下一批首选）

- **现状**：`gacha_banners.up_card_id/guarantee_up/up_ratio` 列已在（0228），数学层 `upRate/upShare` 已算（composite），roll.rs 留注
- **做什么**：pool.rs 读 up_card_id 并定位其 pool_row；roll 出金后按 `hard&&guarantee_up ? 必中 : up_ratio 概率` 决定命中 UP 或按权重选金档其他行；**数学层 upShare 语义以本实现为准做一致性校验**（UP 不改出金率，只改金档内分布——公示页补「UP 命中率」一列）
- **验收**：crater 内测试（hard+guarantee_up 必中 UP；up_ratio=0.5 时 20 万抽命中率 ±2pp）；公示页双列不变
- **依赖**：无（种子池可造一个带 up_card_id 的测试 banner）

### 6.2 包载荷 apply（G31-C 包链路收口）

- **做什么**：站型包新增 `gacha` 数据节（`rarities/rates/pity/exchange/sections/cards` 七段），走 0223 site_pack_applies 台账与快照回滚；apply 重建 pack 层词表（0161 两层架构——global 层永不触碰）；**载荷颜色字面量只许 rarities 段**（pack_guard 树解析已就位，真库分支对齐 changes/snapshot 列）；被引用标签/卡片引用保护
- **验收**：apply → rollback 不残留卡；快照当一次 apply 重放结果一致；切站型后失效绑定以 disabled 选项保留显示且阻断保存

### 6.3 后台管理深化（pane 扩展）

- 卡定义 CRUD 表单（当前只读巡检）+ 池参数编辑（pity/cost/UP）+ 抽取流水查询页 + 分解/兑换审计视图；零散发放已有，补按等级批量
- 落点：`admin-gacha.tsx` 扩展或拆 `admin-gacha-pools.tsx`（≤300 行纪律）

### 6.4 合流项（另案）

- 官种标签接入 bonus 公式（NP official_tag 口径，与经济系统合流）
- 求种转正自动带标签/联动展示（与 requests 深度对齐批合流）
- 保底继承跨池（不改单池分布，只改玩家可见的距保底距离——先只存语义，方案 §7 已裁定不进 DP）

### 6.5 明确不做（延续一期裁定）

自由文本标签、卡牌交易/赠送（可转让随机奖池在 PT 语境=赌博）、赛季通行证、spark 购买抽取、BitTorrent v2 种子形态、原创 IP 卡池

## 7. 风险与已知坑（实施实录沉淀）

| 坑 | 处置 |
|---|---|
| sqlx 元组 INT2 不匹配（lv_max/uc.lv） | SQL 侧一律 `::int` + 元组 i32（三连坑后的铁律） |
| format! SQL bind 顺序错 → 幂等键落 NULL | e2e 断言 idempotency_key 落库非空 |
| make_interval(hours => bigint) 无此函数 | `$3::bigint * interval '1 hour'` |
| module flags TTL 30s | 开关切换断言等 ≥32s |
| CRLF 破迁移 checksum 拒启 | 瞬时态（git touch 窗口），重试；文件保持 LF |

| e2e 调余额裸 UPDATE | 必须「流水行+余额」成对，否则自破连续性 |
