## 1. 定位目标与闭环定义

四大支柱：
1. **只做建站系统**——FluxTorrent 是基础设施，不是某个具体站；自身不能 baked-in "FluxTorrent 综合站"假设。
2. **不偏向任何 PT 类型**——影视/音乐/游戏/电子书/动漫/教育/软件/体育/纪录片/无损……行为中立，差异只能由配置产生。
3. **站长自由搭建**——不写代码就能开关模块、加页面、加面板条目、配分类与维度。
4. **轻松自定义功能和字段**——字段（用户+种子）与功能（模块+插件+模板）都可无代码增改。

**闭环定义（六层自洽）**：站长从 `docker 起服务` → 走安装向导选站型 → 配结构/字段 → 开关功能/写模板 → 日常运营（审核/经济/HR/论坛/反作弊）→ 改品牌主题，每一层都能"自己走完、不卡代码"。任何一层卡代码 = 断点。

### L0 部署与安装向导
**已实现**

- 开站 checklist：`setup_http.rs:92-114` + `page.tsx:254-288`（announce/SMTP/registration 三项人工确认，非自动修正）。

**断点**
- 部署仍需手配 `.env` 的 `DB_PASSWORD`/`REDIS_PASSWORD`/`JWT_SECRET`（`docker/docker-compose.yml:84-96`），`CORS_ORIGINS` 未配生产态直接 panic（`main.rs:70-78`）。

- 管理员唯一来源是 root，root 被删无自愈种子（`setup_finish` 仅查 `class_id=99` 是否存在，`setup_http.rs:83`）。
- `site_settings` 仍是极简键值表（`0025_staffpanel.sql:54`），配置散落直接 SQL 与 `profile_bits`。

**结论**：安装闭环已成型，但"部署手配 + 无迁移入口 + 管理员不自愈"三处仍需站长会命令行。

### L1 站点身份与站型

**结论**：站型参数化但非自由建模——预设+克隆够用，但"从零定义一种站型"仍需代码。

## 3. 四大支柱差距分析

**支柱1 只做建站系统**
- 现状：默认 general 站型（`0119`）已中性；模块开关、自定义页面、动态面板让站长搭自己的站。
- 缺口：促销类型（`promo.rs` 字面量）、考核/HR（`jixiao*.rs` 硬编码）、字幕工作流仍综合站向；torrent schema 残留教育站列。
- 判定：⚠️ 形态中立了，但"运营逻辑"还没完全中立。

**支柱2 不偏向任何 PT 类型**
- 现状：12 站型包差异经 `module_*`+categories+`subtitle_kind`+terms 体现。
- 缺口：`site_type` 不改促销/考核/HR；`custom_*` 只能克隆不能自由定义；音乐/图书站要的"元数据源"只能靠 `metadata_sources` 开关（`0088`/`0181`）有限表达。
- 判定：⚠️ 表层中立，深层运营逻辑不随站型变。

**支柱3 站长自由搭建**
- 现状：模块开关（29）、自定义页面、动态面板、分类/维度/标签、用户字段、8 品牌色、terms 改写——全后台无代码。
- 缺口：站型不能从零定义；torrent 不能加字段；插件不能运行时装。
- 判定：✅ 搭建自由度已高，差在"字段"与"运行时功能"两处。

**支柱4 轻松自定义功能和字段**
- 现状：用户字段可配；功能靠模块+页面+（编译期）插件+适配器。
- 缺口：torrent 无通用字段；插件仅示例；促销/考核模板不可视编辑。
- 判定：❌ "字段"只覆盖用户侧，"功能"缺运行时扩展——这是定位最大硬伤。

## 4. 闭环蓝图（目标态）

六层目标态 + 站长自检 pass/fail 标准：

- **L0 部署安装**：一条 `docker compose up` + 浏览器向导走完即开站；密钥可向导内填（或环境变量）；有 `flux-api migrate` 独立入口；root 被删可自愈。**自检**：不看文档能否 10 分钟起一个空站？
- **L1 站型**：后台可新建站型并从零定义 categories/modules/sections/tags/terms 语义，无需代码。**自检**：能否不写代码造出一种"现有 12 种都没有"的站？
- **L2 字段**：用户字段 + **torrent 字段** 双引擎；教育站三列退场为可选 field；分类/维度/标签全动态。**自检**：能否给种子加"适合年龄段/碟片区码"这类任意字段？
- **L3 功能**：模块开关 + 自定义页面 + **运行时插件市场**（热插拔+熔断）+ **促销/考核模板可视化编辑** + 内容包中央仓库。**自检**：能否不写代码装一个社区插件、改一套考核指标？
- **L4 运营**：29 模块按需启停；促销/字幕/考核口径随站型与模板变；审核/经济/HR/论坛/反作弊完整。**自检**：音乐站能否把"字幕"改成"歌词"且关掉影视向考核？
- **L5 品牌**：品牌名/色/货币名/术语/logo/SEO/多语后台改；深度主题走皮肤内容包。**自检**：能否 0 代码换一套皮肤？

## 6. 风险与护栏

- **撞迁移号**：建文件前先 Glob 最大号（已撞 4 次）；建号后立刻构建/重启。
- **回归面**：torrent 字段、促销/考核外置改动面广 → 单测 + 契约门禁 `scripts/check_type_drift.mjs` 三维（错误码/促销枚举/响应形状）扩展覆盖新增 field/template 响应结构。
- **行为漂移**：所有"外置"必须种入默认值 = 现状，保证老站零变化。
- **插件安全**：运行时装载必须沙箱 + 熔断（复用 `adapters` 机制），禁止直连 DB 自由 SQL。
- **沙箱禁 node spawn**：本机验证脚本别自己调 docker/psql（EBUSY）；端到端验证走运行容器 + python 比对。

## 7. 验证与门禁

- 契约门禁：`scripts/check_type_drift.mjs` 扩 CONTRACTS 表，新增列表/字段/模板响应结构体加行；改后负向测试（删字段确认 FAIL 再还原）。
