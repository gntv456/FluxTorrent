# FluxTorrent「考核 & 任务」系统最佳方案

> 定位：**通用 PT 程序，可建成任何类型站点，默认综合站**，对标 NexusPHP（华语 PT 事实标准）。
> 综合站用户预期的就是 NP 那套「考核 & 任务」合并式（exam + task）。
> 结论先行：综合站默认应提供 NP 合并式。FT 后端已有 `tasks`（M22）/ `resurrections` / `achievements` / `jixiao`，**缺的是面向普通用户的 `exam` 考核引擎**。最佳方案 = 补轻量 exam 引擎（默认能力）+ 接前端 UI + 修 1 个 bug + 按 site_type 参数化。

---

## 一、结论（先给判断）

FT 后端已具备 NP 合并式所需的「任务侧」全部能力：限时任务（`tasks`）、复活任务（`resurrections`）、成就（`achievements`）、H&R 全链路、staff 绩效考核（`jixiao`）。

**但面向普通用户的「考核」（exam：新用户转正 / 周期考核、自动派发、达标判定、记录浏览）FT 完全没有**——这正是 NP `/system/exams` + `/user/exam-users` 那一块。综合站默认必须有它，否则新站用 FT 建综合站时，新人转正考核、周期性考核这套标配就缺了。

所以最佳方案不是「只接 UI」，而是：
1. **补 exam 轻量引擎**（默认能力，承载新人转正 / 周期考核 / 自动派发）—— 主要增量
2. **接前端 UI**：`/tasks`、`/resurrections`、`/me/achievements` 三页 + 统一「考核&任务」入口（对标 NP `task.php`）
3. **补后台**：`/system/exams` 考核配置 + `/user/exam-users` 用户考核记录（对标 NP）
4. **修 1 个 bug**：`ops_http.rs:425` claim_limit NULL → NotFound
5. **按 site_type 参数化**：综合站全开；其他站型可关/调口径

工作量约 **3–4 天**（exam 引擎是主要增量，其余是接 UI + 配置页）。

### 前端缺失
`apps/web/app/(main)/` 下无 `tasks/`、`resurrections/`、`achievements/` 页面（Glob 全量确认）。仅 `jixiao` 已做。

### 已确认的后端缺陷
- **`ops_http.rs:425`**：`let Some(limit) = limit else { return NotFound }`。`claim_limit` 为 `NULL`（不限领）时 `fetch_optional().flatten()` 得 `None`，走 else 直接 `404`。**不限领的任务永远领不了。**
- `fee` 列已于 `0027_task_tiers.sql` 补充，`claim` 查询无误（早前误判，已纠正）。
- `tasks` 表现在字段：`id, name, metric(JSONB), starts_at, ends_at, target_class, reward, penalty, claim_limit, tier, subtitle, fee, duration_days, quota_total, sort`（0001 + 0027 迁移）。

### 缺口（本方案要补）
- **exam 引擎**：无 `exam_types` / `exam_users` 表，无自动派发、无面向用户的考核/转正判定、无用户考核记录浏览。

## 三、方案架构（四层，对标 NP 合并式）

```
考核&任务中心（综合站默认，对标 NP exam+task）
├── 任务 tasks          限时任务（M22 后端已就绪）        ← 对标 NP task.php
│      领取 → 快照基线 → worker task_settle 比对增量
│      → 达标发 reward 火花 / 未达标扣 penalty（保底 0）
├── 考核 exam  【新增·默认】面向普通用户                 ← 对标 NP /system/exams + /user/exam-users
│      新人转正 / 周期考核；auto_assign 自动派发
│      → worker 周期结算 → 达标标记 / 转正 / 解锁
├── 救种 resurrections  死种领任务 → 做种 N 小时 → 奖火花+免费券  ← 对标 U3D Graveyard
└── 成就 achievements  四族里程碑（保种/救种/发种/论坛）            ← 对标 U3D 53 成就

员工绩效（独立，不混入用户成长体系）
└── /jixiao  staff KPI，admin 分配岗位、每月领工资
```

**为什么不只做 U3D 路线**：上轮基于「教育站」选了 U3D 任务+成就路线，缺 exam。但 FT 是通用程序、默认综合站，综合站用户预期 NP 合并式——exam（新人转正/周期考核）是综合站标配，不能省。exam 引擎用独立表实现，语义清晰、对标 NP，且可与 tasks 共享结算/奖励管线。

## 四、exam 引擎设计（综合站默认能力）

### 4.1 数据模型（新增，对标 NP；表结构取舍见 §十一 P1-2——复核后倾向单表方案，此处保留双表原设计供对比）
```sql
CREATE TABLE exam_types (
  id BIGSERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'onboard',   -- onboard 新人转正 | periodic 周期 | promo 晋升
  metric JSONB NOT NULL DEFAULT '{}',     -- 达标指标，如 {"seed_hours":120}
  target_class INT NOT NULL DEFAULT 0,    -- 目标等级（0=全部）
  target_newbie BOOL NOT NULL DEFAULT true, -- 是否面向新人
  auto_assign BOOL NOT NULL DEFAULT false,-- 注册/升级时自动派发
  period TEXT NOT NULL DEFAULT 'once',    -- once | monthly | quarterly
  starts_at TIMESTAMPTZ, ends_at TIMESTAMPTZ,
  reward BIGINT NOT NULL DEFAULT 0,
  priority INT NOT NULL DEFAULT 0,        -- 自动发现优先级
  enabled BOOL NOT NULL DEFAULT true,
  site_type TEXT,                         -- 站型可见性（NULL=全站型）
  sort INT NOT NULL DEFAULT 0
);
CREATE TABLE exam_users (
  id BIGSERIAL PRIMARY KEY,
  exam_id BIGINT NOT NULL REFERENCES exam_types(id),
  user_id BIGINT NOT NULL REFERENCES users(id),
  status SMALLINT NOT NULL DEFAULT 0,     -- 0 进行中 | 1 已完成 | 2 失败
  base_uploaded BIGINT, base_seed_seconds BIGINT, base_uploads BIGINT, -- 基线快照
  started_at TIMESTAMPTZ, finished_at TIMESTAMPTZ,
  UNIQUE (exam_id, user_id)
);
```

### 4.2 关键逻辑
- **自动派发**：worker 定时扫描 `exam_types WHERE auto_assign AND enabled`（按 site_type 过滤当前站型）→ 对满足条件用户（`target_newbie` 取注册 N 天内 / `target_class` 取等级）插入 `exam_users`（唯一约束防重复）。对标 NP「自动发现 / 优先级」。
- **达标判定**：复用 `task_settle` 的同款「base + delta」增量比对（已验证口径），达标置 `status=1` 并发 `reward` 火花；新人转正类可触发等级/权限解锁钩子。
- **新人转正考核（默认开启）**：`exam_types` 种子一条 `kind='onboard', auto_assign=true, target_newbie=true`。注册即派 → 做种满 120 小时 → 标记转正。
  ⚠ metric 键受 worker `TaskMetric` 约束（详见 §十一 P0-1）：现只支持 `upload_delta / download_delta / seed_points_delta / uploads / subtitles` 五个键。做种时长类指标需**给 TaskMetric 新增 `seed_seconds_delta` 键**（秒口径，明确无歧义）；现有 `seed_points_delta` 的折算公式（`seed_d >= v*3600/100`，即 v×36 秒）语义可疑，建议一并厘清或废弃。

### 4.3 后台（对标 NP）
- `/system/exams`：exam_types CRUD（名称/类型/指标/起止/周期/目标用户/自动发现/优先级/状态）—— 即第八轮报告点名的「考核引擎配置缺失」补齐项。
- `/user/exam-users`：exam_users 浏览（筛选 UID/类型/状态/是否完成 + 列 + 批量）—— 即第八轮报告点名的「用户考核浏览页缺失」补齐项。

## 五、前端三页 + 统一入口（对标 NP）

### 5.1 `/tasks` 任务中心（对标 NP task.php）
- 列表字段（来自 `GET /tasks`）：名称 / 副标题 / 指标 / 分层 / 起止 / 目标等级 / 奖励 / 罚则 / 名额 / 已领 / 是否已领。

- 样式复用 `nexus-table` + `baozi-panel`（与 `/jixiao` 一致）。

### 5.2 `/resurrections` 复活任务（对标 U3D Graveyard）
- 可领列表（死种 + 所需做种时长 + 奖励）+ 我的复活（进行中/已完成/过期）。
- 复用 `GET /resurrections` + `GET /resurrections/mine`，领取调 `POST /resurrections/claim`。

### 5.3 `/me/achievements` 成就墙（对标 U3D 53 成就）
- 四族卡片（保种/救种/发种/论坛），已授予高亮 + 进度。

### 5.4 我的考核 `/me/exams`（新增，对标 NP 用户侧考核进度）
- 进行中考核列表 + 当前增量 vs 目标 + 状态（进行中/已完成/失败）。
- 调用新增 `GET /me/exams`。

### 5.5 统一入口
- 导航加「考核&任务」菜单（对标 NP `task.php` 导航项），下拉：任务中心 / 复活任务 / 我的成就 / 我的考核。
- 后台「系统」分组加「考核&任务配置」（exam_types）+「用户考核」记录（exam_users）。

## 六、站型适配（site_type 参数化）

FT 是通用程序，考核&任务按 `site_type` 开/关与调口径（复用既有 `modules` / `site_type` 机制）：
- **综合站（默认）**：全开（exam + task + 成就 + 复活），默认 NP 合并式。
- **教育站**：指标口径偏教材救活（`rescue_count` 权重高）、新人考核周期可延长、复活任务强调老教材价值。
- **影视站**：指标偏做种时长 / 分享率；复活任务偏冷门影视。
- **音乐站（Gazelle 系）**：可关 exam 引擎，仅保留成就 + 观察期（对标 Gazelle 极简式）。
- 实现：`exam_types` / `tasks` 加 `site_type` 可见性字段；worker `auto_assign` 与前端列表按当前站型过滤。

## 七、与 staff `/jixiao` 的边界

- `/jixiao` = **员工工资**：admin 在用户详情「分配考核」登记岗位，每月领工资，语义是 staff KPI（M21）。**不混入用户成长体系**。
- 用户侧「考核 & 任务」= exam + tasks + resurrections + achievements，面向全体普通用户。
- 导航分两个入口：「考核&任务」（用户成长）与「绩效考核」（staff 后台/员工专属），避免概念混淆。

## 九、风险与对策

- **exam 结算口径**：复用 `task_settle` 的 base+delta 逻辑，先单测一个 onboard 考核验证（audit 报告曾指出多处 worker SQL 炸弹，虽已修，仍建议先跑通再铺开）。
- **自动派发幂等**：`exam_users UNIQUE(exam_id, user_id)` 挡重复；worker 重跑安全。
- **经济通胀**：reward 入 `spark_ledger`，已有 `/admin/spark-flow` 月度对账，量级由运营把控。
- **站型过滤**：worker 与前端列表必须按当前 `site_type` 过滤，避免教育站看到影视专属考核。
- **与 jixiao 不混**：exam 走用户成长管线，jixiao 走 staff 工资管线，奖励账户同源但语义隔离。
