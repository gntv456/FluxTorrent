# 站型成熟度对标与达标方案 · 总纲 v2

> **日期**：2026-10-09（终态实测）
> **定位**：FluxTorrent 通用 PT 建站系统 —— 一套代码、11 种站型可切换，
> 站长一键切过去之后，站点应当**像那个内容域的成熟站**，而不只是换了一套分类名。
> **本文性质**：**当前唯一入口**。合并并取代以下两份历史底稿（保留为过程档案，不再维护）：
> - `_doc/各站型成熟度对标与达标方案.md`（v1 总纲）
> - `_doc/站型成熟度对标与补齐方案-2026-10-08.md`（机制层 H1–H10）
> **口径纪律（承自 v1 血泪教训）**：任何"缺口"结论必须**以代码/数据库事实为准**，
> 不得沿用历史快照、竞品对比稿的转述。本文所有"现状"列均为 2026-10-09 本机实测
> （真库 SQL / grep 行号 / 迁移号），取不到出处的竞品能力一律标 `[业内惯例·待核]`。

## 0. 一句话结论

**通用层和维度层已经达标，剩下的差距全部集中在「领域能力」层。**

| 层 | 内容 | 状态 |
|---|---|---|
| L1 通用底座 | 列表三视图 / 实时筛选 / 详情页 BFF / 磁力 / peers / 批量 / H&R / 合集 | ✅ 达 UNIT3D 级 |
| L2 维度层 | `section_kinds` 注册表 **43 个维度**，六类型字段系统全链（写入/详情/筛选/RSS/包） | ✅ 已清零 |
| L3 实体层 | `artists` / `content_networks` / `torrent_artifacts` / `sport_matches` / `torrent_logs` / `textbooks` / `torrent_groups` / `collections` | ✅ 主要实体已落地 |
| L4 领域能力 | 该内容域的**招牌能力**（Logchecker、播放器、试读、trumping、多版本分槽…） | ◐ **剩余主战场** |
| L5 呈现层 | 站型专属页面 + 维度门控导航 | ✅ 11 型入口已按维度显隐 |

**11 型中 7 型（general/movie/documentary/anime/ebook/sports/education）
在"内容模型 + 聚合 + 呈现"三件事上已可判定达标；剩余 4 类各有 1–3 件招牌能力未做**
（music·lossless 的在线试听、ebook 的试读、game 的 trumping/duplicates、movie 的多版本分槽）。

> ⚠️ **达标的第二把尺子（本项目定位特有）**：本项目是**建站系统**，不是单一站点。
> 因此"有该能力"还不够，能力必须**能被站型包声明、随切换开关**（`pack.features` 机制），
> 而不是散落在 `match site_type` 的分支里。散分支 = 自定义站型永远享受不到 = 不符合定位。
> 本文评分卡对每一条基线都按**两把尺子**判定：①能力是否存在 ②是否随站型可声明。

## 1. 方法与证据口径

- **现状**：真库直查（`docker exec flux-postgres psql`）+ 全仓 grep（`apps/api` + `apps/web`）。
- **竞品**：优先取**公开可核**的源码/官方 wiki：
  - Gazelle 系（PTP/BTN/GGn/AB/RED·OPS 同源）有公开代码与 wiki → 标 `[代码核实]`。
  - NexusPHP 系（M-Team/柠檬/观众/U2/BYR）有第三方适配器逐字选择器 → 标 `[实证]`。
  - MAM / 华语教育·体育·软件站无公开源码 → 标 `[业内惯例·待核]`，**不假装有出处**。
- **优先级**：`P0` = 不补这个，切过去就不是那类站；`P1` = 同类站有而我们没有，
  站长第一个月会撞上；`P2` = 拉开体验差距，可排后。

## 2. 市面成熟站型标杆清单（11 型市面对标）

> 每型给出**标杆站 → 该站的核心机制（"成熟"到底成熟在哪）**。这是达标基线的事实来源。

### 2.1 general 综合站
**标杆**：NexusPHP 主线 + 华语魔改（M-Team / HDSky / 柠檬 / 观众 / BYR）
**成熟机制**：多级促销（`sp_state` 七态 + 倒计时）、NFO+MediaInfo+PT-Gen 三位一体、
同 IMDb 副本聚合、字幕区、H&R、**语义 DOM 契约**（`table.torrents` / `.pro_free` /
`details.php?id=`）、原生 RSS、海报墙。`[实证: chain710/ptool site/tpl/tpl.go]`

### 2.2 movie 影视站
**标杆**：PTP（Gazelle 系）、HDBits、BTN（剧集）、M-Team
**成熟机制**：
- 单电影**聚合条目**下按 **SD/HD/UHD/Others 分槽**并列多版本 `[业内]`
- **Collections** 主题合集（策展入口）`[业内]`
- **trumping**：可举报/替换劣质或死种，保证同槽最优版本存活 `[业内]`
- Cover Flow 海报流、元数据（IMDb/MC/演职员）与技术信息**分栏** `[业内]`
- 剧集 **show → season → episode** 三级模型（BTN 范式级）`[业内]`

### 2.3 documentary 纪录片站
**标杆**：MVGroup / PBS·Nature 系 / 央视纪录频道口径 `[业内惯例·待核]`
**成熟机制**：按**出品方/播出机构**（BBC/NHK/PBS/国家地理）浏览、
**题材手法**分面（观察式/说明式/调查式）、**画质档**（4K 是高频检索）、
**解说（narrator）**署名、**获奖**（奥斯卡最佳纪录长片/圣丹斯/IDFA）分面。

### 2.4 anime 动漫站
**标杆**：AnimeBytes（Gazelle 变体）、U2 动漫花园、Bangumi 口径
**成熟机制**：**字幕组（fansub / team）作一等筛选维度** `[业内]`、
MAL/AniDB/Bangumi 外部库关联、**播出季**门户（当季新番）、
series → 话数 → 字幕组版本 三层、生肉/熟肉/官译分档 `[业内]`

### 2.5 music 音乐站
**标杆**：RED / OPS（Gazelle 音乐线）、What.CD 遗产
**成熟机制**：
- **LogScore 0–100 抓轨日志打分**、多碟取 MIN、`HasLog`/`HasCue` 双状态、
  缺日志进「欠日志」队列 `[代码核实: Gazelle app/Manager/Riplog.php]`
- **格式三元组** `Media × Format × Encoding`（Lossless / 24bit Lossless / MP3 是
  **Encoding**，FLAC/APE 是 **Format**）`[代码核实: Gazelle riplog 模板三轴]`
- 三层实体 **Group → Artist → Release**（label/catalog#/发行日/DiscID）`[业内]`
- 分数可被管理员**改判并留痕**（`AdjustedScore/AdjustedBy/AdjustmentReason`）`[代码核实]`
- 请求/投票按最低日志分门槛（`Request\LogCue(minScore:100)`）`[代码核实]`
- collage 策展、标签投票相似推荐、在线试听 `[业内]`

### 2.6 lossless 无损站
**标杆**：RED / OPS（同上，门槛更严）
**成熟机制**：music 全部机制 + **Hi-Res / SACD / 黑胶转制 / 采样率·位深字段**、
**log 100% 硬门槛**（否则不许标无损）、高保真试听。`[代码核实: What.CD 规则 2.2.10.x]`

### 2.7 ebook 电子书站
**标杆**：MAM（MyAnonamouse，业界最强）、Bibliotik
**成熟机制**：`author / narrator / DRM / format / series` 结构化字段
`[实证: AudioBookRequest MamIndexer 解析 author_info/narrator_info JSON]`、
**样章试读 / 在线试听**、**series 聚合**、图书评分 + 书评、
扫描版 DPI/OCR 标记 `[业内]`

### 2.8 game 游戏站
**标杆**：GGn（GazelleGames，业界标杆）、BitGAMER
**成熟机制**：游戏条目聚合**多版本/更新/GameDOX/OST**、
**DRM-Free 显式标签** `[实证: GGn News 上传规则]`、
平台覆盖 NES→Switch+Mac/移动、release type（Scene/GGn Internal/GameDOX）、
**trumping + duplicates 合并规则（劣质即重复）** `[实证: GGn News]`、评测外链

### 2.9 software 软件站
**标杆**：GGn Apps 分区、RuTracker、BitMe `[业内惯例·待核]`
**成熟机制**：平台（Win/macOS/Linux/Android/iOS）、**版本号 + 更新日志 + 校验和**、
激活方式/授权类型、教程配套。

### 2.10 sports 体育站
**标杆**：SportsCult / RuTracker 体育区 / BTN（赛事侧）`[业内惯例·待核]`
**成熟机制**：**赛事 → 赛季 → 轮次 → 对阵（主/客/比分）** 四层、
全场/集锦/回放/直播源分类语义、球队订阅与追赛提醒。

### 2.11 education 教育站

**成熟机制**：**学段 / 学科 / 教材版本 / 年级 / 学期 / 单元**、

## 6. 补齐方案（分批次）

> 交付纪律（本仓既有）：每批次 = **迁移 + 代码 + 一个可跑闸门脚本 + 页面截图**，
> 四件齐了才算完成（结构绿 ≠ 渲染对）。

### 批次 A · 低风险收口（1 批，纯增量）
**内容**：G4（无损三字段）+ G6（DPI/OCR）+ G12（DLC/位数）
——全部是**加维度**，走既有六类型字段系统，**零业务代码**，只需迁移 + 包载荷。
**验收**：扩展 `pt_audit_l_ebook_sports.py` / 新增断言：维度可写、可筛、`sec_*` 命中。
**为什么先做**：成本最低、切过去立即可见、且填掉 3 型最后的字段空白。

### 批次 B · 质量门禁（trumping/duplicates）
**内容**：G1 + G2（movie/game 共用一套"同槽"判据）。
- 迁移：`torrent_groups.quality_tier`（派生或人工）、trump 举报表。
- 代码：`torrent_http/trump.rs`（举报 → 版主裁决 → 替换/合并）；
  详情页按 tier 分组渲染。
- **声明机制**：`pack.features` 增 `trumping` / `quality_tiers`，消费点读 features。
**验收**：新增 `pt_audit_t_trump.py` —— 举报 → 裁决 → 淘汰劣质 → 同槽只剩最优，全链断言。
**依赖**：G1 与 G2 强相关，**同批做**才自洽（分槽是 trumping 的前提）。

### 批次 C · 富媒体预览
**内容**：G5（试读）+ G9（试听）+ G3（cue 合规/改判）。
- 试读/试听复用 attachment 通道，加"预览片段"语义（受限可见性口径）。
- 日志改判：`torrent_logs` 加三列 + 管理端改判入口 + 详情展示调整留痕。
- 播放器：先做"受限试听片段"（非整轨），挂回模块键。
**验收**：`pt_audit_g_logcheck.py` 扩展改判段 + 新增 `pt_audit_u_preview.py`。

### 批次 D · 自动化与深聚合
**内容**：G7（元数据自动拉取）+ G10/G11（anime/ebook 深聚合页）+ G13。
**验收**：各自闸门 + 页面截图。

### 批次 E · 收尾
**内容**：G8（死列处置）+ G14（按需）+ 全量回归 22 个闸门脚本。

### 统一机制改造（贯穿所有批次）
**给 `site_type_packs` 加 `features JSONB`**：该型启用的垂直能力清单
（`["trumping","quality_tiers","preview","player",...]`）。

也是保住"自定义站型"产品口径的唯一做法。

## 7. 风险与纪律

1. **不散 `match site_type`**：能力分支必须走 `pack.features`，否则自定义站型永远缺能力。
2. **不每型建一套表**：走"实体表 + 锚点同步"（0327/0330/0333/0334 范式）。
3. **新聚合页必须挂 `sync_content_anchors`**：否则新实体永不出现（0334 实证过的坑）。
4. **维度门控读 `kinds` 不读词表**：`text` 维度天生空词表，读词表会整类漏掉（0330 真 bug）。
5. **迁移纪律**：改完 `.sql` 必须 rebuild api 镜像（运行时读目录 + 镜像快照双面）；
   建号前 `uniq -d` 查重，`build` 前再查一次（并行会话会撞号）。
6. **`features` 的向后兼容**：新增能力默认关，任何站型包不声明即维持现行为。
7. **`technical_info` 死列不清理前不要写数据**：先定性再使用。
