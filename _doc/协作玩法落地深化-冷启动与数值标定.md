# 协作玩法落地深化：冷启动、玩家旅程与数值标定

> 承接 `_doc/协作玩法实施深化-可信行为与经济模型.md`
> v4 解决了「怎么不被玩坏」，本文解决 v5 的四个落地问题：**① 冷启动 ② 我自己方案里的社交压力 ③ 真实玩家 28 天会经历什么 ④ 公式里的 k 到底填多少**

---

## 一、被忽略的致命问题：冷启动

### 1.1 熊猫根本不需要解决这个问题

回看熊猫的数据：市场 911 人挂牌，**抽样 87% 已有主人**。

它怎么做到这么高的覆盖率？因为**它不需要玩家同意**——系统在新人进场时就把你分配给了某个主人（实测账号 `gntv` 的 `trade_type = seed_init`，"初始归属给 whlwhlwhl"）。你还没搞清这功能是什么，就已经在里面了。

**这里有一个必须承认的权衡**：

> 熊猫的「不好玩」和「87% 参与率」是**同一件事的两面**。它用强制拉入换来了覆盖率。

我们选择了"自愿参与"（这是正确的），**就失去了这个杠杆**，必须自己解决冷启动。而社交玩法最经典的死法就是：

```
第一批契约没人发起 → 招募页是空的 → 新玩家看到空页面就走 → 更没人发起 → 死亡螺旋
```

### 1.2 五条解法（按优先级）

| # | 解法 | 说明 |
|---|---|---|
| 1 | **先做不需要组队的玩法** | 《抢救断种》单人就能认领。**一个人也能玩，是冷启动的入口** |
| 2 | **系统托底队友** | 契约人数不足时，由系统角色补位（类似游戏的 NPC 队友），保证任何人的契约都不会因为招不到人而失败。系统角色产出打折或不产出，只保证流程能跑完 |
| 3 | **梯度解锁社交** | 单人 → 双人 → 小队 → 联赛，逐步开放。**不要一开始就上组队** |
| 4 | **种子用户** | 先定向邀请做种榜前 N 的活跃用户，给他们专属主题包 / 称号，让他们跑出前 10 个示范契约 |
| 5 | **空列表要伪装成机会** | 招募页有条目才展示，没有条目时展示"某玩法 3 天后开放"的倒计时，**永远不要展示一个空页面** |

### 1.3 这重新解释了实施顺序

v4 里我把《抢救断种》（E）排在发行体系（C）之前，理由是"依赖更少"。现在有了更重要的理由：

> **E 不只是依赖少，它是整个玩法的冷启动入口。** 没有单人玩法做铺垫，后面所有组队玩法都会死于无人发起。

**单人玩法先跑 4 周，积累用户与信任，再上协作。** 这不是保守，这是社交产品的唯一可行路径。

## 二、自我批评：我的方案里也有社交压力

v2 我批评过熊猫"用社交压力驱动留存"，但我设计的契约机制里同样有压力：

- "违约影响队友" → 压力
- "掉棒全队受损" → 压力
- "承诺未达成会被差评" → 压力

**我必须回答：这和熊猫有区别吗？** 有，但边界必须划清楚。

### 2.1 正向压力 vs 负向压力

| | 负向（熊猫） | 正向（契约） |
|---|---|---|
| 压力来源 | **我的损失由他人决定** | 我的收益依赖协作 |
| 我是否自愿 | ❌ 被买走不需要同意 | ✅ 自愿报名 |
| 我能否预见 | ❌ 不知道谁买我、何时被挖 | ✅ 知道队友是谁、承诺什么 |
| 我能否选择 | ❌ 无法拒绝 | ✅ 可以挑队友、可以退出 |
| 失败的后果 | 被人放生、被人转卖 | 信誉下降（不影响已有资产） |
| 压力方向 | **向下**（被支配） | **横向**（对队友负责） |

**分界线：压力必须来自"我自愿加入的关系"，且我能提前知道、能选择、能退出。**

### 2.2 四条硬性防护

| 防护 | 规则 | 理由 |
|---|---|---|
| **1. 只在自愿关系里施压** | 未接受契约的人不承担任何义务，也不影响任何人 | 绝不出现"你被选中了所以要负责" |
| **2. 惩罚只针对"逃跑"，不针对"尽力"** | 未达标但坚持到期的：**小扣或不扣**；中途退出：按剩余进度比例扣 | 区分"尽力了"和"跑了"，这是激励设计的底线 |
| **3. 独狼模式** | 不想影响别人的人，可以做单人玩法（抢救断种），收益略低但零社交压力 | 给内向玩家留出路，别逼所有人社交 |
| **4. 压力可见可控** | 进度条透明、随时可见队友状态、可主动退出（有代价但不清零） | 未知才产生焦虑，透明反而降低压力 |

### 2.3 一个反直觉的结论

**契约失败不应该有惩罚性的团队连坐。** 我原本写了"掉棒全队受损"，现在改掉：

- 团队连坐会让**新人不敢加入**（"我万一拖累别人怎么办"），而新人恰恰是最需要参与的人
- 正确做法：**失败只影响信誉的小幅扣减 + 该契约没有产出**。不额外罚款、不追责、不公开点名
- 让"不参与"和"参与了没成功"的差距，体现在**收益**上而不是**羞辱**上

## 三、端到端玩家旅程（28 天）

设计再漂亮，也要用真人走一遍。下面是假设玩家"小李"（分享率 1.8，每天在线 2 小时，保种 300GB）的 28 天：

| 天 | 事件 | 设计意图 | 暴露的问题 |
|---|---|---|---|
| **D0** | 首页侧栏出现「资源抢救」入口，显示"当前有 37 个资源濒危" | 用**站点痛点**做钩子，而不是"来玩游戏" | — |
| **D1** | 认领第一个抢救任务（单人，7 天内把某资源做种数恢复到 ≥3）。5 分钟完成认领 | **零社交门槛**，第一次就成功 | ⚠️ 认领后到 D7 之间**玩家没事做** → 需要日课设计 |
| **D2** | 收到"你的抢救任务进度 30%"通知 | 进度可见，产生回访 | — |
| **D4** | 页面新增"接力保种"入口（需 1 名伙伴）。系统推荐 3 个同好 | **梯度解锁**，此时已有成功经验 | ⚠️ 推荐依据是什么？（同分类兴趣 / 活跃时段） |
| **D7** | 抢救成功。资源永久标记"2026-09 由小李拯救"。**第一次看到贡献从 pending 变 verified** | 荣誉 + 延迟结算的可见性 | 待确认→已确认的 UI 必须极清楚 |
| **D9** | 收到组队邀请（对方是 D4 的接力伙伴） | 社交关系自然生长 | — |
| **D14** | 首次契约结算，拿到赛季第一笔发行 | **正反馈闭环** | ⚠️ 收益若太少会直接流失 → 数值标定见第四节 |
| **D16** | 信誉升级，解锁"美术"岗位（冷门保种） | 准入型奖励，不是数值碾压 | — |
| **D21** | 队伍里有一个人中途退出，契约差点失败 | 社交压力的**真实体验** | ⚠️ 必须有防护（见 2.2）：他退出不影响我的既得 |
| **D28** | 赛季结算。我的荣誉页新增"2026 秋季 · 抢救者 ×5 · 契约完成 ×2"，进度归零 | 累计感 + 归零的合法性 | ⚠️ 归零瞬间的挫败感 → 用荣誉页承接 |
| **D29** | 新赛季开启，全新主题（纪录片季），同一起跑线 | 新鲜感 | — |

**这趟旅程暴露的三个必须补的洞**：

1. **D1~D7 之间的空窗**：认领完就没事干。需要**每日微任务**（如"给 3 个濒危资源投票加急""查看今日新增濒危清单"），保持回访但不重度
2. **D14 的收益量**：第一笔钱太少 = 直接流失。数值标定是生死线
3. **D28 的归零**：必须用荣誉页、称号、历史记录承接，让"归零"读起来像"归档"而不是"清零"

## 四、数值标定（把 k 填上）

v4 给了公式但没给数字。现在标定。

### 4.1 站点参数假设（以中等规模站为例）

| 参数 | 值 |
|---|---|
| 活跃用户 | 10,000 |
| 有做种行为的用户 | 5,000 |
| 全站魔力值总量 | 10 亿 |
| 站点原有年产出（做种） | 6,000 万魔力值 |
| 赛季长度 | 4 周，每年 12 季 |
| 目标年通胀率 | 8%（含站点原有产出） |

### 4.2 赛季发行池上限

```
上限 = (10亿 × 8% − 6,000万) / 12 = (8,000万 − 6,000万) / 12 ≈ 167 万 / 赛季
```

**这是硬顶**，不是目标值。实际发行由贡献总量决定，且**不超过此上限**。

### 4.3 单玩家收益测算

假设赛季内：

| 玩家类型 | 周做种时长 | 冷门保种 | 大致 CP | 赛季收益（估算） | 与做种收益对比 |
|---|---|---|---|---|---|
| 轻度 | 50 h | 1 个 | ~20 | **3,000~5,000 魔力** | 约等于做种收益的 15% |
| 中度 | 200 h | 5 个 | ~120 | **20,000~30,000 魔力** | 约 25% |
| 重度 | 700 h | 15 个 | ~450 | **70,000~100,000 魔力** | 约 30% |

### 4.4 一条硬约束：游戏收益 ≤ 做种收益的 30%

**这是我认为最重要的一条数值纪律。**

理由：如果游戏收益超过做种收益，玩家就会**为了玩游戏而做种**——行为被扭曲，本末倒置。那时我们就不再是"奖励真实贡献"，而是在制造一种新的刷量动机。

| 游戏收益占比 | 后果 |
|---|---|
| < 10% | 玩家没动力参与（激励不足） |
| **10% ~ 30%** | **健康区间**：锦上添花，不改变主行为 |
| > 30% | 行为扭曲：为游戏而做种，可能催生新的刷量手段 |
| > 100% | 灾难：做种成了游戏的副产品 |

**建议把 30% 写进配置，作为发行池的第二个上限**（与 4.2 的硬顶取小值）。

### 4.5 k 的求法

```
k = min(通胀硬顶, 收益占比上限) / (全站有效贡献总量 ^ 0.75)
```

**k 不是常量，而是每赛季根据上赛季数据重算一次的配置值**。这样才能自适应站点规模变化。

## 五、界面信息架构

玩家实际看到的页面（对照熊猫的 10 个页面，我们收敛到 6 个）：

| 页面 | 核心信息 | 关键设计 |
|---|---|---|
| **首页/仪表盘** | 我的进度、待办（今日可做）、预估收益（分"待确认/已确认"两栏显示） | **待确认与已确认必须视觉强区分**（灰 vs 亮） |
| **抢救清单** | 濒危资源列表、地图式展示、认领入口 | 用"还剩 X 天可能断种"制造紧迫感，**不制造焦虑**（不催、不扣分） |
| **契约/组队** | 招募中的契约、我的契约、报价与还价 | 报名者能看到彼此的真实数据（透明降低风险） |
| **荣誉页** | 拯救记录、赛季历程、称号 | **这里承接"归零"的情绪**，比数值页更值得打磨 |
| **信誉页** | 信誉分、来源明细、加减记录 | 让玩家能自己算出为什么升/降，**可申诉入口** |
| **规则页** | 玩法说明 + 数值表 | 全部服务端下发，改规则不发版 |

**一个关键交互**：贡献明细要能**点进去看到原始来源**（"这条 +12 CP 来自 2026-09-14 的做种记录"）。这既是防伪的透明度，也是玩家理解规则的方式。

## 六、赛季衔接与边界情况

### 6.1 赛季之间的空窗期（v4 遗漏）

| 时段 | 处理 |
|---|---|
| 赛季结束 → 结算完成 | **24 小时只读期**：进度冻结，可查看不可操作，避免"结算中还能拿分"的争议 |
| 结算完成后 → 新赛季开启 | 显示荣誉归档 + 新赛季预告，给出明确的开启时间 |

### 6.2 荣誉传承的规则

| 内容 | 是否跨季保留 |
|---|---|
| 拯救记录（永久荣誉） | ✅ **永久保留**，这是最有情感重量的东西 |
| 契约完成次数 / 称号 | ✅ 保留 |
| 信誉分 | ⚠️ **部分衰减**（保留 70%，避免老玩家准入优势过大） |
| 专精等级 | ❌ 重置（否则老玩家永远碾压） |
| 赛季进度、CP | ❌ 重置 |

### 6.3 异常情况处理

| 情况 | 处理 |
|---|---|
| 契约成员被封号 | 该成员贡献作废；契约**不因此失败**（其他成员仍可完成），进度按比例要求下调 |
| 资源在抢救期被删除 | 目标作废，全队不扣分（不是他们的错） |
| 契约跨越赛季边界 | 契约在赛季内必须完成，跨季视为未完成（避免赛季设计被绕过） |
| 玩家中途注销 | 同"被封号"处理 |

## 七、修订后的实施计划（含冷启动路径）

| 阶段 | 周期 | 内容 | 验收标准（DoD） |
|---|---|---|---|
| **P0 · 埋点** | 1 周 | 灰度开关、对照分组、北极星指标采集 | 能按分组拉出"周有效做种时长"对比报表 |
| **P1 · 单人玩法** | 2~3 周 | 抢救清单 + 认领 + 进度 + 荣誉 + 贡献采集 + 延迟结算 | **≥ 5% 的活跃用户完成过至少 1 次抢救**（这是冷启动的及格线） |
| **P2 · 小额发行** | 2 周 | 赛季 + 发行池 + 账本对接 | 发行量 ≤ 4.2 硬顶，游戏收益占比落在 10~30% 区间 |
| **P3 · 双人玩法** | 2 周 | 接力保种 + 组队 + 报价谈判（简化版） | 至少 50 个双人契约完成；违约率 < 30% |
| **P4 · 小队协作** | 3~4 周 | 契约、岗位、专精、羁绊、系统托底队友 | 出现"岗位组合"讨论（说明玩家在玩策略层） |
| **P5 · 主题包与后台** | 2 周 | 主题数据化、后台编辑、多板块挂载 | 新增一个主题包 = 后台插一行数据，不改代码 |

**关键门禁**：P1 的"≥5% 完成过抢救"不达标，**不要进 P2**。冷启动没解决，后面全是空中楼阁。

## 八、通用主题包文案样例（`generic` 包，可直接用于任何站型）

主题数据化的意义就在这里——下面是 `generic` 包的全部内容，插进数据库就能用：

```json
{
  "key": "generic",
  "name": "贡献者计划",
  "roles": [
    { "key": "keeper",  "name": "守护者", "behavior": "seed_rare",  "desc": "保种冷门资源" },
    { "key": "sharer",  "name": "分享者", "behavior": "seeding",     "desc": "长期做种" },
    { "key": "publisher","name": "发布者", "behavior": "publish",    "desc": "发布新资源" },
    { "key": "helper",  "name": "联络人", "behavior": "community",   "desc": "解答与协助" },
    { "key": "lead",    "name": "统筹",   "behavior": "manage",      "desc": "协调团队进度" }
  ],
  "outputs": { "unit": "贡献凭证", "grades": ["合格", "良好", "优秀", "卓越", "传奇"] },
  "seasons": ["常规季", "冷门季", "接力季", "冲刺季"],
  "honors": { "rescue": "拯救者", "relay": "接力手", "frontier": "拓荒者" }
}
```

影视站把 `roles` 换成 摄影/剪辑/配乐/美术/导演、`outputs.unit` 换成"成片"、`grades` 换成 票房分级即可——**机制一行不动**。

## 九、一页总结

| 问题 | 答案 |
|---|---|
| 没人发起契约怎么办？ | **先做单人玩法**（抢救断种）；系统托底队友；梯度解锁；种子用户；空列表永不展示 |
| 我的方案也有社交压力吗？ | 有。分界线：**压力必须来自自愿加入、可预见、可选择、可退出的关系** |
| 要不要团队连坐？ | **不要**。连坐会让新人不敢加入。失败只体现在收益，不体现在羞辱 |
| 玩家 D1~D7 没事干？ | 补**每日微任务**（查看濒危清单、投票加急），轻量保回访 |
| 第一笔收益太少会流失？ | 数值标定：中度玩家赛季收益约 2~3 万魔力，占其做种收益 25% |
| 通胀怎么控？ | 双重上限：**通胀硬顶**（167 万/赛季）+ **收益占比上限**（≤ 做种收益 30%） |
| 为什么是 30%？ | 超过就会**为了玩游戏而做种**，行为被扭曲，本末倒置 |
| 赛季归零会挫败吗？ | 用**荣誉页承接**：拯救记录永久保留，信誉保留 70%，专精才重置 |
| 什么时候能上组队？ | **P1 单人玩法达到 5% 参与率之后再上**，否则是空中楼阁 |
