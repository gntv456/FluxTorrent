## 二、P0 三项详证

### P0-2.1 announce_url —— 成立，但严重度需降档
- 事实链全对：`0034_settings_np_align.sql:13` 默认 `http://127.0.0.1:8080/announce`；`setup_status` 的 checklist（`setup_http.rs:92-114`）聚合三键返回 `announce_local/smtp_unset/registration_mode`；前端 `page.tsx:254-288` 渲染警示卡，纯文字、不阻断、不可点击。
- **但 0209 P2-12 正是本仓自己加的这套 checklist**（见迁移注释与 `setup_http.rs:89-91`），五路方案把自家已做的缓解当空气、把「仅文字警告」当新发现。
- **不成立的子断言**：「apply_pack 时跳过 announce_url」的担忧多余——`pack_core.rs:80-106` 只写 `site_type/site_name/module_*`（外加 categories/sections/tags），从不触碰 announce_url，无覆盖风险。
- 修复方向本身合理（Step2 采集公网 announce 或 checklist 链接化），应与 2.2/2.3 合并成「开站守卫」一批做。

### P0-2.2 注册死锁 —— 全部成立，五路方案最大真贡献
- `0107_module_registry.sql:112` 默认 `invite_only`；`0208` 只是把 email_verify 归一为 open（修「空壳选项」），**没有动默认值、没有产初始码**。
- `setup_finish`（`setup_http.rs:130-209`）purge demo → apply pack → site_name → setup_done，**全程无 invites 表写入**；grep 全 API 源码，`INSERT INTO invites` 只在用户侧发码/商店效果/repo 三处，均不在向导链路。
- 细节纠错：表名是 **`invites`** 不是 `invite_codes`；root 引导在 `0017_bootstrap_root.sql`（root/password123/强制改密），「无法注册第二个账号」的说法要加上「root 可登录、只是无码可发」的精确定义——死的是「第二个用户」，不是「站长自己」。
- 方案 A（向导完成自动产一码并展示在结果页）成本最低，推荐；方案 B（Step3 加注册模式单选）与 0208 的 options 口径兼容，可并行。

### P0-2.3 SMTP —— 半成立
- 降级链属实：`mailer.rs:91-124` host/from 任一为空 → `smtp_config` 返回 None → 主链路静默跳过。
- **「站点设定页的 SMTP 配置不生效」不成立**：0208 P0 修复正是把 `smtp_host/smtp_port/smtp_from`（+ encryption + env 凭据兜底）接入装配，0211 又补了凭据装配；五路方案在「现状」里没说这条，但修复方案 A 的措辞暗示配置无效，易误导。
- 「无测试端点」成立：grep `smtp-test|test_mail|send_test` 全仓无果。POST /admin/smtp-test 值得做，且 checklist 的 smtp_unset 可链过去。
