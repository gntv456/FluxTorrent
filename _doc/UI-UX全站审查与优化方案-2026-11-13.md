# FluxTorrent 全站 UI/UX 审查与优化方案（2026-11-13）

> 本轮只审查、不改生产代码。所有结论都给出可指认的路径与行号，或可由文末「复跑方式」重现。
> 审查依据：`ui-ux-pro-max`（10 大类 120 条 UX 规范）、`ui-styling`、`design-system` 三个已安装的全局 skill；
> 对照基线：项目自带 `docs/design-system.md`（DS-PLAN-01）、`docs/ui-audit-2026-11-03.md`（10 天前审计）与 7 个设计门禁脚本。

## 0. 范围、方法与结论摘要

| 项 | 值 |
|---|---|
| 路由 | 113 个 `page.tsx` + 6 个 `layout.tsx` |
| 组件 | 约 902 个 `.tsx`（本次统计 787 个纳入设计系统覆盖率口径） |
| 样式 | 30+ 个 CSS，5791 行根链按「令牌 → 布局 → 页面域」分层 |
| 主题 | `brand`（潮汐 TIDE）/ `shanhaijing` 亮暗双档 / `brand-night`，多套独立令牌层 |
| 技术栈 | Next.js 15 App Router (RSC) + Tailwind 4 + CSS 变量主题，非 shadcn/ui；自研 `components/ui` 原语层 |
| 产品类型 | 复杂工具类 + 社区门户（PT 建站系统），重度后台 + 桌面/移动双端 |
| 视口 | 375 / 768 / 1440（沿用 10 天前审计的 244 次采集矩阵） |

**方法**：① 全量静态反模式扫描（覆盖全部页面与组件）；② 4 组并行分组精读；
③ 运行项目自带 7 个门禁脚本取得当前量化基线；④ 与 10 天前审计逐项对账，剔除已修项；
⑤ 用 skill 检索脚本把每条问题对照到具体规范条目（见各条「依据」）。

**一句话结论**：这套 UI 的**基础设施（令牌、a11y 骨架、动效降级、状态四态、门禁）已经相当成熟**，
当前主要矛盾不是「缺能力」，而是 **「令牌/原语定义正确，但 60% 的消费点没有使用它们」**。
因此本方案的重心是**收口与覆盖率**，而不是新增组件或重做视觉。

**与 10 天前审计的关系**：`docs/ui-audit-2026-11-03.md` 的 2 项 P0、8 项 P1 大部分已修复
（本次 5 个门禁全绿可佐证）。本报告不重复这些已修项，聚焦**仍未清偿、且门禁尚未覆盖**的缺口。

## 4. 全站性问题（按 skill 10 大类，含证据 / 依据 / 方案）

### 4.1 【P1】触摸目标：219 处 28–36px，与项目自定 `--tap-min: 44px` 冲突

**证据**（全量扫描，`min-h-[28|30|32|34|36px]` / `h-[28|30|32|34|36px]`）：

- `components/modal.tsx:111` 关闭按钮 `h-7 w-7` = **28×28**，且 `aria-label="close"` 是英文硬编码。
- `app/(main)/admin/settings/_parts/settings-pack-dialog.tsx:69,96,114,185,192,387,398,449` 连续 8 处 `min-h-[36px]` + `text-[11px]`。
- `app/(main)/admin/forums/_parts/forum-board-table.tsx:92` `min-h-[30px]`；
  `forum-cat-create.tsx:39,58,63,70` `min-h-[32px]`；`forum-mods-field.tsx:95,100` `min-h-[32px]`。
- `components/admin-applications.tsx:118,127` `min-h-[32px]`。
- 分布：**admin 100 文件 / components 182 文件 / pages 71 文件**（按 <12px 统计的同源分布）。

**依据**：skill `quick-reference.md` §2 `touch-target-size`（44×44pt / 48×48dp）、
`touch-spacing`（相邻目标 ≥8px）；`pro-rules.md` §Interaction「expand the hit area when the visual icon is smaller」。
注意 skill 同时给出更精确的 Web 口径：`quick-reference.md:28` `web-target-size` = **24×24 CSS px（WCAG 2.2 AA）**。
即按 WCAG 最低线多数控件合规，但**项目自己定义了 `--tap-min: 44px`（base.css:555）并把 <44px 列为 P1-3**，
这是自定标准未落地，不是外部规范不达标。方案应尊重项目已有令牌，不推倒重来。

**方案**（视觉尺寸可保持不变，只扩命中区，避免改版）：

```css
/* app/styles/ui.css 新增：可复用命中区扩展类 */
.tap-expand { position: relative; }
.tap-expand::after {
  content: "";
  position: absolute;
  top: 50%; left: 50%;
  width: max(100%, var(--tap-min));
  height: max(100%, var(--tap-min));
  transform: translate(-50%, -50%);
}
@media (pointer: coarse) {
  button, a[role="button"], [data-tap] { touch-action: manipulation; }
}
```

```tsx
// components/modal.tsx:107-114 —— 三处一起修
<button type="button" onClick={onClose}
  aria-label={dict.common.close}          // i18n 收口
  className="tap-expand flex h-7 w-7 items-center justify-center rounded-full border border-line text-xs text-sub">
  <Icon name="x" size={16} aria-hidden />  // 用 SVG 替掉 × 字符
</button>
```

**迁移顺序**：`modal.tsx` → `admin/settings/_parts/*`（8 处）→ `admin/forums/_parts/*`（6 处）
→ 其余按 `grep` 清单批量。验收：375 视口下 `design/_shots/audit-run.mjs` 的 `<44px` 选择器数
从 208 降到 0（或全部带 `--tap-min` 命中区扩展）。

### 4.2 【P1】排版：434 处 <12px 字号，且亮色主题下压在 2.17:1 的浅灰上

**证据**：`text-[9|10|11px]` 239 处（100 文件）+ CSS `font-size: 9/10/11px` 194 处；
`components/admin-arcade-items.tsx:44` 甚至 `text-[10px]` 用于 label；
`admin-arcade-items-new.tsx:139,149` `text-[11px]` 用于表单 label。
`docs/ui-audit-2026-11-03.md` §P1-6 实测 `--text-fainter #a3b1c6` 在 10–11.5px 上白底 **2.17–2.29:1**；
`docs/design-system.md` §7 自登记「明色 25 组关键配对 17 组 <AA，W-40 登记，只测不调」。

**依据**：skill 优先级表第 6 类「Base 16px / Line-height 1.5 / Text < 12px body 属反模式」；
`quick-reference.md:9` `color-contrast` ≥4.5:1；`quick-reference.md:19` `dynamic-type`
（系统放大字号时不得靠截断丢信息）。skill `--domain ux` 检索命中
`Contrast Readability / Severity: High`（Don't: Gray text on gray background）。

**方案**（两步，先解可读性再解字号）：

1. **令牌收口**（1 处改动，收益最大）：把 `--text-fainter` 从 `#a3b1c6` 加深到 `#6f7f98`
   （白底约 4.6:1），`--text-faint` 同步复核。改完跑 `check_dark_contrast.mjs` 确认暗色不回潮。
2. **新增亮色对比度门禁**：复制 `check_dark_contrast.mjs` 的对拍结构做 `check_light_contrast.mjs`，
   把 §7 的 25 组配对写进基线，先锁「只许向好」，再按主题逐组调。
3. **字号棘轮**：扩展 `ui_design_guard.mjs` 增加规则「`text-[9|10|11px]` 与 `font-size: 9|10|11px` 只许降」，
   基线取当前 434。迁移时把**承载信息的正文/单位/时间/状态**统一提到 `text-xs`(12px) + `--text-muted`；
   纯装饰角标（如 9px 的刻度）可保留，但须挂 `aria-hidden` 或 `title`。
4. `admin-arcade-items.tsx:44` 这类 label 直接换 `FormField` 原语（自带 label/hint/error 四槽与 aria id 织入）。

**验收**：亮色 25 组配对全部 ≥4.5:1；<12px 计数只降不增；`Dynamic Type` 最大字号下无截断丢信息。

### 4.3 【P1｜总根源】原语采用率 39.9%：473 个 tsx 绕过 `components/ui`

**证据**：`design_cov_guard.mjs` 实跑「原语采用率 39.9%（314/787 tsx），基线 39.1%」。
同一份扫描里，`components/admin-*.tsx` 中大量重复的类串常量
（`const LBL = "…text-[10px]"`、`const BTN_SKY = "…"`、`const INPUT_CLS = "…"`），
正是 §4.1 / §4.2 / §4.5 各问题的共同来源：每个 admin 组件各写一套按钮/输入框/表格类串。

**依据**：`design-system` skill 的三层令牌结构（Primitive → Semantic → **Component**）与
「Never use raw hex in components / 组件层用 token」；`ui-styling` skill 的
「Component Composition：从简单可组合原语构建复杂 UI」「Extract components only for true repetition」；
`ui-ux-pro-max` 优先级第 4 类「Consistency」。`docs/design-system.md` §1 宪法 L4 页面层「禁止 import L1」。

**方案**：不新建组件，只做**迁移与收口**：

1. 以 `design_cov_guard.mjs` 的缺口清单为工单源，按「被复用次数 × 违规密度」排序，
   优先迁移 `admin-*.tsx`（100 个文件含 11px、219 处小按钮中的多数）。
2. 建立统一常量层（若暂不想大改，可先做轻量收口）：
   ```ts
   // components/ui/primitives.ts —— 与 tone×size 矩阵对齐
   export const BTN = "inline-flex min-h-[var(--tap-min)] min-w-[var(--tap-min)] items-center justify-center gap-2 rounded-full px-4 text-xs font-bold";
   export const INPUT = "min-h-[var(--tap-min)] rounded-[var(--r-sm)] border border-line bg-cloud px-3 text-sm outline-none focus:border-sky";
   export const CELL = "max-w-[320px] truncate";  // 配合 §4.5 的 TruncateText
   ```
   把 45 个 admin 组件里各自声明的 `BTN_SKY / BTN_LINE / INPUT_CLS / LBL` 逐个替换。
3. **门禁升级**：`design_cov_guard.mjs` 增加「原语采用率目标线」——当前 39.9%，
   设季度目标 60%，并在 `ui_design_guard.mjs` 增加规则「`page.tsx` / `_parts/` 中新增
   `min-h-[` / `text-[11px]` / `truncate` 裸样式即 FAIL」（层级宪法 L4 的机器化）。
4. 目标：一个季度内 39.9% → 60%，同时 §4.1/4.2/4.5 的存量自然下降。

### 4.4 【P2】图片管线：`sizes` 无 `srcSet`、LCP 无优先级、0 处 `next/image`

**证据**：`components/poster-image.tsx:72-81` 传了 `sizes` 但**没有 `srcSet`**（`sizes` 单独存在时不生效）；
全仓 `next/image` 0 处、`<img>` 30 处（`lib/format.tsx:109`、`lib/bbcode.tsx:94`、
`components/medal-badge.tsx:58`、`top/page.tsx:45` 等）；首屏海报没有 `fetchPriority`。

**依据**：skill `--stack nextjs` 检索命中 `Use next/image for optimization / Severity: High
/ Don't: <img> tags directly`；`quick-reference.md:57` `image-optimization`（WebP/AVIF + srcset/sizes）、
`:58` `image-dimension`（声明 width/height 或 aspect-ratio 防 CLS）、`:59` `font-loading`。

**但要公允**：`poster-image.tsx:7-16` 的注释说明了刻意不用 `next/image` 的理由
（外链图床走 `lib/poster-src` 代理、`onError` 只能在 client 附加、CSS 检测不到破图），
且 `aspect-[2/3]` 已把 CLS 处理掉，10 天前审计实测 0 破图 0 缺 alt。**这是合理的工程决策，不该推倒重来。**

**方案**（只补增量，不改架构）：

```tsx
// components/poster-image.tsx —— 新增 priority 与 srcSet
const DENSITY: Record<PosterSize, string> = {
  sm: "46w", md: "79w", lg: "400w",
};
<img
  src={realSrc}
  srcSet={realSrc && !realSrc.startsWith("/api/")
    ? realSrc + " 1x, " + realSrc + " 2x" : undefined}
  sizes={sizes ?? DENSITY[size]}
  loading={priority ? "eager" : "lazy"}
  fetchPriority={priority ? "high" : "auto"}
  /* …其余不变… */
/>
```

- **站内附件**（`/api/v1/attachments/*`、自托管 `cat-icons/`）改用 `next/image`：同域、可走优化、
  无需 onError 回退；`next.config.ts` 按需配 `remotePatterns` 后再评估外链。
- **外链海报**保留 `<img>` + 代理，但给首页/资源库/商城首屏 LCP 海报传 `priority`，
  并在 `layout.tsx` 对首屏关键字体补 `font-display: swap` 复核（`fonts-tide.css` 已自托管）。
- 验收：Lighthouse（项目已有 `.lighthouseci/` + `lighthouserc.js`）的 LCP / CLS 不回退，
  `audit-run.mjs` 图片检查仍为 0 破图 0 缺 alt。

### 4.5 【P2】表格截断丢信息：77 处 `truncate` 多数无 `title` / 无障碍替代

**证据**：`components/admin-jixiao.tsx:213`、`admin-p2-tools-menus.tsx:125`、`admin-hr.tsx:201`、
`admin-exams-table.tsx:82`、`admin-fundings.tsx:154` 等，形如
`<td className="max-w-[320px] truncate font-mono text-sub">{reqs}</td>`，无 `title`、无「复制」入口。
`title=` 全仓 451 处，但绝大多数是 `Modal` 组件的 `title` prop 或字典文案，不是 HTML `title` 属性。

**依据**：`quick-reference.md:19` `dynamic-type`（放大字号时不得靠截断丢信息）、
skill `--stack html-tailwind` 命中 `Text truncation / Severity: Medium`（Do: truncate 或 line-clamp，
Don't: Overflow breaking layout）——注意规范允许 truncate，但要求**信息仍可取得**；
`quick-reference.md` §1 `redundant-entry`、`voiceover-sr`。

**方案**：立一个 `TruncateText` 原语（纳入 §4.3 覆盖率）：

```tsx
export function TruncateText({ text, className = "" }: { text: string; className?: string }) {
  return (
    <span className={"block truncate " + className} title={text} aria-label={text}>
      {text}
    </span>
  );
}
```
