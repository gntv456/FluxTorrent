## PTP（PassThePopcorn）
**列表页（视图/筛选/排序/招牌交互）**
- 架构：Gazelle。`[业内]`
- 视图：**Cover Flow**（iTunes 式电影海报横向流，可平滑滚动）`[业内，sb-innovation 评测]`。
- 筛选维度（极细）：语言、国家、tags、容器(container)、codec、source、resolution、release type、freeleech、字幕、IMDb 评分、PTP 评分、Metacritic 评分 `[业内，torrends.to]`。
- 排序：标准 Gazelle 排序（时间/大小/种子数等）；torrent 行有 **color-coded** 配色区分属性 `[业内]`。
- 招牌交互：首页可隐藏局部（最新种子/捐赠/投票/新闻）；Tickets 报障系统入口 `[业内]`。

**详情页（区块清单/招牌能力）**
- 单电影**聚合条目**：条目下按 **SD / HD / UHD / Others** 分组多版本（原盘/重编码并列）`[业内]`。
- **Collections** 主题合集（如 Hammer Horror、Banned in the US、Christmas 等，早期约 144 个）`[业内]`。
- **Golden Popcorn** 标记：双倍 bonus 点的招牌种子 `[业内，inviteland]`。
- **trumping** 机制：可举报/替换劣质或死种，保证同槽最优版本存活 `[业内，onehack/inviteland]`。
- 导演/制片/演员独立页（多数有简介与配图）`[业内]`。
- *据说有*：similar torrents（类似种子）、torrent checks（种子检查）、reseed request（补种请求）、staff review（ staff 评审）、做种者排行榜——本次公开来源**未确认**，标记 `[推断/未确认]`。

**可借鉴点**
- 元数据（IMDb/MC/演职员）与技术信息（码率/音轨/封装）分栏呈现。
- 电影聚合条目 + 多版本分组。
- 主题 Collections 作为发现入口。
- Golden Popcorn 式激励在列表/详情即见。

## 闭源大站共同做对而开源站普遍缺失的能力
1. **元数据与种子技术信息分栏**：PTP/GGn/AB 把 IMDb/MC/演职员/平台等"内容元数据"与码率/音轨/封装等"技术信息"分区块，开源默认模板常混排。
2. **条目级聚合模型（group）**：电影/剧集/游戏/书以"作品条目"聚合多版本，而非一条种子一页；开源多为一维列表。
3. **外部评分/资料库打通**：IMDb/MC/MAL/AniDB/豆瓣聚合，开源站少有原生接入。
4. **列表页即见的激励标记体系**：Golden Popcorn、freeleech、personal freeleech、VIP、金奖章——开源默认模板弱。
5. **内置社区质量门禁页**：offers 投票、trump、tickets、staff review，开源站多靠论坛而非页面内闭环。
6. **追更/通知/日历流**：BTN 新集通知、TL TV Guide，开源站少原生。
7. **富媒体预览**：MAM 样章试听、GGn 截图画廊、PTP Cover Flow，开源默认缺。
8. **内部组/seedbox 激励可视化**：内部组徽标、seedbox 色点，开源少。

## 它们没做的（开源站反而更强的）
- **可自托管与可审计**：闭源大站无法本地部署、代码不可审；NexusPHP/Unit3D/Gazelle 派生可自由改造。
- **第三方脚本生态反哺 UI**：PT 种子海报墙、universal-torrent-gallery（支持柠檬/M-Team）、PTool 等油猴/CLI 多由社区补"海报墙/卡片"短板，说明闭源默认 UI 在此偏弱。
- **开放 RSS/API 与自动化友好度**：开源站（尤 NexusPHP）RSS/API 文档成熟，闭源大站 API 多受限或需内测。
- **部署与迭代成本**：开源站低门槛、社区快速迭代；闭源大站改版慢、依赖内部开发。
- **中文生态成熟度**：华语 nexusphp 站在分类/免费标记/流控上已高度适配国内用户，闭源英语大站反而缺本地化。
