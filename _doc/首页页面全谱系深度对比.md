## 0. 结论先行（10 条）

1. **首页是三种哲学的分野，不是功能多少的分野**：华语 NP 把首页做成「社区运营面板」（签到/魔力/排行/游戏/免责/友链 15+ 区块），Gazelle 做成「新闻发布板 + 论坛枢纽」（News 流 + 封面墙 + 侧栏），UNIT3D 做成「可配置发现面板」（Featured 轮播 + 每用户可见性/拖拽排序）`[实证]`。谁对取决于站点阶段：拉新看发现，留存看运营，氛围看内容流。
2. **「用户级首页配置」只有 UNIT3D 一家做到位**：11 个区块 `{block}_visible/{block}_position` 存 `user_settings`，逐用户开关 + 排序 `[实证]`；NP/XBTIT/U-232 的开关全部是**管理员级**（`$MAIN[...]` / `$BLOCKS` 位掩码 / blocks 表）。XBTIT 早在 2006 年就把区块位置+权限做进了数据库，是这一思路的祖师 `[实证]`，但从未下放到用户。
3. **签到/魔力经济是华语系独有的首页器官**：NP 主线首页源码里**没有**签到、没有海报墙、没有魔力卡片 `[实证]`——这些全是华语大站定制（好学的"签到已得120/补签卡8"用户条、baozi 的整月签到日历+幸运大转盘流水）。国际开源两强（UNIT3D/Gazelle）首页均无签到区块 `[实证]`。
4. **「最新种子」区块的形态梯度**：NP 主线 5 条纯文字表格（无海报，无缓存）`[实证]` < UNIT3D 五 tab（newest/seeded/leeched/dying/dead）×5 行 + 可选海报 `[实证]` < Gazelle 精选封面墙（5 张、按 GroupID 去重、强过滤）`[实证]` < meanTorrent 分类型 Top 榜 + 第一名全屏 backdrop 大图横幅 `[实证]` < baozi/FluxTorrent 海报墙滚动条 `[实证-本地快照]`。**海报墙不是"现代化装饰"，是资源发现的效率器官**。
5. **公告系统的三个层次**：静态列表（NP klappe 折叠）< 可折叠 + 未读自动展开（UNIT3D `ArticleUnread` witness + 通知动画图标）`[实证]` < 头条 + 弹窗 + 置顶促销条（baozi/FluxTorrent 形态）`[实证-本地快照]`。Gazelle 最"论坛化"：News 创建时自动开论坛讨论帖并把链接拼进正文 `[实证]`。
6. **缓存设计是首页工程性的分水岭，且两家给出了可抄范式**：Gazelle 每块独立缓存键 + 写时失效 + TTL 随机抖动 + Top10 锁键防击穿 `[实证]`；UNIT3D `cache()->flexible([5,10])` 梯度重算 + **"凡带 per-user 态的查询刻意绕开共享缓存"** `[实证]`。NP 主线的缓存时长则充满玄学数字（funbox 1043s/756s、polls 7226s/3652s、stats 3000s/1800s/4535s）`[实证]`。
7. **登录墙 vs 公开门面**：UNIT3D/Gazelle(meanTorrent/U-232/sqtracker/Arcadia)/FluxTorrent 全是硬登录墙（Gazelle 匿名首页只有一首莎士比亚诗 + Enter 按钮 `[实证]`）；NP 主线/好学/baozi/Torrust/NyaaPantsu 未登录可看首页。**华语 PT 事实上默认公开首页**（配合邀请制引流），国际 PT 默认零泄露——这是运营策略差异，不是技术差异。
8. **老牌全家桶的启示**：U-232 V4 首页是 20+ portlet 拼装（公告/聊天/新闻/周电影/最新种子/统计/活跃用户/生日/投票/礼包/电台/免责/**捐款进度条**）按用户位掩码开关 `[实证]`——2010 年就把"区块即插件"做全了。新一代反而集体退化：Torrust 首页 = 重定向到 /torrents，公告/统计/投票组件一个都没有 `[实证]`。
9. **聊天盒的技术三代**：NP iframe 整页刷新 → FluxTorrent 15s 轮询（+机器人命令）→ UNIT3D 自托管 socket.io over wss（多房间/私聊/系统 bot/铃铛提醒）`[实证]`。Gazelle 干脆不放首页聊天。**轮询是 PT 规模下的理性选择**（部署简单、可审计），WebSocket 是体验上限。
10. **FluxTorrent 现状：已复刻 baozi 五大板块 + 置顶促销条 + 海报墙（结构上等于华语 NP 首页的完全体），并有 9 键站长级排版系统（0089）——这超过了 NP 主线与绝大多数华语站的管理员配置能力；但缺 5 个高频能力（Featured 精选轮播、Top 榜/濒危种 tab、投票、未读感知公告、个人化区块配置），个性化配置是站长级而非用户级。** 详见 §5。

## 2. 逐派系深入剖析

### 2.1 NexusPHP 系（主线 + 好学/baozi 魔改 + mTorrent SPA）

#### 主线默认首页（`public/index.php`，1.10.3）`[实证]`

12 区块自上而下：Recent News（klappe 折叠，整页缓存 `recent_news` 86400s）→ Funbox（iframe，内容 1043s/票数 756s）→ Shoutbox（iframe）→ **`apply_filter('nexus_home_module')` 首页插件挂载点** → 论坛最新帖子（5 条，实时 SQL 无缓存）→ 最新种子（5 条纯文字表格，无海报无缓存）→ Top Uploader（30 天/全部双 tab，各 60s 缓存）→ Polls（内容 7226s/结果 3652s）→ Stats（users 3000s/torrents 1800s/classes 4535s）→ Tracker Load（`exec('uptime')`）→ 免责 → 友链（86400s）。区块开关 7 个在 `$MAIN[...]`（管理员级）。尾部更新 `last_home` + 清 `unread_news_count`——**首页即"已读公告"判定点**。

关键事实：**主线没有签到区块、没有海报墙、没有魔力卡片、没有排行榜（除 top uploader）、没有等级分布**——这些都是大站定制。

#### 好学站快照（`UI参考/real_pages/index.php.html`）`[实证-本地快照]`

在主线骨架上加装：用户信息条（分享率/上传/下载/当前活动/认领/**签到已得120, 补签卡:8**/火花余额/邀请/私信数）；**上传排行领奖台化**（TOP1-3 冠军/高光席位 + 头像 + "领先15254种"压制文案 + 追赶梯队 4-10 名，双 tab）；**游戏挂载位**（水浒卡牌 via `nexus_home_module`，导航还有五子棋/农场/刮刮乐/九宫格/猜大小/卡牌合成）；站点数据含**等级分布全列**（Peasant→Nexus Master）与**男女比例**、今日/本周访问；服务器负载直出 uptime；footer 显示 "Redis 42 reads / page created in 0.031 sec"。

#### baozi 快照（`UI参考/baozi_live/index.html`）`[实证-本地快照]`

即 FluxTorrent 首页的复刻母本：社区新鲜事（头条摘要 + "查看公告"按钮 + 列表 + **弹窗**）→ **签到得魔力整月日历**（连签/累计/补签卡，今日高亮）→ **新增资源统计**（今日/7 日均/30 日计 + 30 天普通/官种堆叠柱状图 + 明细表）→ **站点数据三列**（用户/种子/做种比/警告/禁/未验证/总流量）→ **幸运大转盘流水**（"[时间] 用户 获得 魔力 1000"×15）→ 免责条款 + 友情链接。顶部另有海报墙（种子入口）。

#### 华语大站逐站 `[实证：PT-Plugin-Plus config / ptool site 反推]`

M-Team 新版为独立 mTorrent SPA（纯 JSON API `/api/torrent/search` + `genDlToken`，海报缩略图表格 + ant-design；`status.discount` 字段化促销 `[实证]`）——**首页即种子发现流**，传统社区板块弱化；首屏模块明细 `[未获取]`。HDHome 有 LIVE 演唱会频道 `[实证]`；黄豆有 Study 学习分类 `[实证]`；OurBits/PTer 有保种列表插件 `[实证]`；U2 有魔力时薪与家用宽带流量抵扣适配 `[实证]`；其余绝大多数为 NP 标准首页 `[业内]`。

#### 优势 / 劣势

**优势**：① 留存运营器官最全（签到/补签/魔力/游戏/排行/领奖台）② 公告即"已读"机制内建 ③ 插件挂载点让大站长出差异化定制 ④ 缓存键意识早（虽参数玄学）。
**劣势**：① 用户个性化为零（全部管理员开关）② 最新种子区块信息量垫底（5 行文字无海报无缓存）③ iframe 聊天/funbox 整页刷新 ④ 首页承担过多（运营面板 + 运维面板 + 法务面板混在一页）。

### 2.2 UNIT3D（首页个性化天花板）

#### 架构：用户可配置区块拼装 `[实证]`

`HomeController` 把 11 个区块的 `visible`+`position` 读自用户设置表动态排序过滤；视图只是 `@foreach($blocks)` 循环 `[实证]`。默认值在 `User::settings()` HasOne `withDefault()`（`app/Models/User.php` L305-345）。**无站点级首页配置**，完全下放用户。

#### 11 区块清单（默认顺序）`[实证]`

| # | 区块 | 数据/缓存 |
|---|---|---|
| 0 | news（Article 最新 3 条，折叠面板，**未读自动展开+动画图标** via ArticleUnread） | 无缓存（含 per-user 态） |
| 1 | chat（Chatbox，Laravel Echo + socket.io over wss，多房间/私聊/bot/铃铛） | WebSocket |
| 2 | featured（**精选种子横向自动轮播**：5s、hover 暂停、箭头循环，纯 scrollLeft 无轮播库） | flexible [5,10]min |
| 3 | random_media（Livewire；Redis `SRANDMEMBER` 预建集合，3 电影+3 剧 backdrop） | Redis 集合 |
| 4 | poll（未过期且**未投过才显示**，投过整块消失） | flexible [5,10]min |
| 5 | top_torrents（Livewire **五 tab**：newest/seeded/leeched/**dying(seeders=1)**/dead，各 take 5；海报按用户 `show_poster` 开关，默认关；行内 withExists 六种用户态） | 实时（含用户态） |
| 6 | top_users（上传者/下载者/上传量/下载量/做种/种时/贡献 等多榜，各 take 8） | flexible [1,2]h |
| 7 | latest_topics（按组权限过滤，take 5） | 无缓存 |
| 8 | latest_posts（带点赞/点踩/BON 小费统计，take 5） | flexible，按组隔离 key |
| 9 | latest_comments（Torrent/Request morph 评论 take 5） | flexible |
| 10 | online（60 分钟内活跃，尊重隐私匿名化） | flexible [5,10]min |

#### 缓存哲学 `[实证]`

统一 `cache()->flexible($key, [5,10]min 或 [1,2]h)`：5 分钟内必命中、5-10 分钟后台异步重算、10 分钟强制重算——防击穿。**凡带 per-user 态（未读/已读/withExists）的查询刻意绕开共享缓存**。这是"个性化 vs 可缓存"矛盾的最成熟解法。

#### 访问控制 `[实证]`

`/` 挂 `['auth','banned','verified']` 三中间件——**无公开 landing**，游客只有 login/register/application。

#### 优势 / 劣势

**优势**：① 用户级开关+排序是社区站标杆 ② Featured 轮播视觉冲击强且实现极轻 ③ flexible 缓存 + per-user 绕行是工程范式 ④ 权限/隐私细节到位（按组过滤/在线匿名化/adult 开关）。
**劣势**：① 无游客首页（宣传页需自建）② 区块数量/take 数全部硬编码，管理员不可调 ③ top_torrents 实时 + 8 个 withExists 子查询在大站有压力 ④ **无全站统计区块**（在 stats 页）、无 freeleech 倒计时横幅 ⑤ 依赖自托管 socket.io，部署重。

### 2.3 Gazelle 系（OPS 实证 + 闭源分支业内）

#### 登录态首页（`sections/index/private.php` 装配）`[实证]`

**主栏** `private-main.twig`：竞赛 banner（横幅+倒计时）→ **Latest Uploads 封面墙**（`Manager\Torrent::latestUploads(5)`：`<ul class="collage_images">` 118px 封面、tooltip 悬停、按 **GroupID 去重**、仅近 3 天 + Lossless 编码 + 有封面 + 尊重上传者隐私，缓存 `latest_up_%d` 3600s、新种上传时主动失效）→ **News 5 条全文框**（BBCode 正文、Hide/Show 折叠、AJAX 加载更多；缓存 `newsv2` **TTL 0 写时失效**）。

## 4. 十大专题对比

### 4.1 首页哲学：运营面板 vs 发现面板 vs 内容流

三种成熟范式各有完整实现：**运营面板**（NP 系：签到/魔力/排行/游戏/免责/友链，纵向 15+ 块）服务留存；**发现面板**（UNIT3D/Arcadia：Featured 轮播/Top 榜/随机媒体）服务拉新与消费；**内容流**（Gazelle：News+封面墙+策展位）服务氛围。**FluxTorrent 目前是纯"运营面板"（baozi 五板块），发现器官只有海报墙一条**。最有性价比的补强是发现向区块（Featured 轮播 + 濒危种 tab），而不是继续加运营块。

### 4.2 区块配置的三级演进

管理员开关（NP `$MAIN`）→ 数据库槽位+权限（XBTIT blocks 表，2006）→ 用户位掩码（U-232）→ **用户级 visible+position（UNIT3D，唯一在役标杆）**。FluxTorrent 的 0089 排版（9 键 × span × 顺序）处于"站长级 DB 配置"层级，与 XBTIT 同代；**升级路径明确：把 home_layout 从 site_settings 挪到 user_settings 即可对齐 UNIT3D**（前端解析/渲染代码完全可复用）。

### 4.3 公告系统：从"贴墙上"到"感知你"

四个递进：静态列表 → 折叠展开（NP klappe）→ **未读自动展开+动画图标**（UNIT3D ArticleUnread witness）→ 头条+弹窗+置顶促销条（baozi/FluxTorrent）。Gazelle 的独门是**公告自动开论坛讨论帖**——把"发布"和"讨论"焊在一起，这招让评论区永远不缺流量，值得直接抄（我们有 forums，契约已备）。NP 的 `last_home` 清 `unread_news_count` 是最朴素的"访问即已读"。**FluxTorrent 缺的是未读感知**：弹窗有了，但每次进首页都弹 vs 只弹没看过的，体验差一档。

### 4.4 最新种子区块：一行文字到一堵海报墙

梯度：NP 5 行文字（无缓存）→ U-232 悬停弹海报 → UNIT3D 五 tab×5 行+可选海报+六种用户态 → Gazelle 精选封面墙（GroupID 去重+质量过滤）→ meanTorrent 分类 Top+第一名全屏大图 → **滚动海报墙（baozi/FluxTorrent，12 张匀速滚动+悬停暂停）**。两个设计洞察：① UNIT3D 的 **dying/dead tab 把首页变成保种工具**（华语站的对应物是独立"保种区"，我们在 /endangered）；② Gazelle 的**按 GroupID 去重**让 5 个坑位展示 5 部作品而非同一作品 5 个版本——FluxTorrent 海报墙当前无去重，同组多版本会挤占坑位。

### 4.5 策展位：AOTM/Showcase/Featured 的共同语法

Gazelle 的 Album of the Month、PTP 的 Featured、UNIT3D 的 FeaturedTorrent 轮播、U-232 的本周电影、Arcadia 的站点精选——**全部是"人工挑选 + 大图 + 限时"三要素**。这是开源界最少被复刻、闭源站最重视的首页器官（它直接驱动下载行为）。FluxTorrent 的 sticky promos 有"人工挑选+限时"但无大图——**加一张海报横幅轮播就能补齐这一档**（LatestPosters 组件可复用）。

### 4.6 聊天盒：iframe → 轮询 → WebSocket

NP iframe 整页刷新（shoutbox.php 独立页内嵌）→ FluxTorrent/U-232 HTTP 轮询（15s/50 条）→ UNIT3D 自托管 socket.io（多房间/私聊/bot）。**PT 规模（百级并发在线）下轮询是完全理性的选择**：无状态、可审计、运维零增量；WebSocket 的收益（秒级实时）在聊天场景并非刚需。FluxTorrent 的差异化是**机器人命令**（`/` 前缀 → bot/exec，回话仅插本会话不落库避免刷屏）——这一设计在所有参评项目中独一份。

### 4.7 缓存与性能：两套可抄范式

**Gazelle 范式**（写时失效）：每块独立键；`newsv2` TTL 0 依赖 create/modify 主动 delete；`stats_req` TTL 3600+随机 300 防雪崩；top10 结果 6h + `_lock` 锁键 3600s 防击穿。**UNIT3D 范式**（梯度重算）：`flexible([5,10])` 5 分钟必命中/5-10 分钟后台重算/10 分钟强制；**per-user 态查询绕开共享缓存**（news/topics/top_torrents 均不缓存）。FluxTorrent 的 `/home` 每次请求打 10+ 条实时 SQL（统计聚合/30 天分组/流水 JOIN），**是全参评项目中唯一零缓存的首页**——两套范式任抄一套即可（Rust 侧 `tokio::sync::OnceCell` + 后台刷新或 Redis SETEX 均一步之遥）。

### 4.8 登录墙与门面策略

硬墙派：UNIT3D/Gazelle/meanTorrent/U-232/Arcadia/FluxTorrent（Gazelle 门面是首诗；sqtracker 是站名+两按钮；UNIT3D 连门面都没有直接跳 login）。公开派：NP 主线与华语站（首页公开、种子页登录）、Torrust/Nyaa（公开索引）。**华语 PT 事实上选择"公开首页"配合邀请制**——门面即招贴画。FluxTorrent 的 middleware 302 是国际派做法；若未来要引流，需要的是 Gazelle 式"可开关的公开门面"（`SHOW_PUBLIC_INDEX` 一个常量的事）。

### 4.9 留存器官：签到/补签/游戏的经济学

华语系首页的核心是**制造每日回访理由**：签到（连签奖励递增 `attendance_continuous_bonus` 配置）→ 补签卡（稀缺道具，商店购买）→ 幸运大转盘流水（社交证明：别人在赢）→ 游戏插件挂载。国际系对应物是 featured 到期时间（7 天免费精选）与竞赛（Gazelle Contest banner+Leaderboard+"我的名次行"）。**Gazelle 的竞赛三件套（banner 倒计时+Top3 榜+自己的名次）是比签到更高级的留存设计**——它激励的是上传行为而不只是登录行为。FluxTorrent 有签到/补签/转盘全套+baozi 复刻，竞赛器官缺失（contests 页面有但首页无入口）。

### 4.10 首页信息密度的两极与中间态

最密：U-232（20+ portlet 单列）与好学（15+ 区块 + 大段文字公告）；最疏：Torrust（0 区块）/sqtracker（3 区块）；中间态被验证最舒服的是 **11 块（UNIT3D）/双栏 7 块（Gazelle/Arcadia）**。密度本身不是问题，**不可裁剪的密度才是**——UNIT3D 用用户级配置把 11 块变成"你的 N 块"。FluxTorrent 默认 9 键全开（约 8 区块+海报墙），密度适中，但**用户无法裁剪**，站长裁剪是全站一刀切。

## 6. 一句话结论

> **抄 UNIT3D 的「用户级区块配置 + Featured 轮播 + dying/dead tab + flexible 缓存」体验层；
> 抄 Gazelle 的「News 自动开讨论帖 + AOTM 策展位 + 写时失效缓存」运营层；
> 抄好学的「领奖台化排行」与 baozi 的「签到日历+资源统计图」（已复刻到位）；
> 以 Torrust 为戒（首页≠重定向到列表页——社区感是 PT 首页的存在理由）、以 U-232 为戒（密度不可裁剪等于绑架用户）。**
>
> 我们的最短路径：**先给 /home 加缓存（一条 SQL 都不用改），再把 sticky promos 升级成海报轮播、/endangered 变成首页 tab、home_layout 挪进 user_settings——四个动作就把首页从「baozi 复刻」升到「UNIT3D 级可配置发现面板」，且每个动作的前置件（poster/排版解析/濒危 API/用户表）今天都在仓库里。**
