# 种子页面全谱系深度对比（列表页 + 详情页）

> **范围**：PT / BT 索引站的**种子列表页**（browse / torrents / search）与**种子详情页**（details / show）。不含上传页、用户页、管理后台。
> **参评**：26 个项目/站点，覆盖 NexusPHP 系、UNIT3D、Gazelle 系及其闭源分支、老牌 PHP 派、新一代编译型、JS 系、闭源自研大站、以及本仓库 FluxTorrent。
> **基准**：FluxTorrent 代码快照 2026-09-22（`apps/web/app/(main)/torrents/`、`apps/web/app/(main)/torrent/[id]/`）。
> **证据分级**：`[实证]` = 抓到源码/官方文档/适配代码原文；`[业内]` = 多篇文章或社区交叉一致；`[推断]` = 基于间接证据推演；`[未获取]` = 检索未命中，未编造。
> **素材来源**：`_doc/_素材-新一代与老牌PHP系.md`、`_doc/_素材-闭源自研大站.md`（子代理一手抓取，含原文标注）。

## 0. 结论先行（10 条）

1. **种子页面的能力天花板在 NexusPHP 与 UNIT3D，不在"新项目"。** 2010 年的 U-232 就已经有 poster / NFO / 字幕 / 评分 / 标签 / 免费种 / YouTube 预告 `[实证]`；2024 年的 Torrust Index 的 API torrent 对象**连 poster 字段都没有** `[实证]`。**技术栈新 ≠ 页面强。**
2. **列表页的真正分水岭是"视图 + 筛选可分享 + 实时性"**：UNIT3D 是唯一同时做到四视图（list/card/group/poster）、全部筛选 `#[Url]` 持久化、`wire:model.live` 无刷新搜索的项目 `[实证]`。
3. **详情页的真正分水岭是"聚合模型 + 外部元数据"**：Gazelle 的 Torrent Group、PTP 的 Collections、BTN 的 show/season/episode、MAM 的 series —— 闭源大站全部把"作品"放在"种子"之上，开源站（除 Gazelle）几乎全是扁平一行一种 `[实证/业内]`。
4. **华语系的护城河是促销与元数据密度**：NP 的 `sp_state` 多级促销 + 倒计时 + NFO + MediaInfo + PT-Gen 简介 + 同 IMDb 副本聚合，是国际站普遍没有的 `[实证]`。
5. **华语系的最大短板是"页面形态停在 2008"**：原生无海报墙、无批量下载、无实时筛选、无官方 JSON API（第三方只能爬 `table.torrents` / `td.rowfollow` 的 DOM）`[实证]`。这些"现代化"体验全靠 PT-Plugin-Plus / PTool 之类的用户脚本补 `[业内]`。
6. **Gazelle 的 Group 聚合是唯一被闭源大站（PTP/BTN/GGn/MAM）集体验证过的结构**，代价是列表页交互停留在表单提交 + Sphinx 语法，UX 最旧 `[实证]`。
7. **新一代编译型两极分化**：Arcadia 的 master/title/edition 四级模型在结构上最接近 Gazelle（甚至更通用）`[实证]`，Torrust 则是"架构现代、页面极简"，详情页 Tab 化但无海报/NFO/MediaInfo `[实证]`。
8. **JS 系（MongoDB 系）曾最接近 NP 密度**（meanTorrent 2017 就有 TMDB 自动拉元数据 + 截图 + 字幕面板 + 合集 + HnR）`[实证]`，但整派已失败（停止开源 + 高危漏洞 + 站点回迁 NP）`[业内]`。
9. **DOM 契约是隐性资产**：`details.php?id=`、`table.torrents`、`.pro_free` 这套事实标准让一套油猴脚本通吃几十个华语站 `[实证]`；自研站不提供等价契约 = 脚本生态零覆盖。
10. **FluxTorrent 现状：筛选维度已超过 NP 原生（体积/日期/种子数/下载数/完成数区间 + 多维 sec_ 动态维度 + chips 摘要），但页面形态仍是"单视图表格 + 提交式搜索 + 游标翻页"，且详情页缺 5 个高频能力（磁力、peers、书签、相似推荐、截图画廊），列表页缺 4 个（多视图、批量下载、每页条数、行内进度）。** 详见 §5。

## 2. 逐派系深入剖析

### 2.1 NexusPHP 系（主线 + 华语大站魔改 + mTorrent）

#### 列表页（`public/torrents.php`，经典版为 `browse.php`）`[实证]`
- **筛选**：关键词 `search` + `search_area`（0 标题/副标题、1 描述、3 上传者、4 IMDb）+ `search_mode`；分类/来源/媒介/编码/标准/处理/团队/音轨多组多选框（`cat/sou/med/cod/sta/pro/tea/aud` + 编号）；`incldead`（0 含死种 / 1 活 / 2 死）；`spstate`（0 全部 · 1 普通 · 2 免费 · 3 2x 上传 · 4 双免 · 5 半 Down · 7 30%Down）；`inclbookmarked`；`approval_status`；区间 `size_begin/end`、`seeders_*`、`leechers_*`、`times_completed_*`、`added_begin/end`；标签 `tag_id`。
- **排序**：`sort` 1–9（name / numfiles / comments / added / size / times_completed / seeders / leechers / owner）+ `type` asc/desc；默认 `ORDER BY pos_state DESC, id DESC`（置顶优先）。
- **视图**：源码**只有** `torrenttable()` 一种表格渲染，**无海报墙/卡片视图切换**。用户看到的"封面模式"是 PT-Plugin-Plus 的插件层增强，非原生。
- **分页**：`pageSize`（GET，上限 100）。**无批量下载**（DOM 层由用户脚本实现）。
- **RSS**：`torrentrss.php?passkey=...`，参数含 `rows(1-50)`、`icat`、`ismalldescr/isize/iuplder`、`inclbookmarked`、`paid`、`sticky`、`linktype=dl`，输出标准 RSS 2.0 + `<enclosure>`，缓存 300s —— **原生订阅能力比绝大多数竞品都完整**。
- **DOM 契约（第三方依赖）**：`table.torrents:last`、`td.rowfollow`、`a[href*=download.php]`、`a[href*=details.php?id=]`；促销徽章 `.pro_free/.free_bg/font.free`、`pro_free2up`、`pro_2up`、`pro_50pctdown2up`、`pro_30pctdown`、`pro_50pctdown`；H&R `span.tags.tjz`。

#### 详情页（`public/details.php`）`[实证]`
- **区块**：IMDb 海报（`#posterimdb`，点击放大）→ BBCode 简介（`#kdescr`）→ NFO（`#knfo`，权限 `viewnfo`）→ MediaInfo/BDInfo（`enable_technical_info` 开关，由 `TechnicalInformation` 类渲染）→ 文件列表（`viewfilelist()` AJAX 填充 `#filelist`，**逐文件大小由前端拉取**）→ torrent hash（`hex_esc(info_hash)`）→ 同 IMDb 副本（`#kothercopy`，折叠）→ peer 列表（`viewpeerlist()` AJAX）→ 评论（每页 10 + 快速回复）。
- **互动**：感谢 `#thanksbutton`、魔力奖励 `ul.magic li`、书签 `#bookmark0`、举报 `report.php?torrent=`、编辑 `edit.php?id=`、审核弹窗 `/web/torrent-approval-page?torrent_id=`。
- **状态提示**：H&R 图与促销副文本拼在标题里（`get_torrent_promotion_append_sub`，含倒计时）；`?uploaded`/`?existed` 提示"已下载过/已存在"。
- **原生不生成 magnet**，只暴露 info_hash（磁力由前端脚本补）。

#### 华语大站魔改（ptool `site/tpl` 硬证据）`[实证]`

| 站 | 免费标记选择器 | 进度选择器 | 特殊 |
|---|---|---|---|
| M-Team（mteam） | 默认（未自定义） | 默认 | `TorrentsExtraUrls:["adult.php","music.php"]`；`BrushExcludes:["[原盤首發]"]`；`FlowControlInterval:30` |
| 柠檬（lemonhd） | `div:contains("免費")` | — | `TorrentsUrl:"torrents_new.php"` |
| 观众（audiences） | 默认 | — | 综合站，WEB/动漫向 |
| U2（动漫花园） | `img.arrowdown + b:contains("0.00X")` | `.leechhlc_current,.snatchhlc_finish,.seedhlc_current,.seedhlc_ever_inenough` | 进度四态（下载中/完成/做种中/曾做种） |
| 北邮人（byr） | `.pro_free, .pro_free2up` | — | `Insecure:true` |

→ **信号**：同一个"免费"语义在华语站有至少 4 种互不兼容的 DOM 实现。**谁定义了稳定契约，谁就拥有脚本生态。**

#### mTorrent（M-Team API 侧形态，反推）`[实证]`
- JSON API 而非页面爬取：`POST /api/torrent/search` → 每项含 `id/name/smallDescr/size/createdDate/category` + 嵌套 `status{seeders, leechers, timesCompleted, discount, discountEndTime, promotionRule}`
- 促销 `discount` 映射：`FREE / 2XFREE / PERCENT_50 / PERCENT_30 / PERCENT_70 / 2XUP / _2X_PERCENT_50`，叠加 `promotionRule` 临时起止算最终折扣与倒计时
- 下载需先 `POST /api/torrent/genDlToken` 换**签名直链**（`api/rss/dlv2?sign=...`）；无原生 magnet

#### 优势 / 劣势
**优势**：① 促销/折扣模型最精细（多级 + 倒计时 + 临时叠加规则）② 元数据富度行业领先（NFO + MediaInfo/BDInfo + PT-Gen + 同 IMDb 副本 + 字幕区 + H&R 免罪）③ DOM 事实标准 → 工具生态默认适配 ④ 原生 RSS 完整。
**劣势**：① 无多视图、无批量下载、无实时筛选（全靠脚本补）② 无官方 JSON 搜索 API（除 M-Team）③ 服务端渲染表格 + `klappe_*` 折叠，UX 停留在 2008 ④ CVE 记录 31 条（含 6 条 CVSS 9.8 SQL 注入），根因是逐文件拼 SQL + 无统一鉴权 `[实证]`。

### 2.2 UNIT3D（当前页面能力天花板）

#### 列表页 —— Livewire `TorrentSearch` `[实证]`
- **实时无刷新**：搜索框与全部筛选器 `wire:model.live`，输入即查，无需提交/刷新。
- **四视图**：`list / card / group / poster`（`<select wire:model.live="view">`），并按用户设置 `torrent_layout`（1=card、2=group、3=poster）自动选默认。
- **筛选（全部 `#[Url(history:true)]` 持久化）**：分类、类型、分辨率、流派、地区/发行商、原始语言、年份区间、大小区间（带乘数）、**健康度 alive/dying/dead/graveyard**、免费 `free[]`（0/25/50/75/100）、doubleup、featured、internal、personalRelease、bookmarked、wished、notDownloaded、downloaded、seeding/leeching/incomplete、Trumpable、Refundable、Highspeed、关键词、上传者、IMDb/TMDB/TVDB/MAL 外部 ID。**无** anonymous 筛选、**无** 做种数区间。
- **排序**：`name / rating / size / seeders / leechers / times_completed / created_at / bumped_at`（海报/分组视图白名单收窄）。
- **分页**：`perPage` 25（card/poster 24），可选 25/50/75/100，`WithPagination` + `links()`（**非无限滚动**）。
- **卡片交互**：卡上直接下载按钮，显示做种/下载/完成数、评分、流派、上传者、`<time>`；列表行免费图标含 `fl_until` 到期 `diffForHumans()` **倒计时 tooltip**。
- **引擎**：`TorrentSearchFiltersDTO` 双路输出 → 默认走 **Meilisearch**（普通用户也能全文+过滤），仅 staff 强制 SQL 时才查 `description`/`mediainfo`。API 与 Web 复用同一套 DTO。

#### 详情页 —— `show.blade.php` 按 meta 类型 `@include` `[实证]`
`movie-meta/tv-meta/game-meta/no-meta` → 标题 → `general` → `buttons` →（staff）`tools` →（modo）`audits/reports/downloads` → `mediainfo` → `bdinfo` → `description` → `subtitles` → `extra-meta` → `comments`
- **MediaInfo 解析到专业级**：Alpine 折叠面板解析 General/Video（含 HDR 判定 DV5/7/8、HDR10+）/Audio/Subtitles/Encode settings + Copy 按钮；NFO 以 dialog 呈现。
- **字幕区**独立 block（movie/tv）；文件列表 "Show Files" dialog。
- **交互组件全 Livewire**：`thank-button`、`bookmark-button`、playlist dialog、**reseed 请求**（seeders≤2 且你有活跃下载）、**FL token 使用**（Alpine 二次确认，0 种再确认）、tip 打赏、trumpable 骷髅标记、Bump 图标。
- **Similar**：按 **TMDB movie/tv id 取 TMDB 推荐**，非 Meilisearch（→ 非影视类目相似弱）。
- **Peers**：做种/下载数链接到独立 peers 页（客户端/进度/ETA）。
- **管理**：`tools`（编辑/删除）、`reports`（举报 + 未处理数）、`audits`。
- 无文件时按 `config('torrent.magnet')` 生成 magnet。

#### 优势 / 劣势
**优势**：① 唯一做到"实时筛选 + 四视图 + URL 可分享"三者合一 ② MediaInfo 解析专业度最高 ③ 详情页交互组件化（感谢/书签/FL token/playlist/reseed 即时可用）④ Meilisearch 搜索体验 ⑤ 促销到期 tooltip 让"还剩多久"可读。
**劣势**：① **无原生批量多选/zip 下载**（这点甚至不如用户脚本补的 NP）② 无列自定义、无 compact 视图 ③ Similar 依赖 TMDB，音乐/游戏类目失效 ④ Livewire 全栈耦合，复杂查询下前后端边界模糊、性能开销大 `[业内]` ⑤ 运维组件膨胀（Meili + Redis + Reverb + Supervisor + 队列）⑥ H&R warned 提示未在详情页清晰呈现 `[推断]`。

### 2.3 Gazelle 系（OPS/RED 主线 + PTP/BTN/GGn 闭源分支）

#### 列表页（`browse.php` / `sections/torrents/`）`[实证]`
- **筛选**：`taglist`（支持 `!tag` 排除、Any/All）、`artistname`、`groupname`、年份（支持 `2005-2009` 区间）、`releasetype`、`media`、`format`、`encoding`、`haslog`（100%/99%/<100%/无）、`hascue`、`scene`、`vanityhouse`、`freetorrent`（Free/Neutral/Either/Normal）、`filter_cat[]` 多选、`filelist`、`description`、`remastertitle/year`、`recordlabel`、`cataloguenumber`。
- **无** 列表内 `downloaded`/`bookmarked`/`language` 筛选（走独立 `bookmarks.php` 等页）。
- **视图**：普通表格；开启 CoverArt 选项时 group 行内联缩略图（`ImageProxy::tgroupThumbnail`）。**无独立 gallery/海报墙模式**（PTP 的 Cover Flow 是 fork 自研增强）。
- **Group 聚合是核心**：默认 `group_results=1`，**一个 TGroup 一行**，展开显示多 edition/torrent 版本；`DisableGrouping2` 设置或 `group_results` 复选框可切。
- **排序**：`time / year / size / snatched / seeders / leechers / random`。
- **高级搜索**：SphinxQL 语法（`!` 否定、`SPH_BOOL_AND/OR`、字段分隔符、`filelist` 用 `"term"~20` 邻近短语）。
- **可书签**：`setdefault/cleardefault` 把整段 query string 存为用户 `DefaultSearch` 选项。
- **查询实现**：`Search\Torrent` 主查询 `group_by groupid` + 聚合；命中 torrent 级全文时发**第二遍 Sphinx 查询**按 torrent id 精筛；仅属性时退回 PHP 端 `filter_torrent_internal` 逐种校验。

#### 详情页（`details.php` 渲染 tgroup）`[实证]`
- 组级：封面、艺术家/年份/发行类型、标签（可点筛选）、BBCode 描述、collage 汇总、相似推荐（`similarVote`，基于**标签投票**而非 ML）、request 及 bounty 投票。
- 单 torrent 行：format/encoding/media、size、seeders、snatches、freeleech、**View log**（Logchecker 计分）、scene；展开含上传者、`Request re-seed`、查看下载者/做种者/peers/**contents**/reports。
- **文件列表是真实文件树**（`View contents` AJAX 拉 `torrent->fileList`，非 BBCode 折叠），并检测文件夹冲突。
- 音乐站不强调 MediaInfo/NFO（以 Logchecker 日志分为核心），电影 fork 才补。

#### 闭源分支的页面级增强 `[业内]`

### 2.6 新一代编译型（Torrust / Arcadia / NyaaPantsu）

#### Torrust Index（Rust + Nuxt/Vue3）`[实证]`
- **列表页**：`pages/torrents.vue`，顶部 **`Default / Table` 两种视图切换**；搜索框 + `TorrustSelect` **多选分类** + **多选标签**（带搜索）；**排序 UI 仅 4 项**（Uploaded 新→旧 / 旧→新、Seeders 高→低、Leechers 高→低，API 另有 name/size 未在 UI 开放）；分页 `Pagination.vue` **每页 20/50/100 可选**（默认 50，写入 URL `?pageSize=`）。
- **详情页**：Tab 化 —— `TorrentDescriptionTab`（Markdown，内嵌 PNG 经后端代理 + 配额）、`TorrentFilesTab`、`TorrentTrackersTab`、`TorrentCommentTab`、`TorrentCreatedByTab`、`TorrentCreationDateTab`、`TorrentEncodingTab`、**`CanonicalInfoHashGroup`（多 info_hash 格式归组，现代亮点）**、`TorrentActionCard`（下载 + 带个人 announce 的 .torrent）。
- **致命缺失**：API 的 torrent 对象字段为 `title/description/category_id/file_size/seeders/leechers/files/info_hash/uploader` —— **没有 poster/cover 字段，没有 NFO、MediaInfo、截图独立区块**。
- **判定：弱。** 列表交互尚可（标签多选、视图切换、每页可配），详情页空。价值在架构（Rust 性能、API 化），不在页面富度。

#### Arcadia（Rust actix + Vue3 + PrimeVue）`[实证]`
- **`master groups / title groups / edition groups / torrents` 四级分组** + `Collections` 聚合 + `series/authors`。
- 内容模型极丰富：电影（长片/短片）、剧集（季/集跟踪）、音乐（专辑/EP/单曲/原声/混音）、书籍（含 manga/comics/VN）、软件、游戏、期刊。
- **image and icons first**（海报/封面是原生概念，与 Torrust 相反）+ **Visual layout configuration**（信息密度可配）。
- 论坛/审核标注 WIP。
- **判定：中—强。** 模型层最接近（甚至超越）Gazelle/UNIT3D，UI 完整度仍在早期。

#### NyaaPantsu（Go，公开站）`[实证]`
- 列表：分类下拉 + 子分类（如 English-translated）、搜索（正则/排除运算符）、按用户筛选、按种子数排序。
- 详情：文件列表、描述、.torrent、磁力、评论、Trusted/Remake 行染色。
- **天然缺失全部 PT 维度**：无促销、无魔力/积分、无等级/邀请、无比例强制、无 HnR、无海报/NFO 体系（因为它是公开站）。
- **判定：中。** 作为公开索引合格，作为 PT 参照无意义（缺的正是 PT 的灵魂）。

#### 该派总结论
> **"新一代"内部严重分化。Torrust 是「架构新、内涵空」——详情页不如 2010 年的 U-232；Arcadia 是「模型强、UI 早期」；NyaaPantsu 天然出局。真正在页面功能密度上逼近 NP/U3D 的只有 Arcadia（模型层）与已死的 meanTorrent（功能层）。**
> **与 NP/U3D 的 4 个差距维度**：① 海报/媒体资产体系 ② 元数据组织与分组 ③ PT 经济与治理（促销/魔力/HnR/邀请/举报审核）④ 现代 UX（这一项反而新一代赢）。

### 2.7 JS 系（meanTorrent / sqtracker / rartracker）—— 功能做对了，架构做错了

- **meanTorrent（MEAN.js，2017）** `[实证]`：发种时填 **TMDB ID 自动拉取电影元数据**（海报/简介）；种子可绑多个 attr **tag** 用于搜索筛选；评论全 Markdown；上传者/管理员可**上传编辑截图**；独立**字幕面板**；**电影合集 collections**；VIP 属性种；resources group；**HnR**；积分/邀请；IRC 公告；论坛；聊天；请求系统；RSS；多语言。
  - **判定：强（2017 即接近 NP/U3D 密度）**，唯一短板是 AngularJS 技术栈偏老。
  - **但整派已失败**：停止开源 + 高危信息暴露漏洞 + 衍生站 PTDream+ 于 2019-07 宣布回迁 NexusPHP `[业内]`。
- **rartracker**（AngularJS + PHP）：响应式 Bootstrap，bonus/leeches bonus/种时/请求系统/RSS/多语言。判定：中—强。
- **sqtracker**（Node + React + Mongo + Docker）：截图含 Home/Torrent/Upload/Categories/Profile。判定：中。

> **教训**：MongoDB 弱事务 vs PT 计费强一致天然冲突 + 单维护者 = 单点故障。功能密度不是存活的充分条件。

### 2.8 闭源自研大站：共同做对而开源站普遍缺失的 8 件事

1. **元数据与技术信息分栏**：PTP/GGn/AB 把 IMDb/MC/演职员/平台（内容元数据）与码率/音轨/封装（技术信息）分区块；开源默认模板常混排。
2. **条目级聚合模型**：作品条目 > 种子条目（PTP 单电影多版本、BTN show/season/ep、GGn 游戏条目、MAM series）。
3. **外部评分/资料库打通**：IMDb / Metacritic / MAL / AniDB / 豆瓣聚合。
4. **列表页即见的激励标记体系**：Golden Popcorn、personal freeleech、VIP、内部组徽标。
5. **页面内闭环的社区质量门禁**：offers 投票（HDB 上传需 15 票）、trump、tickets、staff review —— 开源站多靠论坛，不在页面内闭环。
6. **追更/通知/日历流**：BTN 新集通知、TL 的 TV Guide。
7. **富媒体预览**：MAM 样章试听、GGn 截图画廊、PTP Cover Flow。
8. **内部组 / seedbox 激励可视化**。

**它们没做的（开源站反而更强）**：可自托管与可审计；油猴脚本生态反哺 UI（PT 种子海报墙、universal-torrent-gallery 说明闭源默认 UI 在此偏弱）；开放 RSS/API 与自动化友好度；中文本地化与华语生态成熟度。

### 2.9 FluxTorrent 现状（基准）

**列表页**（`apps/web/app/(main)/torrents/page.tsx`）
- 已实现：常驻搜索行（关键字 + 范围 + 匹配模式）+ 折叠高级面板（按语义分组：基础 / 数值与时间 / 发布者与状态 / 标签与排序 / 多维 `sec_*`）；**已选条件 chips 摘要条可逐个移除**（体验优于 NP 与 Gazelle）；分类多选；`alive` 三态、`status`、`approval`、`promo`、`mine`、`owner`、`anonymous`、`official`、`tag_id`、`exclude`；体积/日期/种子数/下载数/完成数区间；排序 6 列（name/comments/size/seeders/leechers/completed，同列再点反转）；封面列；RSS 入口（携带 keyword + cats）；游标翻页（`next_cursor`）。
- 未实现：**单一表格视图**（无卡片/海报墙/紧凑切换）；**提交式 SSR 搜索**（非实时）；固定每页 20（不可配）；**无批量下载/多选**；**无列自定义**；**无行内用户下载进度条**（`torrent-table.tsx` 无 progress 相关代码）；sort 无时间字段入口（表头未挂 added）。

**详情页**（`apps/web/app/(main)/torrent/[id]/page.tsx`）
- 已实现：面包屑；海报头（poster + 主信息 + 促销徽章 + 做种/下载数 + `DownloadButton` + 状态卡）；规格网格（大小/文件数/分类/介质/学段/版本/**动态 sections**/评分/info_hash）；标签行 + `PromoBuyButton` + `TorrentManage`（编辑/删除）；简介；**MediaInfo 折叠**；**NFO 折叠**；**同组版本 GroupVersions**；**真实文件树 FileTree**（含 size）；**字幕面板**（同 IMDb 合并）；下载/做种记录 SnatchList；感谢者；评论。
- 未实现/弱：**无磁力链接**（`download-button.tsx` 无 magnet）；**无 peers 列表**（只有 SnatchList）；**无书签/收藏 UI**（`bookmark_count` 只在类型里出现，页面未渲染）；**无相似推荐**；**无截图画廊**；评论无点赞/嵌套/排序；无 FL token / reseed 请求按钮；**无 series/collection 聚合**（只有平坦 group）；H&R 提示未进详情页（独立 `/myhr` 页）。

## 4. 十大专题对比

### 4.1 视图模式：为什么"海报墙"是分水岭
- 只有 **UNIT3D（4 视图）** 与 **PTP（Cover Flow）**、**IPT（海报墙）** 把海报墙做成一等公民；NP/Gazelle 原生都没有，靠用户脚本补。
- Torrust 有 2 视图但无海报数据 → 视图切换形同虚设。
- **结论**：海报墙的前提是 **poster 是数据模型的一等字段**，不是 CSS 布局问题。FluxTorrent 已有 `t.poster` 与封面列 → **缺的只是视图切换与卡片/海报组件**，成本低于多数竞品。

### 4.2 筛选：维度数量 vs 交互质量
- **维度最全**：UNIT3D（25+ 个 `#[Url]` 属性）。
- **维度最"懂行"**：NP（促销七态 + 团队/音轨/处理/标准等影视向维度）、Gazelle（log/cue/scene/vanityhouse 等音乐向维度）。
- **语法最强**：Gazelle（SphinxQL + `!tag` + 邻近短语）。
- **UX 最好**：UNIT3D（实时 + chips 式移除 + URL 可分享）。
- **FluxTorrent**：维度数量已接近 UNIT3D（含 NP 没有的多维 `sec_*` 动态维度与 chips 摘要），但交互是提交式 → **"有维度但不顺手"**，是最高性价比的改进点。

### 4.3 聚合模型：作品 > 种子
| 模型 | 代表 | 适合 |
|---|---|---|
| 扁平 | NP、UNIT3D（部分）、老牌、我们 | 通用/混合站，实现最简单 |
| Group（TGroup） | Gazelle、PTP、BTN、GGn | 音乐/影视/游戏/书 |
| 四级（master/title/edition/torrent） | Arcadia | 通用且最细，维护成本高 |
| CanonicalInfoHashGroup | Torrust | 只解决"同内容不同 hash"，不解决"多版本" |
| Collections / Series | PTP / MAM / BTN | 发现与策展 |

**建议**：通用站不必上四级，但至少要有 **Group（同作品多版本）+ Collection（策展合集）** 两层。FluxTorrent 已有 `torrent_groups`（0069）+ 详情页 `GroupVersions`，**缺 collection 与 series**。

### 4.4 海报与媒体资产体系
- 一等公民：NP（IMDb 海报 + 简介首图）、UNIT3D（TMDB meta）、Gazelle（CoverArt）、Arcadia（image-first）、PTP/GGn/MAM。
- **缺失**：Torrust（无 poster 字段）、Nyaa（公开站）。
- 差异化：MAM 样章试听、GGn 截图画廊、PTP Cover Flow。
- **我们的缺口**：有 poster、有 MediaInfo/NFO/字幕，**缺截图画廊与预览**（详情页无 screenshots 表/组件）。

### 4.5 促销与经济治理的可读性
- NP 的 `sp_state` 七态 + 标题内倒计时是最精细的；M-Team 用 `discount + promotionRule` 叠加算最终折扣（API 层）。
- UNIT3D 把到期时间做成 tooltip（`fl_until.diffForHumans()`）——**"还剩多久"比"是否免费"更能驱动行为**。
- Gazelle 最弱：FL 只是徽标，无倒计时。
- **我们**：`promotion_ends_at` → 详情页算"x天x时" `[实证：torrent/[id]/page.tsx:91-99]`，列表页徽章有；**建议补列表行 hover 倒计时**（对齐 UNIT3D）。

### 4.6 实时性代价
UNIT3D 的 `wire:model.live` 换来体验，代价是 Livewire 全栈耦合 + 复杂查询性能开销 `[业内]`。
**我们（Next.js SSR + Rust API）的正确路线**不是照抄 Livewire，而是：**URL 状态 + 客户端软导航（router.replace + 局部 Suspense）**，做到"输入即筛选"但业务逻辑仍在 API。这样既拿到体验，又不把查询逻辑写进页面组件。

### 4.7 分页与性能
| 形态 | 代表 | 评价 |
|---|---|---|
| 游标（cursor） | **我们** | 深分页稳，但**丢了"跳页"与"总数精确"**（我们 `total_estimate` 是估算） |
| Laravel 分页（offset） | UNIT3D、NP | 可跳页、有总数，深分页慢（`count(*)` 是经典坑） |
| 无限滚动 | 多数 SPA | 体验好，但 URL 状态与 SEO 差 |
| 明确不提供总数 | YemaPT（文档写明"不提供总数接口"，要求按 id 去重）`[实证]` | 极端务实 |

**建议**：保留游标（架构优势），补**每页条数可配（20/50/100）**与**首屏总数缓存**（对齐 YemaPT 的务实口径：总数可缓存 60s，不追求实时精确）。

### 4.8 DOM 契约与脚本生态（隐性护城河）
NP 的 `table.torrents` / `td.rowfollow` / `.pro_free` / `details.php?id=` 是一套事实标准，让 PT-Plugin-Plus、PTool 一套 schema 通吃几十站 `[实证]`。
**我们已有** `/compat/nexusphp/*` 兼容层（迁移 0069 后落地）`[实证]`。**下一步**：把列表页/详情页的语义选择器也稳定下来（如给表格加 `table.torrents`、行加 `data-torrent-id`、促销加 `pro_free` 类），让脚本作者零成本适配。

### 4.9 移动端
- 只有新一代（Torrust/Arcadia/sqtracker/meanTorrent）与我们（Tailwind 响应式）原生友好。
- NP/Gazelle/老牌/多数闭源站：桌面表格在手机上只能用横向滚动。
- **这是我们的结构性优势**，但**海报墙卡片视图在移动端收益最大**，与 4.1 联动。

### 4.10 别踩的坑（死因复盘）
| 坑 | 出处 | 我们怎么防 |
|---|---|---|
| hack 式扩展生态（升级要 reapply hacks） | XBTIT `[实证]` | 插件契约化，禁止 patch core |
| 重写半途人消失 | TBSource BrokenWings `[实证]` | 增量交付，禁止 big-bang rewrite |
| MongoDB 弱事务 vs 计费强一致 | JS 系集体失败 `[业内]` | 已用 PG + 流水账本，坚持 |
| 单维护者单点故障 | meanTorrent `[业内]` | 经济系统与契约的文档化 |
| 逐文件拼 SQL → 31 条 CVE | NP `[实证]` | sqlx 参数化已免疫，盯住 `dangerouslySetInnerHTML`（简介/NFO 渲染处） |
| 种子绑帖子 → 丧失元数据空间 | TorrentPier / Discuz-PT `[实证]` | 保持种子为独立聚合根 |

## 6. 一句话结论

> **抄 UNIT3D 的「四视图 + 实时筛选 + URL 持久化 + 促销倒计时 tooltip」交互壳；
> 抄 Gazelle 的「Group 聚合 + 真实文件树 + 筛选可存默认」结构骨；
> 抄 NP 的「多级促销 + 元数据密度 + DOM 契约」生态位；
> 抄 PTP/MAM/BTN 的「作品级聚合 + 富媒体预览 + 内容/技术信息分栏」呈现层；
> 以 Torrust 为戒（架构新≠页面强，poster 必须是一等字段）、以 TorrentPier/Discuz 为戒（种子别绑帖子）、以 XBTIT/meanTorrent 为戒（hack 生态与弱事务都是死路）。**
>
> 我们的最短路径不是补"功能"，而是补"形态"：**同样的筛选能力，换上多视图 + 实时化 + 每页可配，体验就能从「2010 年表格」跳到「2024 年 UNIT3D 级」，而后端一行 SQL 都不用改。**
