# FluxTorrent 论坛管理后台改版开发策划案

> 版本：v1.0 ｜ 2026-09-22 ｜ 作者：纳纳
> 关联文档：`_doc/论坛版块完善策划案.md`（功能侧 Phase0-4，已基本落地）、
> `_doc/论坛UI设计策划.md`（前台视觉）、`design-system/FluxTorrent-Tide主题设计方案.html`
> 配套原型：`design-system/FluxTorrent-论坛管理改版样例.html`
>
> **本文只解决「管理侧」问题**：分区管理失效、编辑不可用、管理页难用。
> 功能侧（帖子类型/点赞/悬赏/抽奖…）不在本文范围。

## 0. 一页结论

现状一句话：**论坛管理被塞进 `/admin?tool=forums` 这一个 tab 里，数据契约错位导致分区名全看不见，
前台不渲染空分区导致新建的分区"凭空消失"，编辑表单不回填导致编辑功能实质不可用。**

实测确认（非推断，证据见 §1）：

| 编号 | 问题 | 现象 | 严重度 |
|---|---|---|---|
| **B1** | 分区列表数据契约错位 | 后台「分区管理」一排**空白胶囊**，分区名看不见 | **P0** |
| **B2** | 前台不渲染空分区 | 新建分区后前台**完全不出现**，像没建成功 | **P0** |
| **B3** | 版块编辑表单不回填 | 点「编辑」表单全空，保存会被拦或**静默把门槛改成 0/0/0** | **P0** |
| **B4** | 分区无编辑/排序/隐藏入口 | 后端 `PUT /admin/forum-categories/{id}` 已就绪，前端没接 | P1 |
| **B5** | 版主输入框 state 全表共享 | 在任一行输入，所有行输入框同步显示同一文本 | P1 |
| **B6** | 管理入口深埋 + 版主够不着 | 论坛管理是 ~30 个 `?tool=` tab 之一；版主**无任何管理入口** | P1 |
| **B7** | 卫生问题 | 未使用 import、重名分区可建、`sort` 全为 0 顺序不稳 | P2 |

改版主轴（三件事）：

1. **修契约**——B1/B2/B3 三条 P0 当天可修完，是改版的止血步骤。
2. **正结构**——管理从「一个 tab 里的表单堆」升格为**独立「论坛结构」管理页**，
   采用「左分区树 + 右版块表」的主从布局，分区与版块在同一屏内完成增删改排。
3. **开入口**——把**版主就地管理**（本版块主题置顶/锁定/移动/加精）还给前台版块页，
   版主不必进后台；staff 才进独立管理页。

## 1. 问题诊断（实测证据）

### 1.1 B1 — 分区列表数据契约错位【P0，必现，已实测】

**后端** `apps/api/src/admin_http/forum.rs:58-64`：

```rust
let categories: Vec<(i64, String, i32, bool)> = sqlx::query_as(
    "SELECT id, name, sort, visible FROM forum_categories ORDER BY sort, id",
)
```

元组 `Vec<(i64, String, i32, bool)>` 序列化为**数组的数组**，不是对象数组。

**实测** `GET /api/v1/admin/forums`（root 身份，见 `_forum_admin_probe.py`）：

```json
"categories": [[1, "综合交流", 0, true], [3, "资源交流", 0, true]]
```

**前端** `apps/web/components/staff-tools-forums-cats.tsx:44-59` 却按**对象**访问：

```tsx
{(forumData?.categories ?? []).map((c) => (
  <span key={c.id} className={CAT_TAG}>   {/* c.id === undefined */}
    {c.name}                              {/* c.name === undefined */}
```

**后果**：`c.id` / `c.name` 恒为 `undefined` →
- 每个分区渲染成一个**没有文字的空白胶囊**（只剩一个 `×` 删除按钮）；
- 多个分区时 `key={undefined}` 全部相同 → React key 重复警告。

**对照组**：同一个接口的 `mods` 返回 `Vec<(i64,i64,String)>`，前端
`staff-tools-forums.tsx:107` 用 `m[0] / m[1] / m[2]` **索引**访问，因此工作正常。
→ 说明 `categories` 是拆文件时**漏改的访问方式**，不是设计如此。

> 用户所说的「新建了分区，看不到分区」，在后台这一侧的直接原因就是 B1：
> 分区确实建成了（DB 里 `id=3 资源交流` 真实存在），但名字渲染不出来。

### 1.2 B2 — 前台不渲染空分区【P0，必现，已实测】

前端 `apps/web/app/(main)/forums/page.tsx:20-29` 的分组是**从版块列表反推**的：

```tsx
for (const f of forums) {
  const name = f.category_name ?? dict.forums.uncategorized;
  ...
}
```

分区本身没有独立数据源，**没有版块的分区永远不会被渲染**——连导航锚点、连标题都没有。

后端 `apps/api/src/community_http/forums.rs:104-117` 的 `forum_list` 同样：
只 `SELECT ... FROM forums f LEFT JOIN forum_categories c`，
**不返回 `categories` 列表本身**，也**完全没有过滤 `c.visible`**。

**实测** `GET /api/v1/forums`（当前库里 2 个分区 / 8 个版块）：

```
返回条数: 8
  id=1  站务公告   category_name=综合交流
  id=3  新手报到   category_name=综合交流
  id=4  播种帮助   category_name=综合交流
  id=6  活动专区   category_name=综合交流
  id=7  议事厅     category_name=综合交流
  id=8  水族馆     category_name=综合交流
  id=9  回收站     category_name=综合交流
  id=2  资源交流   category_name=None        ← 注意这个
出现过的分区名: {None, '综合交流'}
```

**两个致命细节**：

1. 用户新建的分区 **`id=3 资源交流`（sort=0, visible=t）在响应里完全不出现** ——
   因为它下面还没有版块，前台按「已有版块」反推分组，自然漏掉它。
2. 库里**同时存在**一个**版块** `id=2`，名字也叫「**资源交流**」，且 `category_id = NULL`
   （落在「未分组」）。用户在前台看到底部孤零零一个「资源交流」版块，
   **极易误判为"我新建的分区跑到未分组去了 / 分区建成了空壳"** —— 这是重名带来的认知陷阱。

> 所以「新建了分区，看不到分区」是 **B1 + B2 + 重名版块**三者叠加的结果：
> 后台看名字是空白（B1），前台压根不渲染（B2），而前台那个同名的「资源交流」是版块不是分区（重名）。

### 1.3 B3 — 版块编辑表单不回填【P0，编辑功能实质不可用】

`apps/web/components/staff-tools-forums-form.tsx:37-43`：

```tsx
const [fName, setFName] = useState("");      // 永远从空开始
const [fDescr, setFDescr] = useState("");
const [fMr, setFMr] = useState(0);
const [fMw, setFMw] = useState(0);
const [fMc, setFMc] = useState(0);
const [fProt, setFProt] = useState(false);
const [fCatId, setFCatId] = useState<number | "">("");
```

全文件**没有** `useEffect` 依据 `fEditId` 去回填数据。
而进入编辑态的路径（`staff-tools-forums.tsx:172`）只做了一件事：

```tsx
onClick={() => setFEditId(f.id)}
```

**后果链**：

1. 点「编辑」→ 标题变成「编辑版块 #3」，但**名称/描述/门槛/分区/保护 全部为空**（`fMr=0`）。
2. 用户以为表单坏了（因为看不到当前值），或者只改了名称就点「保存」。
3. 提交 payload 里门槛变成 `0/0/0`，`category_id` 变成 `null`。
4. 后端 `forum_upsert_check` 只校验「读 ≤ 回 ≤ 发」（`0≤0≤0` 通过），
   **不会发现门槛被清空**。

**实测**（`PUT /api/v1/admin/forums/2`，空 name）：
```
被拒: 400 {"code":1002,"message":"参数校验失败: 版块名不能为空"}
```
→ 空名称会被拦（这是唯一的护栏）；但**只要用户填了名称，门槛就会被静默改成 `0/0/0`**，
即把「读/回/发」三档门槛**全部放开给最低等级** —— 这是一次**静默的权限放宽**，
比"编辑不能用"严重得多。受保护标记、分区归属同样会被一并清掉。

### 1.4 B4 — 分区不可编辑 / 不可排序 / 不可隐藏【P1】

后端**已经就绪**，前端没接：

| 能力 | 后端 | 前端 |
|---|---|---|
| 建分区 | `POST /admin/forum-categories`（`forum.rs:81`） | ✅ 有 |
| 改分区 | `PUT /admin/forum-categories/{id}`（`forum.rs:114`） | ❌ **无入口** |
| 删分区 | `DELETE /admin/forum-categories/{id}`（`forum.rs:154`） | ✅ 有（裸 `×`，**无二次确认**） |
| 排序 `sort` | 字段存在，`PUT` 支持 | ❌ 不可见不可改 |
| 隐藏 `visible` | 字段存在，`PUT` 支持 | ❌ 不可见不可改，**且后端 `forum_list` 也没用它过滤** |

**实测库内数据**：两个分区 `sort` **都是 0**（`综合交流`=0、`资源交流`=0）。
`ORDER BY sort, id` 在 sort 相同时靠 id 兜底，**用户无法调整分区展示顺序**。

同时 `forum_categories` 表**没有 `UNIQUE(name)`**（见 §7 迁移前的 `\d` 输出），
可以建出同名分区 —— B2 里那个「资源交流」版块/分区重名事件，就是这类歧义的温床。

### 1.5 B5 — 版主输入框 state 全表共享【P1】

`apps/web/components/staff-tools-forums.tsx:60`：

```tsx
const [fModName, setFModName] = useState("");
```

**单一 state 被用在每一行的"任命版主"输入框上**（同文件 `:148-153`）：

```tsx
{(forumData?.forums ?? []).map((f) => (
  ...
  <input value={fModName} onChange={(e) => setFModName(e.target.value)} />
```

**后果**：在任意一行输入用户名，**所有行的输入框同步显示同一串字符**。
用户在 A 版块输入后、误点 B 版块的「+版主」，就会把 A 的同名用户**任命到 B 版块**。
（`guard` 里 `setFModName("")` 只清一次，掩盖了问题，但编辑过程中是明显错乱。）

### 1.6 B6 — 管理入口深埋 + 版主完全够不着【P1】

**staff 侧**：论坛管理是 `/admin` 页里 `?tool=forums` 的一个 tab。
`apps/web/components/staff-tools.tsx:159` 的 `TABS` 数组里共 **~30 个** tab：

```tsx
["ipcheck",...], ["maxlogin",...], ["resetpass",...], ["deldisabled",...],
["emailbans",...], ["testip",...], ["stats",...], ["cleanup",...], ["ads",...],
["notconnect",...], ["uploaders",...], ["agents",...], ["polls",...],
["dbstats",...], ["syslog",...], ["locations",...], ["hrpardon",...],
["plugins",...], ["agentrules",...], ["forums", "论坛版块"],   ← 第 20 个
["reports",...], ["menu",...], ["roles",...], ["perm",...], ["seedstats",...],
```

入口是「后台 → 找到第 20 个 tab → 点开 → 一个表格 + 两个表单堆在下方」。
没有分区树、没有版块分组、没有搜索、没有排序。

**版主侧**：入口权限是 `forums.manage`（`staff-tools.tsx:122` 的 `TAB_PERM`）。
**版主（`forum_mods` 记录，不挂 `forums.manage` 权限）根本打不开这个 tab**，
而后端 `forum_access()` 明确授予了版主 `can_mod` 能力 —— 能力有、入口无。
前台版块页 `apps/web/app/(main)/forums/[id]/page.tsx` 里
**grep `admin|manage|mod` 零命中**，即版主在自己的版块页上**看不到任何管理按钮**。
（主题管理接口 `POST /forums/topics/{id}/manage` 已在 `community_http/topic_admin.rs` 实现，
但只在主题详情页零散暴露，缺少统一的「版主工具栏」入口。）

## 2. 根因分析

三个 P0 各自独立，不是同一个 bug：

1. **B1 是「拆文件时的契约漂移」**——`staff-tools-forums.tsx` 原来是一个大文件，
   `mods` 用了索引访问、`categories` 用了对象访问；拆成三个文件时没人核对
   `admin_http/forum.rs` 的 `Vec<(..)>` 序列化形状。**类型定义（`ForumCategory`）写成了对象，
   与实际 JSON 不符**，TypeScript 编译期无法发现（`api.get<T>` 的 `T` 是断言，不是校验）。
2. **B2 是「数据源选错」**——前台把「分区」当成「版块的附属字段」而非独立实体，
   用 `forums` 反推分区，导致「空分区」这一合法状态无法表达。
3. **B3 是「受控组件缺初始化」**——典型的 CRUD 表单只写了 create 分支，
   edit 分支的 `useEffect(fEditId => 回填)` 缺失。

**共性**：三者都是"接口/数据层有、UI 层没接对"。所以改版方案必须是
**「先对齐契约、再补 UI、最后重排信息架构」**，而不是直接重画界面——
否则新界面会把同样的 bug 一起搬过去。

## 3. 改版目标与设计原则

### 3.1 目标（可验收）

| 目标 | 验收口径 |
|---|---|
| **看得见** | 后台新建分区后，分区名在管理页立即可见；前台 `/forums` 立即可见（含空分区） |
| **改得动** | 点「编辑」→ 表单**预填当前值** → 只改想改的字段 → 其余字段零变化 |
| **找得到** | 论坛结构管理有稳定直达 URL（`/admin/forums`），从后台导航一步到位 |
| **管得住** | 版主能在**自己版块页内**完成置顶/锁定/移动/加精，不必进后台 |
| **不出错** | 任何破坏性操作（删分区/删版块/清空门槛）都有明确确认与后果说明 |

### 3.2 设计原则

1. **契约先行**：所有管理接口的返回形状，必须与前端 `interface` 逐字段对齐；
   元组数组（`Vec<(..)>`）一律改成具名结构体序列化，**不再让前端猜索引**。
2. **分区是一等实体**：`forum_categories` 独立成接口资源，前台/后台都取它的完整列表，
   版块是它的子项。空分区是**合法状态**，必须能被表达和渲染。
3. **就地管理**：谁在内容现场，谁就能管理。版主不进后台（B6）。
4. **复用 Tide 令牌**：所有新 UI 走 `--font-display` / `bg-cloud` / `border-line` /
   `text-sky` 等既有令牌与 `styles/theme-tide.css`，不引入新色板（原主题零改动换肤纪律）。
5. **单点真相**：分区排序只由 `sort` 决定；分区可见性只由 `visible` 决定，
   且**前台/后台用同一个判定**。
6. **不膨胀**：不新增表；迁移只加必要约束与一个排序列。管理 UI 组件继续走「按域拆分」，
   单文件 ≤300 行、行宽 ≤80（`scripts/line_limit_guard.mjs` 门禁）。

## 4. 信息架构重构

### 4.1 三类角色与能力边界

| 角色 | 判定依据（现有） | 应该能看到的管理 UI |
|---|---|---|
| **staff（论坛管理员）** | `forums.manage` 权限 | 独立「论坛结构」管理页：分区 CRUD + 排序 + 可见性 + 版块 CRUD + 版主任免 |
| **版主（mod）** | `forum_mods` 有记录（`forum_access().can_mod`） | **前台版块页/主题页**的版主工具栏：置顶/锁定/加精/移动/删帖 |
| **版主（超版）** | `postmanage`（class ≥ 90） | 叠加跨版块能力（沿用 `forum_access()` 既有叠加，不另立体系） |

> 关键改动的实质：**把「结构管理」与「内容治理」拆开**。
> 结构管理归 staff（低频、危险），内容治理归版主（高频、就地）。

### 4.2 入口地图（改版后）

```
后台 /admin
 ├─ 左侧导航新增一级项「论坛」  ← 新增，不再埋在 tool tab 里
 │   └─ /admin/forums  论坛结构（独立整页，非 tab 内容）
 │        ├─ 左栏：分区列表（可拖拽排序 / 可见性开关 / 重命名 / 删除）
 │        └─ 右栏：选中分区下的版块表（新建/编辑/删除/任命版主）
 │
 └─ /admin?tool=forums   ← 保留为兼容重定向到 /admin/forums

前台 /forums/[id]  版块页
 ├─ 已登录 && can_mod → 页面右上「版主工具」按钮组
 │    ├─ 批量选择主题 → 置顶 / 取消置顶 / 锁定 / 加精 / 移动版块 / 删除
 │    └─ 快捷入口「版块设置」（staff 时直达 /admin/forums?focus=<id>）
 └─ staff 额外看到「编辑本版」直达管理页

前台 /forums/topic/[id]  主题页
 ├─ 楼层操作（已有）：编辑 / 删除 / 打赏
 └─ 版主操作（补齐）：置顶 / 锁定 / 加精 / 移动 / 删主题
```

## 5. 界面设计

### 5.1 主设计：`/admin/forums` 论坛结构管理页

**布局**：Tide 主题下的**主从双栏**（左 280px 分区树 / 右自适应版块表），
顶部一条操作条。整页高度撑满，两栏各自独立滚动。

```
┌───────────────────────────────────────────────────────────────────────┐
│  论坛结构                              [预览前台]  [新建分区]          │  ← 页头
├──────────────────┬────────────────────────────────────────────────────┤
│ 分区 (3)         │  综合交流           6 个版块                      │
│ ────────────────│  ┌──────────────────────────────────────────────┐ │
│ ▸ 综合交流    6 │  │ 版块      门槛读/回/发  保护  主题  版主  操作 │ │
```

## 6. 接口层改动

### 6.1 契约修正（B1，必做，向后兼容）

**`GET /api/v1/admin/forums`** — `categories` 从元组数组改为对象数组：

```rust
#[derive(serde::Serialize, sqlx::FromRow)]
struct ForumCategoryRow {
    id: i64,
    name: String,
    sort: i32,
    visible: bool,
    forums: i64,   // 新增：该分区下版块数（左栏徽标数据源）
}
```

响应体：

```json
{
  "forums": [ { "id":1, "name":"站务公告", "category_id":1,
                "category_name":"综合交流", "minclassread":0,
                "minclasswrite":0, "minclasscreate":99, "protected":true,
                "topics":12, "sort":0, "mods":[...] } ],
  "categories": [ { "id":1, "name":"综合交流", "sort":0,
                    "visible":true, "forums":6 } ],
  "mods": [[1, 7, "alice"]]
}
```

**决策**：
- `categories` 改对象数组（前端 `ForumCategory` 类型不用动，契约对齐）。
- `mods` **保持元组不动**（前端已用索引访问，改动无收益、徒增回归面），
  但把前端类型标注从隐式改成显式 `type ModTuple = [number, number, string]`，**消除歧义**。
- `forums[]` 顶层新增 `sort` 字段（右栏行内排序用）。

> **同时补一个类型漂移门禁**：`scripts/check_type_drift.mjs` 已存在（挂 `build-test.yml`）。
> 建议把「管理端返回的 JSON 形状 ↔ 前端 interface」纳入该脚本的检查范围，
> 让 B1 这类「TS 断言骗过编译器」的问题在 CI 阶段暴露。见 §8 P2。

### 6.2 前台列表补分区（B2，必做）

**`GET /api/v1/forums`** — 新增顶层 `categories` 字段（不破坏现有 `data` 为数组的形状）：

方案选择：现有响应 `data` 是**裸数组** `Forum[]`，直接改成 `{forums, categories}`
会打断 `lib/data-forum.ts:17` 的 `getForums(): Promise<Forum[]>` 及所有调用方。

**决定**：改为对象是更干净的结构，但影响面需要一起改。**采纳「改结构 + 同步改调用方」**：

```json
{ "categories": [ { "id":1, "name":"综合交流", "sort":0, "visible":true,
                    "forums":6 } ],
  "forums":     [ { "id":1, "name":"站务公告", "category_id":1, ... } ] }
```

同步改动：
- `apps/web/lib/data-forum.ts` → `getForumIndex(): Promise<{categories: ForumCategory[]; forums: Forum[]}>`
  （保留 `getForums()` 作为 `.forums` 的薄封装，避免大面积改调用方）。
- `apps/web/app/(main)/forums/page.tsx` → 改为遍历 `categories` 渲染分组，
  **空分区渲染成「此分区暂无版块」的占位卡**（而不是整段消失）。

**可见性口径统一**：

```sql
-- 非 staff：只看 visible 分区；staff：全看（前台加「已隐藏」标记，便于预览）
SELECT id, name, sort, visible FROM forum_categories
WHERE visible = TRUE OR $is_staff
ORDER BY sort, id, id
```

`forum_list` 里版块的过滤同步加上：版块所属分区 `visible=false` 时，
非 staff 不列出该版块的版块卡片（避免"分区藏了、里面的版块还裸奔"）。

### 6.3 新增/补齐接口清单

| 方法 | 路径 | 用途 | 状态 |
|---|---|---|---|
| `GET` | `/api/v1/admin/forums` | 管理数据（分区对象数组化 + `forums` 计数 + `forums[].sort`） | **改造** |
| `PUT` | `/api/v1/admin/forum-categories/{id}` | 改分区（名/sort/visible） | 已有，前端接上 |
| `POST` | `/api/v1/admin/forum-categories/reorder` | **批量排序**：`{"ids":[3,1,2]}` 按数组序写 `sort=0,1,2` | **新增** |
| `POST` | `/api/v1/admin/forum-categories/{id}/merge` | 把某分区下版块并入另一分区（可选，P2） | **新增（可选）** |

**批量排序的幂等实现**（单事务，避免部分成功）：

```sql
UPDATE forum_categories AS c
SET sort = v.ord
FROM (SELECT unnest($1::bigint[]) AS id, generate_subscripts($1::bigint[], 1) - 1 AS ord) v
WHERE c.id = v.id;
```

`GET /forums/boards` 走 `require_auth`，仅返回当前用户 `minclassread` 可见的版块
（与 `forum_list` 同一套谓词，避免泄漏隐藏版块名）。

## 7. 数据层改动

### 7.1 迁移 `0154_forum_manage_upgrade.sql`

> **建号纪律**：先 `ls apps/api/migrations/ | tail -5` 确认最大号仍为 0153 再落文件；
> 落到 0154 后**立刻** `docker compose up -d --build api` 让迁移应用，
> **不要编好号放着**（本项目已发生过 4 次并行会话撞号）。

```sql
-- 0154 论坛管理改版：分区唯一性 + 版块分区内排序（幂等）

-- 1) 分区名唯一（大小写不敏感、忽略首尾空白）——防 B2 的「分区/版块重名」歧义
CREATE UNIQUE INDEX IF NOT EXISTS uq_forum_categories_name
  ON forum_categories (lower(btrim(name)));

-- 2) 版块在分区内的排序（forums 表当前无 sort 列）
ALTER TABLE forums ADD COLUMN IF NOT EXISTS sort INT NOT NULL DEFAULT 0;

-- 3) 回填：按现有 id 顺序给每个分区内的版块铺开 sort，保证顺序稳定可预期
WITH ranked AS (
  SELECT id, row_number() OVER (PARTITION BY category_id ORDER BY id) - 1 AS rn
  FROM forums
)
UPDATE forums f SET sort = r.rn FROM ranked r WHERE f.id = r.id;

-- 4) 分区 sort 去重（现状两个分区 sort 都是 0，顺序不稳）
WITH ranked AS (
  SELECT id, row_number() OVER (ORDER BY sort, id) - 1 AS rn FROM forum_categories
)
UPDATE forum_categories c SET sort = r.rn FROM ranked r WHERE c.id = r.id;

-- 5) 支撑排序查询
CREATE INDEX IF NOT EXISTS idx_forums_cat_sort ON forums (category_id, sort, id);

-- 6) 清理「分区 / 版块」重名歧义：把与任一分区同名的未分组版块标出来（人工确认，不自动改）
--    这里只输出候选，不做变更——避免误伤真实意图。
--    （迁移里不写 SELECT 输出；由运维脚本 _forum_admin_probe.py 附带报告）
```

> **注意**：第 1 条唯一索引若当前库已有重名分区会**迁移失败**。
> 迁移前必须先跑一次探查（见 §9.1 的预检脚本）。当前实测库里
> `forum_categories` 只有 2 条且名字不同（综合交流 / 资源交流），**索引可安全创建**。

### 7.2 不新增表

分区/版块的管理能力全部可由现有表 + 上述两个列/索引承载。
**不新建 `forum_category_perms` 之类的表**（本项目教训：功能往往已存在，先查四步再动手）。

### 拖拽排序实测

分区顺序改为**可拖拽**（HTML5 原生 DnD，不引第三方库），与原有 ↑↓ 按钮**共用同一套提交路径**
（`_parts/use-category-dnd.ts`：乐观更新 + 失败回滚）。

设计取舍：
- **不替代 ↑↓ 按钮**：按钮是键盘可访问性保障，拖拽只是效率增强。
- **dragover 实时挪动**（而非交换）：被拖项跟着指针走，预览即最终结果。
  安全性来自 `dragIdx === i` 早退 —— 挪完目标位后指针下的元素就是被拖项，不会来回抖。
- **编辑态关闭 draggable**：否则拖拽会抢走改名 input 里的文本选择。
- 拖过但落回原位 → 顺序字符串比对相同 → **不发请求**。

实测（`chk-drag-cat.js`，无头 Edge + 外层 shell 比对 DB）：
拖拽线索 `draggable=true / cursor=grab / 有 ⋮⋮ 手柄 / title 提示`；
「资源交流」拖到首位 → DOM 与接口顺序同时变、`sort` 真落库（`3:sort0 / 1:sort1`）；
再拖回 → 完全复原；↑↓ 按钮同路径同样生效并可还原；
**编辑态 `draggable=false`**；**全程 0 console error**；`forum_categories` 快照**净变化为零**。

**失败回滚用单测锁**（`apps/web/tests/category-dnd.test.ts`，8 例）：
浏览器里要触发回滚得停掉 api 容器（会打断同一仓库的并行会话），所以放在单测里。
覆盖：乐观换位后回滚、拖拽失败回滚、边界 no-op、拖动途中不发请求、**服务端顺序变化时本地乐观顺序让位**。
已做**负向测试**：删掉 hook 里的 `setOrder(prev)` 回滚行 → 两个回滚用例准确报红（退出码 1），
按 md5 还原后 8/8 通过。全量套件 5 文件 34 例全绿。

- **重名分区原本返回 500**：0154 的新唯一索引冲突未被映射，用户会看到「内部错误」。
  已在 `forum_check.rs::unique_or_internal` 把 PG `23505` 转成

  （`admin_http` 生效、`forum_mods`/`community_http` 没生效），表现成「一半改了一半没改」。
  改完再构建，或在大量改动后连续构建两次核对。
- **⚠️ 把 RSC 表格改成客户端组件会引入 React #418（hydration 文本不匹配）**：
  `forums/[id]/page.tsx` 的表格原本由 RSC 直出，**没有 hydration 就没有比对**；
  搬进客户端组件后，`new Date(...).toLocaleDateString()` 在容器（UTC）与浏览器（本地时区）
  渲染出不同日期 → 每个主题行报一次 #418。
  **归因方法**：`chk-hyd418-forum.js` 对「改过的页 / 没改的页」横比 —— 只有
  `/forums/3`、`/forums/4` 报错，`/forums`、`/forums/topic/*` 为 0，据此定位。
  **修法**：给该 `<td>` 加 `suppressHydrationWarning`（React 对时间戳场景的官方建议），
  保留按访问者本地时区显示。修后 5 个页面全部 0 error。
  **推广**：任何 SSR→CSR 的搬迁，都要先扫一遍「依赖时区/随机数/`Date.now()`」的渲染。
- **本环境沙箱禁止 node spawn 子进程**：从 node 里 `execFileSync('docker', …)`
  甚至 `execSync`（走 `cmd.exe`）一律抛 `EBUSY`。
  所以无头脚本**不要自己调 docker/psql 取数据**，把「运行前后取快照并比对」交给外层 shell。
- **缩略截图会骗人**：1x 截图里 `🛡 版主模式` 看着像豆腐块、「清空选择」看着是粉底红字，
