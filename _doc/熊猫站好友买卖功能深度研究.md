# 熊猫站（pandapt.net）好友买卖功能深度研究

> 调研时间：2026-09-17
> 调研对象：`https://pandapt.net/friend-trade.php` 及其 9 个子页面
> 数据来源：已登录会话实测（10 个页面完整 HTML + 45 个后端 action 只读实测 + 全站真实运营数据）
> 结论口径：只调查询类接口，未触发任何写操作，未对站点产生任何数据变更

---

## 0. 一句话结论

**这不是传统意义上的"好友买卖"小游戏，而是一个挂在 PT 站上的重型经营养成子系统（带完整经济闭环）**：以「玩家之间用魔力值互相买卖」为交易外壳，套上经营等级、事务所委托、每日放映三套经验产出，再挂上 250 部电影海报的收集/拍卖市场作为长线追求，最终目的是**给站内过剩的魔力值（积分）造一个可回收的泄洪阀，同时把用户留存从"下载行为"拉长到"每日上线经营"**。

工程上，它是一个 **NexusPHP 服务端渲染壳 + Vue 2.7 SPA + 单入口 ajax.php（45 个 action）** 的混合架构，显著特征是把**全部数值配置放在服务端下发**，前端只做展示与校验，便于热调平衡性。

## 1. 系统定位与设计意图

### 1.1 与传统 NexusPHP「好友买卖」的区别

| 维度 | 老式好友买卖玩具 | 熊猫站此功能 |
|---|---|---|
| 定位 | 单页面小游戏，玩几天就腻 | 10 页面子系统，有等级线（Lv.1→100） |
| 货币 | 单项积分消耗 | 与站点魔力值（bonus）深度绑定，双向流动 |
| 内容 | 只有买卖/打工 | 交易 + 养成 + 经营 + 收集 四层 |
| 生命周期 | 无更新 | 有版本号（`friend_trade_game_v3`）、生效时间、平衡性调整公告 |
| 反作弊 | 基本没有 | 幂等请求 ID、每日次数限制、批次操作白名单、结算对账 |

### 1.2 设计意图（从数值结构反推）

1. **消化魔力值通胀**。PT 站老用户魔力值动辄百万（实测站点一用户 `魔法值 805,990.3`）。此系统给魔力值开了大量出口：槽位 12 万/24 万起、研修 3 万/次、包养 1 万/次、维护费每日扣、拍卖手续费 2%~10%。实测被调研账号身价 9 万，说明**货币确实回流到了系统**。
2. **制造社交摩擦**。买卖的是真实用户（87% 的市场玩家已有主人），被挖角/被追回/被放生会触发站内信，形成"人盯人"的互动压力。
3. **拉长日均在线**。每日必须做的动作：领收益、安排佣人工作、互动、撩主人/回应佣人、放映 5 局、事务所委托结算、包养续期。这套"日课"显著提高 DAU。
4. **给影视站做内容包装**。收集物是 250 部经典电影海报，按 IMDb 排名编号（肖申克=1、教父=2……），与影视站属性天然贴合——**这层皮是可以替换的**（见第 9 节）。

## 2. 技术架构

### 2.1 技术栈

| 层 | 实现 |
|---|---|
| 页面壳 | NexusPHP PHP 服务端渲染（页脚 `Powered by NexusPHP`，带 debug 行 `2 db queries, 16 reads of Redis`） |
| 前端框架 | Vue 2.7.16（本地 `/js/vue@2.7.16.js`）+ Element UI（外部 `unpkg.com/element-ui`） |
| 遗留依赖 | jQuery 1.12.4、layer.js、domTT、ddlevelsmenu（NexusPHP 老底子） |
| 数据注入 | 服务端把首屏数据以 `const bootstrap = {...}` / `const <name> = {...}` 内联进 `<script>`，Vue 直接接管 |
| 接口 | **单入口 `ajax.php`**，POST，45 个 action |
| 存量数据量 | 首页 HTML 196 KB（含内联 JS 110 KB），市场页 56 KB |

### 2.2 接口协议

```
POST /ajax.php
Content-Type: application/x-www-form-urlencoded

action=friendTradeMarketList&params[page]=1&params[keyword]=xxx

→ {"ret":0,"msg":"OK","data":{...},"time":0.049,"rid":"e51a6aaba4ec47714070617829d38f0c"}
```

- 成功 `ret=0`，失败 `ret=-1` + `msg`（如 `Invalid action: xxx`、`Require target_uid`）
- 每个响应带 `rid`（请求标识），前端提交时另生成 `request_uuid` 做幂等
- 部分接口有专用头，如背包赠送要求 `X-Friend-Trade-Inventory-Gift: 1`
- 前端统一 15 秒超时 + `AbortController` 取消

## 3. 玩法机制拆解

### 3.1 交易层（核心外壳）

**身价机制**

- 新玩家初始身价统一 **10,000 魔力**（实测 whlwhlwhl 已到 **300,000 上限**）
- 每次成交后身价 **×1.15**，硬上限 **300,000**

**买入与挖角**

| 场景 | 成交价公式 | 上限 | 手续费 |
|---|---|---|---|
| 签下自由身 | 当前身价 | 300,000 | 无 |
| 普通挖角 | 身价 × 1.20 | 300,000（基础部分） | 买方付全款；原主人实收 92%，系统抽 8% |
| 挖角（主人关系=得力媚助） | 身价 × 1.20 × 1.05 | 315,000 | 同上 |
| 挖角（主人关系=专属娇宠） | 身价 × 1.20 × 1.10 | 330,000 | 同上 |

实测 `kaka`（身价 10,000，主人 quanmingxin，关系生疏侍佣）：`trade_context.price = 12000`、`next_price = 11500` —— 与公式完全吻合。

**追回 / 赎身 / 放生**

| 动作 | 触发方 | 价格 | 时效 | 主人实收 |
|---|---|---|---|---|
| 限时追回 | 被挖走的原主人 | 按操作时基础挖角价 × 关系加价（其他 +10%、得力媚助 +5%、专娇 0） | 挖角后 **24 小时**内 | 92% |
| 赎身 | 被持有者本人 | 当前身价 × 120% | 随时 | 92% |
| 放生 | 当前主人 | 返还 当前身价 × 85% | 随时 | 15% 蒸发 |

**反刷规则**

- 目标玩家每日最多被交易 **5 次**
- 操作人每日最多主动买入/挖角 **10 次**
- 追回资格：只有**普通挖角**产生；追回本身不产生新资格；一旦有人成功追回，本轮此前资格全部作废；赎身/放生/自由身买入也会终结资格
- 追回不继承旧主关系，但「得力媚助及以上」在有效窗口内追回可**完整恢复关系经验**（`reclaim_exp_rate = 0.95`）

**包养与槽位**

| 项 | 数值 |
|---|---|
| 包养费 | 固定 10,000 魔力 |
| 时长（按关系） | 其他等级 24h / 得力媚助 36h / 专属娇宠 48h |
| 作用 | 只阻止普通挖角，**不阻止**限时追回、本人赎身、主人放生 |
| 正式槽位 | 默认 5 个；第 6 个 120,000，第 7 个 240,000，之后翻倍，**购买不可回收** |
| 临时槽 | 超出正式数量的历史佣人降级为临时：不产生每日收益、不计入资产榜 |
| 维护费 | 每日 00:20 扣：`min(对应永久槽价 × 1%, 10,000)` / 槽；欠费则无法签佣人、挖角、接收下家 |

### 3.2 养成层

**五维资质**（上限 100）

| 属性 | key | 描述（服务端下发） |
|---|---|---|
| 德 | `virtue` | 忠诚、稳定和护主倾向，适合护主值守、贴身照料 |
| 智 | `wisdom` | 判断、理财和应变倾向，适合理财看账、私密差遣 |
| 体 | `physique` | 精力、抗压和执行倾向，适合跑腿、加班 |
| 美 | `charm` | 魅力、亲和和招待倾向，适合迎客、陪聊、按摩 |
| 劳 | `diligence` | 勤快、细致和服务倾向，适合打扫、整理 |

**两条提升路径（互不占用额度）**

- **免费资质**：工作历练每累计 10 个有效工作日得 1 点（上限 10 点）；稀有度突破成功另得 5 点。1 点资质 = 1 点属性
- **魔力培养**：付费，累计最多 20 点、单项最多 10 点

**天赋**

- 研修 30,000 魔力/次 → 三个候选，选一或保留当前，可反复刷新
- 分「普通 / 高级」两档，**同时只有一个生效**
- 天赋双面描述：`本人效果`（作为佣人时）+ `主人效果`（作为主人派遣时，可获事务所天赋匹配分）
- 实测样例：`swift_hands 手脚麻利` — 本人「打扫、整理类工作效果提高」；主人「适合的事务所委托可获得天赋匹配分」

**稀有度突破**

- 消耗魔力尝试升一级，成功 **+5 点资质**，冷却 **7 天**
- 失败只扣费、**不降级**，可继续尝试
- 稀有度 5 档：`normal 普通 / excellent 优秀 / rare 稀有 / precious 珍贵 / legendary 传说`

**关系阶段（5 阶）**

| 阶段 | key | 所需关系经验 |
|---|---|---|
| 生疏侍佣 | `unfamiliar_servant` | 0 |
| 熟悉娇仆 | `familiar_pet` | 80 |
| 贴身暖侍 | `close_attendant` | 240 |
| 得力媚助 | `capable_aide` | 560 |
| 专属娇宠 | `exclusive_favorite` | 1000 |

关系阶段直接驱动一组数值（实测 `level_benefits`）：包养时长、挖角加价率、追回加价率、工作收益系数、心情消耗减免、佣人小费比例（0.1）、追回经验返还率（0.95）。

**心情**：影响工作表现，可被「休息」「陪聊」「贴身照料」「大保健」等动作恢复。

**工作（15 种，按关系阶段解锁）**

| 阶段 | 工作 | 能力倾向 |
|---|---|---|
| 生疏侍佣 | 打扫 / 跑腿 / **休息** | 劳 / 体·智 / — |
| 熟悉娇仆 | 整理 / 迎客 / 陪聊 | 劳·智 / 美·劳 / 美·德 |
| 贴身暖侍 | 洗头按摩 / 贴身照料 / 护主值守 | 美·体 / 德·美 / 德·体 |
| 得力媚助 | 外联应酬 / 理财看账 / 私密差遣 | 美·智 / 智·德 / 智·美 |
| 专属娇宠 | 大保健 / 暖侍加班 / 默契协作 | 美·德 / 体·劳·美 / 德·智·美 |

每佣人**每天只能工作一次**；工作可能产生**小费**（`servant_tip_rate = 0.1`，小费不扣主人收益）。

**互动与"撩主人"**

- 每佣人每天可互动 1 次（积累关系经验/解锁后续工作）
- 反向机制：**佣人每天可主动撩主人 1 次**，主人 24 小时内回应后，佣人**下一次普通工作收益 +10%**（`work_bonus.rate = 0.1`）。4 个选项：

|---|---|---|---|---|
| `nuzzle` | 让我蹭一蹭，就一下 | 3 | 8 | +4 |
| `warm_bed` | 给主人暖个被窝 | 3 | 6 | +8 |
| `pillow_talk` | 吹点枕边风 | 5 | 4 | +2 |
| `extra_shift` | 今晚我主动加钟 | 3 | 10 | −4 |

## 4. 经济模型

### 4.1 魔力值流转闭环

```
做种/挂机  ──产出──▶  用户魔力值  ──消耗──▶  ┌── 槽位购买（12万/24万…，不可回收）
                                            ├── 临时槽维护费（每日 00:20，min(槽价1%, 1万)）
                                            ├── 天赋研修（3万/次）
                                            ├── 稀有度突破（费用随稀有度）
                                            ├── 包养（1万/次，24~48h）
                                            ├── 交易手续费（8% 系统抽水）
                                            ├── 放生损耗（15% 蒸发）
                                            ├── 拍卖手续费（买家 2~10% + 卖家 5%）
                                            └── 商城（月卡 3万 / 年卡 30万）
用户魔力值  ◀──回流──  佣人每日收益 / 工作魔力 / 打工小费 / 放映与事务所奖励 / 任务奖励（最高 50 万）
```

### 4.2 系统抽水点汇总

| 抽水点 | 比例/金额 | 说明 |
|---|---|---|
| 挖角/追回/赎身 | **8%** | 原主人/被挖方实收 92% |
| 放生 | **15%** | 返还 85%，其余蒸发 |
| 拍卖买家 | 2% / 4% / 6% / 8% / **10%** | 按海报稀有度 |
| 拍卖卖家 | 5% | 仅成交时收 |
| 包养 | 10,000 固定 | 一次 24~48h |
| 槽位 | 120,000 起，每级翻倍 | 不可回收 |
| 维护费 | min(槽价 1%, 10,000)/日 | 临时槽 |
| 研修 | 30,000/次 | 可反复刷新 |
| 赠送道具 | 商品价 +10% | — |

### 4.3 关键平衡观察

1. **身价有硬顶但关系无顶**。身价封顶 30 万（挖角 33 万），但关系经验、经营等级、海报收藏是**开放式长线**——把玩家从"炒身价"引导到"养关系/收集"。
2. **双倍惩罚保护既得利益**：挖角后身价 ×1.15（涨），但原主人只拿到 92%，且新主人要多付 20%。**每次转手系统抽走约 8%+ 身价涨幅带来的价差**，天然抑制高频倒手（每日上限 5 次/10 次进一步封死）。
3. **追回机制是"反挖角"的社交威慑**：24 小时窗口 + 原主人追回可保住关系经验（0.95 返还），让"挖角"不是纯掠夺，而是引发互动。
4. **临时槽的维护费是"自动降级税"**：老玩家历史遗留的佣人若超过正式槽位，每日被扣维护费，逼迫购买永久槽位（12 万起）—— 这是**针对存量用户的定向回收**。
5. **海报是"抽卡+市场"复合体**：0.5%~0.65% 的传说概率 + 250 款图鉴 + 三档拍卖模式 + 10% 传说手续费，构成完整的长线收集经济。

## 5. 工程实现亮点（值得抄的部分）

### 5.1 服务端下发全部数值

工作表、关系阶段表、评级概率表、委托模板、力益系数（`level_benefits`）全部随接口下发。前端只有少量**校验常量**：

```js
const FRIEND_TRADE_LEVEL_POSTER_MILESTONES = Object.freeze([10, 20, 30, 40, 50, 60, 70, 80, 90]);
const FRIEND_TRADE_POSTER_RARITIES = Object.freeze(['normal','excellent','rare','precious','legendary']);
const FRIEND_TRADE_BATCH_STAGES = Object.freeze(['unfamiliar_servant','familiar_pet','close_attendant','capable_aide','exclusive_favorite']);
```

好处：调平衡不用发版；规避逆向；前端只做展示。代价：每次请求 payload 偏大（首页 20 KB）。

### 5.2 幂等与一致性

- 每个提交动作生成 `request_uuid`（`crypto.randomUUID()`，无则 `getRandomValues` 手工构 UUIDv4）
- 失败时界面**保留原请求编号**提供"按原授权重试"，并明确文案：「重试将核对原记录，不会重复扣费」
- 批量操作语义：**按持有记录顺序逐人执行，状态变化的跳过；余额不足时保留已成功项并逐项提示结果**
- 降价抢拍："抢拍结果不明时，保留原请求编号，查询结果或按原授权重试，不要重新购买"

### 5.3 前端健壮性

- 全量数据 `isValidXxx` 校验函数（字段名精确匹配 + 数量一致性 + 枚举白名单 + 数值范围），不合法直接 `throw`
- `AbortController` + 15 秒超时；`operationGeneration` 计数器防止过期响应覆盖新状态
- 账号切换检测：「登录账号已变更，本页已停止提交操作」

### 5.4 通知与社交

- 被买、被挖、被追回、被放生、佣人被挖走/追回/赎身/收到海报 → 默认发站内信，用户可一键开关（`friendTradeSetNotificationPreference`）
- 首页「小喇叭」滚动全站动态：`X 刚刚通过 Y 获得传说海报《Z》`、`X 挖角了 Y，成交价 N`（实测 20 条动态：包养 8 / 挖角 7 / 追回 3 / 自由身买入 1 / 赎身 1）

## 7. 对 FluxTorrent 的借鉴建议

### 7.1 可直接复用的架构决策

| 熊猫做法 | FluxTorrent 对应动作 | 优先级 |
|---|---|---|
| 单入口 `ajax.php` + `action` 路由 + 统一 `{ret,msg,data}` | API 已按资源分路由，可另开 `POST /api/v1/game/action` 承接小游戏类指令，**action 名 + params 袋**，避免为每个小动作开路由 | 高 |
| 服务端渲染壳 + 内联 `bootstrap` JSON + Vue 接管 | Next.js 已有 SSR，可对齐「首屏数据内联进 `__NEXT_DATA__`，前端只做交互」的做法 | 中 |
| 全部数值配置服务端下发 + 前端仅校验 | 关键：把「工作表/阶段表/概率表」做成**数据库配置表 + 管理后台可编辑**，而不是硬编码。FluxTorrent 目前若把数值写死在 Rust 常量里，后期调平衡要重新编译发版 | **最高** |
| `request_uuid` 幂等 + 原编号重试 | 交易类接口（挖角/追回/赎身）必须幂等，否则网络重试会造成重复扣费 | **最高** |
| 每日次数限制（目标 5 次/操作人 10 次） | 直接用 Redis 计数器（`INCR` + TTL 到次日 0 点），与现有 Redis 基础设施契合 | 高 |
| 批次操作「按等级分组配置，存 localStorage」 | 服务端只接收最终指令列表，配置属于客户端偏好，不必占用服务端存储 | 中 |

### 7.2 数值设计上的注意点

1. **别让身价封顶变成唯一目标**。熊猫设 30 万硬顶 + 关系/等级/收集三条开放式长线，值得照抄这种"多点追求"结构。
2. **抽水率参考**：交易 8%、放生 15%、拍卖 2~10%。若 FluxTorrent 的魔力值产出速度不同，需要重算：**目标是让系统回收速率 ≈ 做种产出速率**，否则通胀依旧。
3. **临时槽维护费**是针对存量用户的定向回收手段，配合"购买永久槽可把临时槽转正"的转化钩子，是很成熟的付费设计。
4. **关系阶段驱动数值**（包养时长、挖角加价、工作收益系数）比单纯"等级解锁"更有黏性，因为它绑定的是**人与人**的关系，不是一个人的进度。

### 7.3 站型参数化建议（结合 FluxTorrent 通用站定位）

熊猫这层皮（电影海报 250 部）是影视站特化，但**结构完全通用**。建议在 FluxTorrent 里做成配置：

```toml
[friend_trade]
enabled = true
theme = "movie"            # movie | music | book | education | generic
collectible_catalog = 250  # 收集物总数
collectible_source = "imdb" # 或 douban / musicbrainz / custom
currency = "bonus"         # 复用站内魔力值
```

- `theme = movie` → 电影海报（影视站）
- `theme = music` → 专辑封面（音乐站）
- `theme = education` → 教材/公开课（教育站，对应好学那套）
- `theme = generic` → 纯抽象徽章/成就（综合站兜底）

**核心机制（交易/养成/经营/抽成）与主题解耦**，只换素材表与文案表。这是 FluxTorrent 相对熊猫的**架构优势点**——熊猫这套是硬编码在页面里的，换主题要改代码。

### 7.4 不建议照抄的部分

1. **首屏 196 KB HTML（内联 110 KB JS）**：Vue 2 + Element UI 全量 CDN 引入，在现代前端标准下过重。FluxTorrent 用 Next.js + 组件按需加载会好得多。
2. **`unpkg.com` 外链 CDN**：依赖外部可用性，且是供应链风险。本地化打包。
3. **事务性语义模糊的「按原授权重试」**：概念正确但实现复杂（需要服务端保留 pending 记录 + 对账）。建议 FluxTorrent 直接用**幂等键 + 唯一索引**做，别搞"原授权"这套叙事。
4. **等级线一次性放出 Lv.1→100 但实际无人爬升**：上线一个月被查账号全 Lv.1，说明**经验产出速率与等级需求严重不匹配**（Lv.1→2 要 80 EXP，而放映一局才 8~25 EXP 且每日 5 局）。上线前应做数值仿真，否则后期功能（Lv.6 事务所、Lv.15 双人队）实际上等于不存在。

## 8. 风险与合规提示

- 该系统涉及**真实用户之间的资产转移**，被买卖的玩家形象表述（「佣人」「娇宠」「暖床」等）偏向成人化戏谑。若 FluxTorrent 面向教育/正规场景，**文案层必须重做**（改为"合伙人""学徒""经纪人"等中性词），否则会有合规与舆情风险。
- 交易涉及魔力值（可视为虚拟财产），需在规则页明确免责与回滚条款。
- 站内信默认全开可能造成骚扰，熊猫提供了一键关闭，FluxTorrent 应**默认关闭、按需开启**或用聚合摘要。
