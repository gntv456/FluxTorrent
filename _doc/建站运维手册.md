# FluxTorrent 建站与运维手册（面向想用本项目建站的站长）

> 全流程：拿代码 → 配置 → 建站 → 日常启停 → 查看文件 → 备份恢复 → 升级回滚 → 日常维护清单。
> 所有命令都基于本仓库现有结构实测过（Docker Compose 六容器架构）。

## 0. 架构一览（建站前先了解）

| 容器 | 作用 | 端口 | 对外暴露 |
|---|---|---|---|
| flux-postgres | PostgreSQL 16，**所有数据都在这**（含 .torrent 原始字节） | 127.0.0.1:5432 | 否（反代也不需要） |
| flux-redis | Redis 7（缓存/限流/announce 事件流） | 127.0.0.1:6379 | 否 |
| flux-api | Rust Actix 业务 API + **启动时自动跑数据库迁移** | 127.0.0.1:8080 | 经反代 |
| flux-worker | 定时任务（计费/做种收益/H&R/成就/银行/众筹结算） | 无 | 否 |
| flux-tracker | BT Tracker（passkey 鉴权） | **0.0.0.0:7070** | **必须公网直通**（BT 客户端不带 Cookie） |
| flux-web | Next.js 前端 | 127.0.0.1:3000 | 经反代 |

数据只有两处：`pgdata` Docker 卷（全部业务数据）+ `backups/` 目录（你自己的备份）。

## 1. 建站（从零到站点可访问）

### 1.1 拿代码、装依赖
```bash
git clone <本仓库地址> FluxTorrent && cd FluxTorrent
# 服务器只需 Docker + Docker Compose 插件（v2 语法 docker compose）
docker compose version   # 确认可用
```

### 1.2 写配置（唯一的必做步骤）
```bash
cp docker/.env.example docker/.env   # 注意：env 放在 docker/ 目录（compose 的 project 目录）
vim docker/.env
```
必填四项（缺一项或含 change_me 字样会**拒绝启动**，这是故意的防呆）：
```ini
DB_PASSWORD=<强密码>          # PostgreSQL
REDIS_PASSWORD=<强密码>       # Redis
JWT_SECRET=<≥32字节随机串>     # openssl rand -hex 32 生成
CORS_ORIGINS=https://你的域名  # 逗号分隔白名单；生产留空会直接启动失败
```
按需可选：
```ini
PUBLIC_TRACKER_URL=http://tracker.你的域名:7070   # 写进 .torrent 的 announce 地址
PUBLIC_SITE_URL=https://你的域名                   # RSS 输出的绝对链接前缀
PUBLIC_API_URL=https://api.你的域名                # Torznab/开放API 输出前缀
NEXT_PUBLIC_API_URL=https://你的域名               # 浏览器侧 API 地址（同源可留空）
SMTP_URL=smtp://user:pass@smtp:587                # 邮件通知（留空=邮件类跳过）
ANN_METRICS_TOKEN=<随机串>                         # 开启 tracker /metrics 监控端点
API_BIND=127.0.0.1                                # 默认仅本机，外部流量走反代
WEB_BIND=127.0.0.1
```

### 1.3 一键起站
```bash
docker compose -f docker/docker-compose.yml up -d
```
首次会构建三个 Rust/Next 镜像（约 10-20 分钟）。起来后：
- 站点：http://localhost:3000（生产经 Nginx 反代后用域名访问）
- API 健康检查：`curl -s localhost:8080/api/v1/health` → `{"status":"up"}`
- 迁移自动执行：api 容器启动时跑 `apps/api/migrations/`（目前 81 个），**不需要手动建表**

### 1.4 创建站长账号 + 发首批邀请码
注册是邀请制，冷启动直接进库造 root（class 99 = sysop）：
```bash
docker exec -it flux-postgres psql -U flux -d fluxtorrent
```
```sql
INSERT INTO users (username, email, pass_hash, passkey, class_id)
VALUES ('root', 'root@你的域名', 'stub', '改成32位随机hex', 99);
-- 用 /admin/adduser 给 root 设真密码更省事；或 argon2 哈希替换 stub
INSERT INTO invites (inviter_id, code, expires_at)
VALUES (1, '恰好32位字符的邀请码', now() + interval '3 days');
```
把邀请码发给第一批用户 → 他们走 `https://你的域名/register` 注册。

### 1.5 反向代理要点（Nginx）
```nginx
# web + api 同域
server {
    listen 443 ssl http2;
    server_name 你的域名;
    location / { proxy_pass http://127.0.0.1:3000; }        # 前端（含同源 /api 转发）
    client_max_body_size 20m;                                # 上传 .torrent 体积
}
# tracker 直通（BT 客户端无 Cookie，独立端口，不做 TLS 终结也可）
# 7070 端口在防火墙放行即可，通常无需反代
```
详见 `_doc/生产部署指南.md` §4（含 tracker 边缘限流建议：每 IP 10r/s，高于正常 announce 间隔流量）。

## 2. 启动 / 停止 / 重启

所有命令都在仓库根目录执行：

```bash
# 启动（全部）
docker compose -f docker/docker-compose.yml up -d
# 停止（全部；数据卷保留）
docker compose -f docker/docker-compose.yml down
# 停止并清空数据卷（危险！= 删库重来）
docker compose -f docker/docker-compose.yml down -v

# 重启单个服务（日常最常用）
docker restart flux-api flux-worker flux-tracker
# 全部重启
docker compose -f docker/docker-compose.yml restart

# 改了代码后重新构建并滚动更新
docker compose -f docker/docker-compose.yml up -d --build api worker
docker compose -f docker/docker-compose.yml up -d --build web

# 看运行状态
docker compose -f docker/docker-compose.yml ps
```
注意启动顺序是编排好的：postgres/redis 健康后 → api（跑迁移）→ worker/tracker。**全新库时 worker 必须等 api 建完表**，compose 已用 `depends_on: condition: service_healthy` 处理，不需要手动干预。

## 3. 查看站点文件与数据

### 3.1 「站点文件」在哪
本项目**没有独立的种子文件目录**——.torrent 原始字节、封面等全部存 PostgreSQL（`torrent_files.raw` bytea 列）。所以：
```bash
# 业务数据 = pgdata 卷
docker volume inspect docker_pgdata
# 站点源码 = 仓库本身（apps/api、apps/web 等）
# 配置 = docker/.env（密码都在这，权限收紧 chmod 600）
# 备份输出 = ./backups/
```

### 3.2 进数据库查数据（最常用的运维入口）
```bash
docker exec -it flux-postgres psql -U flux -d fluxtorrent

# 常用速查
SELECT id, username, class_id, status, spark_balance FROM users ORDER BY id;      -- 用户
SELECT count(*), min(created_at) FROM torrents WHERE approval_status = 0;          -- 待审种子
SELECT id, name, seeders, leechers FROM torrents ORDER BY id DESC LIMIT 10;         -- 最新种子
SELECT kind, sum(amount) FROM spark_ledger GROUP BY 1 ORDER BY 2 DESC;              -- 经济总账
SELECT * FROM audit_log ORDER BY id DESC LIMIT 20;                                  -- 管理操作审计
SELECT count(*) FROM hr_violations WHERE resolved_at IS NULL;                       -- 未处理违规
\dt        -- 共 168 张表
\q
```

### 3.3 进容器排查
```bash
docker exec -it flux-api sh        # API 容器（busybox，有 wget/sh）
docker exec -it flux-postgres sh   # psql/pg_dump 都在这
docker exec -it flux-redis sh      # redis-cli -a $REDIS_PASSWORD
docker exec -it flux-web sh
```

### 3.4 看日志
```bash
docker compose -f docker/docker-compose.yml logs -f api worker tracker   # 跟踪全部
docker logs flux-worker --tail 100                                       # 单服务尾部
docker logs flux-api --since 10m 2>&1 | grep ERROR                       # 近10分钟错误
docker logs flux-postgres --since 5m 2>&1 | grep -i error                # 数据库层错误
```

## 4. 备份与恢复（最重要的维护动作）

### 4.1 每日备份（建议 cron）
```bash
# crontab -e
0 4 * * * cd /path/to/FluxTorrent && ./scripts/backup.sh 14
# 输出 backups/fluxtorrent-<日期>.dump（-Fc 压缩格式），保留 14 天自动轮转
```

### 4.2 手动备份 / 恢复演练
```bash
# 手动全量
docker exec flux-postgres pg_dump -U flux -Fc fluxtorrent > backups/manual-$(date +%F).dump

# 恢复到新库（灾难恢复）
docker exec -i flux-postgres psql -U flux -c "CREATE DATABASE fluxtorrent_restore;"
docker exec -i flux-postgres pg_restore -U flux -d fluxtorrent_restore --no-owner < backups/fluxtorrent-XXX.dump

# 定期演练恢复（本仓库自带脚本，只读不写原库）
python scripts/backup_drill.py
```

### 4.3 迁站（换服务器）
```bash
# 旧机
docker exec flux-postgres pg_dump -U flux -Fc fluxtorrent > site.dump
# 新机：clone 代码 → cp .env → docker compose up -d → 恢复
docker exec -i flux-postgres pg_restore -U flux -d fluxtorrent --clean --if-exists < site.dump
docker compose -f docker/docker-compose.yml restart
```

## 5. 升级与回滚

升级有两条路径，按你是否改过代码选：

### 5.1 预构建镜像升级（推荐，无需本机 Rust/Node 工具链）

```bash
# 升级（拉官方镜像 → 重建容器；api 启动会自动跑新增迁移）
docker compose -f docker/docker-compose.yml pull
docker compose -f docker/docker-compose.yml up -d

# 回滚到指定版本（迁移不自动回退！回滚前先确认新迁移无破坏性变更，必要时先恢复备份）
# 在 docker/.env 中设置 FLUX_VERSION=<版本号> 后：
docker compose -f docker/docker-compose.yml up -d
```

镜像地址由 `.env` 的 `FLUX_IMAGE_PREFIX`/`FLUX_VERSION` 控制（默认 `ghcr.io/gntv456/fluxtorrent/*:latest`）；
fork 站长可指向自己 registry 构建的镜像。`docker compose pull` 只拉镜像不重建，秒级；`up -d` 重建有变化的容器。

> **从本地源码构建切到官方镜像的存量站（一次性）**：如果你的库曾用 Windows 机器 `--build` 部署过
>（2026-09-16 之前），6 个历史迁移（28/54/57/58/59/61）以 CRLF 行尾入过库，官方镜像（LF）校验不过
> 报 `migration XX was previously applied but has been modified`。执行一次对齐脚本即可：
> ```bash
> docker exec -i flux-postgres psql -U flux -d fluxtorrent < scripts/align_migration_checksums.sql
> ```
> 幂等，重复执行无害。全新建站（直接 pull 镜像）不需要此步骤。

> **回滚纪律**：api 启动即校验迁移集合——新版 api 在库上启动过一次（迁移已 apply）后，
> 回滚到旧版镜像会直接 crash-loop（`migration NN was previously applied but is missing`）。
> 回滚 = 恢复 DB 备份 + 旧镜像，两者必须配套。已发布的迁移文件永远不要再修改（改注释也不行，
> checksum 会变，全量用户启动报 modified）。

### 5.2 源码构建升级（二次开发/内网环境）

```bash
# 升级（拿新代码 → 重建镜像 → 滚动替换；api 启动会自动跑新增迁移）
git pull
docker compose -f docker/docker-compose.yml up -d --build

# 回滚（迁移不自动回退！回滚前先确认新迁移无破坏性变更，必要时先恢复备份）
git checkout <上一个tag或commit>
docker compose -f docker/docker-compose.yml up -d --build
```

## 6. 日常维护清单

### 每日（5 分钟）
```bash
docker compose -f docker/docker-compose.yml ps          # 六容器应全部 Up (healthy)
docker logs flux-worker --since 1d 2>&1 | grep -c ERROR # 应为 0
ls -lh backups/ | tail -3                               # 昨夜备份存在
```

### 每周
- `SELECT count(*) FROM torrents WHERE approval_status = 0;` 处理待审种子
- 后台「工单/举报/作弊事件」页面过一遍（`/stafftickets`、`/admin/cheat-events`）
- 检查磁盘：`df -h`（pgdata 卷 + backups 目录）

### 每月
- `python scripts/backup_drill.py` 恢复演练一次
- 经济对账（余额=流水，不符说明有异常写入）：
```sql
SELECT (SELECT sum(spark_balance) FROM users) = (SELECT sum(amount) FROM spark_ledger) AS reconciled;
```
- 升级宿主机 Docker/系统补丁

### 常见故障速查
| 症状 | 排查 |
|---|---|
| api 反复重启 | `docker logs flux-api` 多半是 .env 缺项或密码含 change_me；或迁移失败（看 PG 日志） |
| worker 每分钟报 ERROR | `docker logs flux-worker`；若是「事件计费失败」看 `flux:announce:dlq`（redis）积累 |
| 用户做种不上量 | tracker 7070 公网可达？`PUBLIC_TRACKER_URL` 配对？announce 是否进了 stream（redis XLEN flux:announce） |
| 站点打不开但 BT 正常 | web/api 容器健康？反代配置？`curl 127.0.0.1:8080/api/v1/health` |
| 忘记管理员密码 | 用另一个 sysop 走 `/admin/resetpass`；或直接 SQL 重置后走必改流程 |

### 监控（可选）
```bash
# tracker 指标（.env 设置 ANN_METRICS_TOKEN 后）
curl -H "X-Metrics-Token: <token>" http://127.0.0.1:7070/metrics
# API 指标
curl -s localhost:8080/api/v1/metrics
```
接入 Prometheus/Grafana 的细节见 `_doc/生产部署指南.md` §8.5。

## 附记：sqlx 迁移 checksum 算法口径（2026-09-18 补）

- sqlx 0.8 的 _sqlx_migrations.checksum 是 **SHA-384**（48 字节 / 96 hex），不是 SHA-256。
- 校验触发条件隐蔽：仅当目录中存在**待执行的新迁移**时才全量校验历史——对齐脚本用错算法
  当时不报错，容器重建/新迁移上线时才爆 "migration N was previously applied but has been modified"。
- 手工对齐 checksum 一律用：sha384sum 文件 → UPDATE _sqlx_migrations SET checksum='\x<96位hex>' WHERE version=N;
- 本次事故面：0107-0113（开发期连续建迁移 + compose 挂载宿主迁移目录），已全部按 SHA-384 对齐并
  实测容器重启通过。与上文「checksum 行尾漂移」属同源纪律：**改迁移文件内容 = 必须重算 checksum**。
