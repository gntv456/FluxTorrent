## 0. 总评

**这是一个安全意识与工程纪律明显高于同类开源 PT 项目的代码库**：经济核心「行锁 → 幂等检查 → 流水 → 快照」单事务管线一致、幂等约束下沉 DB（唯一索引 + 触发器）、worker 任务 advisory lock 互斥、促销倍率按事件时点裁决、announce 计费增量设计天然抗重放；错误信封三语统一到 404/malformed JSON 级别、SQL 注入面实测为零（全部拼接点白名单/参数化）、RBAC 下沉为 PG 函数 `user_can()` 与 worker 共用；前端 RSC-first（54/66 服务端组件）、统一 API client、`strict` 下全库零 `any` 零 `@ts-ignore`、运行时依赖只有 next/react；DB 按月分区 + 软删纪律 + 备份恢复带 `--drill` 演练模式；compose 密钥强制非空、数据面端口收口 127.0.0.1、CORS fail-close。

**主要风险集中在四类横切问题**：
1. **「扣款与副作用」的幂等重放语义未在调用方闭合**（本次修复的最大一类：重放时不再扣款但存单/池账/众筹/置顶照加 = 多个印钞口）；
2. **迁移文件不可变性被破坏**（换号让存量环境无法启动，本次已回退并立规矩）；
3. **巨型文件 + HTTP 层零测试**（http.rs 7826 行，鉴权/分页/隐私类细节缺陷漏到生产的直接原因）;
4. **「快照与流水」双写纪律的漏网点**（付费下载、捐赠套餐、管理端调量三处旁路）。
