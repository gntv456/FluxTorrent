> 日期：2026-10-26 · 方法：四路并行盘点（新手旅程/经济循环/内容发现/召回参与），代码 + docs 双向验证，承接 v0.5.1 后基线

## 一、总体判断

**底盘已是一线水平，短板集中在「软触达」与「发现广度」。**

分面看：

| 产品面 | 成熟度 | 一句话结论 |
|---|---|---|
| 注册/闸门/考核（硬机制） | ★★★★★ | 三注册模式+四道治理闸+考核状态机，超 NexusPHP/UNIT3D 同类 |
| 经济循环 | ★★★★☆ | 单账本+三段式商店+税收入池+银行正利差，但平衡表失真、高净值 sink 稀缺 |
| 检索深度 | ★★★★★ | 40 参数筛选+keyset 游标+55 维度引擎+Torznab 出口，同类最强档 |
| 发现广度 | ★★☆☆☆ | 无内容热榜、无个性化推荐、无作品级订阅——「推存量内容给对的人」全空缺 |
| 触达/召回 | ★★☆☆☆ | 防御型全齐（H&R 三通道），进攻型全缺（召回圈选、促销触达、正反馈回路） |
| 新手软引导 | ★★★☆☆ | 后端清单完备但入口深、指南不可发现、出厂文案与运营模板脱节 |

一句话：**这是一台「机制强、触达弱」的机器**——反作弊、经济、检索的护城河已经建成，但把内容推给用户、把用户拉回站点的「最后一公里」系统性缺失。而后者恰是 PT 站留存与 ARPU 的直接杠杆。

## 二、用户画像与旅程痛点

### 画像 A：新下载者（注册第 1~30 天，最大流失窗口）

旅程：注册 →（直接扔进 /torrents）→ 海量种子无指引 → 装 qBittorrent 默认开 DHT → 触发作弊判定/泄漏风险 → 或 H&R 阶梯触发 → 停下载 → 流失。

**痛点根源（按杀伤力排序）**：
1. **注册成功即裸奔**：`register/page.tsx:210` 注册跳种子列表；新手清单 `/me/onboarding` 后端完备（7 步全库内事实判定，`gaps_http/my_onboarding.rs`）但只有 `/account-health` 二级页一个展示位，主导航与 footer 均无入口。
2. **客户端指南不可发现**：`/clients` 页内容到位（DHT/PEX 必关、禁用清单），全站唯一入口在 `/help` 页底部。新手「注册三天被封」的最典型路径就是 DHT 泄漏，而防御知识被藏在第四层。
3. **从严模板下新号无保护期**：STRICT 模板（`ops_http/onboarding.rs:23-29`）= 0 初始缓冲 + 96h H&R + demotable，全库无 probation/新手豁免机制；0277 迁移里 Peasant→User 门槛全 0，低做种环境新人第一周极易触发 H&R 阶梯。
4. **「同意站规」是死文字**：注册页 termsNote 仅一句话无链接无勾选（`register/page.tsx:240`）；出厂 `reg_quiz_enabled=no`，新用户全程可能没点开过任何规则页。
5. **欢迎 PM 与站点模板脱节**：`register.rs:261-266`「起步三步」写死签到/娱乐屋/抽卡（游戏化口径），考核淘汰制站点新人最该看到的「30 天转正考核」不在其中。

### 画像 B：资深下载者（找片、追更、刷活动）

1. **无内容热榜**：`/top/boards` 只有用户六榜（`content_http/misc.rs:88`），全库无「今日热门/本周最多下载/新晋免费」端点；首页海报墙纯 created 排序。多数 PT 站「免费区+热门榜」是拉下载第一入口，此处空缺。
2. **订阅对象错位**：只能订字幕组（group_subscribe）+ 关键词愿望单（纯 ILIKE，`social_team_expire.rs:151`）；works 已带 imdb/tmdb/douban id（`works.rs:50-58`）却没有「订阅作品新版本」入口——剧集党（最高 ARPU）追更靠手动翻页。
3. **评分筛选口径混乱**：`rating_min` 直读 media_info.rating 单字段（`torrents/types.rs:256` 自认豆瓣/IMDb 混口径），烂评分资源混入高筛结果，伤「按评分选片」主路径。
4. **中文召回弱**：主搜索 AND 模糊 LIKE + 人工同义词表（上限 200 条），无拼音/别名映射，tag 不参与搜索命中。

### 画像 C：发布者/保种组（供给侧核心，最该被善待的人群）

1. **种子侧互动零正反馈**：评论、感谢均不通知发布者（`torrents/comments.rs`、`interact.rs` do_thank 只转账）——对比论坛侧点赞/回复/提及通知全齐，双标明显。发布是 PT 核心 UGC，「有人谢你」回路缺失直接削弱发布留存。
2. **产出无消耗闭环**：保种 100/天、复活 5000、绩效最高 50000/月全是纯产出，这群人最不需要买上传量，火花最终只能流向娱乐场（被动成为「高净值回收站」）或沉淀死钱。无身份型 sink（专属装扮/工具/绩效勋章续费）。

### 画像 D：流失/沉睡用户（当前只有惩罚没有拉回）

沉睡链路 = 90 天未登录 → dormant_mark → 降级 → 登录拦截（`worker/jobs/achv_dormant.rs`、`auth_http/login.rs:169`），**纯惩罚零召回**；playbook 承诺的周年庆邮件召回（`docs/webmaster/playbook/02-promotions.md`）代码零实现；massmail 固定全量无人群圈选（`staff_http/massmail.rs`）；push 的 promo topic 事实上只有愿望单在用。

### 画像 E：站长/运营（本产品的直接客户）

1. **经济平衡表失真**：`_doc/魔力经济收支平衡表-2026-09-26.md` 未覆盖 10 月新增的游戏/保种/绩效/抽卡券产出面，数值基准已不可用于开站自查。
2. **促销上线零触达**：自动促销（魔法池 x2free）与手工促销均不发任何通知（`worker/jobs/promos.rs`），每次大促的唤醒势能全部浪费——用户不回站根本不知道有活动。
3. **触达基础设施碎片化**：mail_outbox 重试队列全库仅 1 个调用方；massmail 同步逐户失败即中断；无统一 dispatch、无频率上限、无摘要聚合。

## 三、已知问题核查结果（项目现存问题清账）

**已闭环（此前挂账，本次核实已修）**：
- 商店 spend/freeze 两段事务：裁 B 已落地——`repo/shop.rs::freeze_order` 单事务+幂等，调用点自动退款（`:refund` 后缀防双退）+库存回滚+error 日志（`economy_http/shop.rs`）。
- gacha 橱窗问题：0418 三路解决（商店 SKU 500/4500 + 签到 daily_free + 街机里程碑发券）。

**仍挂着待拍板**：
- 火花标签 ja 字典：真缺口仅 ja.ts 的 my 段 27 键（段级回落 zh-CN 是既定全局口径），补不补是产品口径问题非死配置。

**本次盘点新定性**：
- 无信用体系：贷款纯额度制（bank_loan_ratio 系数），无信用评级/抵押，「credit」仅是审核工具名。

- 论坛投票 Poll 未实现；种子评分（rating）无。

| # | 方案 | 改动面 |
|---|---|---|

### P2 —— 经济健康与长期债

1. **重算收支平衡表**：把保种/绩效/游戏面/抽卡券全量入表；经济仪表（0226 已建）加「时薪 P50/P90 用户 vs Top SKU 价格」比值看板，防做种大户无东西可买。
2. **券-火花汇率键化**：抽卡券 500 火花/张写死在 0418 SKU price 里，提为 `gacha_ticket_price` setting 并进仪表可见。
3. **新手可达定价**：上传量 3000/GB 对纯签到用户=11 个月（平衡表自算），新手期（≤30 天）小包 1GB 入门价或折扣，把「长线锚点」与「新手可达」分开。
4. **高净值身份型 sink**：保种组/发布组专属装扮、绩效勋章续费、专属工具位。
5. **复活奖励分档**：5000 一刀切未随体积/稀有度调整，易引导刷小种复活。
6. **长期债承接既有策划**：前端原语层→DS-PLAN-01；契约工程→FRAME-PLAN-01；中文分词/拼音搜索、信用体系、活动引擎择机立项。

### 不建议做的

- 个性化推荐矩阵（协同过滤）：低做种密度站 ROI 差，先把热榜/订阅这两个确定性转化位做满。
- IRC announce：能力声明已置 false，属刻意留白，Torznab/增量流已覆盖自动化生态。
