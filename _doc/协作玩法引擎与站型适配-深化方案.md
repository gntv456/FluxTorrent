# 深化方案：协作玩法引擎与站型适配

> 承接 `_doc/社交经营玩法设计方案-片场.md`
> 本文回答两个问题：**① 片场是不是只适合影视站？② 方案怎么再深化一档？**
> 结论先说：**不是只适合影视站，但《片场》这个包装确实带影视基因**——所以正确的做法不是"换名字"，而是把**机制提成引擎、把叙事降成主题包**，并且把玩法的**对象**从"人"扩到"资源"。

---

## 一、先拆开看：哪些是影视专属，哪些是通用

把《片场》掰开，分成三层：

| 层 | 内容 | 是否影视专属 |
|---|---|---|
| **叙事层** | 片场、剧组、导演、摄影、成片、票房、影史经典 | ❌ **影视专属**（这是隐喻，不是机制） |
| **主题素材层** | 岗位名、产出物名、评级名、图标、色板 | ❌ 影视专属 |
| **引擎层** | 自愿组队 / 有期限档期 / 岗位互斥 / 真实行为驱动 / 按贡献分账 / 赛季与信誉 | ✅ **与站型完全无关** |

**所以答案是：影视只占最上面两层，引擎层一点影视成分都没有。**

但有一个真问题必须承认：**隐喻自带基因**。把"剧组"硬套到音乐站（"上传量岗位叫摄影"）会显得廉价、违和，玩家一眼看出是抄的。所以正确的做法不是换名字，而是**换一整套从站型资源里长出来的主题**。

---

## 二、一个更有用的分析工具：玩法对象是"人"还是"资源"

判断一个社交玩法能不能上任何站型，看它的**玩法对象**：

| 代际 | 玩法对象 | 代表 | 问题/优势 |
|---|---|---|---|
| **一代** | **人（作为被支配的资产）** | 熊猫站《好友买卖》 | 负向社交，被玩的人不快乐；靠社交压力驱动 |
| **二代** | **人（作为平等的协作者）** | 《片场》主方案 | 正向，但仍以人为核心；依赖"愿意组队"的社群氛围 |
| **三代** | **资源（人作为伙伴）** | 待设计（见第五节） | **最干净**：对象是物不是人，没有社交压迫；且直接产出站点价值 |

**三代优于二代的地方**：二代的乐趣依赖"我想和谁合作"，这在陌生人社群（PT 站大部分是陌生人）里不一定成立；三代的乐趣依赖"我们一起救活这个东西"，目标感是外部赋予的，**陌生人也能协作**。

**最重要的一点**：三代玩法的对象就是站点自己的资源（种子），所以它**不需要任何主题包装**——它本身就是 PT 站的原生玩法。

> 这是一个判断标尺：**一个玩法越依赖"主题包装"才能成立，说明它离站点原生越远。**

## 三、引擎与叙事解耦（可落地的三层结构）

FluxTorrent 要做的不是"一个玩法"，而是**一套引擎 + N 套主题包**：

```
┌─────────────────────────────────────────────────────┐
│  L3 素材层   图标 / 色板 / 动效 / 产出物贴图          │  ← 主题包自带
├─────────────────────────────────────────────────────┤
│  L2 叙事层   岗位名 / 产出物名 / 评级名 / 文案模板     │  ← 主题包自带
├─────────────────────────────────────────────────────┤
│  L1 引擎层   （与站型完全无关，只写一次）              │
│             组队 · 档期 · 岗位互斥 · 真实行为采集       │
│             贡献结算 · 分账 · 赛季 · 信誉 · 幂等        │
└─────────────────────────────────────────────────────┘
```

### 引擎层的接口设计（主题包只需实现这几个钩子）

| 钩子 | 作用 | 影视包示例 | 教育包示例 |
|---|---|---|---|
| `theme_roles()` | 声明岗位及其绑定的行为类型 | 摄影→`upload`、美术→`seed_rare` | 讲师→`upload`、助教→`help` |
| `theme_behaviors()` | 声明本包用到的真实行为采集器 | `upload`、`publish`、`seed_rare`、`forum` | `upload`、`helped_count`、`quiz` |
| `theme_naming()` | 岗位名/产出物名/评级名的文案表 | 成片、票房、影史经典 | 课件、教学评分、精品课 |
| `theme_assets()` | 图标/色板 | — | — |

**关键约束：行为类型（`upload` / `publish` / `seed_rare` / `community`）是引擎枚举，不是主题自由定义的。** 主题包只能**组合**这些行为，不能发明新行为——否则采集层无法校验，反作弊就漏了。

## 四、站型 → 主题包决策表

### 4.1 选型标准（一句话）

> **主题必须从站点的真实资源里长出来，而不是从"哪个游戏好玩"里选。**

影视站有电影 → 主题是电影；音乐站有专辑 → 主题是专辑；教育站有课程 → 主题是课程。硬套别人的皮，玩家一眼看穿。

### 4.2 决策表

| 站型 | 站点的核心资源 | 推荐主题包 | 岗位映射（行为 → 岗位名） |
|---|---|---|---|
| 影视站 | 电影、剧集、字幕 | **片场 / 剧组** | 上传→摄影；发布→剪辑；冷门保种→美术；社区→配乐；协调→导演 |
| 音乐站 | 专辑、无损、现场 | **乐队 / 录音棚** | 上传→录音师；发布→制作人；冷门保种→母带修复；社区→乐评；协调→指挥 |
| 教育站 | 课程、教材、题库 | **课题组 / 教研组** | 上传→讲师；发布→课程编辑；冷门资料→资料抢救；答疑→助教；协调→组长 |
| 电子书站 | 书籍、扫描、OCR | **编辑部 / 出版组** | 上传→录入；发布→校订；冷门书→古籍修复；社区→书评；协调→主编 |
| 游戏站 | 游戏、补丁、汉化 | **工作室 / 汉化组** | 上传→资源；发布→汉化；冷门游戏→移植；社区→攻略；协调→项目负责人 |
| 综合站 | 什么都有 | **多包共存（见 4.3）**，或通用包 | 上传→主力；发布→发布者；冷门保种→守护者；社区→联络人；协调→队长 |
| 无明确主题 | — | **抽象成就包** | 不包装，直接叫"贡献/发布/守护/联络/统筹" |

### 4.3 综合站怎么办（这是 FluxTorrent 的默认场景）

综合站不该二选一，而是**让主题包按板块挂载**：

- 核心机制和数值**全站统一**（信誉、赛季、分账只一套）
- **叙事按板块切换**：影视区进去看到"片场"，音乐区进去看到"录音棚"，教育区看到"课题组"
- 玩家的**引擎层进度互通**（信誉、赛季积分、档期），只有**叙事层和素材层随板块变**
- 好处：老玩家跨板块无迁移成本，新板块上线零成本（写个主题包即可）

**这是 FluxTorrent 相对熊猫的结构性优势**——熊猫把"电影海报"硬编码在页面里，它想加个音乐主题得改代码。

## 五、跳出影视隐喻：PT 原生玩法三件套

上面聊的都是"以人为对象的协作"。但 PT 站真正独有的东西是**资源**，而且资源有三种天然痛点。把它们变成玩法，**不需要任何主题包装，天然适配所有站型**：

### 5.1 《抢救断种》Rescue —— 最推荐

**痛点**：老资源做种数掉到 1-2 个，随时断种消失。这是所有 PT 站最真实的长期焦虑。

**玩法**：
1. 系统扫描「做种数 < N 且发布超过 M 天」的资源，生成**待抢救清单**（公开可见）
2. 玩家**组队认领**（2~5 人），承诺 X 天内把该资源的健康做种数恢复到阈值以上
3. 成功 → 全队获得奖励；该资源被永久标记「**20XX 年被 XX 等人拯救**」
4. 失败 → 不惩罚，但该资源回到清单，且下次认领的奖励降低（稀缺感）

**为什么好**：
- 对象是**资源**，不是人 → 零社交压迫
- 产出**直接是站点价值**（保住了资源）→ 游戏即贡献
- **陌生人也能协作**（目标外部赋予）
- 「拯救记录」是永久荣誉，比徽章更有情感重量
- 天然反刷：必须真的有资源被救活，做不了假

### 5.2 《接力保种》Relay —— 把苦差变社交

**痛点**：单个资源要求连续保种 30 天，一个人扛太累，很多人因此放弃。

**玩法**：
- 把一个长期保种任务切成 N 棒（如 6 棒 × 5 天）
- 玩家认领其中一棒，到点交接给下一棒
- **掉棒全队受损**（但方向是正向的：大家目标一致，压力来自"别拖累队友"而非"被人支配"）
- 全棒完成 → 团队荣誉 + 该资源的永久"接力记录"

**与熊猫的区别**：熊猫是"主人压榨佣人"（上下关系、负向）；接力是"队友互相托付"（平等关系、正向）。同样是"人际压力"，性质完全不同。

### 5.3 《拓荒首发》Frontier —— 奖励多样性

**痛点**：热门资源挤破头，冷门类型没人发。

**玩法**：
- 对**冷门分类 / 长期无新资源的分类**发起拓荒任务
- 首个完成「发布 + 首周保种达标」的玩家获得「**拓荒者**」标记
- 拓荒者名单公开，并按分类沉淀（"纪录片类拓荒者：XXX"）

**本质**：用荣誉引导内容多样性，直接反哺站点的资源结构。

### 5.4 三件套与主线的关系

| | 主体 | 周期 | 定位 |
|---|---|---|---|
| 协作经营（片场/乐队/课题组） | 人 | 1~4 周 | **主线**：长期追求、赛季循环 |
| 抢救断种 / 接力保种 / 拓荒首发 | 资源 | 数天~数周 | **日常**：随时随地可参与、无门槛 |

**建议：主线用主题包（发挥站型特色），日常用三件套（全站通用）。** 三件套甚至可以独立于主线单独上线——因为它们不需要主题包装，实现成本低、效果直观。

## 六、机制深化（让"有抉择"变得更硬）

上一版说了"要有取舍"，但取舍还太浅。补四个机制：

### 6.1 岗位专精 → 产生"我是谁"的定位抉择

- 连续在同一岗位工作，**专精等级**逐级上升（加成递增）
- **换岗位专精衰减一半**（不是清零，保留回旋余地）
- 结果：玩家必须决定「**专精一项做到顶**」还是「**多面手哪都能补**」
- 出品人则要判断："我这个片场缺的是专精还是多面手？"

### 6.2 岗位羁绊 → 让"招募谁"变成真正的策略

不同岗位组合产出不同**片种**，片种决定收益结构与稀有概率：

| 组合 | 产出片种 | 特性 |
|---|---|---|
| 摄影 + 剪辑 | 商业片 | 魔力倍率高，稀有概率低 |
| 美术 + 配乐 | 文艺片 | 魔力倍率低，**稀有概率高** |
| 三岗以上齐备 | 大制作 | 全队收益 +，但协调成本高、违约风险大 |
| 特定稀有组合 | 隐藏片种 | 有专属称号 |

叠加**团队规模权衡**：

| 规模 | 产出 | 风险 |
|---|---|---|
| 小队（2~3 人） | 低但稳定 | 低 |
| 大队（5~8 人） | 高 | 高（一人掉棒全队损失，协调成本大） |

**于是出品人的核心决策变成**：在报名池里挑人，凑出想要的组合，同时控制规模风险。**这才是真正的策略层**——熊猫版完全没有这一层。

### 6.3 赛季规则变形（不是换皮，是换规则）

| 赛季主题 | 规则变形 |
|---|---|
| 科幻季 | 新增「特效」岗位（绑定技术类贡献：教程/工具/脚本），羁绊组合全变 |
| 恐怖季 | 高风险高回报：产出 ×1.5，但**中途退出惩罚翻倍** |
| 纪录片季 | 冷门保种权重 ×2，「美术」从边缘变成核心岗位 |
| 经典季 | 全站统一模板，取消个性化岗位，比拼纯执行力 |

**每季换规则**，才是赛季制的意义。只换名字叫换皮。

### 6.4 师徒机制 → 新人留存

- 老玩家带新人：新人达成目标 → 师傅得荣誉（不给数值，防止刷）
- 新人首次参与不占档期（降低门槛）
- 与 PT 站"老人带新人"的传统吻合，不违和

### 6.5 违约与信誉的细化

| 行为 | 信誉影响 |
|---|---|
| 按时完成承诺 | **+**（主来源） |
| 中途退出 | **−**（按剩余进度比例扣） |
| 未达标但未退出 | 小 −（区分"尽力了"和"跑了"） |
| 被队友好评 | +（**每季评价次数有限**，防互刷） |
| 被队友差评 | −（需附理由，可申诉） |

信誉只影响**准入资格**（能不能当出品人、能不能接高级片场），**不影响已获得的东西**——不做"剥夺式惩罚"，避免挫败感过强。

## 七、通用 PT 程序的适配要求（FluxTorrent 特有约束）

FluxTorrent 是**可建任何站型的通用程序**，站长不是每个都想要这套玩法。因此：

### 7.1 必须可选、可关、可配置

```toml
[social_play]
enabled = false              # 总开关，默认关闭（通用程序不应默认开启游戏）
modules = ["rescue"]         # 只开抢救断种：最低成本、最直接反哺站点
theme = "generic"            # 或用按板块挂载：themes = { movie = "film", music = "band" }
season_weeks = 4
reputation_enabled = true
```

**默认关闭**很重要：通用程序装上就跑出一个"好友买卖"，会让不想做社区运营的站长很尴尬。

### 7.2 每个模块独立开关

| 模块 | 依赖 | 建议默认 |
|---|---|---|
| 抢救断种 | tracker 数据 | **建议默认开启**（成本低、直接反哺站点） |
| 接力保种 | tracker 数据 | 可选 |
| 拓荒首发 | 分类数据 | 可选 |
| 协作经营（主题包） | 信誉 + 赛季 | 默认关闭 |

### 7.3 降级路径（诚实面对"没人玩怎么办"）

1. **不影响主体功能**：玩法挂掉不能拖累下载/Tracker
2. **保底不亏**：不参与的用户不产生任何损失（对比熊猫：不参与也会被买走、被扣维护费）
3. **可一键下线**：站长能随时关闭，且**历史数据保留**（重新开启时进度还在）
4. **灰度**：先对部分用户开放，看数据再全量

### 7.4 数值全部配置化

赛季主题、岗位表、羁绊组合、产出倍率、信誉规则**全部进数据库**，后台可改。熊猫这点做对了（服务端下发），必须继承。

## 八、修订后的路线图

原 MVP 是"两周验证核心假设"，现在可以更精准地分三步：

| 阶段 | 内容 | 验证目标 | 成本 |
|---|---|---|---|
| **P0** | **只做《抢救断种》** | 玩家会不会为救资源而多做种？（这是整个方向的地基假设） | 最低 |
| **P1** | 加协作经营 MVP（2 岗位、4 人、1 周、无谈判） | 玩家会不会主动组队？（社群氛围假设） | 中 |
| **P2** | 加谈判 / 专精 / 羁绊 / 赛季 | 策略层能不能撑住长期留存？ | 高 |

**把《抢救断种》提到 P0 是关键调整**：

- 它不需要主题包装（所有站型通用）
- 它不需要信誉分和赛季（依赖更少）
- 它的产出直接是站点价值（保住的资源可量化）
- 它验证的假设最底层：**"游戏能不能驱动真实行为"** —— 如果这个都不成立，后面的协作经营、谈判、赛季全都不用做了

原方案里的"片场"则降到 **P1**，且以"主题包"形式实现——这样它对影视站是片场、对音乐站是乐队，对其他站型是各自的包。

## 九、一页总结

| 问题 | 答案 |
|---|---|
| 片场只适合影视站吗？ | **机制通用，叙事影视专属。** 影视只占叙事层和素材层 |
| 那怎么办？ | 机制提成**引擎**（写一次），叙事降成**主题包**（每站型一套） |
| 综合站怎么选？ | **按板块挂载主题包**，引擎层进度互通 |
| 还有更本质的方向吗？ | 有：**把玩法对象从"人"换成"资源"**，产出即站点价值，且不需要主题包装 |
| 最该先做什么？ | **《抢救断种》**——最低成本、全站型通用、直接验证最底层的假设 |
