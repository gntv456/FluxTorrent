## 1. 实测亮点（值得骄傲的部分）

### 1.1 后端 API 健康度极高
实测 97 个只读端点，**除 3 个被"本站未开放"门控、1 个端点改名、1 个测试数据缺种子外，其余全部返回 `200/code=0`**。错误处理统一为 `{code,message,data,request_id}` 信封，中文报错可读（如 `资源不存在`、`无效 passkey`）。这是工程纪律很好的表现。

### 1.2 管理后台是"真后台"，不是摆设
- `/admin/staffpanel-entries` 返回 **66 条**后台入口，AdminShell 药丸体系完整。
- `/admin/permission-matrix` 提供 **5 个角色** + 细粒度权限并集，RBAC 下沉到 PG 函数，设计专业。
- `/admin/audit` 审计日志实测 **200 条**滚动记录，且代码侧有 HMAC 防篡改链。
- 治理闭环齐备：`/admin/reviews`（审核队列）、`/admin/reports`（举报）、`/admin/cheaters`（作弊）、`/admin/hr/records`（H&R）、`/admin/rename-logs`/`modify-logs`（改名/修改留痕）。
- 运营工具：`/admin/version` 暴露 `app/batch/db/git/latest_migration`（运维可见性到位）；`/admin/backups` 带 `restore_runbook`（备份可演练）。

### 1.3 经济系统差异化明显（对标的护城河）
- 银行：**定期（5 档利率）+ 活期 + 借贷**三件套，`/bank/overview` 数据完整。
- 站免池众筹 `/fundings`、商店、勋章（14 枚 + 4 稀有度）、装扮中心（11 件 SKU）、头像框（7 款）均已落地。
- 娱乐矩阵：刮刮乐/猜大小/九宫格/农场/趣味投票，`/games` 统一风控管线（限注/限次/速率）。
- 签到：`/attendance` 含连签/补签卡/里程碑，逻辑自洽。

### 1.4 社区与内容骨架健全
- 论坛 9 个版块（`/forums/boards`）、投票（2）、趣味链接（2）、喊话机器人指令、好友系统。
- 首页后端数据已齐：`home_sections=9`、`news=4`、`site_data=11` 字段——**前端一旦修好，首页是"开箱即用"的**。
- RSS 鉴权正确：匿名访问 `/rss/abc123` 返回 `400 invalid passkey`，passkey 即身份的设计安全。

### 1.5 站点形态可配置（通用建站定位）
模块开关 `module_{name}='no'` + 站点类型包（site_type_pack）一键 apply，可切换综合/教育等站型。这是"一套引擎服务多类 PT 站"的正确抽象。

### 1.6 定位符合度：对照"建站系统"四支柱（关键修正）

> 评测中根据站长澄清，本项目定位是**"只做建站系统、不偏向任何 PT 类型、站长自由搭建、轻松自定义功能和字段"**。据此重新校准评测轴——很多初看像"缺口"的现象，其实是这套定位在正确生效。实测证据如下：

| 支柱 | 是否兑现 | 实测证据 |
| :--- | :---: | :--- |
| **不偏向任何 PT 类型** | ✅ | `/admin/settings` 实测 **14+ 个模块开关**（`module_textbooks/exams/bank/dressup/games/forums/friends/...` 显式 `yes`/`no`）；当前综合站型只是把教育类置 `no`，并非引擎偏见 |
| **站长自由搭建** | ✅ | ①`GET/POST /admin/site-type-packs`（+`apply`/`diff`/`save`）一键切换综合/教育站型并重建分类；②`/admin/content-packs/catalog` 返回 **13 个内置包**（`degraded=False`、无远程依赖），含 `builtin.taxonomy.education`（K12/高教 7 分类/4 维度）、`builtin.taxonomy.movie`（馒头口径 7 分类/5 维度）；支持 install/export/import/**rollback**/rule-try —— 既有"一键装内容"，又有"安全回滚" |
| **轻松自定义功能** | ✅（引擎就绪） | 模块开关即功能级自定义；内容包即功能套件自定义 |
| **轻松自定义字段** | 🟡（引擎就绪，内容空） | 通用字段引擎 `fields.rs` 支持 **6 种类型**（text/number/select/multiselect/date/bool）校验；种子分类学 `section-kinds`(4)/`section-dict`(25)/`section-modes`(1, 可配置可见字段组)；用户字段 `/admin/user-fields` CRUD 端点齐备 |

**核心结论**：四大支柱的**引擎层已兑现**。所谓"教育模块关闭"，不是缺陷——`builtin.taxonomy.education` 安装包就躺在内置目录里，本部署只是没 apply。这正是"建站系统不该替站长预设内容"的正确姿态。

**唯一软肋（非缺陷，是体验欠账）**：内容尚未预填。实测 `user-fields=0`、`register-fields=0`、当前 `section-kinds` 仅综合站默认 4 类。也就是说，引擎给了，但**首屏引导没把"一键 install 教育包 / 填自定义字段"做成显式推荐**，新站长容易以为"只能做综合站"。这是 UX/引导问题，不是能力问题。

## 2. 关键问题（按优先级）

### ✅ P0 — Web 前端整站 404（部署故障，**已于 2026-09-26 现场重建镜像修复**）

**首轮现象**（评测初稿，当时属实）：以匿名/登录态访问 `/`、`/login`、`/torrents`、`/admin`、`/shop`……**每一条路由都渲染 Next.js 默认 404 页**。连公开页 `/login` 都 404。

**根因定位（已取证，并更正初稿误判）**：
- web 容器进程存活，`node apps/web/server.js`（standalone 生产构建）正常启动，经它代理的 `/api/v1/me` 返回 `200` —— server 本身没死。
- 当前运行镜像是 `ghcr.io/gntv456/fluxtorrent/web:latest`（**registry 预构建镜像，非本次源码本地构建**）。结论：线上跑的是一份**坏掉的/过期的预构建 web 镜像**——这是我们最初就锁定的根因，复测后确认成立。
- **初稿中的两个误判，在此更正**：
  1. 初稿称"`app-paths-manifest.json` 缺失" → 实为**探针脚本文件名写错**：真实文件名为 `app-path-routes-manifest.json`（App Router 路由表），容器内**确实存在且内容完整**（含 `/login/page`、`/(main)/admin/page` 等全部路由映射）。
  2. 复测中途一度出现 `next build` 报 `rlLevel` 类型错误，曾怀疑源码漂移 → 实为 **BuildKit 缓存脏**（首轮 `--no-cache` 仍命中陈旧 `zh-CN.ts`）；执行 `docker builder prune -af`（清掉 **276.9GB** 脏缓存）后再次 `--no-cache` 构建即**完整通过**，`next build DONE 85.9s`。源码无漂移。

**修复（已执行）**：
```bash
docker builder prune -af                                  # 清空全部 BuildKit 缓存（关键：消除陈旧上下文）
docker compose -f docker/docker-compose.yml build --no-cache web
docker compose -f docker/docker-compose.yml up -d web      # 用新镜像重建容器
```
**复测结果（已验证）**：新镜像下 20 个代表页面（含 `/`、`/login`、`/torrents`、`/admin`、`/shop`、`/bank`、`/top`、`/me`、`/upload`、`/donate`、`/magic-pool`、`/preserve`、`/subtitles`、`/users`、`/textbooks`、`/requests`、`/offers`、`/medals`、`/games`）在**登录态**下全部 `200` 且渲染真实内容（与登录页基线文本明显不同），**0 失败**。

> **复测方法论（避免再次被假象误导，重要）**：
> 1. **认证闸门读的是 `flux.session` cookie，不是 `flux_token`**（`middleware.ts:41`）。只带 `flux_token` 会被判匿名 → 所有受保护页 302 到登录页，看起来像"全站 404/登录页"。正确姿势：同时带 `flux_token`（真凭证，服务端经 `api-client.ts:81` 转 Bearer 调 API）+ `flux.session=1`（仅作中间件入场标记）。
> 2. **Next.js 正常页面 HTML 里也内嵌了 `This page could not be found` 这段文本**（客户端导航兜底边界），所以不能拿这个字符串判定 404——要以"可见文本是否异于登录页基线 / 是否含页面专属 chunk（`app/<route>/page-*.js`）"为准。
> 3. 建议把"登录态下页面 200 且可见文本 ≠ 登录页"写入 CI/上线门禁，避免再次被坏镜像蒙混过关。

### 🟢 已澄清（非问题）— "教育模块关闭"是建站系统在生效，不是缺陷

**现象（保留原观察）**：`GET /textbooks`、`GET /me/exams`、`GET /me/hr` 返回 `4101/本站未开放此功能`。

**纠正**：经站长澄清，本项目定位是"建站系统"，教育模块由模块开关 `module_textbooks/exams/hr='no'` 关闭**正是这套定位在生效**——当前部署仅选择了综合站型。更关键的是：内置内容包目录里**已存在 `builtin.taxonomy.education`（K12/高教 7 分类/4 维度）**，站长只需 `POST /admin/content-packs/install` + `POST /admin/site-type-packs/apply` 即可一键开启，无需写代码。详见 §1.6。

**建议**：把它从"缺陷"改为"首屏引导机会"——在开站向导/初始化 checklist 里把"选择站型 → 一键 install 对应分类学包"做成显式推荐，避免新站长误以为平台只能做综合站。

### 🟠 P1 — NexusPHP 兼容层对标准鉴权返回 401（第三方工具适配存疑）

**现象**：`GET /compat/nexusphp/torrents.json` 带 `Authorization: Bearer <JWT>` 仍返回 `401/未认证`；匿名同样 401。

**背景**：对照成熟站型，FluxTorrent 的最大生态短板是**第三方工具（ptool / IYUU / PT Mate / Autobrr）默认适配 NexusPHP 而非本引擎**。代码里已建 `/compat/nexusphp/*` 兼容层，方向正确，但实测用标准会话 JWT 无法通过这些端点。NexusPHP 系工具通常以 **passkey（URL 参数 / Basic Auth）** 鉴权而非 Bearer，兼容层应优先认 passkey。

**建议**：
1. 用 passkey 实测 `/compat/nexusphp/{user,torrents,torrent,download}.json`，确认兼容层按 NexusPHP 语义工作；
2. 若不通，补齐 passkey 鉴权分支；打通后，**在文档里给出 ptool/IYUU 的配置样例**（这是拉新和留存的关键）；
3. 这是从"能用"到"生态可用"的卡位点，优先级高于多数新功能。

### 🟡 P2 — API 端点命名不一致（契约漂移）

**现象**：`GET /admin/forum-categories` → `1004/接口不存在`；而 `GET /admin/forums` 正常且返回 `categories`。说明后台论坛分类的取数端点被改名/合并，但旧路径未保留或文档未同步。

**建议**：这类"路径消失"对前端/第三方是隐性地雷。建议在 `scripts/check_type_drift.mjs` 契约门禁中**把已知管理端点纳入存在性断言**，改名必须同步改调用方与文档，避免无声断裂。

### 🟡 P2 — 内容冷启动：站内仅 1 个种子

**现象**：`resource_stats` 显示近 30 天 `total=1`、`today=1`；`/admin/torrents` 总数为 1。这是测试实例的正常状态，但提醒一点——**经济/排名/促销等玩法都依赖真实种子与真实流量才有意义**。

**建议**：开站前准备"种子播种计划"（首批官种 + 核心教育资料），否则银行利率、做种收益、排行榜都会是空转。可考虑内置"演示/种子数据"开关，便于评审与演示。

## 4. 站长视角的产品与运营建议

1. **Web 已修复，下一步是防复发**。P0（整站 404）已现场重建镜像解决；把"登录态页面渲染断言"作为发布闸门第一条，避免坏镜像再次上线（判据见 §2 P0 复测方法论）。
2. **把"教育"做成真壁垒，而不是口号**。课本中心/年级/教材版本筛选是 NP/UNIT3D 装不出来、也懒得装的能力。要么在本部署真正启用并打磨体验，要么别在对外叙事里主打——二选一，别两头空。
3. **生态适配是生死线**。PT 用户黏性来自 "我用 ptool 一键辅种、用 IYUU 自动追剧"。兼容层一旦打通并给出配置样例，留存会质变。这是比再加一个娱乐小游戏重要十倍的事。
4. **开站前准备"冷启动内容包"**。1 个种子的站，经济系统再漂亮也是空城。首批官种 + 核心教材资料 + 几个活跃水帖，比任何功能都更能让新站"活"起来。
5. **运营动作闭环已具备，建议做"开站 checklist"**：SMTP 发信验证 → 模块开关核对 → 种子播种 → 兼容层工具联调 → 备份恢复演练 → 页面渲染抽查。把它固化成文档/向导，降低每次开新站的踩坑成本。
6. **可观测性已经不错**（审计链、版本、备份 runbook、登录日志 65 条、流水 21 条）。建议再加一层**关键业务指标看板**（DAU、新增种子、做种率、促销参与），供站长日常决策。

### 6.2 体验痛点与修复（2026-09-26 已现场修复并复测）

> 以下 1/3/4 三项已在本轮动手修完并重建复测；2 属运营侧准备（非工程）。

1. **✅ 已修复 — 首页 SSR 只渲染"加载中…"壳**（原 🔴）
   - 根因：`components/home-sections.tsx` 是 `"use client"` 组件，所有板块数据（`/api/v1/home`）在 `useEffect` 里拉取，SSR 阶段永远只输出 `dict.my.loading`（"加载中…"）；首页 RSC 虽已取好海报墙，但主体板块不进 HTML。
   - 修复：首页 `page.tsx` 一次取回完整 `HomeData` + 站点 `modules`，作为 `initialData`/`initialMods` 传入 `HomeSections`；组件用 `useState(initialData)` 直接渲染，SSR 即出真内容，`useEffect` 仍保留做后续刷新（且刷新失败不再把已有首屏内容替换成错误页）。
   - 复测：`GET /` 由 `len=289 + 含"加载中"` → **`len=1088`、无"加载中"，直出"社区新鲜事 / 站点开放测试 / 签到得魔力 / 签到日历 / 站点数据 / 免责 / 友情链接"**。
   - ⚠️ 附带修掉一个真回归：`parseHomeLayout()` 原本放在 `"use client"` 的 `home-layout.tsx` 里，被 RSC 调用会报 `Attempted to call a client function from the server` → 首页 500。已把纯函数抽到无 `"use client"` 的 **`components/home-layout-parse.ts`**，`home-layout.tsx` 降级为 re-export 兼容层（所有历史 import 路径不变）。
2. **🟠 冷启动内容全空（运营侧，非工程缺陷）**：站内 0 种子、1 名会员、排行榜"榜单虚位以待"、论坛 0 帖。建议开站前准备"种子播种计划 + 几个水帖 + 官种"。（本项目尚未上线、当前为本地测试实例，此为空库正常态。）
3. **✅ 已修复 — root 管理员起始魔力 = -61,990**（原 🟠，且更正定性）
   - 查实：**不是产品缺陷、也不是初始种子数据错**。0017 给 root 的初始余额是 `+100000`；负值来自 2026-09-25 的 **e2e/回归测试扣费残留**（`idempotency_key` 前缀 `e2e-0204-` / `medal-gift:` / `shop:1:regr-buy-`，共约 -62,002），而正规入账仅 +12。**扣费链路本身有健全保护**：统一入口 `economy_http/spend.rs::spend_spark` 有 `if balance < amount { InsufficientSpark }`（错误码 4001「余额不足」），正常用户路径不会透支。
   - 修复：迁移 **`0220_fix_root_negative_spark.sql`**（幂等、保守）——仅当 root 余额 `< 0` 时补一笔 `initial_grant` 入账把余额抬回 0，使 `spark_ledger` 汇总与 `users.spark_balance` 账平；不抬高正常库余额、不删任何既有流水。已在测试库执行生效（余额 -61,990 → **0**）。
4. **✅ 已修复 — 后台路径式深链 404**（原 🟡）
   - 根因：后台工具走 `/admin?tool=<tab_key>` 客户端路由；`/admin/torrents` 这类"路径式"猜测并非真实路由，此前落 Next 默认 404。
   - 修复：新增 catch-all 路由 **`app/(main)/admin/[...slug]/page.tsx`**，把未知 `/admin/*` 重定向到 `/admin?tool=<末段>`，并复用 `LEGACY_TOOL` 做旧命名映射；真实子路由 `settings`/`forums`/`users/[id]` 由静态路由优先匹配，不受影响。
   - 复测：`/admin/torrents`、`/admin/audit`、`/admin/users`、`/admin/reports` 全部 **`200`**（重定向到 `?tool=`）；`/admin/settings`(1313字)、`/admin/forums`(309字) 正常未被吞。
