# 字幕工作流与激励生态策划方案（0148 候选）

> 2026-09-21。目标流程（用户原话拆解）：
> **申请翻译 req → 认领 → 进入翻译流程 → 申请多人合作 → 制作完成，自动 IMDB 链接合并到种子页 → 手动或自动给予 free 奖励 → 字幕评分，帮助用户选择下载和字幕质量竞争 → 进入字幕「金字字幕」评选 → AI 字幕和人工字幕区分和结合**
>
> 现状核查结论：9 环节已实现 2.5 个（req 悬赏池完整、评分完整、AI 字幕半接线）。
> 本方案给出剩余 6.5 个环节的设计、迁移、接口、验收与分批。前一轮 0146/0147 的
> 治理基建（审核态/举报闭环/成就族/match 排序）全部复用，不推倒。

## 1. 现状盘点（别重建，先看清有什么）

| 资产 | 位置 | 本方案怎么用 |
|---|---|---|
| 求字幕悬赏池（发起冻结/凑赏/交付结算，CAS+幂等） | `subtitles_requests.rs` | 工作流的骨架：认领/流程状态长在这张表上 |
| 评分 1-10（一人一票，覆盖重算）+ ★8.0(N) 回显 | `subtitles_meta.rs` / 列表 | 环节 7 已闭环；金字幕评选直接吃聚合列 |
| `machine_translated` 字段（库表有、前端没接） | `subtitles` 表 | 环节 9 只需接线 + 筛选 + 角标 |
| `producer/proofreader/author_name` 元数据 | `subtitles` 表 | 多人协作的「署名」落点（展示层已有） |
| 促销系统 `promotions`（kind=free/x2/... source=manual/magic_pool/task） | `promotions` 表 | 环节 6 的 free 奖励**直接 INSERT**，不动 pos_state（那是置顶） |
| 成就族（subtitle_count 三档）+ 火花幂等发放 | worker `achv_dormant.rs` / `earn_spark` | 评选奖励、协作奖励的发放通道 |
| 站内信 `messages` + shoutbox 公告 | 既有 | 认领通知、评选揭晓 |
| 勋章体系（medals/user_medals，后台可发） | `community_http/medal.rs` | 「金字幕」获得者的荣誉承载（发勋章，不新建荣誉表） |
| 审核态/举报自动隐藏/软删 | 0146 | 工作流产物照走现有审核闸 |

**数据基础缺口（环节 5 的硬前提）**：`torrents` 无 `imdb_id` 列，`media_info` 全站只有
`rating` 键。不做录入链路，IMDB 自动合并无从谈起——本方案 C1 先补数据基础。

## 2. 竞品取法

- **KG（Karagarga）**：求字幕 pots 的认领锁定 + 超时释放——认领后 N 天无交付自动回池，防白翻。
- **U3D**：字幕无独立工作流但有 torrent 缺失字段（IMDB/TMDB 全量结构化）——`imdb_id` 一等公民。
- **OpenSubtitles**：AI 生成字幕打 `machine_translated` 标且默认排在人工之后——排序降权而非隐藏。
- **NexusPHP 系（馒头/包子）**：字幕 Free 奖励走种子促销（对齐我们 `promotions.source='task'` 的先例）；「金字字幕」类似月度评选帖 + 勋章。
- **PTP**：字幕质量竞争的极致——同一种子多版本字幕并存，评分 + 认证双维度竞争。我们已有评分，差认证维度的「评选」。

## 3. 环节设计（P0→P2 三批）

### C0｜P0：AI 字幕区分接线（环节 9 前半，最便宜，先做）

| # | 改法 |
|---|---|
| C0-1 | 上传表单加「AI 生成/机翻」勾选框（默认否）→ POST `machine_translated`（后端已收，只是前端不传） |
| C0-2 | 列表行 AI 字幕显「机」角标（灰色小字）；种子页字幕面板同 |
| C0-3 | 列表筛选加 `ai=0/1/only`（`?ai=only` 只看人工——用户找字幕的实际诉求） |
| C0-4 | 默认排序（match/created_at）人工优先：`ORDER BY machine_translated ASC, ...`（对齐 OpenSubtitles：AI 不隐藏、只降权） |
| C0-5 | 举报理由区分「AI 冒充人工」（骗悬赏场景）：report body 注明，处理时罚金上限翻倍的后台运营约定（不写死代码） |

验收：上传勾选机翻 → 列表「机」角标 + `ai=only` 筛掉它；不勾则无角标。

### C1｜P0：IMDB 数据基础（环节 5 前半，解锁自动合并）

| # | 改法 |
|---|---|
| C1-1 | 迁移：`torrents ADD COLUMN imdb_id TEXT`（稀疏索引；允许 NULL） |
| C1-2 | 录入链路三处：上传表单可填（正则 `tt\d{7,8}`）、管理后台种子编辑可改、发布解析 descr 里的 IMDB 链接自动提取（`tt\d+`） |
| C1-3 | 字幕上传时：若挂了 `torrent_id`，回填 `subtitles.imdb_id`（同列冗余，省 JOIN） |
| C1-4 | 种子页字幕块升级：显示「本片字幕 N 条」时，除 torrent_id 命中外，追加同 `imdb_id` 的字幕（**自动合并**，环节 5 后半落地） |
| C1-5 | match 排序补 IMDB+语言 +50 档（0146 方案 §5 第 3 条的欠账，此时有数据了） |

验收：给种子 A 填 imdb tt1234567 → 另一种子 B 同 imdb → B 的页面字幕块能看到挂在 A 下的字幕；上传字幕填了 torrent 的行 `imdb_id` 回填。

### C2｜P1：认领锁定 + 翻译流程状态机（环节 2/3）

`subtitle_requests` 状态机扩展：`0 open → 3 claimed(认领中) → 4 delivering(交稿待验收) → 1 paid(结算)`；认领超时（默认 7 天，`subtitle_claim_timeout` 可配）worker 自动 3→0 回池。

| # | 改法 |
|---|---|
| C2-1 | 迁移：`subtitle_requests` 加 `claimed_by BIGINT / claimed_at / deadline_at`；status 加 3/4 两档 |
| C2-2 | `POST /subtitles/requests/{id}/claim`：本人以外任意登录用户；CAS `0→3`；已有 claim 者的请求不可再认领；发起人不能认领自己的单（可配，防自薅） |
| C2-3 | `POST /subtitles/requests/{id}/abandon`：认领人放弃 3→0（计入弃单次数，连续 3 次禁认领 30 天——防霸单） |
| C2-4 | 现有 `fulfill` 改两步：认领人交稿 `3→4`（挂 subtitle_id，走 0146 审核闸）→ 审核过/发起人确认 `4→1` 结算整池 |
| C2-5 | 交稿通知发起人（站内信 + 发起人可「接受/异议」按钮，异议转 reports 走管理仲裁） |
| C2-6 | worker：`deadline_at` 过期未交稿的 claimed 单自动回池 + 通知 |

验收：A 发起 → B 认领（C 再认领被拒）→ B 交稿 → A 确认 → 整池结算给 B（幂等键复用 `subtitle-bounty-pay`）；B 认领 8 天不交 → worker 回池。

### C3｜P1：多人协作（环节 4，最小化：不建协作流程，建分账声明）

设计取舍：完整协作工作流（分工/进度/审校签收）是论坛帖 + 网盘的活，PT 站做成「**认领时可组队 + 交付后按约定分账**」即可，避免把字幕区做成项目管理工具。

| # | 改法 |
|---|---|
| C3-1 | `POST /subtitles/requests/{id}/claim` 支持带 `crew: [{user_id, share, role}]`（份额合计 ≤ 100%，role=翻译/校对/时间轴/后期） |
| C3-2 | 被邀请人站内信确认（accept/decline）；全员 accept 后 claim 生效 |
| C3-3 | 结算改整池按 share 分账（每人独立幂等键 `subtitle-bounty-pay:{rid}:{uid}`）；share 之和 <100% 的余量归主认领人 |
| C3-4 | 字幕行的 `producer/proofreader/author_name` 元数据自动按 crew 回填（署名与分账一致） |

验收：B 认领带 C(40%) → 双人确认 → 交付结算 B 得 60%、C 得 40%（两笔独立流水）；C decline 则回退单人。

### C4｜P1：free 奖励联动（环节 6）

复用 `promotions` 表，新增 source 枚举值 `subtitle`：

| # | 改法 |
|---|---|
| C4-1 | 迁移：`ALTER TYPE promotion_source ADD VALUE 'subtitle'` |
| C4-2 | 自动档：求字幕单结算时，若发起时勾选「愿以 Free 酭谢」（新字段 `offer_free BOOL`，发起人从自己的「免费券」或魔力池预付），结算同时 INSERT promotions(kind=free, source=subtitle, torrent_id, 30 天) |
| C4-3 | 手动档：管理后台种子编辑已有促销工作台，无需新码；补一条运营约定：字幕悬赏兑现的种子默认给 30 天 free（写进规则页） |
| C4-4 | 传完字幕若种子因字幕变 free，种子页角标注明「字幕贡献 Free」（前端读 promotions.source） |

验收：发起单 offer_free=true + 悬赏 200 → 交付结算 → 该种子 promotions 出现 free/30 天行 + 种子列表 Free 角标；offer_free=false 则无。

### C5｜P2：金字字幕评选（环节 8）

月度自动榜 + 人工终评，不建投票活动系统（复用评分 + 勋章）：

| # | 改法 |
|---|---|
| C5-1 | worker 月度 job：统计上月字幕的 `评分均分 × ln(1+评分人数) + 下载量 × 权重 + verified 加成`，取 Top 10 入候选（写 `subtitle_awards` 表：期号/字幕id/得分/名次） |
| C5-2 | 后台评选页：候选列表 + 管理勾选 Top 3「金字幕」→ 发 medals（勋章后台先建「金字幕」三档：金/银/铜，`admin_p3/medals` 已支持）+ 火花奖励（1st 5000 / 2nd 2000 / 3rd 1000，幂等键 `sub-award:{期号}:{uid}`） |
| C5-3 | 字幕列表金字幕行加 👑 角标（join subtitle_awards）；用户主页勋章墙自然展示（已有） |
| C5-4 | 揭晓公告：shoutbox + 站内信（复用 0146 announce 通道） |
| C5-5 | AI 字幕参评规则：`machine_translated` 可参评但单独赛道（评选 job 按 AI/人工各出 Top 3——「区分和结合」的落点：同台不同榜） |

验收：造 3 条高评分字幕 + 跑月度 job → 候选入表 → 后台评金 → 勋章到用户 + 列表 👑 + 公告可查。

### C6｜P2：AI 与人工「结合」（环节 9 后半，开放性——只做最小闭环）

定位：AI 初翻 + 人工校对是行业常态，不是对立。

| # | 改法 |
|---|---|
| C6-1 | 上传表单：勾「AI 生成」后追加「已人工校对」二级勾选（`proofread_by_ai_source` 场景）——即 `machine_translated=true + proofreader 非空` 的组合语义 |
| C6-2 | 列表角标三态：无（纯人工）/ 机（纯 AI）/ 机✓（AI+人工校对，排序等同人工档） |
| C6-3 | 运营位：字幕区规则卡注明三态口径与评选赛道规则 |

验收：勾 AI+校对 + 填 proofreader → 列表「机✓」+ 排序归人工档。

## 4. 数据模型（迁移 0148，创建前重新确认最大号——当前 0147）

```sql
-- 0148_subtitle_workflow.sql
-- 1) IMDB 基础
ALTER TABLE torrents ADD COLUMN IF NOT EXISTS imdb_id TEXT;
CREATE INDEX IF NOT EXISTS idx_torrents_imdb ON torrents (imdb_id) WHERE imdb_id IS NOT NULL;
ALTER TABLE subtitles ADD COLUMN IF NOT EXISTS imdb_id TEXT;

-- 2) 求字幕工作流
ALTER TABLE subtitle_requests
  ADD COLUMN IF NOT EXISTS claimed_by BIGINT REFERENCES users(id),
  ADD COLUMN IF NOT EXISTS claimed_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS deadline_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS offer_free BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS crew JSONB NOT NULL DEFAULT '[]';
-- status: 0 open / 1 paid / 3 claimed / 4 delivering（smallint 复用，加 CHECK 可选）

-- 3) free 奖励来源
ALTER TYPE promotion_source ADD VALUE IF NOT EXISTS 'subtitle';

-- 4) 金字幕评选
CREATE TABLE IF NOT EXISTS subtitle_awards (
  id BIGSERIAL PRIMARY KEY,
  period TEXT NOT NULL,              -- '2026-10'
  subtitle_id BIGINT NOT NULL REFERENCES subtitles(id) ON DELETE CASCADE,
  user_id BIGINT NOT NULL REFERENCES users(id),
  score NUMERIC(10,2) NOT NULL,
  rank SMALLINT NOT NULL,            -- 1/2/3（0 = 入围未获奖）
  tier TEXT NOT NULL DEFAULT 'human',-- human / ai（双赛道）
  granted_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (period, subtitle_id)
);

-- 5) 站点设定
INSERT INTO site_settings (name, value, descr) VALUES
  ('subtitle_claim_timeout_days', '7', '求字幕认领超时（天），超时自动回池'),
  ('subtitle_crew_max', '4', '协作队伍人数上限')
ON CONFLICT (name) DO UPDATE SET descr = EXCLUDED.descr;
```

## 8. 风险与待确认（实施前要站长拍板）

1. **认领锁定的时长**：默认 7 天是否合适？（教育站长片翻译周期长，影视站短——要不要按站型出默认值）
2. **offer_free 的成本承担**：发起人预付（免费券/魔力）还是站方出？倾向发起人预付（防滥发）
3. **金字幕双赛道**是否必要？小站 AI 赛道可能凑不齐 3 条——可配开关 `subtitle_award_ai_track`
4. **IMDB 录入的信任度**：普通用户上传时可填（可信度低）还是仅管理可填（慢）？倾向：用户可填、管理可改、评选加分以 verified 为准
5. **旧悬赏单兼容**：C2 上线时存量 status=0 的单直接回池还是保留旧「直接 fulfill」通道一个过渡期？

## 9. 与站型开关的联动（沿 0146 §12 口径）

- 全部新能力挂 `module_subtitles` 总开关之下（现有网关拦截自动覆盖新端点——前缀登记即可）
