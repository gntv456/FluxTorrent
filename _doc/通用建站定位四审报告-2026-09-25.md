# 通用建站定位四审报告（逐层闭环核查）— 2026-09-25

> **四审主题**：承接一审（G1–G5）、二审（G6–G11）、三审（收口复核）。三审裁决「架构与引擎层已完全符合通用建站定位，定位整改工作全部收口」——本轮**证伪该结论**，并按站长数据流重新分层给出闭环判据。
> **方法**：8 路并行子代理做静态核查（禁止改文件/跑构建/写库）+ 主代理用只读 psql 与源码行号逐条复核承重结论。
> **口径**：只谈「站长不改代码能否搭出自己的站」，不谈崩溃类 bug。

---

## 总裁决

| # | 层 | 判词 | 断在哪（一句话） |
| :-- | :--- | :--- | :--- |
| L1 | 安装 / 初始化 | **不闭环** | 生产态空库首启自锁，进不了向导；无空站起步路径 |
| L2 | 站型包体系 | 半闭环 | 包是 DB 行、引擎通用，但站长只能「另存快照→apply」，而另存丢 5 类载荷 |
| L3 | 内容自定义字段 | **不闭环** | 数据模型上只能表达「单选枚举」，文本/数字/日期/多选一概做不到 |
| L4 | 分类体系与筛选 | 半闭环 | 读取面真数据驱动；写入面缺色/排序/多语，层级建了不下发 |
| L5 | 功能模块开关 | 半闭环（偏闭合） | 前台四处同源一致；后台面板完全不看开关；无法新增模块 |
| L6 | 呈现层可定制 | 半闭环 | 内容层（站名/菜单/页面）可配；视觉与结构层是代码枚举；SEO 面板全断 |
| L7 | 词汇与术语 | **中度违反定位** | 术语无覆盖机制；379 处中文校验串绕过 i18n；出现「词面即逻辑」 |
| L8 | 日常运营 | 半闭环 | 内置运营动作齐；凡涉及「站长自建数据」的动作全部断链 |

**结论**：定位目标的三条硬约束里，三审自评「C1 不偏向任何类型 / C2 不改代码自由搭建 / C3 关闭即四处一致」——四审判定 **C3 成立，C1 部分成立，C2 不成立**。C2 不成立不是因为缺面板，而是因为**可扩展性被冻结在 schema 的列名与枚举里**：面板都在，但面板能表达的粒度小于「站长自由搭建」所需的粒度。

## L1 安装 / 初始化 —— 不闭环

### P0 生产态空库首启自锁

- `migrations/0017_*.sql:9` 引导 root 的 argon2 哈希，与 `apps/api/src/main.rs:124` 的 `DEMO_PUBLIC_HASH` **逐字节相同**。
- `main.rs:123` 的防线条件是 `FLUX_DEV != 1`，而 `docker/docker-compose.yml:102` 写 `FLUX_DEV: ${FLUX_DEV:-}`（默认空）⇒ 生产默认路径下，UPDATE 按哈希匹配会把 **root 一起随机化**，新随机口令只在内存里存在过，日志仅打 `count`（`main.rs:141-146`）。
- 安装向导**不建管理员**：`setup_http.rs:94-103` 的 `SetupFinishBody` 只有 `pack` / `site_name` / `games_compliance_ack`，无任何凭据字段；文件头注释「建管理员（如未建）」与实际不符。前端 `app/setup/page.tsx:155-161` 反过来要求站长「先用引导 SQL 建 root」。
- 结果：按 `_doc/生产部署指南.md` 的 `root / password123` 登不进；SMTP 未配时密码找回静默禁用 ⇒ 唯一出路是带外 SQL 改密，而文档未写这一步。

**修法（两步，缺一不可）**：① `main.rs` 的 neutralize 谓词加身份排除（只清 0018 演示账号，其 `passkey` 为 `demo0000…01..12` 字面量），② 补**服务端** must-reset 闸门——`0017:4-5` 注释声称「服务端强制 root 首登改密」，实测只到前端：`auth_http/login.rs:135`、`auth_http/me.rs:101` 仅下发布尔，全仓无请求级拦截。只有 ① 会弱化安全，必须成对做。

### P1 无空站起步 / 装完无引导

- `app/setup/page.tsx:121-142` step1 只有站型按钮，无「跳过 / 空白」；后端其实容 `pack=""`（`setup_http.rs:135`），但 UI 走不到。11 个包与默认 general（`0119_default_pack_general.sql:36-39`）都预置 7–10 分类。
- `components/admin-overview-panel.tsx:37-62` 只有运营待办 + DB/Redis 健康，全站无「缺 SMTP / 未配分类 / 未设域名」类装机后告警 ⇒ 半成品站无人带。
- **CI 不覆盖装站旅程**：`.github/workflows/e2e-smoke.yml:106` 只断言「setup 未就绪时返回 401/403/404/410」，空库→向导→可用站全程无自动化。

### P2

- 强制「机会类游戏合规」勾选不分站型（`setup_http.rs:119-123`，文案 `page.tsx:213-216` 专指刮刮乐/猜大小）。

## L2 站型包体系 —— 半闭环

## L3 内容自定义字段 —— 不闭环（本轮最重）

**唯一维度定义处**：`migrations/0085_section_kinds.sql:5-9` 只有 `kind,label,sort`；写入口 `admin_p3_http/section_kinds.rs:21-27,85` 同形；选项表 `0063_admin_p3_suite.sql:52-57` 只有 `id,kind,name,sort,mode_id`；关联表 `torrent_sections` 主键 `(torrent_id,kind)`（`0063:62-66`）**结构上限一条**。

| 字段能力 | 内容侧 | 用户资料侧（对照） |
| :--- | :--- | :--- |
| 单选枚举 | ✅ | ✅ |
| 多选 / 数字 / 文本 / 日期 / 布尔 | ❌（值必须是预置 dict_id） | ✅（`0186_user_fields.sql:10-21` 六类型） |
| 必填 / 默认值 / 取值校验 / 可见范围 | ❌ 无列 | ✅ |
| 排序 | ✅ | ✅ |
| 图标 / 颜色 / 多语言名 / 层级 | ❌ 无列 | ❌ |

⇒ **「轻松自定义字段」目前只在用户侧成立，内容侧不成立。** 站长要「ISBN / 出版年份 / 时长 / 页数 / 多选标签」只能 SQL 或塞进描述。

**消费面通断**（通：上传 `upload-form-quality.tsx:57-66`、编辑 `torrent-manage-parts.tsx:219-271`、详情 `torrents/detail.rs:122-141`、列表筛选 `torrent_http/list.rs:42-70`、包导入导出 `pack_store.rs:331-420`）：

- **P0** 批量走旧三列那条分支不反写 sections（`admin_p3_http/torrent_batch.rs:193-209` 只 UPDATE `category_id/medium_id/grade_id/edition_id`）⇒ 与批次 3 拍板的「写时反向落列」直接冲突，后台批量改完，详情页与筛选仍显旧值。
- **P0** 对外协议面不接自建维度：`rss_http.rs:85-92` 只对 `kind='media'` 一个维度做名称桥接，自建维度在 RSS 不可筛、item 不带维度；`openapi_http/open.rs:29-49`、v4、NP compat（`compat_http/nexusphp.rs:135` 只回 `medium_id`）同理不下发。
- **P1** 后台种子列表零维度（`admin_http/torrents.rs:105-131`）；`change_sections` 批量有 API 无 UI（`torrent_batch.rs:211`，web 端零引用）。
- **P1** 假开关：`category_modes` 是 **7 个固定布尔列** `show_source/medium/codec/audio_codec/standard/processing/team`，`section_public.rs:69-78` 按 kind 名 match、其余 `_ => true` ⇒ 站长自建维度永远不受模式管辖。这 7 个名字（含 `audio_codec/standard/processing`）本身就是影视/音频词表进了 schema——**偏向不只藏在文案和缺省值里，也藏在列名里**。
- **P1** 前端第二套词表回潮：`components/admin-sections-shared.ts:43-46,57-65` 硬编码九维兜底与 7 项开关名单。
- **P2** 列表列 `slice(0,3)` 只剩值无名（`torrent-table.tsx:216`、`torrent.tsx:57`、`torrent/[id]/page.tsx:140`）；关键词搜索不覆盖维度值（`list_noclamp_as.rs:75-81`）；包导出丢 `section_dict.mode_id`（`pack_format.rs:163-164`）。

> **更正一处子代理误判**：`show_*` 对 grades/editions 与自建维度恒可见，是批次 3（2026-09-25）拍板的**有意设计**，本轮重新判为缺陷的理由不是「当时没做」，而是「自建维度无法纳入模式管辖」缺一张 `(mode_id, kind)` 关联表可走的路。

**用户自建字段/自定义页面**：user_fields 链路更闭合（注册 `register.rs:41,119`、usercp、公开档案 `profile.rs:258`、后台面板），缺 staff 代改他人值（只有 `/me/fields`，`auth_http/user_fields.rs:387,414`）与按字段筛选；custom_pages 闭合但单语言、不进搜索、无 SEO 字段（`0187_custom_pages.sql:8`）。

  在第一条 DELETE 就先炸，坏 SQL 从未执行到，一直被掩盖。另：清理动作经事务内干跑 +

- **P1 自助改密不失效 5s 状态缓存 → 装机时序上会假死**：`auth_infra.rs:237` 的
