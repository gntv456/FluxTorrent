## 一、修掉一处 P1：娱乐屋大厅聚合整页 500

`GET /api/v1/games/arcade-meta`（大厅表面：账本/周常/票根册/赛季星轨/外观货架/
预算环/体检闸）实测 500，Postgres 侧：

    ERROR:  incorrect binary data format in bind parameter 2
    STATEMENT:  SELECT COALESCE(-sum(amount), 0)::bigint FROM spark_ledger
                WHERE user_id = $1 AND kind = 'game'
                  AND created_at >= now() - make_interval(days => $2::int)

根因：`arcade_meta.rs` 把 `eco_i64` 取回的 `win`（i64）直接绑进
`make_interval(days => $2::int)`——参数位是 int4，sqlx 按 i64 发 8 字节，
服务端解析参数即报错，整个大厅聚合读不出来。同一条 SQL 的另一份拷贝
（`arcade_claim.rs` 的预算闸）写的是 `win as i32`，所以「领取」不炸、只有大厅炸——
又一次「两份规则里被改漏的那一份」，与本轮 A/B 批同源。

修法：`win_days = win.clamp(1, 3650) as i32`，两处 `back`/`det_spark` 都改绑它，
`det_cost_value` 也收同一个已钳值；`arcade_claim.rs`、`arcade_rewards.rs` 里
原来裸 `as i32`（站长把窗口天数配成天文数字时会回绕）一并改成 clamp 后再转。

复验（api=2c16c25ca9c9）：`/games/arcade-meta` → 200，
`ledger = {base:1500, budget:1592, det_cost:0, magic_back:461, net:461, window_days:7}`；
`e2e_arcade_rewards.py` 23 条由 1 红转全绿（红的那条正是「预算环读数含物品折算价」）。

## 二、农场土地阶梯 e2e：一条断言写错了，不是产品坏了

`e2e_arcade_farm_land.py`（0260，项目记忆里记着「代码已提交但 e2e 未跑」）首跑
28 绿 1 红：「等级只买周转：Lv.3 与 Lv.1 的价值侧一字不差」拿到 {3: 59, 1: 58}。

查 `farm_actions.rs` 收获计价：`base_yield × 请求内随机市场因子(±50%)`，
该随机化是 2026-10-06 安全审计 P1-1 的改动——旧版按窗口起点纯哈希定价，
可离线预计算做「低价窗买种 × 高价窗收获」的套利，所以改成 `thread_rng`。
于是这条断言等于要求两次随机数相等，是**脚本落后于机制**，不是等级漏进价值侧。

改成带内判定：两侧价值都落在 `base_yield × (1±50%)` 带内，并在注释里写清局限
——随机 ±50% 意味着这条只能挡「大额等级因子混入价值侧」，要精确测必须给
roll 开注入口。改完 29 条全绿。
