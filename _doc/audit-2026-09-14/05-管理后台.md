# 管理后台/运营审计报告（agent_cf419a37）

## 缺陷清单

### [P0-1] 删除用户为非事务且清理表清单严重不全 → 部分删除后 500，用户数据不可逆丢失
- 位置：apps/api/src/admin_http.rs:910-950（user_admin_delete）
- 证据：代码注释自认"整个操作无事务，前序清理已生效"；清理仅约 20 张表，FK 实查 del=a 引用 users 的表远不止：audit_log、reports、password_resets、api_tokens、appeals、staffmessages、pmboxes、friendships、shoutbox、farm_plots/farm_harvests、gomoku_games、fun_items/fun_votes、requests/offers/offer_votes、subtitles、seed_preserve、jixiao_claims、torrent_groups、download_keys、resurrections、push_subscriptions、seed_milestones、username_change_logs、user_modify_logs、donation_ledger、pool_donations、user_vouchers、message_flood 等。audit_log.actor_id FK 使任何做过审计操作的账号删除必失败于最后一步 DELETE users（前序清理已生效，半死状态且无法重试）。
- 修法：整个清理序列包单事务；或改软删+匿名化（status=3、username 打码），FK 改 SET NULL/CASCADE。

### [P1-2] 删除被种子引用的拒绝理由返回 500（非 4xx）
- 位置：admin_http.rs:2065（deny_reasons_delete）+ FK torrents → torrent_deny_reasons del=a
- 复现：种子置 deny_reason_id=9 → DELETE /admin/deny-reasons/9 → 1000 内部错误（实测）。
- 修法：删前 count torrents 引用，>0 返回 Validation（参考 category_delete 护栏）。

### [P1-3] 删除版块静默级联删除全部主题/帖子，无确认或数量提示
- 位置：admin_http.rs:2660（forum_admin_delete）+ FK topics→forums del=c、posts→topics 级联
- 复现：DELETE /admin/forums/1 返回 ok，主题全部级联消失（审计中实测命中：forum 1 主题被删，已重建空 forum 行，内容无法恢复——即本缺陷实证）。
- 修法：删除前检查 topics 数量，非空要求先搬移（或 force 参数+二次确认）。

### [P1-4] 勋章负数价格/负时长 → 500（仅 DB CHECK 兜底，无应用层校验）
- 位置：admin_p3_http.rs:973（admin_medal_add/update）
- 复现：POST /admin/medals {price:-5000,duration_days:-10} → 1000（实测）。
- 修法：应用层校验 price>=0、duration_days>=0、bonus_addition_factor 范围。

### [P1-5] 分类新增/修改/删除完全不写审计日志
- 位置：http.rs:1953-2005（category_create/update/delete 均无 state.repo.audit）
- 证据：audit_log 有 faq.create/rules.delete/forum.delete 却无 category.*（同类的 jixiao_type/section_dict 均有审计）。
- 修法：三处补 .audit(...)。
