# 种子全链路审计报告（agent_f9e602fd）

## 缺陷清单

### [P0-1] announce→计费链路断死：worker 消费游标永久卡死
- 位置：apps/worker/src/jobs.rs:407-531（consume_announce）、565-715（process_event）
- process_event 抛错后 break 不推进游标（防丢计费设计），但错误为持久性 SQL 绑定错误 → 死循环。日志每 60s 重复错误；XLEN flux:announce=1815 待处理；6 次测试 announce 零落账（snatches 无新行、traffic_ledger 停在 2026-07-11）。全站上传/下载量、snatches、做种数、H&R、做种收益全部停摆。
- 修法：修 P0-2 语句错误；游标加熔断（同 ID 连续失败 N 次进 flux:announce:dlq 并告警）。

### [P0-2] snatches UPSERT 类型错误：COALESCE($12,1) 写 boolean 列
- 位置：jobs.rs:646/665。snatches.connectable 为 boolean NULL，ev.conn 为 Option<i16>。psql PREPARE 实测复现 "column connectable is of type boolean but expression is of type integer"。
- 修法：列改 smallint（对齐 0071 迁移意图，见 07 报告）或绑定转 boolean。
- （与 worker 审计报告 P0 同根因互证）

### [P0-3] 下载的 .torrent 中 announce URL 指向不存在的路由（双重 /announce + 错端口）
- 位置：apps/api/src/http.rs:5161-5173（build_torrent_bytes 拼 {base}/announce/{passkey}）+ migrations/0034 默认 announce_url='http://127.0.0.1:8080/announce'
- 实测：GET /torrents/76/download 返回 announce=http://127.0.0.1:8080/announce/announce/<passkey>；curl 该 URL 404；tracker 实际在 :7070/announce/{passkey}。真实客户端拿到必然失败的 tracker 地址。
- 修法：站点设定改 tracker 根地址（http://host:7070）；build_torrent_bytes 拼接前剥离尾部 /announce 双保险。

### [P1-1] 众筹达标链路断：API 手动触发版 funding_settle 只置状态、不挂促销不发通知
- 位置：admin_p3_http.rs:3213-3221（仅 UPDATE status=1）vs worker jobs.rs:1515-1547（含 INSERT promotions+消息）
- 实测：POST /admin/jobs/run funding_settle → fundings#7 status=1 但 promotions count=0、无达标消息；worker 版随后 WHERE status=0 匹配不到。参与者实付 1053（税 52）已扣、承诺的 free×2h 永久丢失。
- 修法：API 触发器补齐促销+通知（与 worker 同款 SQL）或唤醒 worker。

### [P1-2] staff 无法经列表查看未过审种子

- 修法：给 class 90+ 补 role_permissions。

### [P1-3] 上传者在待审期间无法查看自己的种子详情

- 实测：owner 上传 id=76(status=0) 后 GET /torrents/76 → 404。
- 修法：vis 增加 OR (approval_status=0 AND owner_id=uid)。

### [P1-4] 服务端 info_hash 为"规范化重编码哈希"，与客户端原始字节口径可能不一致
- 位置：bencode.rs:97-113（键重排序）+ 127-131（对重编码结果 SHA1）
- BEP3 客户端按 info 字典原始字节计算；键序非排序时 DB hash ≠ 客户端 announce hash → process_event 静默跳过丢计费。
- 修法：parser 记录 info span 对原始字节 SHA1。
