# 认证/授权/安全审计报告（agent_b659325c）

## 缺陷清单

### [P1] must_reset_password 无服务端强制，临时密码可无限期调用全部 API
- 位置：apps/api/src/http.rs:332（登录响应仅回传布尔）、http.rs:586（改密才清标志）
- 证据：/admin/adduser 建 must_reset_password=true 账号，未改密直接带 token 访问 /torrents、/messages/inbox、/me 全部 200（响应含 must_reset_password:true）。强制改密仅靠前端跳转。
- 修法：require_auth（http.rs:396）对 must_reset_password=true 账号只放行改密/登出端点，其余返回 2008。

### [P2] 封禁未通知 tracker 刷新缓存，被 ban 用户 announce 仍有效 ≤60s
- 位置：admin_http.rs:1241（user_set_status 无 bump_guard_ver 调用；对照 admin_http.rs:1214 /admin/users/flags 有调用）
- 证据：置 status=2 后 1s 内 tracker announce 仍 200 正常响应；SQL 侧有 status<2 检查（tracker main.rs:228）但 60s 内存缓存未失效。
- 修法：user_set_status 中 status≥1 时追加 bump_guard_ver。

### [P2] 开放 API Token 不校验用户状态，封禁后 token 仍可用
- 位置：openapi_http.rs:47-59（require_token 只查 revoked/expires，不 JOIN users.status）
- 修法：查询改 JOIN users WHERE u.status < 2。

### [P2] 前端 token 双存 localStorage + 非 HttpOnly Cookie，XSS 可直接窃取 12h JWT
- 位置：apps/web/lib/api-client.ts:62、api-client.ts:22（samesite=lax 无 HttpOnly/Secure）
- 修法：服务端下发 HttpOnly+Secure Cookie，或缩短 JWT TTL + refresh 轮换。

### [P2] 登出撤销（logout_nbf）与全站限流对 Redis 故障 fail-open
- 位置：http.rs:410-422（unwrap_or(None) 跳过 nbf）、http.rs:341（unwrap_or(0) 恒放行）
- 修法：Redis 异常时登录端点 fail-closed 或内存本地限流兜底。

### [P2] 2FA 关闭仅验 TOTP 码不要求密码
- 位置：twofa_http.rs:124-153
- 说明：会话被劫持+能看到验证器码时可无声关闭 2FA。建议 password+TOTP 双因子关闭；totp_secret 明文存库（base32）建议加密。

### [P2-低] 参数解析错误回传 serde 内部细节
- 位置：main.rs:102-115：畸形 JSON → "Json deserialize error: key must be a string at line 1 column 2"。无堆栈/SQL 泄漏，可换通用文案。

## 已验证安全面
1. JWT：无 token 401、篡改签名 401、伪造密钥（含过期声明）401、alg 混淆防护（RS256 锁算法+单测）。
2. 登出撤销：logout 后旧 token 即刻 401，新登录正常（iat 语义正确）。
3. ban 即时失效：status=2 后既有 JWT 立即 403（每请求查库）。
4. 2FA 无绕过：仅密码→400、错码→400、对码→发 token；enable 需 setup→enable 两步。
5. RBAC：class 0 打 18 个 admin 路由全 403；ensure_outranks 防同级操作上级。
6. IDOR：消息身份全取自 token（?user_id=1 被忽略）；无越权路由。
7. tracker passkey：伪造→"passkey 无效"；scrape 同校验；每 IP 限流先于 passkey 校验；leak_events 链路完整（worker leak_scan→staff 复核端点）。
8. API Token：上限 3 枚强制、sha3-256 落库、revoke 即刻 401、无 token 401、按 token 分桶限流。
9. 注入面：format!+SQL 全为白名单标识符+bind 参数化；like_pattern 转义 %_\。
10. CORS/头/限流：未配 CORS_ORIGINS 直接 panic；nosniff/XFO(DENY)/Referrer-Policy 齐备；登录双维度 5/min/用户名+5/min/IP（INCR 先于密码校验，不泄露用户名存在性）。
11. 注册链路：验证码+邀请码一码一用原子消费+邮箱黑名单三形态+IP 封禁+限流，失败回滚。
