## 二、最严重的三个发现（修复过程比预期更深）

### 1. announce 计费链路自 07-11 起整体瘫痪（P0，根因三层）
- **表象**：worker 每分钟报 `bind message supplies 0 parameters`，Redis 游标冻结，全站上传/下载/snatches/H&R/做种收益全部停摆（traffic_ledger 停在 07-11）。
- **根因一（schema 漂移）**：0032 建 `snatches.connectable BOOLEAN`，0071 想改 SMALLINT 但 `ADD COLUMN IF NOT EXISTS` 静默 no-op → 迁移 0080 矫正列类型。
- **根因二（绑参错位）**：snatches UPSERT 里 `$10`=bigint（容忍窗）与 `$11`=boolean（stopped）在 Rust 侧**绑反**。
- **根因三（真凶，PG 日志实锄）**：`promo(global)` 语句 `$1` 出现 3 次但只 bind 1 次——sqlx Describe/Bind 计数协商失败后发出 0 参数 Bind。改为 `$1/$2/$3` 三占位符 + 三 bind。cheat 豁免语句同款双引用一并修复。
- **验证**：live announce 端到端（started→periodic→stopped）全部落账：snatches 6000/2000、traffic_ledger +2、users uploaded/downloaded 同步；游标追平流头。

### 2. 三处零门槛无限铸币（P0，全部实测实锤后封堵）
- **hr 自助免罪**：退款幂等键拼 UUID 每次全新 + spend 返回 Replayed 被忽略 → 重放净赚 20000/次（审计实测 +60k 已冲销）。修复：确定性退款键 + Replayed 一律拒绝。
- **jixiao 考核工资**：任意用户可自选任意岗位领薪（无归属校验，min_requirements 全站空转），每用户每月 ≈89,500。修复：必须存在 admin 分配行。
- **农场种植退款**：幂等键含分钟窗口 + Replayed 不检查 → 同槽换高价作物白拿 7500/次。修复：Replayed 拒绝 + 退款额取实际扣款额。
- **成就奖励双发**（修复过程中新发现）：INSERT 流水有幂等护栏、UPDATE 余额没有 → 每小时任务重跑时余额再加一次（实测 10 用户各 +200 已冲销）。修复：UPDATE 与 INSERT 同护栏，并推广到 resurrection/class_promotion/funding_refund 四处同型代码。

### 3. 删用户非事务 + 清理清单严重不全（P0）
- 实测 del=a 引用 users 的列有 **83 处**，旧代码只清约 20 张表——任何做过审计操作的账号删除时，前序清理已生效、最终 DELETE 因 `audit_log.actor_id` FK 必 500，账号半死、数据不可逆丢失。修复：单事务 + 全 83 列覆盖（本人数据 DELETE、留痕列 SET NULL）。
