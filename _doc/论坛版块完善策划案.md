# FluxTorrent 论坛版块完善策划案

> 版本：v1.0 · 日期：2026-09-18
> 依据：对 **Zsens BBS / BBS-GO / Flarum / 修罗(Xiuno) / rhex** 五个开源论坛的深入研究 + FluxTorrent 现有代码盘点（证据见各节引用）
> 目标：把当前 M15「基础论坛」升级为「综合站级社区经营引擎」，且**不重复造轮子**——勋章、等级(class)、火花(spark)、私信、好友、小游戏、模块门控、admin 论坛管理都已存在，本方案只补缺口并打通联动。

---

## 0. 一页结论

- **现状**：论坛骨架已成型（forums→topics→posts、三层权限+版主+全局管理、匿名、精华、已读、搜索、admin 全量管理、spark 行为奖励）。但**互动层（赞/藏/关注/@）、内容形态层（悬赏/投票/抽奖/红包）、治理层（举报/敏感词/审核）、基座层（分区/标签/Markdown）几乎全缺**。
- **五个竞品给的三条主线**：
  1. **内容形态化**——rhex/Zsens 把帖子分成「普通/悬赏/投票/抽奖/红包」，并用站点货币（spark ⇄ 金币）做悬赏托管、抽奖、打赏；
  2. **互动与成长闭环**——BBS-GO/rhex 用「赞/藏/关注/订阅 + 通知 + 等级/勋章/任务」把发帖变成成长行为；
  3. **轻内核 + 强治理**——修罗的极简表结构、Flarum 的扩展点、rhex 的后台运营台，是可持续性的答案。
- **落地策略**：以 spark 经济为中枢，分四期补齐「基座→互动→形态→治理」，所有经济行为复用 `earn_spark`/`spend_spark` + `spark_ledger` 幂等，所有权限复用 class 三档 + `forum_mods` + `postmanage(90)/forummanage(93)`。

## 1. 竞品深度研究

### 1.1 Zsens BBS（zsens.cn / cnzss.com）— 开发者/插件社区
- **定位**：面向插件开发者的内容社区，论坛与「资源/插件经济」深度绑定。
- **核心能力**（来自 zsens.cn/thread/364.html 实站抓取）：
  - **双货币**：积分 + 金币（金币用于下载付费插件）；2026-09-06 因滥用**关闭积分兑换金币**，体现反通胀治理意识。
  - **悬赏问答**：用积分发布问题悬赏激励他人解答。
  - **幸运抽奖**：单次消耗 100 积分、50% 概率得 20 金币。
  - **红包拼手气**：帖内随机红包互动。
  - **勋章**：执序官者 / 社群翘楚 / 勋望元宿 等 badge 体系。
  - 用户主页 `/u/user/1.html`。
- **可借鉴**：论坛与「资源经济」绑定的范式；**双货币 + 悬赏 + 抽奖 + 红包**的互动经济可直接映射为 spark 玩法（FT 已有 spark，无需造第二货币）。
- **局限**：闭源/半公开，技术栈不可考；经济模型偏「下载付费」，对 PT 社区应改为「做种/分享激励」导向。

### 1.2 BBS-GO（mlogclub/bbs-go）— Go + React 全栈
- **技术栈**：Go（Gin，早期 Iris）+ MySQL + GORM；React + React Router 前端；**GPLv3**；一体化部署（server 直接托管前端静态资源）。
- **核心能力**（bbs-go.com/docs）：
  - 内容三态：**论坛 + 问答 + 文章** 合一；标签/节点/分类。
  - 互动：关注、通知、点赞、收藏；问答式「采纳答案」工作流。
  - 成长：**积分、等级、任务、徽章**。
  - 管理：内容/用户管理、系统配置、数据统计、审计日志。
- **可借鉴**：轻量一体化部署思路；「讨论/问答/文章」内容三态；**任务+徽章成长体系**（FT 已有 medals/tasks，可接通论坛行为）。
- **局限**：MySQL 单库；Q&A 与论坛耦合较深，对 PT 站可简化为「悬赏问答」一种形态。

### 1.3 Flarum — PHP + Laravel + Mithril SPA
- **技术栈**：PHP + Laravel 组件 + **Mithril.js SPA** + **JSON:API**；**MIT**；多 DB（MySQL/PG/SQLite）。
- **核心哲学**：fast / simple / extensible；**Extension API（extenders 声明式扩展前后端）**，保证小版本升级不破扩展。
- **原语**：灵活权限/群组、通知、审核原语；活跃扩展生态。
- **可借鉴**：**扩展点/插件化设计哲学**（声明式 extenders）、轻量内核、SPA 体验。
- **局限**：PHP 生态，与 FT 的 Rust/Next 栈不互通，仅作架构理念参考。

### 1.4 修罗 / Xiuno BBS 4.0 — 极简 PHP 论坛
- **技术栈**：PHP 7/8 + MySQL（DB 层抽象支持 Redis/Memcached/Yac）；Bootstrap4 + jQuery；**MIT**（官方停更，社区延续版 NextLNMP/xiunobbs）。
- **核心能力**（xiunobbs 镜像站、designshidai 评测）：
  - **极简内核**：~15–17 张表、压缩包 ~1MB、单请求 0.01s 级（开 Opcache/Yac 进 0.00x 秒）。
  - **Hook + Overwrite 插件机制**：在模板/逻辑点插代码并合并缓存，不侵入核心、不影响编译。
  - 多端自适应、相对路径 URL、**不强制 Rewrite、可子目录部署**。
  - **Session + Token 双登录、全站可返回 JSON**（方便配套 App/小程序）。
- **可借鉴**：极简数据模型（FT 的 forums/topics/posts 已是精简形态，应坚守）；**API 友好（Token 登录 + JSON）**对 FT 移动端/App 化有启发；插件不侵入核心的工程纪律。
- **局限**：PHP、官方停更；仅理念借鉴。

### 1.5 rhex（rhex.im，herper/Rhex、wanniwa/Rhex）— 现代 Next.js 全功能论坛
- **技术栈**：Next.js 16 (App Router) + React 19 + **Prisma + PostgreSQL + Redis** + Tailwind；前后端结构清晰，约 80% AI 辅助开发。
- **核心能力**（GitHub + rhex.im 实站抓取）：
  - 论坛模型：**分区/节点/标签/关注/热门流/最新流/搜索**。
  - 帖子类型：**普通 / 悬赏 / 投票 / 抽奖**；**匿名发帖/回复/马甲**。
  - 互动：**楼层 + 楼中楼、点赞、收藏、关注、举报、屏蔽、@提及通知**。
  - 商业化：**红包帖、聚宝盆、打赏、礼物、热度权重**。
  - 可见性门槛：帖子**可见等级/VIP 限制、登录解锁、回复解锁、积分购买解锁**。
  - 附件：上传 / 购买 / 回复解锁 / 外链。
  - 内容渲染：**Markdown + 代码高亮 + KaTeX + Mermaid + TaskList + 图片灯箱 + 自定义表情**。
  - 用户：账密 / GitHub / Google OAuth / **Passkey**；等级/勋章/认证/VIP；积分/签到/补签/邀请；邀请码/兑换码。
  - 后台：仪表盘、用户/帖/评管理、**节点申请审核**、等级/勋章/认证、公告/帮助、举报中心、日志中心、**敏感词**、站点设置、全局搜索。
  - 内置应用：**AI 助手**（@ 后异步回复）、**RSS 抓取中心**、五子棋、阴阳契、自助广告位。
- **可借鉴**：**最完整的现代论坛功能全集**，几乎覆盖本方案所有想做的点；「帖子类型化 + 可见性门槛 + 互动经济 + 后台运营台」是一套可直接映射的蓝本。
- **局限**：Node 生态，与 FT 栈不同；部分功能（AI 助手、广告位）对 PT 站属远期/可选。

## 3. 总体设计原则

1. **复用优先，零重复造轮子**
   - 货币 ⇨ **spark**（`spark_ledger` 幂等、`earn/spend_spark`），不再造第二货币（Zsens 双货币在 FT 用「spark 单货币 + 悬赏托管」表达）。
   - 等级 ⇨ **class**；勋章 ⇨ **medals**；私信 ⇨ **messages**；好友 ⇨ **friendships**；小游戏 ⇨ **gomoku/fun_items**（已存在，远期应用中心直接挂）。
   - 权限 ⇨ 沿用 `forum_access()` 三档 + `forum_mods` + `postmanage/forummanage`，新功能只在既有判定上**加维度**，不另立体系。
2. **坚守极简内核（修罗教训）**：不因为加功能就膨胀表；互动类新表走独立小表 + 必要索引，posts 分区表不动结构。
3. **综合站 + site_type 参数化**：所有新功能默认综合站语义，用 `site_type_packs.modules` JSONB 开关，教育/影视等站型可关。
4. **迁移号避让**：每次新增迁移前先 `Glob apps/api/migrations/010*.sql` 查最大号，从最大号 +1（本方案草案用 **0100+** 占位，实施时以实际最大值为准）。
5. **防通胀/防刷**：任何发 spark 行为必须走 `spark_ledger` 幂等键；删帖/删主题的对称回收已验证，新奖励沿用同一纪律。

## 4. 分阶段功能规划

### Phase 0 — 信息架构与内容基座（P0，地基）
**G1 分区/节点 + G3 Markdown + G4 帖子类型列**

- **数据模型（迁移 0100）**
  ```sql
  -- 分区/节点：forums 归属某个 category
  CREATE TABLE forum_categories (
    id    BIGSERIAL PRIMARY KEY,
    name  TEXT NOT NULL,
    sort  INT NOT NULL DEFAULT 0,
    visible BOOLEAN NOT NULL DEFAULT TRUE
  );
  ALTER TABLE forums ADD COLUMN IF NOT EXISTS category_id BIGINT REFERENCES forum_categories(id) ON DELETE SET NULL;
  CREATE INDEX IF NOT EXISTS idx_forums_category ON forums(category_id);

  -- 帖子类型（先加列，形态逻辑在 Phase 2 落地）
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS topic_type TEXT NOT NULL DEFAULT 'normal'; -- normal|bounty|poll|lottery
  -- Markdown 源文存储：posts.body 保留原样，前端渲染；另存纯文本摘要用于搜索/列表
  ALTER TABLE posts ADD COLUMN IF NOT EXISTS body_text TEXT; -- 渲染前剥离后的纯文本
  ```
- **Markdown 管线**：后端 `posts.body` 原样存（含 Markdown）；前端引入 `markdown-it` + `highlight.js`（代码高亮）+ 可选 KaTeX/Mermaid（技术社区强需求，rhex 验证）。`body_text` 由后端在写入时生成，供搜索/列表预览。
- **前端**：`forums/page.tsx` 改为「分类分组 + 节点栏」；列表/详情渲染 Markdown；编辑框升级为 Markdown 编辑器（带预览）。
- **接口**：`GET /forums` 支持按 `category_id` 分组；`forum_admin_create/update` 增加 `category_id`。

### Phase 1 — 互动与成长（P1，社区黏性）
**G5 点赞/收藏 + G6 关注订阅 + G7 @提及 + G11 热度 + G2 标签 + G9 举报(基础)**

- **数据模型（迁移 0101）**
  ```sql
  CREATE TABLE post_likes (user_id BIGINT REFERENCES users(id), post_id BIGINT, topic_id BIGINT, created_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(user_id, post_id));
  CREATE TABLE topic_favorites (user_id BIGINT REFERENCES users(id), topic_id BIGINT REFERENCES topics(id) ON DELETE CASCADE, created_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(user_id, topic_id));
  CREATE TABLE follows (user_id BIGINT REFERENCES users(id), target_type TEXT, target_id BIGINT, created_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(user_id, target_type, target_id)); -- forum|topic|user
  CREATE TABLE mentions (from_user BIGINT, to_user BIGINT, topic_id BIGINT, post_id BIGINT, created_at TIMESTAMPTZ DEFAULT now());
  CREATE TABLE tags (id BIGSERIAL PRIMARY KEY, name TEXT UNIQUE NOT NULL);
  CREATE TABLE topic_tags (topic_id BIGINT REFERENCES topics(id) ON DELETE CASCADE, tag_id BIGINT REFERENCES tags(id) ON DELETE CASCADE, PRIMARY KEY(topic_id, tag_id));
  CREATE TABLE notifications (id BIGSERIAL PRIMARY KEY, user_id BIGINT REFERENCES users(id) ON DELETE CASCADE, kind TEXT, payload JSONB, read BOOLEAN DEFAULT FALSE, created_at TIMESTAMPTZ DEFAULT now());
  CREATE INDEX IF NOT EXISTS idx_notif_user_unread ON notifications(user_id, read);
  ```
- **行为 → spark（在既有 earn_spark 纪律上加）**：被点赞 +1（幂等键 `like:{post}:{user}` 防重复）；关注/收藏不直接发 spark，但驱动「关注流」与通知。
- **通知中心**：新增 `notifications` 表区分「系统通知（@提及、关注更新、悬赏采纳、红包到账）」与既有 `messages`（私信）。前端新增 `/notifications` 页 + 顶栏红点。
- **@提及**：发帖/回帖时解析 `@username`，写 `mentions` + 插 `notifications` + 站内信（复用 messages 通知范式，见 community_http.rs:344 收礼通知写法）。
- **热度排序**：查询时计算 `hotness = (replies*2 + likes + views*0.1) / (1 + hours_since_last_post/24)`，提供「热门流 / 最新流」切换；`topic_list` 增加 `sort=hot|new`。
- **标签**：`topic_create` 接受 `tags[]`；列表/搜索支持按标签过滤。

### Phase 2 — 内容形态扩展（P1/P2，对接 spark 经济）
**G4 悬赏/投票/抽奖 + G8 红包/打赏 + G13 可见性门槛**

> 本阶段是「Zsens/rhex 经济玩法」在 FT 的落地，**全部经 `spend_spark`/`earn_spark` + `spark_ledger` 幂等**，复用 Phase 0 的 `topic_type`。

- **悬赏问答 bounty（迁移 0102）**
  ```sql
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS bounty_spark BIGINT DEFAULT 0;
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS bounty_status TEXT DEFAULT 'open'; -- open|claimed|awarded|expired
  CREATE TABLE topic_bounty_claims (topic_id BIGINT, user_id BIGINT, answer_post_id BIGINT, created_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(topic_id, user_id));
  ```
  - 发悬赏帖：`spend_spark(author, bounty_spark, 'bounty', idem)` 托管；楼主采纳某回复 → `earn_spark(答主, bounty_spark, 'bounty-award', idem)` 发放；超时未采纳按规则退回或滚入「最佳贡献」。
- **投票 poll（迁移 0103）**
  ```sql
  CREATE TABLE topic_polls (topic_id BIGINT PRIMARY KEY REFERENCES topics(id) ON DELETE CASCADE, multi BOOLEAN DEFAULT FALSE);
  CREATE TABLE poll_options (id BIGSERIAL PRIMARY KEY, topic_id BIGINT, label TEXT, sort INT);
  CREATE TABLE poll_votes (topic_id BIGINT, option_id BIGINT, user_id BIGINT, PRIMARY KEY(topic_id, user_id));
  ```
  - 投票免费或消耗微量 spark（可选）；结果实时统计。
- **抽奖 lottery（迁移 0104）**——参照 Zsens 幸运抽奖
  ```sql
  CREATE TABLE topic_lotteries (topic_id BIGINT PRIMARY KEY, cost_spark INT, prize_spark INT, win_rate NUMERIC(4,3), total INT DEFAULT 0, hits INT DEFAULT 0);
  ```
  - 用户参与：`spend_spark(cost_spark)` → 按 `win_rate` 判定 → 中则 `earn_spark(prize_spark)`，记录 `total/hits` 供审计。
- **红包/打赏（迁移 0105）**
  ```sql
  CREATE TABLE red_packets (id BIGSERIAL PRIMARY KEY, topic_id BIGINT, sender BIGINT, total_spark BIGINT, count INT, mode TEXT, remaining BIGINT, claimed INT DEFAULT 0, created_at TIMESTAMPTZ DEFAULT now());
  CREATE TABLE red_packet_claims (packet_id BIGINT, user_id BIGINT, amount BIGINT, PRIMARY KEY(packet_id, user_id));
  CREATE TABLE tips (topic_id BIGINT, post_id BIGINT, from_user BIGINT, to_user BIGINT, spark BIGINT, created_at TIMESTAMPTZ DEFAULT now());
  ```
  - 发红包：`spend_spark(total)` 托管，抢红包随机瓜分（拼手气/等额两模式）；打赏：直接 `spend_spark(from,to)`。
- **可见性门槛（迁移 0106）**
  ```sql
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS min_class_view INT DEFAULT 0;
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS require_reply BOOLEAN DEFAULT FALSE; -- 回复后可见
  ALTER TABLE topics ADD COLUMN IF NOT EXISTS vip_only BOOLEAN DEFAULT FALSE;
  ```
  - 复用 `forum_access` 判定，叠加 topic 级门槛（`can_read` 后再判 `min_class_view`/vip/是否已回复）。

  CREATE TABLE reports (id BIGSERIAL PRIMARY KEY, reporter BIGINT, target_type TEXT, target_id BIGINT, reason TEXT, status TEXT DEFAULT 'open', handled_by BIGINT, created_at TIMESTAMPTZ DEFAULT now());

## 5. 经济与权限联动规则（中枢设计）

### 5.1 Spark 发放/回收矩阵（在既有纪律上扩展）
| 行为 | 方向 | 数量 | 幂等键范式 | 备注 |
|---|---|---|---|---|
| 发主题 | + | 2 | `forum-topic:{uid}:{tid}` | 已有(:723) |
| 回帖 | + | 1 | `forum-reply:{uid}:{pid}` | 已有(:958) |
| 精华加权 | + | 待定(建议 +3) | `digest-bonus:{tid}:{uid}` | 新增，版主标记时发 |
| 被点赞 | + | 1 | `like:{post}:{fan}` | 新增，去重 |
| 悬赏托管 | − | bounty | `bounty:{tid}` | 托管不立即给答主 |
| 悬赏采纳 | + | bounty | `bounty-award:{tid}:{ans}` | 发放 |
| 抽奖参与 | − | cost | `lottery:{tid}:{uid}` | 每次独立 |
| 抽奖中奖 | + | prize | `lottery-win:{tid}:{uid}` | 命中发放 |
| 发红包 | − | total | `redpacket:{pid}` | 托管 |
| 抢红包 | + | 随机 | `redpacket-claim:{pid}:{uid}` | 瓜分 |
| 打赏 | −(from)/+(to) | tip | `tip:{tid}:{pid}:{from}:{to}` | 直转 |
| 删帖/主题 | − | 对称 | 已有(:1048/:1119/:1142) | 防刷回收 |

> 所有负值走 `spend_spark`、正值走 `earn_spark`，均落 `spark_ledger`，**绝不在应用层直接 UPDATE balance**（遵循 working memory 中 spark_ledger 分区表 + 应用层先查后插的幂等纪律）。

### 5.2 权限叠加规则
- 读取：`forum_access().can_read` **且** `topics.min_class_view ≤ class` **且**（非 `vip_only` 或用户 VIP）**且**（非 `require_reply` 或该用户已在本主题回帖）。
- 互动（赞/藏/关注/@）：需 `can_read` + 未禁言 `forumpost`。
- 治理（举报/敏感词/审核）：全员可举报；处理权归版主/`postmanage`；敏感词配置归 `forummanage`。

## 7. 风险与对策

1. **Spark 通胀**：所有发放走 `spark_ledger` 幂等 + 悬赏/红包「托管制」（先扣后发）+ 删帖对称回收（已验证）。抽奖 `win_rate` 与奖池须运营配置上限。
2. **内容安全合规**：敏感词同步过滤 + 举报通道 + 审计；匿名发布保留 `authority_viewanonymous` 穿透能力给 ≥60 级。
3. **性能**：`posts` 是分区表，互动新表（`post_likes`/`follows`/`notifications`）加必要索引；通知写入走 worker 异步；RSS/热门流可缓存。
4. **Markdown 安全**：渲染必须**白名单 sanitize**（防 XSS），代码高亮在服务端或受控前端做。
5. **迁移撞号**：严格执行「先查最大号 +1」约定（working memory 已记录 2026-09-15 撞号事故）。
6. **过度设计**：Phase 4 的扩展点/AI 助手属远期，不要在早期抽象插件框架。

### Phase 1（第二片）—— 已完成（2026-09-18）：关注订阅（用户/版块/主题）+ 关注流
- **迁移 `0121_forum_follows.sql`**：`follows (user_id, target_type, target_id, created_at, PK(user_id,target_type,target_id))` + `CHECK target_type IN ('user','forum','topic')`。
  - **为什么不复用 `friendships`**：`friendships.list` 走 `pending|friend|black` 的**双向好友申请**流程，而关注是单向、无需同意的订阅语义，塞一起会把两种语义搅乱。
