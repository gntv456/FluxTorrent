## 二、FluxTorrent 的实现链路

| 层 | 位置 |
|---|---|
| 迁移 | `0093_exam_engine.sql`（考核引擎）、`0094_task_quota_unify.sql` |
| 表 | `tasks`（考核定义，`kind IN ('task','onboard','periodic')`）+ `task_claims`（用户认领，含基线快照） |
| 用户接口 | `GET /api/v1/me/exams`（`ops_http.rs:665`） |
| 管理接口 | `admin_p3_http.rs` 的 `exam_users` 等 |
| 页面 | `apps/web/app/(main)/me/exams/page.tsx` |
| 自动派发 | `worker/src/task_jobs.rs`（hourly tick 内） |
| 自动结算 | `worker` 的 `task_settle` |

### 派发条件（`task_jobs.rs`）

```sql
INSERT INTO task_claims (task_id, user_id, base_uploaded, base_seed_seconds, base_uploads)
SELECT t.id, u.id, u.uploaded, ...snatches 汇总..., ...已过审发布数...
FROM tasks t
JOIN users u ON u.class_id >= t.target_class
             AND u.created_at > now() - ($1 || ' days')::interval   -- 新人窗口，默认 30 天
WHERE t.auto_assign AND t.kind = 'onboard'
  AND now() BETWEEN t.starts_at AND t.ends_at
  AND NOT EXISTS (SELECT 1 FROM task_claims tc WHERE tc.task_id = t.id AND tc.user_id = u.id)
```

**认领时快照基线**（`base_uploaded` / `base_seed_seconds` / `base_uploads`），
进度 = **现值 − 基线**（实时计算，不落明细表）。实测已有 13+ 名用户被派发了「新人转正考核」。

### 指标口径

`tasks.metric` 是 JSONB，支持：
`upload_delta` / `download_delta` / `seed_seconds_delta` / `seed_points_delta` / `uploads` / `subtitles`。

`tier` 非空时切换为**累计口径**（基线视为 0，直接报现值）。

当前新人考核用的是：`{"seed_seconds_delta": 432000}` = 做种满 120 小时。

## 三、同类项目怎么做：NexusPHP 自带完整考核系统

本地 `.np-research/np/`（NexusPHP 源码）里有一套成熟的 Exam 模块，我们的 `0093` 正是对标它。

### 三张表

```php
exams          (name, description, begin, end, duration, filters, indexes,
                status, is_discovered, priority)
exam_users     (uid, exam_id, status, begin, end, progress, is_done)
exam_progress  (exam_user_id, exam_id, uid, torrent_id, index, value)   // 明细
```

### 四个定时命令 + 后台资源

| 文件 | 作用 |
|---|---|
| `Console/Commands/ExamAssign.php` | 分配考核 |
| `Console/Commands/ExamAssignCronjob.php` | 定时分配 |
| `Console/Commands/ExamUpdateProgress.php` | 更新进度 |
| `Console/Commands/ExamCheckoutCronjob.php` | 定时结算 |
| `Filament/Resources/System/ExamResource` | 后台考核管理 |
| `Filament/Resources/User/ExamUserResource` | 后台用户考核管理（**含 avoid / recover / bulkAvoid**） |

指标定义方式（`ExamController::store` 的校验）：

```php
'indexes' => 'required|array|min:1',
'indexes.*.index'         => ['required', Rule::in(array_keys(Exam::$indexes))],
'indexes.*.require_value' => 'nullable|numeric',
'duration'                => 'nullable|numeric'
```

即一个考核由**多个指标**组成，每个指标有达标值 `require_value`。

## 四、对比与可借鉴之处

| 维度 | NexusPHP | FluxTorrent |
|---|---|---|
| 表数量 | 3 张（含**明细表**） | 2 张（`tasks` + `task_claims`） |
| 进度存储 | `exam_progress` 按**种子粒度**逐行记录 | 基线快照 + **实时计算** |
| 多指标 | `indexes` 数组（天然支持多指标） | `metric` JSONB（同样支持） |
| 用户可见 | 偏后台（Filament 为主） | ✅ **有 `/me/exams` 用户进度页** |
| 自动派发 | ExamAssignCronjob | ✅ `task_jobs.rs` |
| 自动结算 | ExamCheckoutCronjob | ✅ `task_settle` |
| **豁免 / 恢复** | ✅ `avoid` / `recover` / `bulkAvoid` | ❌ 没有 |
| **隐藏考核** | ✅ `is_discovered` | ❌ 没有 |
| **优先级** | ✅ `priority`（多考核并存时排序） | ❌ 没有 |

### 值得借鉴的三点

1. **豁免 / 恢复（avoid / recover）** —— 实用性最高。管理组遇到特殊情况（老用户回归、特殊贡献者、误判）需要临时免除或恢复某人的考核。我们现在只能改数据库。
2. **`is_discovered`（隐藏考核）** —— 考核默认不展示，用户"发现"后才可见。用在彩蛋式挑战/隐藏任务上很有意思，成本很低（一个布尔位）。
3. **`priority`** —— 一个人可能同时有多个考核，需要顺序/优先级决定展示与结算次序。

### 我们更好的两点

- **用户可见的进度页**：NP 偏后台，用户不太能看到自己的考核进度，我们直接给了 `/me/exams`
- **实时计算代替明细表**：省掉 `exam_progress` 这种逐种子明细表，存储更省（代价是失去逐种子审计能力）

## 五、发现一个实际问题：新人转正考核给了**整整一年**

实测数据（任务 id=28）：

```
kind=onboard, duration_days=365, metric={"seed_seconds_delta": 432000}
```

- `duration_days = 365` → 截止时间显示为 **2027/9/15**（截图可见）
- `exam_onboard_days = 30` 是**派发窗口**（注册 30 天内派发），**不是考核期限**

**后果**：新人转正考核实际上只是"注册后一年内做种满 120 小时"，约束力约等于没有——
一年时间对"做种 120 小时"这个目标来说过于宽松，考核失去了筛选意义。

**建议**：把 `duration_days` 调整为 **30~60 天**（与派发窗口对齐或略长）。
改法是在后台的考核管理里改这个任务，或直接：

```sql
UPDATE tasks SET duration_days = 45 WHERE id = 28;
```

（注意：`duration_days` 在认领时**不是快照**，`my_exams` 用
`c.claimed_at + (t.duration_days || ' days')::interval` 实时计算 deadline，
所以改任务会影响**已派发但未结算**的考核 —— 调整前要确认这一点是否符合预期。）

## 六、小结

| 问题 | 答案 |
|---|---|
| 进度在哪看？ | **`/me/exams`**，导航「更多 ▾ → 成长荣誉 → 我的考核」 |
| 新人会自动被派考核吗？ | ✅ 会，注册 30 天内自动派发「新人转正考核」 |
| 考核要求是什么？ | 做种满 120 小时（`seed_seconds_delta: 432000`），达标奖励 2000 |
| 同类项目怎么做？ | NexusPHP 有成熟 Exam 模块：三表 + 四定时命令 + Filament 后台 |
| 我们缺什么？ | 豁免/恢复、隐藏考核、优先级 |
| 有什么问题？ | **考核期限 365 天过长，几乎没有约束力，建议改为 30~60 天** |
