> 承接 `_doc/契约失败流转与信誉.md`

> 并记录验证过程中发现的两个**方法论问题**。

## 一、先补了一个被忽略的接口

`GET /api/v1/social/team/list` —— 之前只有 `team_mine`（我的队伍），**没有"浏览可加入的队伍"**。
组队的前提是能看到有哪些队伍可加，缺这个接口前端就只是个空壳。

返回字段：`team_id / torrent_id / torrent_name / leader_name / member_count / team_size_max /
deadline_at / seeders / joined`。其中 `joined` 让前端把「加入」直接换成「已加入」，无需二次请求。

顺带给 `team_mine` 加了 `viewer_is_leader` —— 前端据此决定是否显示「退出」按钮
（队长不能直接退出，要先处理队伍）。这个字段是写组件时才发现缺的：前端根本不知道自己是不是队长。

| 位置 | 内容 |

| `/teams` | 招募列表（资源 / 发起人 / 人数 / 做种者 / 截止 / 加入）+ 我的队伍（成员、队长标记、全队做种总计） |

## 三、验证方法上的两个发现（本轮最有价值的部分）

### 3.1 客户端组件**不能用 curl 的 SSR HTML 验证**

`endangered-panel` / `team-panel` 都标了 `"use client"`，数据靠浏览器端 `useEffect` 里的 fetch。
SSR 阶段只输出 loading 态 —— 所以**curl 抓到的 HTML 里根本没有列表数据**。

我第一次就是这样误判的：`/teams` 的 HTML 里搜不到队伍名、`/endangered` 里 `nexus-table` 数量为 0，
差点当成 bug。实际是**验证手段不适用**。

正确做法：用 playwright + 系统 Edge 做真实渲染，用**渲染出的元素计数**判断
（`await page.locator('table.nexus-table').count()`），而不是字符串匹配。

### 3.2 登录态要设**三处**，最容易漏 localStorage

| 位置 | 键 | 作用 |
|---|---|---|
| cookie | `flux.session` | middleware 的登录存在性判断（只看有没有值） |
| cookie | `flux.token` | 服务端组件（RSC）取数 |
| **localStorage** | `flux.token` | **客户端组件 fetch 时读它**（`api-client.ts:68`） |

只设 cookie 时：middleware 放行、首屏能出来，但客户端 fetch 拿到 **401**，
接着被 `api-client.ts:105` 重定向到：

```
/login?next=%2Fteams&expired=1
```

**表现为「明明登录了却被踢到登录页」**。我为此排查了 cookies 设置方式、Node 铸 JWT 是否有差异，
最后才定位到 localStorage。

两条排查经验：

- **`expired=1` 不是 middleware 加的**（它只加 `next`），是 api-client 收到 401 后加的 —— 这个参数本身就是"客户端 fetch 失败"的线索
- **别怀疑 middleware**，它只检查 `flux.session` 存在性，逻辑在 `middleware.ts` 的 4 行里一目了然

修正后 `errors=0`，两个页面均正常渲染。

## 四、顺手修的一个文案 bug

截图后发现「我的队伍」里最后一行显示 **「人数 | 0 h」** —— 标签与值不匹配
（我复用了 `colMembers` 做标签，但值是全队做种时长）。

已改为独立的 `teamTotal`（「全队做种」/「全隊做種」/「Crew total」）。

**这个 bug 只有真的把页面渲染出来看才会发现** —— 类型检查、API 测试、SSR HTML 全部通过。

### 附带发现

开发库里**没有任何种子满足 `times_completed >= 3`**（最多 2），所以濒危页在该库上永远为空。
这是**数据问题不是代码问题** —— 验证时需要临时把某个种子改成 `seeders=1, times_completed=10`。
