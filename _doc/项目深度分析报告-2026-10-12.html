01

身份定位

证据：README.md、Cargo.toml、apps/api/src/modules.rs、migrations/0315 等站型迁移、docs/。

1.1一句话定位

FluxTorrent 是一个不偏向任何 PT 类型的中立通用建站系统：「站长自由搭建、轻松自定义功能和字段」（README.md:3）。它是 Rust workspace（api / worker / tracker）+ PostgreSQL + Next.js 的全新自研系统，不是 NexusPHP 的 fork 或二开——「NexusPHP 体系」仅指领域模型与功能参考，不存在代码血缘。

1.2站型参数化：一套引擎，十一个起点

事实证据与说明
11 种预置站型综合/教育/影视/音乐/动漫/电子书/体育/游戏/软件/纪录片/无损 + custom 克隆（README.md:5）；站型差异经 site_type 参数化，考核&任务走 NP 的 exam+task 合并式（0093_exam_engine.sql）
六类型字段引擎用户字段与内容维度共用同一套字段类型系统（apps/api/src/fields.rs:1；user_field_defs 表 0186；section_kinds 注册表 + section_dict 词表）
内容维度锚点表content_networks 为通用锚点表（已含 19 种 kind：network / subtitle_group / league / subject…），枚举值→content_networks、artist 自由值→artists，同事务增量同步（publish_http/upload_sections.rs::write_sections → sync_content_anchors）
30 个模块开关四端联动（api 模块网关 fail-close + web requireModule + worker module_on + 管理端可见性），注册表 modules 表（apps/api/src/modules.rs:1）
术语覆盖层站长可改「种子」类固有词；后端 terms.rs::apply 与前端 i18n/apply-terms.ts 逐条对齐（长词优先、单次正向扫描）

1.3「零魔改升级」的架构承诺

全部变更走 sqlx 迁移（0001 起，api 启动自动执行，main.rs:140-155），不碰代码即可 git pull && up -d（README.md:7,64）。这条承诺的代价是迁移纪律：仓库内沉淀了完整的撞号/checksum 处置规程（CONTRIBUTING.md 第 1/1a/1b/1c 条），本报告 §7.3 记录了并行会话撞号的三次实证。

定位推论（强度：强，基于代码事实）

「解耦白纸架构」带来一个结构性优势：没有 PHPSESSID、没有内联脚本 CSP 死结、没有 15 年 accreted schema——API 端 default-src 'none' 的最严 CSP（main.rs:251-265）在 NP 衍生产物上几乎不可能落地。代价是全部领域逻辑（ratio / 做种奖励 / HnR / freeleech）从零写对，项目用 PostgreSQL 函数 + Rust worker 把最易错的做种奖励拆成可测单测的纯函数（0133/0136）。

2.2API：单一 scope 的模块化组装

全站路由经唯一 .configure(community_http::configure)（main.rs:275）挂到单一 /api/v1 scope，21 个 mount 链依次组装（community_http/mod.rs:193-214）：setup → economy → v1_scope → community → ops → content → games → gacha → admin(p3→p2→admin) → settings → adapters → push → gaps → rss → twofa → compat → v4 → openapi。http/mod.rs:53-280 注册约 230 个 service。

全局中间件链（main.rs:249-287）：access_log 脱敏 → CORS → 安全头/CSP → request_id → i18n locale → setup_gate → 写方法跨站来源闸 → module_gate → metrics 计数 → 404 信封兜底。

结构判断（强度：强）

「单一 scope + 域目录拆分 + 300 行文件门禁」是一种克制的单体组织：没有微服务拆分成本，靠目录边界和迁移纪律控复杂度。管理端三代并存（admin_http 36 文件 / admin_p2 7 / admin_p3 43）是演进痕迹，模块间以 mount 链显式排序，未见循环依赖。

2.4数据流：announce → Redis Stream → 异步计费

tracker announce 即 XADD flux:announce（apps/tracker/src/http_track/emit.rs:64），worker 以消费组 fluxcg-announce 组内唯一投递消费，失败进 DLQ flux:announce:dlq，dlq_watch 每 60s 巡检 + 24h 去重告警。同类流：flux:agent_block（客户端黑名单命中）、flux:xreport（交叉上报佐证）。

一个有据可查的架构决策（强度：强）

Redis 从 allkeys-lru 改为 noeviction（docker-compose.yml redis 段注释，ZT81 2026-10-02）：它承载计费事件流与死信，不是纯缓存——「宁可写失败也不静默驱逐未计费 stream 条目」。这是把 Redis 当队列用时最容易被忽视的一刀，此处显式写了改因。

03

安全设计

证据：apps/api/src/auth.rs、http/auth_infra.rs、auth_http/login*.rs、openapi_http.rs、apps/tracker/src/、apps/worker/src/jobs/ledger_guard.rs 等。

3.1认证链路

环节设计与证据
JWT 双算法HS256 要求 secret ≥32 字节否则启动报错（auth.rs:49-53）；RS256 私钥只在 api 进程，缺失 fail-fast 拒绝启动（auth.rs:29-32,126-135）；RS 校验锁死 RS256 防算法混淆，单测锚定「HS 签的 token 不能被 RS 校验」（auth.rs:200-205）
凭证提取Authorization: Bearer 优先，回落 HttpOnly cookie flux_token，多值逐个候选（http/auth_infra.rs:155-188）
撤销线DB token_revocations 与 Redis logout_nbf: 取大者，iat ≤ nbf 拒（auth_infra.rs:191-227）；用户状态以库为准（status≥2 封禁即 Forbidden），5s TTL 缓存 + 管理端主动 invalidate
Cookie 形态path=/ + http_only + same_site=Lax，secure 仅 x-forwarded-proto=https 时置位（auth_http/login.rs:232-248）
页面闸门flux.session 是浏览器可写的非凭证标记（12h），middleware 只做页面准入；真凭证永不经 JS（apps/web/middleware.ts:50、lib/api-client.ts:10-16）；RSC 服务端读 cookie 显式转 Bearer 直连 API（api-client.ts:80-97）
密码哈希Argon2id 默认参数（m=19456,t=2,p=1），OsRng 盐，非法哈希判失败不 panic（domain/mod.rs:31-51）

3.2限流与跨站闸

机制参数与证据
登录双限流用户名 5/min + IP 20/min（独立宽阈防 NAT 误伤）（login.rs:69-75）；账户级 5 连败锁 15 分钟，fail-close 读计数（login.rs:46-60,129-135）；TOTP 失败同样计锁
登录 Origin 闸表单路径无 Origin 放行（非浏览器）、Origin: null 拒、白名单放行（login_origin.rs:21-57）
写跨站闸/api/v1 非 GET：Origin 优先、Referer 兜底（http/write_origin.rs:21-105，挂载 main.rs:269-272）
发种/下载Token 发种 20/min（openapi_http/upload.rs:59-69）；网页下载 20/min（publish_http/download.rs:26）
tracker 限流每用户 1800/min、每 IP 3600/min、全局熔断默认关；stopped 事件 4 倍宽阈独立桶（http_track/guard.rs:158-204）
限流原语固定窗口写进键名；Redis 故障 fail-close（读失败即错误，不当 0）（http/throttle.rs:20-24,67）
metrics 门禁x-metrics-token 或 Bearer 双头；未配置或失败一律 404 不暴露；tracker 侧用定长时间比较防侧信道（v4_http/metrics.rs:55-88、tracker/http_track/metrics.rs:17-59）

3.3CSP 与头

API 端最严形态：default-src 'none'; frame-ancestors 'none' + nosniff + DENY + Referrer-Policy（main.rs:251-265）。Web 端 Next headers 全站 CSP（next.config.ts:18-74）：default-src 'self'、object-src 'none'、form-action 'self'、frame-ancestors 'none'；登录/注册/找回页 no-store。CORS 白名单未配置且非开发态 panic 拒绝启动（main.rs:83）。

3.4Tracker 边界安全

  • 未注册 info_hash 拒绝：白名单快照 O(1) → 60s 负缓存 → DB 兜底（approval_status IN (0,1)）；DB 抖动 fail-open 且不写负缓存（http_track/guard_whitelist.rs:22-71；拒绝点 announce.rs:147-156）——防幽灵种子。
  • 字节层 percent-decode：%00–%FF 全字节手工解码，绕开 UTF-8 反序列化损坏（peers/bencode.rs:107-126）；info_hash 必须 20 字节、port 0..65535、数值超 i64 报错不静默当 0（http_track/params.rs:41-71）。
  • passkey → 用户快照（60s 缓存）：挂起/禁下载即时拦；分享率闸只拦下载（left>0）不拦做种（announce.rs:101-145）。
  • 客户端黑名单：UA 头 + peer_id 双正则交叉，命中经 Redis 去重投 cheat_events（announce.rs:184-206）。

3.5反作弊五层（全场最深的设计）

层机制与证据
① 计费守卫ledger_guard.rs：速率钳（增量 ≤ 秒窗 × credit_ceiling，缺省 128 MiB/s clamp[1MiB/s,1TiB/s]，:96-102,220-227,295-318）；终身上限单种 ≤ size×1000（:109-111）；基线重置三情形（单调跟随 / 双侧 ≤16MiB 才认可重启 / 下降钉死 + refused，:49-91）；24h 内二次近零重置钉死（:163-185）；返回具名 GuardOutcome
② 幽灵做种判定纯函数 + 单测：seeding = left==0 && port>0 && reachable && proven && covered（process_event/seeding_gate.rs:83）；covered = phys_down ≥ size×10.4% 或佐证达标（:75-80）
③ BT 三阶段探测peers/bt_probe.rs：握手 68B 校验 → interested 诱 bitfield → request 随机 piece → SHA-1 比对；哈希不符 = 实锤伪造判 DEAD，拿不到数据返回 None 不判作弊（:193-197,312-315）；探针 peer_id 每次随机防指纹；piece 上界 8 MiB 防畸形分配；预算 clamp(len/8, 50,400)，5min 一轮 + 抖动（probe_loop.rs:17-48）
④ 交叉上报封顶xreport：leecher 为他人背书上传量，物理上界 = 本人 credited 下载 − 已背书（seeding_gate.rs:95-116）；荒谬线默认 10 GiB；超额留痕；入账按 corroborated − 已入账 封顶（process_event.rs:76-113、xreport.rs）
⑤ connectable 四档-1 未测 / -2 SUSPECT（加密客户端、白名单、CGNAT——不误伤）/ 0 DEAD / 1 OK；仅 DEAD 阻断收益（peers/model.rs:11-31）；connectable_gate 缺省 off，hard 才一票否决（0308、seeding_gate.rs:133-168）
设计判断（强度：强）

反作弊体系最难的不是「抓」，而是「不误伤」：三阶段探测把「验不了」与「造假」严格分开（None ≠ DEAD）；SUSPECT 单列一档不惩罚；freeleech 下 credited down 恒 0 时改用 raw 读数（10.4% 不变量须用原始 raw 而非 credited）。这套口径在通用站场景下是必要的克制。

3.6RBAC

权限 = 用户级覆盖（可显式拒绝）> 角色权限（class 累进 ∪ 职务）（0055/0056 语义，实现 authz.rs:28-44 下沉 SQL 函数 user_can(uid, perm)）。管理端守卫 = require_auth + require_perm(STAFF_PANEL)（admin_http/guard.rs:9-17）；ensure_outranks 要求操作者等级严格大于目标（guard.rs:19-39，修复过 93 档可封 94/95/99 的缺陷）。

4.2邀请体系

  • 邀请链：users.invited_by + invites 表（0001:43-50）；注册单事务完成「建号 + 耗码 + 绑邀请人」，耗码 SQL 带三重条件（未用 + 未过期 + 邀请人未被封）（repo/auth.rs:101-137）。
  • 周配额原子占位：invite_quota 表（0010）INSERT ON CONFLICT + UPDATE ... WHERE used < quota，防 count+insert 并发穿透；class≥3 默认 2/周，持 invites.bonus 权限 4/周（invite_http.rs:58-71,192-215）。
  • 定向邮件邀请：码绑目标邮箱防转发滥用；邮箱策略 + email_bans + SMTP/PUBLIC_WEB_URL 缺失拒发（invite_http/email.rs:19-153）。
  • 封禁联动：status=2 封禁时该用户名下未用未过期码全部作废——「信任链在封禁动作上不能断开」（admin_http/user_status.rs:132-148）。
  • 商品化：商店 invite 商品定价 50000 火花（0281，注释说明恢复高定价的准入属性理由）；撤销不返还配额；管理端可直发 1–50 枚（默认 30 天）。

4.3考核：exam+task 合并式，指标型而非答题型

关键事实澄清（强度：强，来自 0093 与全仓 grep）

考核没有题库、没有问题选项表、没有答题交互。0093 起考核与普通任务合并为 tasks 单表（kind = task / onboard / periodic，auto_assign，period = once/monthly/quarterly），进度指标是 JSONB 六键（upload_delta / download_delta / seed_points_delta / seed_seconds_delta / uploads / subtitles）。「考核通过即升级」不成立：reward.rs:61-62 明确转正只确认 + 发奖，不动 class_id；target_class 是领取门槛而非晋升目标（task_overview.rs:192-196）。
