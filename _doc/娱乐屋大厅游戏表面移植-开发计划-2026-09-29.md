## 0. 一句话目标

让 `/games` 娱乐屋页下半部拥有**真数据驱动**的：纹章预算环、周常任务条、票根册、赛季星轨、外观货架；并把原型 `checks()` 里那套「EV 三口径 + 确定侧发放闸」做成**服务端校验 + 运营面板**，而不是前端玩具。

## 2. 必须从原型继承的设计原则（不继承 = 埋雷）

| # | 原则 | 原型出处 | 违反后果 |
|---|---|---|---|
| ① | **随机侧 / 确定侧分账**，合起来才是真净回收 | `ledger()` | 只看奖池一侧会算出假回收 |
| ② | **EV 三口径同时 < 1**：登记价 / anchor 权威折算价 / 库存耗尽回落 | `economics()` + `checks()` | 压低登记价即可绕过守卫（后门②） |
| ③ | **确定侧发放闸 = 第二道闸**：EV 闸只管随机侧，周常/赛季绕得过它 | `BUDGET` + `checks()`「确定侧发放在预算内」 | 周常改发「免考核卡」就是侧门（后门⑤） |
| ④ | **负债按 anchor 记**，不按奖池登记价 | `grant()` 行 329 | 登记价可改小，anchor 不可改 |
| ⑤ | **经济类物品必须有每人上限 + 全服库存** | `checks()`「经济类物品必须有每人上限」 | 无限刷（后门①③） |
| ⑥ | **一档一张独立主图，不共用** | `ART_BY_RARITY` + 守卫 | 玩家读不出稀有度差异 |
| ⑦ | **票根持有数与点亮态解耦** | `renderAlbum` 注释 | 分解重复卡会让卡重新变灰 |
| ⑧ | **清单 DOM 守卫**：读真实渲染子节点，不读渲染时写的快照 | `checks()` 行 436–442 | 清单漏渲染发现不了（后门④） |
| ⑨ | **券独立账本、不可购买/不可转让** | `GACHA.note` + `grant()` 行 331 | 玩法变成抽卡免费印券机 |
| ⑩ | 回收率可隐藏（`showEv` 岔路③），但**三口径仍须同时 < 1** | `renderPools` | 隐藏回收率≠可以 EV 倒灌 |

## 3. 目标架构

```
娱乐屋页 /games (生产已有四卡网格)
 └─ <ArcadeMetaPanel>            ← 新增，下半部游戏表面
      ├─ <CrestPanel>            纹章预算环（detCost / budget）
      ├─ <WeeklyQuests>          周常任务条（可领整条泛虹彩）
      ├─ <StampAlbum>            票根册（复用 gacha-album 的 .stk；locked 压灰雕版）
      ├─ <SeasonTrack>           赛季星轨（.node 节点，2/4 点亮）
      ├─ <AppearanceShelf>       外观货架（零负债角标 + 库存条）
      └─ <GateBadge>             门禁自检（10 检，红则阻断原因）
```

- **前端数据**：单聚合接口 `GET /api/v1/games/arcade-meta` 返回 `{ ledger, quests, season, stubs, shelf, checks, feed }`；领取走 `POST`。
- **后端**：新增 `apps/api/src/games_http/arcade_meta.rs`；`checks()`→`games.rs::ev_gate`（服务端权威）；复用 `games.rs` 已有 play 结算与 `gacha_http` 的券账本。
- **样式**：并入 TIDE 设计系统令牌（`app/styles/layout.css` 的 `--surface-card` / `--grad-aurora` 等），**不**写 `arcade.css` 那套独立类（除非作为迁移期参考）。
- **i18n**：三/四语字典新增 `adminArcade` / `arcadeMeta` 命名空间（遵循仓库 i18n 纪律：先跑 `_admin_i18n_audit.py`）。

## 4. 数据模型与迁移

基于原型 `S / ITEMS / QUESTS / SEASON / STUBS / BUDGET / ledger()` 抽取：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `play_quests` | id, key, game, label, target, give_item, give_n, period(weekly) | 周常/成就（原 `QUESTS`） |
| `user_quest_progress` | user_id, quest_key, done, claimed, period_no | done 由玩法事件累加 |
| `season_milestones` | id, season_key, label, need_stubs, give_item | 原 `SEASON.milestones`（need 3/6/9/12） |
| `user_season` | user_id, season_key, got_milestones[], claimed_at | 到达即点亮（原 `m.got`） |
| `stub_album` | stub_key, name, tier, holders, obtained | 票根册（原 `STUBS`） |
| `user_stubs` | user_id, stub_key, obtained_at | 持有/点亮态 |
| `appearance_items` | key, name, icon, value, anchor, stock, per_user, kind, src | 原 `ITEMS`（kind: economic/collectible/voucher） |
| `user_inventory` | user_id, item_key, qty, per_user_count | 每人持有/上限 |
| `ledger_daily` | day, magic_back, rand_cost, det_cost, net, season_key | 原 `ledger()`，按窗口聚合 |
| `arcade_feed` | id, at, who, what, from | 全服公示（原 `feed`，仅经济类物品） |

**财务常量**（原 `BUDGET`）：`base=1500`、`pct=0.20`、`windowDays=7`；`anchor` 由 `appearance_items.anchor` 权威给定，`src∈{shop,derived,declared}` 中 `declared` 视为高风险（原则④）。

> **迁移号避让**：建文件前先 `ls apps/api/migrations/*.sql` 查最大号从 +1 起；建号后立刻 `docker compose build api`（本仓已撞号 4 次）。

## 5. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/games/arcade-meta` | 聚合：ledger + quests + season + stubs + shelf + checks + feed |
| POST | `/api/v1/games/quests/{key}/claim` | 周常领取（校验 done≥target；计入 det_cost） |
| POST | `/api/v1/games/season/{milestone}/claim` | 里程碑领取（校验 ownedStubs()≥need） |
| GET | `/api/v1/games/season/track` | 星轨节点 + 点亮态 |
| GET | `/api/v1/games/stubs/album` | 票根册 + 持有/点亮 |
| GET | `/api/v1/games/appearance/shelf` | 货架 + 零负债角标 + 库存条 |
| GET | `/api/v1/games/ev-gate` | 运营/调试用：三口径 EV + 10 检（权限 gate） |

所有发放路径**复用** `games.rs::grant`（anchor 负债记账、券独立账本、库存/每人上限→FALLBACK），不得各页各抄一份（原则⑧、⑨）。

## 8. 风险与已知坑（原型复盘）

**样式 bug（前端必踩）**
- bug① `.tray/.gframe` 合并选择器带 `width:min(560px,100%)` → 描金框被限 560px；合并时把尺寸类属性摘出。
- bug② `.medal→.node` 只改节点类没改容器类 → 星轨无样式；探针 `nodes:0` 才暴露；节点/容器类一起改。
- bug③ 绶带牌写 `赛季钥匙 ×${SEASON.key}`（key='S12'）→ 假数量；改 `赛季 S12 · 轨迹 2/4`，由 `ownedStubs()` 与里程碑阈值派生。

**设计/数值风险（服务端必守）**
- 确定侧侧门：周常/赛季发经济类物品（免考核/补签/银行券）绕过随机侧 EV 闸 → 必须过确定侧发放闸（原则③）。
- 折算价来源可信：`src='declared'` 或 `value < anchor*0.5` 一律视为后门，门禁必红（原则④）。
- 库存/每人上限回落：触顶/耗尽走 FALLBACK 档，EV 按回落口径重算（原则②）。
- 蒙特卡洛对照：`simulate()` 用多条独立种子流池化，`z≥2` 才判「对不上」，单条种子可能撞 3σ 抖动（原 `simulate` 注释）。
- 回收率隐藏（岔路③）：玩家端可只显示票面与物品，但服务端三口径仍须同时 < 1。

**工程风险**
- 迁移号撞车（本仓已 4 次）→ 建号前查最大号、建号即 build。
- SSR 直出：聚合接口失败降级为空态，客户端再拉（参考首页 `HomeSections`）。
- 缓存：`arcade-meta` 含实时 ledger，短 TTL（参考 `cache:tlist:v2` 20s 口径），非 viewer 视角共享缓存。
