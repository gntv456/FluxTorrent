## 0. 现状核对（先说清楚"为什么只有 3 个"）

读代码确认，不是拍脑袋：

- **大厅页** `apps/web/app/(main)/games/page.tsx` 实际渲染 4 张玩法卡：`scratch`(刮刮乐)、`bigsmall`(猜大小)、`jgg`(九宫格)、`farm`(农场)。
- `farm` 卡受模块开关约束：`cardMod = { "/games/farm": "farm" }` → `.filter(c => mod(cardMod[c.href] ?? "games"))`。`mod("farm")` 取 `profile.modules["farm"] !== false`。**你的部署里 `farm` 模块没开 → 只显示 3 张**，这就是"只有 3 个游戏"的根因，不是少做了。
- `/games/odds` 是**概率公示页**（L3 透明披露），不是游戏；`/games/fun` 之类不存在。
- **趣味盒 `FunBox`**（`apps/web/components/fun-box.tsx`）当前以 `<FunBox embedded />` 嵌在大厅底部（`page.tsx:156`）。它是旧站 `fun.php` 复刻：用户发段子、他人投 😂/😑 票 —— **社交功能，不是下注玩法**，不该占娱乐屋的"游戏"位。
- 后端游戏 handler 全集（`apps/api/src/games_http/mod.rs`）：`casino.rs`(scratch/bigsmall/jgg)、`farm.rs`+`farm_egg.rs`、`fun.rs`(投票)、`arcade_*`(大厅表面/周常/赛季/货架/背包)。
- 奖池已**行表化 + 站长可配**：`arcade_pools` / `arcade_pool_entries`（`0242`/`0244` 迁移），保存走 `POST /admin/arcade/pool`（`arcade_admin_write.rs`），写侧带 EV 闸 + 机制闸（猜大小 49/2/49）。**刮刮乐奖励本来就是站长可随意配的**，本方案不重造，只补"展示元数据 + UI 动效"。

## 1. 目标与原则

1. **猜大小 = 只输赢魔力**：赢区/平局/输区全部是魔力位，不再直接发物品（免考核卡等改为"道具加权"实现，见 §2）。
2. **道具只做加权**：道具（倍率券/护盾/幸运符）在下注时挂载，仅改变本局魔力的输赢幅度，绝不变成"另一种奖品"。
3. **刮刮乐奖励站长可配**（已具备）+ 补财神式**展示层**（稀有度/图标/标题/回落值）与**刮卡动效**。
4. **大厅 9 个游戏**：4 个已有（scratch/bigsmall/jgg/farm）+ 5 个新增（抽卡/宠物/钓鱼/扭蛋/大转盘）；大厅改**注册表驱动**，加游戏不再改大厅代码。
5. **趣味盒移出娱乐屋**：保留功能，挪到独立页面 `/fun`，大厅不再嵌入。
6. 全程守既有纪律：统一魔力交易管线、EV<1 回收口、幂等、限次、i18n 零硬编码、行宽 ≤80、契约门禁。

## 2. 模块一：猜大小「纯魔力 + 道具加权」

### 2.1 后端改动

**a) 猜大小池改为纯魔力**
`apps/api/src/games_http/pool.rs::load_table` 已支持 `kind=magic|item`。现状 bigsmall 池若含 `item` 档（如赢区挂免考核卡），需：
- 迁移把 bigsmall 现有 `item` 档转成 `magic` 档或删除；之后 bigsmall 池只允许 `magic` 档。
- 在 `load_table` 或写侧 `arcade_admin_write.rs` 增加一道闸：**`game='bigsmall'` 时拒绝 `kind='item'` 的条目**（机制决定纯魔力，配错即拒）。`settle`（`casino.rs`）对 bigsmall 永远走 `Magic` 分支，`earn_spark` 入账。

**b) 道具加权模型（新增）**
复用现有 `arcade_items` 物品管线，新增"游戏修饰"类道具：

- `arcade_items` 增加列 `game_effect jsonb`（可空）。一个道具若是游戏修饰，`use_kind` 设为 `'game'`，`game_effect` 形如：
  ```json
  { "game": "bigsmall", "effect": "mult",   "value": 2.0 }   // 倍率券：赢时魔力 ×2
  { "game": "bigsmall", "effect": "shield", "value": 0.5 }   // 护盾：输时返还 50% 注额（魔力）
  { "game": "bigsmall", "effect": "luck",   "value": 0.03 }  // 幸运符：赢区权重 +3%（高级，见 2.4）
  ```
- 持有数仍走 `arcade_item_held` 视图（发放账 − 消耗账），与现有物品同口径，不另存一份。
- 消耗走现有 `arcade_item_uses` 表（加 `game`/`round_id` 字段以便对账）。

**c) 下注接口扩展**（`POST /games/bigsmall`，`casino.rs::guess_bigsmall`）
请求体加 `props: string[]`（挂载的道具 key，可空）。在一笔事务内：
1. 校验每个 key：`arcade_items` 存在、`enabled`、`use_kind='game'`、`game_effect->>'game'='bigsmall'`、持有数 ≥ 1。
2. 扣减道具（写 `arcade_item_uses`，与 `grant_item` 同事务、同幂等纪律，防并发双扣）。
3. 出号后按 `game_effect` 修正魔力结算：
   - `mult`：仅当 `player_win` 时 `payout = floor(payout × value)`；平局/输不生效。
   - `shield`：仅当 `side=='lose'`（且非平局）时 `net += floor(bet × value)`（返还魔力，记为 `shield_refund`）。
   - `luck`：在下注**前**改写本局赢区权重（见 2.4），影响出号概率。
4. 响应新增 `props_applied: [{key, effect, value}]`、`shield_refund`、`effective_mult`，前端据此渲染。

> 关键约束：**道具永不发物品、只动魔力**。结算出口仍是 `earn_spark`（赢/返还）与注额抵扣（输），与现有管线完全一致。

### 2.2 前端改动

`apps/web/app/(main)/games/bigsmall/_inner.tsx`：
- 新增**道具选择区**（参考好学 `bigsmall.js` 的 `bs-prop-select` + `bs-prop-grid`）：从 `/api/v1/games/bigsmall/props`（或扩展 `arcade-meta`/`backpack`）拉取 `usable_in_bet` 道具，展示图标+持有数，可勾选挂载。
- 下注时把选中的 `props` 一并提交。
- 结果弹层补"道具生效"提示（如「护盾返还 50 魔力」「倍率券 ×2」），参考好学 `showMyResult` 的 `propHint`。
- 保留现有跑道减速定格 + 路单；可选加参考好学的**加成倍率徽标**（`bonus_rate`）。

### 2.3 参考：好学/熊猫的猜大小布局

好学 `games/bigsmall/bigsmall.js` 要点（本地可读，直接复刻其交互骨架）：
- 大/小两个主按钮 + 金额输入 + 梭哈 + 追加下注；
- **道具下拉 `bs-prop-select`** + 道具九宫格弹窗（`bs-prop-item`），`usable_in_bet` 标记哪些能下注时用；
- 亏返卡 `bigsmall_loss_refund`（按昨日亏损返还）—— 对应本方案的 `shield` 思路；
- 走势圆点 `bs-trend-dots`、排行榜、聊天、红包（社交层，本期**不搬**，仅借布局灵感）。
熊猫站点（用户给的 cookie）布局思路同好学，如需像素级对齐可在确认后由其 cookie 拉取页面核对；**不影响本方案落地**，列为可选。

### 2.4 经济/风控守卫（必须做）

- 道具是**稀缺资源**：只能经 EV<1 的奖池或确定侧预算发放，否则玩家免费拿倍率券会击穿 EV。
- 在 `arcade_meta.rs` 的 `checks` 增加一条：「bigsmall 道具加权不突破站点回收口」—— 校验近窗道具发放成本纳入 `arcade_budget_*` 预算。
- `luck` 类（改概率）需同步改服务端 `outcome_side` 权重，且**必须**在 `validate_bigsmall` 之外单列上限（赢区权重不可无上限抬高），建议首期**只上 mult + shield**，luck 作为二期。

## 3. 模块二：刮刮乐「站长可配 + 财神式 UI」

### 3.1 确认：奖励本就可配

`arcade_pools(game='scratch')` + `arcade_pool_entries`（`kind=magic|item`）+ 写侧 EV 闸，站长在 `/admin?tool=arcade` 配池即可。**"奖励站长随意配置"在数据与后端层面已经满足**，本模块重点是把它"长得好看 + 动得漂亮"。

### 3.2 展示元数据扩展

财神 `ScratchCardRepository` 的亮点：`rewardDisplayList`（图标 URL + 标题）、`reward_rarity`（稀有度）、`reward_num`/`reward_conversion`（奖品数/回落值）、奖励类型多达 元宝/上传量/补签卡/勋章/卡包/不中奖。对应扩展 `arcade_pool_entries`：

- 增加列：`rarity smallint`（1–5，对应 财神 rarity）、`image_url text`（奖励图标，复用 `arcade_items.icon` 或外链）。
- 现有 `arcade_items`（economic/voucher/cosmetic）已覆盖财神的"元宝=魔力 / 上传量=sku / 补签卡=sku / 勋章=sku / 卡包=collect"映射，无需新建奖励类型，只需把展示信息接到条目上。
- 写侧 `arcade_admin_write.rs::PoolEntryReq` 增加 `rarity`/`image_url` 字段并落库；`load_pool` 投影带回前端。

### 3.3 前端 UI / 动效（参考财神）

- `apps/web/components/game/scratch-canvas.tsx`：增强刮卡动效——刮开过半自动揭晓（已有）、**中奖稀有度光效**（按 `rarity` 上色）、金光/纸屑（`confetti`）动画、未中奖温和反馈。
- `games/scratch/_inner.tsx` 揭晓层：按 `rarity` 显示**稀有度徽标** + 奖励图标 + 标题（替代当前纯 `multiplier x` 数字），对齐财神 `reward_img`/`reward_title` 的"好看"观感。
- 大厅刮刮乐卡（`page.tsx` 的 scratch 卡）角标与 `/games/odds` 公示页：补稀有度图例。
- 可选：参考财神 `getRewardMsg` 的"全服稀有掉落播报"，接 `arcade-meta` 的 `feed`（已有全服票根/领取事件流）。

> 不引入外部图片依赖风险：图标优先用项目已有 `arcade_items.icon`（emoji）或 `public/games/` 本地资源，外链 URL 仅作可选填充。

### 4.1 大厅注册表驱动（关键架构改动）

把 `page.tsx` 里硬编码的 4 张卡改成读注册表，新增游戏零改大厅：

- 新增表 `arcade_games`：`key, title_dict_key, icon, href, module_gate, sort, visible`。
  默认值播种 9 行（见 4.2）。
- 大厅读 `SELECT ... FROM arcade_games WHERE visible ORDER BY sort`，拼接角标（角标数据仍来自 `/api/v1/games` 概览，与现在一致）。
- **顺带修掉"只有 3 个"**：`farm` 行 `module_gate='farm'`，大厅渲染时 `mod(gate)` 判定；或把 `farm` 默认 `visible=true` 并在站点设置里默认开启 `farm` 模块。二选一，推荐后者（配置即开关，不改代码）。

### 4.3 五个新游戏的机制草图

- **扭蛋机 gacha**：完全复用 `draw_entry`+`settle`。新增 `arcade_pools(game='gacha')` 池（magic/item 档，EV<1）。前端胶囊掉落动画（`games/gacha/_inner.tsx`）。零新机制，仅页面+动画+池种子。
- **抽卡 draw**：池抽复用；额外加**卡牌收藏**层——抽到的卡记为 `collect` 类 `arcade_items`（或独立 `arcade_card_codes` 表），`user_card_collection(user_id, code, dup)` 记录图鉴与重复数；页面含「图鉴」页签。二期可让特定卡给被动加成（如 +1% 猜大小 mult），首期只做收藏展示。
- **大转盘 wheel**：池抽复用；前端转盘旋转动效（`games/wheel/_inner.tsx`），落点=加权抽中的条目。零新机制。
- **宠物 pet（有状态）**：新增 `arcade_pets(user_id, species, level, exp, hunger, last_feed_at, last_yield_at)`。
  - 喂食：扣魔力（`spend_spark` kind='pet_feed'），`hunger`↓、`exp`↑；满 exp 升级。
  - 产出：访问时按 `now()-last_yield_at` 结算累计产出（魔力/限定物品），封顶防刷；EV 必须 <1（产出经 `arcade_budget_*` 或池 EV 闸守）。
  - 死亡/饥饿：纯展示惩罚，不扣已得资产（避免争议）。
- **钓鱼 fishing（计时）**：`POST /games/fishing/cast` 扣「鱼饵」(魔力) 并开一局，返回 `bite_at`（now+随机 3–8s）；前端在 `bite_at` 附近弹「上钩！」窗口，`POST /games/fishing/reel` 在窗口内提交=成功（加权池抽鱼/魔力），超时/过早=跑空（鱼饵白扣）。幂等 + 限次同现有玩法。

### 4.4 趣味盒移出娱乐屋

- 保留 `FunBox` 组件与 `fun.rs` 后端（投票功能本身有价值）。
- 从 `games/page.tsx` 删除 `<FunBox embedded />`。
- 新建独立页 `games/fun/page.tsx`：`requireModule("games")` 后渲染 `<FunBox />`（非 embedded 模式，自带标题/返回），并导航栏或大厅底部放一个低调文字链「趣味盒 →」指过去——**不再占游戏网格位**。
- 不动 `fun_polls`/`fun_vote` 接口；`FunBox` 的 `embedded` 分支可保留供其他页（如社区）复用。

### 4.5 `/games/odds` 处理

概率公示页合法且必要（L3 透明），**保留**，继续作为大厅底部低调链接。若觉得与游戏混排乱，可归入"规则"区而非游戏区——不影响功能。
