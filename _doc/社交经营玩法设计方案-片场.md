# FluxTorrent 社交经营玩法设计方案：《片场》

> 起点：熊猫站（pandapt.net）《好友买卖》功能逆向研究（见 `_doc/熊猫站好友买卖功能深度研究.md`）
> 目标：保留"玩家之间的社交经营"这一赛道，但把不好玩的部分换掉
> 适用：FluxTorrent 通用 PT 站（机器与站点真实行为数据耦合），可 `theme` 参数化

---

## 一、诊断：熊猫版为什么不好玩

不是数值没调好，而是**三个根上的设计问题**：

### 1. 参与是被动的 → 负向社交

市场 911 人里 **87% 已被持有**。你不需要同意，就可能成为别人的"佣人"。

- 被买的人得到的是**羞辱感**，不是游戏乐趣
- "被玩"不产生参与感，只产生被冒犯感
- 系统靠"人盯人的社交压力"（挖角/追回/被放生会发站内信）维持活跃 —— 这是**用负情绪驱动留存**，短期有效、长期伤站

**检验标准**：如果玩家 A 的乐趣来自玩家 B 的不快，这个设计就是在消耗社群信任。

### 2. 玩法是日课，不是抉择

每天固定动作：领收益 → 安排工作 → 互动 → 放映 5 局 → 收委托。

- 15 种工作、4 种互动、3 个放映游戏，**没有一个需要取舍**
- 所有选项都是"哪个期望收益高选哪个"，算完就没有第二次决策
- 没有风险、没有代价、没有谈判、没有信息不对称

**检验标准**：玩家能不能在两次操作之间做出**他自己会后悔或庆幸**的选择？熊猫版不能。

### 3. 与站点真实行为完全脱节 → 零和抽税

这是最致命的一条。你在游戏里买卖人、养佣人、抽海报，**跟你的做种量、分享率、发布贡献没有任何关系**。

- 整个系统的产出是"无中生有的魔力值"，玩家之间互相转移，系统在中间抽 8%
- **零和偏负和**：整体不创造新价值，只决定"谁更会玩"
- 于是它只能靠"抽水出口"（槽位/维护费/研修/拍卖手续费）来回收通胀 —— 本质是**给魔力值加了个税种**，而不是创造新的玩家价值

**检验标准**：这个系统关掉之后，站点的做种/发布数据会有任何变化吗？熊猫版：不会。

### 4. 附带的三处浪费

| 问题 | 实测证据 |
|---|---|
| 市场设计出来但没人交易 | 抽水 8% + 身价 ×1.15 + 每日 5 次上限三者叠加，倒手无利可图；市场身价全在初始 10,000 附近 |
| 等级线被架空 | 连 class 12 管理组在内全站都是 Lv.1 / 0-80 EXP；Lv.1→2 要 80 EXP，放映一局才 8~25 EXP —— Lv.6 事务所、Lv.15 双人队实际上不可达 |
| 线性永久成长 | Lv.1→100 不可逆不可重置，新人永远追不上；老人到顶就没目标 |

## 二、三条转换原则

| 熊猫版 | 改成 | 为什么这样更好玩 |
|---|---|---|
| **占有他人**（被动、羞辱、无限期） | **自愿结盟**（主动报名、有期限、可退出） | 参与感是一切乐趣的前提 |
| **点一下就收益**（无决策） | **有代价的抉择**（取舍、风险、谈判） | 好玩的不是结果，是选择本身 |
| **孤立小游戏**（只连货币） | **真实站点行为是唯一产出引擎** | 游戏奖励真实贡献 → 正循环 → 反哺站点生态 |

## 三、主方案：《片场》（Production Crew）

### 3.1 一句话

把"买人当佣人"改成"**组剧组拍片**"：玩家自愿报名进组、用**真实做种/发布行为**推动片场进度、按贡献分账、每赛季结算重置、成就沉淀为荣誉。

### 3.2 角色设计（三层，都可自由选择）

| 角色 | 门槛 | 职责 | 收益结构 |
|---|---|---|---|
| **出品人** | 高信誉 + 魔力值出资 | 发起片场、定目标、招募、分配资源 | 分成最高，但**承担亏损风险** |
| **主创** | 中信誉 | 报名并认领岗位（导演/摄影/剪辑/配乐/美术） | 岗位系数 × 贡献占比 |
| **群演** | 无门槛 | 低强度参与，稳定小额产出 | 固定小额，适合新人试水 |

关键差异：**你永远是自愿进入的，且合约有档期**（详见 3.4）。

### 3.3 核心机制：真实站点行为是唯一产出引擎

**这是整个方案最重要的设计**。片场进度条不由"点击"推动，而由成员在站点上的**真实行为**推动：

| 岗位 | 真实行为要求 | 产出贡献 | 特殊效果 |
|---|---|---|---|
| **摄影** | 本周保种时长 / 有效上传量达标 | 片场进度 +X% | 稳定主力，收益曲线平滑 |
| **剪辑** | 发布种子 / 字幕 / 整理资源 | 进度 +Y% | 提升成片"技术分" |
| **配乐** | 论坛发帖、答疑、求种应求 | 进度 +Z% | 提升成片"人气分" |
| **美术** | 保种**低做种数**的冷门种子 | 进度 +W% | **唯一能开出"传说"成片的岗位** |
| **导演** | 协调进度、分配资源、处理突发事件 | 全队收益 +% | 需要高信誉，管理属性 |

由此得到几个自然结果：

1. **玩这个游戏 = 在站点上做贡献**。它不再是外挂小游戏，而是站点生态的**奖励层**。
2. **岗位互斥产生真实取舍**。去做"美术"（保冷门种）就没法做"摄影"（冲上传量）；每人同期只能在一个片场。**玩家必须选**。
3. **天然反刷**。刷游戏就是刷站点贡献，没有套利空间 —— 熊猫版要靠每日次数上限硬堵，这里从机制上就不成立。
4. **这是熊猫做不到、而 FluxTorrent 做得到的**：tracker 的保种/做种/上传数据就在自己手里，采集与校验成本极低。

### 3.4 谈判机制（把"点一下"换成"谈一轮"）

报名不是即时的，是一次**真实的博弈**：

- 主创报名时**报价**：希望分多少成
- 出品人可**接受 / 还价 / 拒绝**
- **报价过高没人要，报价过低自己亏** —— 信息不对称 + 双向选择
- 出品人能看到候选人的**真实数据**（近 30 天做种时长、分享率、历史片场评级），需要判断"这人靠不靠谱"
- **违约机制**：中途退出或未完成承诺按比例扣信誉分，并影响下一次被选中的概率

**这是熊猫完全缺失的一层**：它的所有操作都是确定性的收益计算，没有任何博弈深度。

### 3.5 赛季制（解决"线性永久成长"）

| 项 | 设计 |
|---|---|
| 赛季长度 | **4 周**一轮 |
| 季末 | 进度归零，重新开始 |
| 主题轮换 | 科幻季 / 恐怖季 / 纪录片季 / 黑白片季……**每季换规则与加成**（如"纪录片季：冷门保种贡献 ×1.5"） |
| 荣誉传承 | 上季成就沉淀为**永久徽章/称号**（纯展示，不影响数值） |
| 新人友好 | 新玩家与老玩家**同一起跑线**；老玩家的优势是"更懂规则"，不是"数值碾压" |
| 目标感 | 每季有新主题 → 不会出现"爬到顶就没目标" |

### 3.6 信誉系统（替代"身价"）

熊猫的"身价"是投机品（可以买卖、可以炒作）。改成**不可交易的积累值**：

**信誉分来源**
- 按时完成片场承诺（主要来源）
- 长期真实的分享率与保种表现
- 被队友好评（每季有有限的评价次数，防止互刷）

**信誉分用途**
- 决定能接什么级别的片场
- 决定能不能当出品人（发起权）
- 解锁稀有岗位（如"美术"需要一定信誉）

**信誉分消耗**
- **只有违约会掉**：中途退出、未完成承诺、被队友差评

**效果**：熊猫版"被挖角"的焦虑彻底消失，取而代之的是"**我想被好导演选中**"的正向追求。

### 3.7 产出与评级（保留收集快感，但改成可努力）

不用 0.5% 抽卡，改成**"成片评级"**：

```
片场完成 → 汇总全队真实贡献分 → 综合评级（技术分 + 人气分 + 完成度）
         → 评级决定开出什么"成片"（稀有度）
         → 最高档 = "影史经典"
```

- **评级是可努力的**，不是纯随机：选对岗位组合、协调好档期、按期完成，就能冲高评级
- 保留一点随机性作为惊喜：**黑马机制**（冷门题材有概率爆款，给"美术"岗位额外期待）

### 3.8 经济设计（正和，且反哺站点）

| 环节 | 设计 |
|---|---|
| 产出从哪来 | 片场完成时由系统**发行**魔力值（真正的增量），而不是从其他玩家身上转移 |
| 发行量锚定 | 锚定**全队真实贡献总量**（保种时长/上传量/发布数）—— 贡献多少，发行多少 |
| 系统回流 | 出品人出资的保证金、违约罚金、稀有道具手续费 |
| 与熊猫的本质区别 | 熊猫是"玩家互转 + 系统抽税"（零和）；这里是"贡献换发行"（正和），**且发行量由真实行为背书，不会凭空通胀** |

**这一点非常重要**：它把"魔力值通胀治理"从"加税"变成了"**按贡献发行**"—— 通胀的根源是"做种产出魔力但没有出口"，这个设计让魔力值的产出与站点价值直接挂钩。

## 四、备选方案（改造深度递减）

### 备选 A：《艺人工会》—— 最小改动版

保留熊猫的"买卖"框架，只改三处：

1. **自愿挂牌**：玩家可自行上架/下架，不被强制卷入
2. **合约有期限**：到期自动恢复自由身，不是无限期占有
3. **被买者拿分成**：收益按比例分给本人（不再是被剥削方）

**改动量最小，能复用熊猫约 80% 的后端结构**（槽位/收益/工作/互动全保留）。适合"想快速上线、先跑通数据"的路线。缺点是核心的"零和"没解决。

### 备选 B：《片酬竞拍》—— 保留刺激，去掉占有

把交易对象从"人"改成"短期产能分成权"：

- 每周仅少数玩家"上拍"（自愿报名）
- 买家竞拍的是**他们本周的产能分成权**，不是人身
- 拍完即止，无长期绑定

保留了竞价的刺激感，去掉了人身占有。适合"市场热度优先"的路线。

## 五、给开发者的落地路径

### 5.1 可直接复用熊猫做法的部分

| 熊猫实现 | 复用建议 |
|---|---|
| 槽位式容量限制（正式/临时/维护费） | 改造成"档期槽位"：同期只能参与 N 个片场 |
| 每日次数限制（Redis 计数） | 直接复用做"每日报名/还价次数" |
| 评级倍率表（C→SSS，75%~220%） | 直接复用做成片评级倍率 |
| 任务板 / 赛季任务 | 复用做"赛季主题任务" |
| 幂等提交（`request_uuid` + 原编号重试） | **必须复用**，谈判/结算涉及真实资产 |
| 服务端下发全部数值配置 | **必须复用**，赛季换规则要能不发版就生效 |
| 批量操作（按等级分组配置） | 复用做出品人的批量处理工具 |

### 5.2 必须新写的部分

| 模块 | 说明 | 难度 |
|---|---|---|
| **真实行为采集与校验** | 从 tracker / 保种记录聚合到片场进度。**这是整个方案的地基** | 中（数据在手，成本低） |
| 报价谈判状态机 | 报名 → 报价 → 还价 → 成约 / 拒绝 / 超时 | 中 |
| 赛季生命周期 | 赛季开启/结算/重置/荣誉沉淀 | 中 |
| 信誉分体系 | 计算、扣减、申诉 | 低 |
| 成片评级与产出结算 | 贡献汇总 → 评级 → 发行 | 中 |

### 5.3 建议的 MVP（2 周可验证）

**不要一次做完**。先做最小闭环，验证一个核心假设：

> **玩家会不会为了这个游戏，去站点上多做种？**

MVP 范围：

1. **只做两个岗位**：摄影（上传量）、美术（冷门保种）
2. **4 人小队，1 周一轮**（不做赛季，先跑通）
3. **产出只给魔力值 + 徽章**，不做成片/海报/拍卖
4. **不做谈判**，报名即入组，先验证"真实行为 → 游戏产出"这条链路通不通
5. 埋点重点：**参与玩家的做种时长/上传量，相比未参与玩家的变化**

如果第 5 条数据显著为正，再投入做谈判、赛季、评级、拍卖。如果为负或持平，说明"游戏激励真实行为"这条假设不成立，及时止损，回到备选 A。

### 5.4 主题参数化（结合 FluxTorrent 通用站定位）

"片场"是影视站的皮，但**结构完全通用**（协作 + 真实行为驱动 + 赛季）：

```toml
[production]
enabled = true
theme = "film"        # film | music | book | education | generic
season_weeks = 4
roles = ["camera", "editor", "score", "art", "director"]
```

| theme | 外层叙事 | 产出物 |
|---|---|---|
| `film` | 片场 / 剧组 | 电影成片 |
| `music` | 乐队 / 录音棚 | 专辑 |
| `book` | 编辑部 / 出版组 | 出版物 |
| `education` | 课题组 / 教研组 | 课程成果 |
| `generic` | 项目组 / 工作室 | 抽象成就 |

**机制不变，只换素材表与文案表**。

## 六、顺带解决的两件事

### 6.1 合规风险归零

熊猫版的措辞（佣人 / 娇宠 / 暖床 / 大保健）无法上正规站型。本方案的核心设定是**自愿、协作、有期限的"剧组"**，文案层天然干净，可直接用于教育站、音乐站等场景。

### 6.2 反作弊简单得多

熊猫要在"玩家互转"里堵套利（每日次数、追回资格、包养窗口……规则页里一大半篇幅都是反套利条款）。

本方案的产出锚定真实行为，**套利空间从机制上就不存在**：想多赚就得多做种。规则可以写得极短。

## 七、方案对比总结

| 维度 | 熊猫版 | 备选 A（艺人工会） | 备选 B（片酬竞拍） | **主方案（片场）** |
|---|---|---|---|---|
| 参与方式 | 被动被买 | 自愿挂牌 | 自愿上拍 | **自愿报名** |
| 社交性质 | 负向（占有） | 中性（雇佣） | 中性（交易） | **正向（协作）** |
| 决策深度 | 无 | 低 | 中（竞价） | **高（取舍+谈判）** |
| 与站点耦合 | 无 | 无 | 无 | **强（真实行为驱动）** |
| 经济性质 | 零和抽税 | 零和抽税 | 零和抽税 | **正和发行** |
| 新人体验 | 被卷入 | 一般 | 一般 | **同起跑线** |
| 长期目标 | 线性到顶 | 线性到顶 | 线性到顶 | **赛季循环** |
| 合规性 | 差 | 中 | 中 | **好** |
| 改造量 | — | 小 | 中 | 大 |

**推荐路径**：如果只想快速上线 → 备选 A；如果要做成招牌玩法 → 主方案，且按 5.3 的 MVP 分阶段验证。
