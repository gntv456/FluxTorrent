## 1. 二审总裁决

**一审的骨架判断成立，但一审低估了三个层面的伤情：**

1. **门禁是"一张静态表"，表的欠账就是裸奔**。全后端只有网关中间件一处做模块判定（无第二处调用 `require_module`），网关靠"前缀/精确路径映射表"工作，而这张表漏登了至少 11 个属于可选模块的端点——其中 `PUT /me/avatar-frame` 在 dressup 关闭后仍可**真实扣魔力**；worker 侧 6 个任务漏挂模块锁，论坛抽奖结算甚至不在任何锁内，forums 关闭后仍持续开奖动账。**"四处一致"在一审是设计描述，二审发现它是漏的。**
2. **站型切换的承重链路（setup/apply/save）语义有实错**：安装向导只应用站型包的一小段（extras），分类/模块/维度/标签/字幕口径全部不落地，"向导引导先调 apply"的引导不存在；apply 会把站长自定义标语无声清空（代码与 0145 注释直接矛盾）、会把在线种子的多维筛选数据级联清光（无引用守卫）；自定义站型快照只存 4 个字段，音乐站另存再应用会把歌词上传校验整体打回影视口径。
3. **"换掉站型"甩不掉的硬编码内容比一审认定的多得多**：前端三语词典内嵌"人教/部编/苏教"数组；demo 教育内容随迁移无条件执行且无开关；初装论坛版块叫"课本讨论"、勋章叫"开学先锋/放暑假啦"、成就叫"初为人师/桃李天下"；教育词表被删后 0174 迁移还会**幂等回填重新长回来**。

一句话总评：**这个系统的"通用建站"能力目前更像"demo 演示链路通了，生产链路四处漏风"**——站型包数据模型（一审确认的优秀部分）是真的，但从安装向导到日常运营的**执行层**还欠一轮系统性收口。

## 3. 二审新发现：G6–G11

### G6【P0】安装向导只做"半套 apply"——建站门面断在最后一步

**这是二审最重的单条发现**：安装向导是"建站系统"的门面（总纲 §8.3），但 `POST /setup` 完成时对站型包只做两件事——`apply_pack_extras`（等级叙事/经济/元数据三段）+ 裸 `UPDATE site_type`（`setup_http.rs:143-155`）。代码注释自认："分类由既有 apply 端点处理，**向导引导先调**"（`setup_http.rs:130`）——但这个引导**不存在**：前端 `finish()` 只调 login + setup，从不调 `/admin/site-type-packs/apply`（`app/setup/page.tsx:62-74`；apply 端点全仓只有 `staff-tools-content-cats.tsx:118` 一个调用方）。

**站长在向导选 movie 的实际后果**：

| 应该变成 | 实际变成 |
| :--- | :--- |
| 分类 = movie 7 类（电影/BluRay…） | 仍是 0119 的 general 10 类快照 |
| module_* = movie 矩阵（showcase/subtitles 开…） | 仍是迁移默认（module_textbooks=no，其余键=缺省全开） |
| sections = movie 5 维 + 影视词表 | 仍是 0175 通用四维 |
| pack 层标签 5 条 | 无 |
| subtitle_kind | 保持 subtitle（movie 恰好同值，music 则错） |

附带缺陷：`site_type` 写入是裸 UPDATE 非 upsert（行缺失则静默无效，`setup_http.rs:149-155`）。

**结论**：新站长的第一次站型选择被静默丢弃一半。这是"站长自由搭建"目标上最直接的断点。

### G7【P0】apply / save 承重语义五连缺陷

切换站型是本系统的核心动作，其实现（`pack_apply.rs` / `pack_save.rs`）存在五个已实证的语义错误：

**7a. 自定义标语被 apply 无声清空（代码与注释直接矛盾）**
`pack_apply.rs:106-113` 注释写"站长自定义值也被保留，不会被下一次 apply 无声重置"，SQL 却是 `ON CONFLICT (name) DO UPDATE SET value = ''`——每次 apply 把 site_tagline 打回空。0145 确立的"覆盖语义"被 apply 自己违反。站长改了标语再切一次站型，标语没了。

**7b. 词表整维重建级联清空在线种子数据（无引用守卫）**
`pack_apply.rs:255-286`：对包内声明的每个维度直接 `DELETE FROM section_dict WHERE kind=$1` 再重插，经 `torrent_sections.dict_id ON DELETE CASCADE`（0063）**级联清光在线种子的多维筛选数据**。注释自称"显式应用包 = 重建口径"，但：内置九维删除有 in_use 守卫（194-207），**唯独 dict 没有**；对比生态商店导入路径有"被引用则退化为追加"守卫（`pack_store.rs:381-407`）——同一生态两条路径口径不一致。有种子的站重复 apply 同一个包 = 已填维度数据全灭。

**7c. 自定义站型快照只有 4 个字段**
`pack_save.rs:168-172` INSERT 列清单仅 `code,name,description,brand,categories,modules,sort,tagline`。站长调好了**维度词表（sections）、标签（tags）、等级叙事（classes）、经济参数（economy）、元数据源（metadata）**再"另存自定义站型"，这些**全部不进快照**；之后 apply 这个 custom 包，extras 三段因 NULL 全跳过（`0108:89-113`）——自定义站型丢掉一大半自定义。

**7d. custom 包 apply 会打断音乐站的歌词链路**
`pack_apply.rs:304-307` 无条件调用 `apply_subtitle_kind(site_code)`，该函数按 `site_code IN ('music','lossless')` 分支（`0146:152`）——custom_* 前缀永不命中 → music/lossless 站另存再应用自己的自定义包，kind 被重置为 subtitle、扩展名白名单换成影视口径，**歌词（lrc）上传全部被拒**。

**7e. 分类图标两条路径语义相反**
站型 apply 只 UPDATE name 不碰 icon_key（`pack_apply.rs:83-90`，保住现有图标）；生态商店 taxonomy 路径却是 `icon_key=EXCLUDED.icon_key` 全量覆盖（`pack_store.rs:205-217`），而 `builtin.taxonomy.custom_*` 生成的 payload icon 缺省空串（`pack_format.rs:239-243`）→ **custom 包经商店路径安装会把 0166 铺的分类图标全部抹空**。

另录两个轻项：merge 模式按 id 覆盖可改名被种子引用的分类（无守卫，行为反直觉）；pack 层标签 upsert 遇与通用六件套同名时会把 global 行劫持进 pack 层（触发面小）。

四个结构性问题：

1. **metadata 预设 5/11，且 musicbrainz 是死字**：music/lossless 包预设 `douban,musicbrainz`，但 PT-Gen host 白名单没有 musicbrainz 分支（`ptgen.rs:101-121`）——该源链接直接被拒"未在本站启用"。ebook/software/sports 没有任何对口元数据源，发布只能纯手填。
2. **适配器是空货架**：`adapters` 表建好后全仓无一条种子（无 INSERT、无随包 wasm）——"内置自营适配器"承诺（0170 注释）未兑现，元数据获取 100% 依赖外部 PT-Gen。
3. **商店目录条目≠完整包**：`builtin.taxonomy.*` 只携带 categories+sections（`pack_catalog.rs:356-400`），modules/tags/tagline/classes/economy/metadata **进不了商店安装路径**——市场与站型包是两套不对称载荷，商店买的"movie 包"拿不到 movie 的模块矩阵和标签。
4. **分类图标系统性偏心**：0166 是一次性 UPDATE 只作用于迁移时已存在的分类；apply 重建分类不写 icon_key（G7e）——**切站型后图标全部回落首字色块**，且 sports/software/documentary 的分类名 0/7 命中模式表。

### G11【P2】内容包边界缺陷（生态商店收尾项）

- rules 包回滚会删掉快照外**所有** `rule_%` 键——导入后管理员手工加的规则被误删（`pack_import.rs:494-508`）；
- marketplace 拉取无大小上限（index 与包文件全量入内存，`pack_catalog.rs:121,426-431`）；index URL 不限 scheme（http 可用，`94-103`）；install 时二次拉索引反查 url 存在 TOCTOU（`272-281`）；远程包无签名/hash（设计取舍，靠同路径守卫+回滚兜底，已记录）；
- `core_compat` 字段只存不校验（死字段）；kind 字符集两处口径不一（`pack_types.rs:15-20` 仅小写 vs `pack_format.rs:261-268` 允许大写）。
