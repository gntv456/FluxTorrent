# PT 游戏策划：宠物养成系统

- **日期**：2026-09-29
- **作者**：纳纳
- **状态**：策划稿（未落地）
- **定位**：§9 二维评估排名第一——**好玩性高 + 魔力回收极强（纯 sink 型）**，是"大力回收且不失趣味"的标杆玩法。

---

## 1. 目标与定位

- **核心价值**：把魔力消耗包装成"养一只属于自己的宠物"，玩家**主动、乐意**花魔力，回收力度大且不破数值平衡。
- **设计铁律**：宠物**不向玩家返魔力**（不做 RNG 产出），只给展示 / 称号 / 个人页特效。回收最干净、零通胀风险。
- **参考**：现有 `farm.rs` 养成范式、`medals` 成就体系、`spend_spark` / `earn_spark` / `helpers`。

## 2. 核心循环

```
抽蛋孵化(花魔力) → 喂养(花魔力,涨亲密度) → 达阈值进化(花魔力,sink) → 展示/社交
        ↑                                          │
        └──────────── 稀有度影响外观/称号 ──────────┘
```

玩家每一次"投入"都是 sink；回报是**情感价值 + 社交货币**，不是魔力。

## 3. 数据模型（SQL 草图，迁移号需避让最大号）

```sql
-- 物种定义（种子数据）
CREATE TABLE pet_species (
  id         BIGSERIAL PRIMARY KEY,
  name       TEXT NOT NULL,
  rarity     SMALLINT NOT NULL,   -- 1普通 2稀有 3史诗 4传说
  stage_max  SMALLINT NOT NULL DEFAULT 3,
  base_art   TEXT NOT NULL        -- 前端资源 key
);

-- 用户宠物实例
CREATE TABLE user_pets (
  id          BIGSERIAL PRIMARY KEY,
  user_id     BIGINT NOT NULL REFERENCES users(id),
  species_id  BIGINT NOT NULL REFERENCES pet_species(id),
  stage       SMALLINT NOT NULL DEFAULT 1,
  intimacy    INT NOT NULL DEFAULT 0,     -- 亲密度
  satiety     INT NOT NULL DEFAULT 100,   -- 饱食度(可仅展示)
  hatched_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_fed_at TIMESTAMPTZ
);
CREATE INDEX idx_user_pets_uid ON user_pets(user_id);

-- 孵化抽取记录（审计 + 防刷）
CREATE TABLE pet_hatch_log (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT NOT NULL,
  species_id BIGINT NOT NULL,
  cost       BIGINT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 进化记录（审计）
CREATE TABLE pet_evo_log (
  id          BIGSERIAL PRIMARY KEY,
  user_id     BIGINT NOT NULL,
  pet_id      BIGINT NOT NULL,
  from_stage  SMALLINT NOT NULL,
  to_stage    SMALLINT NOT NULL,
  cost        BIGINT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 4. 经济设计（sink 为主）

| 行为 | 魔力流向 | 金额（可调，走设置键） | 性质 |
|---|---|---|---|
| 抽蛋孵化 | 支出 | 500（建议，gacha 概率按稀有度权重） | **sink** |
| 单次喂养 | 支出 | 10 | **sink** |
| 进化（按形态递增） | 支出 | 200 / 600 / 1000 | **sink** |
| 额外互动（抚摸） | 支出 | 5 / 次，每日免费 1 次 | **sink** |
| 宠物产出魔力 | — | **不做** | 避免通胀 |

> 所有支出走 `spend_spark(db, uid, amt, "pet", idem, "pet_xxx", ref_id)`，幂等键防重放（同 `casino.rs` 口径）。

## 5. 玩法机制

- **孵化（gacha）**：按 `rarity` 权重 RNG 出物种；传说概率建议 ≤ 2%。孵化消耗即 sink。
- **喂养**：每次 +亲密度（带小幅随机）；饱食度仅展示，不做惩罚机制以免逼氪。
- **进化**：亲密度达阈值（如 100/300/600）且支付进化费 → `stage+1`，外观变化。
- **稀有度**：决定外观精细度 + 可解锁称号（挂钩现有 `medals`）。
- **收集墙**：用户页展示已孵化物种 + 进化进度，社交攀比驱动持续投入。

## 6. 社交展示

- 个人页新增"我的宠物"卡片（复用个人页容器）。
- 好友互访可见对方主宠 + 收集度。
- 高稀有度宠物解锁动态头像框 / 个人页特效（**纯外观**，不返魔力）。

## 7. 接口设计（复用 `helpers`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/games/pets/hatch` | 抽蛋，`check_bet` + `idem_key` + `spend_spark` |
| GET  | `/games/pets` | 我的宠物列表 |
| POST | `/games/pets/feed` | 喂养，`spend_spark(10)` + 涨亲密度 |
| POST | `/games/pets/evolve` | 进化，校验阈值 + `spend_spark(按stage)` |
| GET  | `/users/:id/pets` | 社交展示 |

下注上限受 `games_max_bet` 约束（同 `casino.rs`）。

## 9. 风控

- 孵化 / 喂养 / 进化全部幂等（`idem_key("hatch"|"feed"|"evo", uid, client_key)`）。
- 单用户每日孵化 / 喂养次数走 Redis 限次（`check_rate`）。
- 亲密度增长服务端校验，防前端伪造。
- 审计：孵化 / 进化落 `pet_hatch_log` / `pet_evo_log`。
