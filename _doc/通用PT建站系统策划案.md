## 1. 定位与目标

### 1.1 一句话定位

**FluxTorrent = 开箱即用的通用 PT 建站系统**：站长选站型（或自定义）→ 应用站型包 → 微调开关与参数 → 开站。
官方镜像只发一份，所有站型差异由**数据与配置**表达，不 fork 代码。

### 1.2 与旧定位的关系

| 维度 | 旧（教育站产品） | 新（建站系统） |
| :--- | :--- | :--- |
| 产品形态 | 一个教育 PT 站 | 可配置的 PT 站引擎 |
| 站型 | 硬编码教育假设 | 站型包驱动，11 预置 + 自定义 |
| 功能集合 | 全量固定 | 模块注册表 + 站级开关 |
| 教育特有功能（课本中心等） | 核心功能 | 一个可关模块（教育站型默认开） |
| 文档口径 | 「下一代教育类 PT 站」 | 「通用 PT 建站系统，教育为预置站型」 |

### 1.3 成功指标（量化）

1. **切换验证**：任选 2 个预置站型（如 lossless、game）在干净库上 apply 后，
   分类/品牌/质量维度/模块开关/导航全部随站型变化，**零代码改动、零手工 SQL**；
2. **开关验证**：任一可选模块关闭后，导航入口消失、页面守卫拦截、API 返回专用错误码、
   worker 相关任务跳过——四处行为一致（详见 §5.3 验收矩阵）；
3. **回归零伤**：默认配置（≈当前教育站形态）下，现有 `scripts/regression.py` 全量通过，
   既有站点升级后行为无变化；
4. **文档对齐**：README / `_doc` 总纲 / OpenAPI 描述全部改为通用建站口径。

### 1.4 非目标（明确不做）

- **单实例多租户**（一套库跑多个站）：本期不做，架构上不阻断（site_settings 已按站隔离）；
- **运行时动态加载插件 / 第三方插件市场**：沿用编译期装配（M28 现状），WASM/sidecar 不立项；
- **为不同站型 fork 分支**：任何「某站型专属 if」进代码都视为违例（见 §10 纪律 D3）。

## 3. 总体设计：三层配置模型

```
┌─────────────────────────────────────────────────────────┐
│ L1 站型包 site_type_packs（模板层，可重置）                │
│    品牌 / 分类 / 质量维度 sections / 模块默认值 / 经济预设  │
│                          ↓ apply（站长显式触发）           │
│ L2 站点设置 site_settings（运行时权威，单一事实源）         │
│    site_type / module_* / 货币名 / 元数据源 / 导航开关 …    │
│                          ↓ /site-profile 合并下发          │
│ L3 消费端（行为层）                                       │
│    API 守卫 / 前端导航与页面守卫 / worker 任务守卫 / 文案    │
└─────────────────────────────────────────────────────────┘
```

三条铁律（延续既有修正，写死在评审清单里）：

- **T1 快照不权威**：L1 一切字段只是初始值，运行时一律读 L2（`http.rs:4343` 注释已确立，推广到全部消费点）；
- **T2 开关是行为开关**：任何 `module_*` 关闭必须同时作用于导航、页面、API、worker 四处，只藏入口视为未完成；
- **T3 默认等于现状**：全部可选模块的默认值 = 当前教育站形态，保证存量站升级零感知（§1.3 指标 3）。

## 5. 后端改造方案

### 5.1 模块守卫（新增 `modules.rs`）

```rust
/// 模块开关守卫：fail-close。读 site_settings.module_{key}，
/// 缺省回落注册表默认值（T3：缺省=当前教育站形态）。
pub async fn require_module(state: &Arc<AppState>, key: &str) -> DomainResult<()> {
    if state.module_enabled(key).await? { Ok(()) }
    else { Err(DomainError::ModuleDisabled(key.into())) }
}
```

- `AppState` 增加模块开关**进程内缓存**（TTL 30–60s，改设置后台主动失效），
  避免每请求打 `site_settings`——`/site-profile` 已是每页 RSC 必调，不能放大 DB 压力；
- 新错误类型 `ModuleDisabled` → 专用错误码（在 `domain-types` 错误码分段里新开一段，建议 41xx：`4101 模块未开启`），
  与 401/403 区分——前端据此显示「本站未开放此功能」而非「无权限」。

### 5.2 路由挂载策略：静态挂载 + 入口守卫（不搞动态 scope）

维持 `community_http.rs:2312` 的静态 mount 链（Rust 编译期装配是优点不是缺陷），
在**每个可选模块的 handler 入口**调 `require_module`。实施方式：

- 逐 handler 加守卫（机械但显式，评审可查）；同模块多 handler 的，提供 `module_guarded(scope, key)` 包装函数收敛样板；
- `/site-profile` 的 `modules` 合并逻辑已存在，仅需注册表扩容后自动受益；
- OpenAPI（`openapi_http.rs`）按开关标注端点可用性（描述里注明「依赖 module_xxx」）。

### 5.3 行为一致性验收矩阵（每个可选模块过一遍）

| 关闭 module_xxx 后 | 期望 |
| :--- | :--- |
| 导航入口（web） | 消失（§6.2 联动） |
| 页面直访 URL | 服务端守卫 → 「本站未开放」页（404/410 语义，不露内部态） |
| API 直调 | 统一信封 `4101 module_disabled` |
| worker 定时任务 | 跳过（日志一条 debug，不动账） |
| 他人个人主页/种子页相关挂件 | 不渲染该模块组件 |
| 关联横切（成就/任务/绩效指标） | 该模块产出的事件不再计入（§5.6） |

### 5.4 worker 守卫

`jobs.rs` / `bank_jobs.rs` / `task_jobs.rs` 的每个周期任务入口读模块缓存（与 API 共用 `module_enabled`）：
银行结算看 `module_bank`、农场窗口看 `module_farm`、任务结算看 `module_tasks`……
**跳过不报错**，恢复开启后补跑逻辑保持幂等（现有幂等重跑纪律直接复用）。

### 5.5 与 RBAC 的关系（正交，不合并）

- RBAC 回答「**这个人**能不能做」；模块开关回答「**这个站**有没有这个功能」；
- 判定顺序：先模块开关（4101）后权限（403）——模块关了连权限判定都不必做；
- 管理员也不绕过模块开关（站长要启用请先开开关），避免「隐形功能」。

### 5.6 横切面处理（绩效考核/任务/成就/反作弊）

这些模块从全站流水采集指标（M21 纪律：零手工填报）。模块关闭后：

- 其流水源头消失，指标自然归零——**不需要**在每个采集点加 if；
- 但「任务中心里游戏类任务」「成就里游戏类成就」需要标记 `module_key` 归属：
  模块关闭时任务/成就列表过滤其条目（列表 SQL 按 join 注册表过滤），历史已完成记录保留展示（历史不抹除）；
- 反作弊（cheat_events）不受开关影响，持续记录 agent 命中。

## 6. 前端改造方案

### 6.1 契约先行

`packages/domain-types` 新增：

```ts
export type ModuleKey = 'games' | 'farm' | 'bank' | ...; // 与 Rust/SQL 契约测试锁定
export const MODULE_NAMES: Record<ModuleKey, { zhCN: string; zhTW: string; en: string }>;
```

`SiteProfile.modules: Record<ModuleKey, boolean>` 收紧类型（现为宽泛 `Record<string, boolean>`）。

### 6.2 导航联动（推广 textbooks 先例）

[layout.tsx:22](../apps/web/components/layout.tsx) 的 `textbooksOn` 模式推广为通用规则：

- 每个导航项声明 `module?: ModuleKey`，构造时按 `profile.modules` 过滤——一处收敛在导航工厂；
- 默认导航与自定义导航（menu_items）统一走此过滤；menu_items 表加 `module_key` 列（可空），
  站长自建菜单项也能挂模块归属；
- 首页区块（0089 home_sections）每张卡片声明 module 归属，`/home` 返回时过滤。

### 6.3 页面守卫

- 可选模块页面（games/farm/bank/...共 20+ 页）包一层 `ModuleGate`（服务端组件）：
  关闭 → 渲染统一「本站未开放此功能」空态页（三语文案 + 不暴露模块内部结构）；
- 页面内嵌挂件（个人主页的勋章墙、种子页的求字幕入口等）同样按 modules 过滤；
- API 返回 4101 时 `api-client` 识别并路由到空态页（防直链深页场景）。

### 6.4 品牌与主题

- 站名/Logo/favicon 已走 `site_settings`（brand），补齐：**主题色 Token 覆盖**（主色/强调色两个 CSS 变量级自定义，写入 `<html>` style，设计系统 §7.1 Token 不动结构只覆值）——P2 交付，先留接口；
- 默认品牌去教育化（见 §7.4）。

## 7. 站型包做实与矩阵

### 7.1 apply 端点强化

`/admin/site-type-packs/apply` 现已重建分类/品牌/sections；追加：

1. **落 module_* 设置**：包内 modules 默认值写入 `site_settings.module_*`（显式覆盖站长手改值前弹确认，向导里做成 diff 预览：将变更哪些键/旧值→新值）；
2. **经济预设**：包可携带 `economy` JSONB（签到额/银行利率档/游戏赔率等建议值，仅 apply 时一次性写入，之后归设置中心管）；
3. **元数据源预设**：影视站默认 imdb+douban、音乐站默认 douban+musicbrainz 型源（0087 机制不变，只补包内默认）。

## 10. 工程纪律、测试与风险

### 10.1 纪律（评审清单，违例即打回）

## 11. 复审补充：八个遗漏计划面

> v1.0 定稿后复审发现的缺口。每项标注：现状证据 → 计划 → 归属阶段。
> 原则：**只补计划不扩范围**——P2 项进 backlog 表，不膨胀 U1–U3。

### 11.1 数据面：演示数据与站型数据的隔离（归 U2）

**现状**：`0018_demo_data.sql`（12 用户/种子/评论/火花流水）与 `0004/0006/0008` 等种子迁移
在 sqlx 迁移框架内**必然随正式站执行**，生产站会带上 demo 用户与教育口径种子；`migrate!` 宏无「跳过」机制。
**计划**：新增迁移把 demo 数据抽成幂等清理脚本 + 站型化——正式向导（§8.3 setup_done 置位）时自动跑清理；
演示模式（`FLUX_DEMO=1`）才保留并按站型重生成 demo 内容。种子数据全部声明所属站型，apply 时非本站型的种子归档。
**验收**：干净库走 setup 向导后，无 demo 用户、无跨站型种子残留。

### 11.2 等级体系站型化（归 U2）

**现状**：LV1 新芽 → LV12 森林（植物成长叙事，0053）是教育站品牌故事；影视/游戏站用户看到「新芽/硕果」违和。
**计划**：站型包增加 `classes` 快照（名称可选、**晋升数值阈值保留全站默认**——升降级规则跨站型通用，只换叙事皮肤）；
apply 时 UPDATE class_rules 名称列。教育包保留植物系，综合包提供 中性 命名（LV1–LV12 数字裸名），其余站型走中性 + 包内可改。
**不做**：等级数量/阈值按站型变化（无收益，徒增验证面）。

### 11.3 合规红线：博彩类玩法与成人站型的分发策略（归 U3，法务口径先立）

**现状**：刮刮乐/猜大小是「火花」动账（虚拟货币），但通用建站系统分发后，**第三方站长所在司法域可能视为赌博服务**；
0037 注释里提过 adult 站型但种子未建（幸未建）。
**计划**：
1. `module_games` 下细分子开关语义文档化（机会类玩法标注「合规敏感」），《建站手册》明示站长自查司法域；
2. **adult 站型永久不进预置包**（尊重现状），自定义站型可自建但文档声明「与本项目无关」；
3. `LICENSE` 明确（当前缺失！）：核心 MIT、博彩类玩法模块可考虑独立 feature 或文档警示——U3 与法务口径一并定稿；
4. 安装向导增加「玩法合规确认」勾选步骤（留审计记录）。

### 11.4 邮件通道打通（归 U2；当前是隐形断点）

**现状**：SMTP 设置键已有（0034：smtp_host/port/from…），lettre 投递只在**找回密码**一条链路接了
（gaps_http.rs `send_reset_mail`）；邀请邮件（`/invites/email`）、群发 massmail、注册确认信的投递通道未统一。
**计划**：抽公共 `mailer.rs`（读 site_settings + 连接复用 + 失败队列重试），三条链路收口；
安装向导含「SMTP 测试信」步骤（很多站长卡在这一步）。站型包补邮件模板默认（品牌名注入）。
**注**：0034 的键名（accountname 等 NP 风格）顺带对齐标准命名，迁移做别名兼容。

### 11.5 注册/准入模式开关（归 U1，小成本高价值）

**现状**：代码是纯邀请制（M01），但通用建站系统需要三种准入：**开放注册 / 验证码注册（邮箱验证）/ 纯邀请**。
**计划**：`settings` 增加 `registration_mode`（invite_only 默认｜open｜email_verify），注册端点按模式分支；
开放模式下邀请配额逻辑旁路。三模式各配限流参数（防开放注册被刷）。**默认 invite_only = 现状（T3）**。

### 11.6 访客可见性（归 U2）

**现状**：`/open/recent` 已是公开端点（openapi_http），但「未登录能看到什么」没有站级策略——
有的站型要公开橱窗拉新（showcase 关联），有的站（版权敏感）要求**全站登录可见**。
**计划**：`site_settings.guest_policy`（all_private 默认 ｜ recent_only ｜ showcase）；
web 中间件 + API `/open/*` 按策略放行；SEO 需求（Torznab/RSS 已是 passkey 鉴权，不受影响）记录在手册。

### 11.7 多站点运维分发口径（归 U3）

**现状**：单仓单镜像，`docker/.env.example` 面向单站。
**计划**（文档+模板级，不做 SaaS）：
- Compose 栈模板支持「一机多站」（每站独立 compose project + 端口/卷隔离），`.env` 增 `SITE_TYPE`（§8.4 已列）；
- **升级纪律单列**：多站共版本时逐站灰度（先低流量站），回滚 = 镜像回退 + 迁移前滚检查——
  sqlx 迁移**没有 down**，回滚方案必须「恢复备份」而非降迁移，写进《建站手册》升级章节红线；
- 版本发布说明模板增加「站型包变更」小节（哪站型默认值改了）。

### 11.8 i18n 规模治理（归 U1/U3 分摊）

**现状**：字典 ~2490 键 ×3 语言，U1 又要新增「模块开关名/影响说明/ModuleGate 空态」批量文案。
**计划**：新键命名强制 `mod.*` 前缀（一处命名空间，便于审查与后续按需加载）；三语文件键数一致性进 CI

## 12. 二遍深挖：六个产品硬缺口

> v1.1 之后再深挖一轮（逐处读代码核实，非推测），发现六个「不补就不算通用建站系统」的硬缺口。
> 与 §11 的区别：§11 是配套面（做法务/数据/口径的收口），§12 是**功能本身缺失或半成品**。
> 每项标 P0（进 U 期）或 P1/P2（backlog 表），不再扩 U 期范围。

### 12.1 真实支付通道缺位（P1，捐赠/站免池当前是模拟支付）

**现状核实**：`donate_topup`（http.rs:4720）收到 `alipay/wechat` 渠道参数后**直接加余额**，
流水备注明写「模拟支付成功」——没有拉起任何支付网关。演示站可用，真实站点捐赠一分钱都收不到，
且有被刷余额的风貌（任何登录用户可无限 topup）。
**计划**：
1. `payment_providers` 设置（网关类型/商户号/密钥，走 settings_meta secret 型）+ 抽象 trait（当面付/扫码/回调验签）；
2. 首发只接一家（建议易支付或 Stripe 二选一，按目标站长群体定），回调幂等入账（复用 donation_ledger）；
3. **未配置网关时 donate 页面显示「捐赠通道未开通」而非模拟充值**（现在这种静默假支付对通用系统是事故级）；
4. 汇率/定价多币种（USD 面值 vs 人民币收款）进设置。
**归属**：P1 backlog（U3 后单开一周）；但第 3 点（关掉模拟支付）**提进 U1**——一行守卫的事，先堵住。

### 12.2 经济数值参数化不完整（P0，U2 做）

**现状核实**：赔率/奖池在 `games.rs` 是**编译期常量**（MAX_BET=1000、刮刮乐 EV 0.66 硬编码）；
签到/银行利率/商店定价散在各迁移种子。§7.1 的「经济预设」若只搬设置键，搬不动这些常量。
**计划**：
1. 盘点全部经济数值 → 分三类：已是设置键 / 迁移种子(可 UPDATE) / 代码常量；
2. 代码常量全部改为读 `site_settings`（进程缓存同 §5.1，缺省回落现值——T3）；
3. `settings_meta` 补「经济参数」分组卡片；站型包 economy 预设（§7.1）覆盖同一批键；
4. 契约测试：常量表 key 集合 == settings_meta 经济分组（防止改代码忘改元数据）。
**范围**：MAX_BET、限次/时限、刮刮乐五档分布、猜大小赔率、农场作物表与市场窗口、签到三档、
银行五档利率、做种收益公式系数、magic_pool 目标值。约 25–35 个键。

### 12.3 反作弊配置产品化（P1，现为散装规则）

**现状核实**：能力都在——agent_rules（UA + peer_id 双正则，0071）、cheat_events、connectable 抽测、
Ratio Watch、IP/邮箱封禁——但全是管理端散页，无「防吸血客户端」一站配置面，参数（观察期天数、
阈值、自动处置动作）不可调。
**计划**：设置中心加「防作弊」分组：agent 规则导入导出（JSON，站长圈共享规则包）、
Ratio Watch 参数化、命中动作分级（记录/警告/限速/封禁）。归 P1；**规则包 JSON 导入导出提进 U3**（成本半天，
对建站系统拉新价值高——新站长最缺的就是一份现成规则）。

### 12.4 存量站数据迁移器（P1，决策四「保数据不保代码」的另一半没做）

**现状核实**：全仓无 NexusPHP → FluxTorrent 导入器（仅 compat 方向的对外兼容端点）。
方案 §2.4 承诺「保数据迁移」，但目前只有文档没有工具。通用建站系统的真实用户是**存量 NP 站搬迁**，
没有导入器等于逼站长从零建站。
**计划**：`apps/importer`（或 scripts 下 CLI）：NP 库只读连接 → 用户(pass_hash 兼容验证)/种子(含 raw)/
做种统计/论坛帖/邀请关系 → 分阶段映射导入 + 校验报告（计数比对 + info_hash 全量 diff）。
复用 pieces_hash 二级指纹做断点续导。**P1 单独立项**（预计 2–3 周），U3 后排；
先在 U3 手册里明示「当前仅支持全新建站，导入器 roadmap 见此」。

### 12.5 种子内容审核工作流半成品（P1）

**现状核实**：reviews 有通过/驳回/暂缓/恢复，但驳回后**没有退回修改-重提环**：发布者收到拒绝后
只能重新走完整上传；deny-reasons 词典有了，但与被拒种子的关联闭环（通知 + 原种子可改后重提）未通。
**计划**：被拒种子允许 owner 编辑后 resubmit（状态机 rejected→pending，保留原 id 与评论区）、
审核结果站内信通知（接 §11.4 mailer）、deny_reason 关联落库可统计。归 P1；
**其中「审核结果通知」提进 U2**（消息中心已有，只差事件接线，半天）。

### 12.6 可观测性只有计数（P1）

**现状核实**：/metrics 是请求/5xx 计数（v4_http），无 RED 指标（延迟分布）、无业务指标
（announce DLQ 深度、worker 任务 lag、spark 动账异常告警线）。原方案 Phase 6 有 Prometheus/Grafana，
但 U 系列改造后多站长自运维，观测面更重要。
**计划**：/metrics 补 histogram（P99 延迟）、DLQ 深度/消费 lag gauge、经济异常告警（接 §5.6 反作弊联动）；
《建站手册》附 docker-compose 带 prometheus+grafana 可选栈 + 预置仪表盘 JSON。P1；
**DLQ 深度 gauge 提进 U1**（几行代码，announce 链路最关键的健康信号）。
