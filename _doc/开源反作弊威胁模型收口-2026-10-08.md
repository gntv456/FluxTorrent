# 开源反作弊威胁模型收口——审计与落地报告（2026-10-08）

> 议题源头：站长问「我们开源（MIT），反作弊/审核/考核逻辑公开等于给作弊者发地图，怎么办」。
> 结论先行：**藏代码买不到安全（黑盒可探测），只会杀死开源战略（信任/装机/零魔改升级）。
> 正确姿势是「算法公开、密钥私有」**——本批把这句话从口号落成机制。全批已实施、已验证。

## 一、威胁模型分析（先想清楚再动手）

### 1.1 开源到底泄露了什么

| 泄露物 | 实际风险 | 定性 |
| :--- | :--- | :--- |
| 检测**维度**（查什么） | 作弊者知道要避开回连/速率/佐证 | 不可避免，接受 |
| 检测**默认参数**（出厂值） | 留默认值的站等于把钥匙插在门上 | **P1，本批修** |
| 检测**时机**（300s 固定 tick） | 客户端可「卡表」避开探测窗 | **P1，本批修** |
| piece 抽查**位置**（idx<前 N） | 排在采样序后段的 peer 永不被抽查 | **P1，本批修** |
| 检测**算法本体** | 见 1.2——公开的代价被高估 | 可接受 |

### 1.2 为什么「算法公开」风险有限（三层论证）

1. **密钥与算法分离**：全仓反作弊参数（`cheat_enforce.rs:53`、`ledger_guard.rs:283`、
   ratio_gate 四值、announce_interval…）全部读 `site_settings`——每站私有。
   作弊者读上游源码只知道「检测哪些维度」，不知道任何一个站的实际调参。
2. **物理验证读码绕不过**：工作区已有的 `bt_probe.rs`（BT 握手+bitfield）
   → `piece_cache.rs`+`torrent_parse.rs`（piece SHA-1 比对）验证的是
   「数据物理上是否存在且正确」，对抗的是现实不是规则。
3. **领域实证**：NexusPHP（GPL）/UNIT3D（AGPL）的反作弊代码同样全公开，
   中文圈所有 NexusPHP 站在「作弊者能读源码」条件下运转十几年——
   军备竞赛发生在各站私有调参层，不在引擎基线。

### 1.3 MIT 的战略对价（为什么不改许可证）

- GPL 拦不住「跑网站」（无分发即无义务）；AGPL 理论上拦得住但 PT 圈无人执行、
  也告不动半地下站。PT 站不开源是领域铁律（魔改大头是反作弊，公开=给作弊者地图），
  所以「逼二开开源」是伪目标。
- 许可证剩下的真实功能只有**降低采用者法律摩擦**：MIT 下站长怎么用都干净
  （代装/传 fork/卖站交接不留 GPL 传染风险），商用采购不撞 AGPL 红线。
- 残留风险（多人同引擎，一次研究摊薄到所有站）的对冲=红队自查制度化（见 §四）。

## 二、落地清单（本批全部实施）

### 2.1 迁移 0309（`apps/api/migrations/0309_probe_randomization_and_opensource_hints.sql`）

| 项 | 内容 |
| :--- | :--- |
| `probe_jitter_secs`（缺省 90） | 探测循环每轮附加 0~本值随机延迟，杀「卡表」 |
| `probe_piece_ratio`（缺省 0.25） | piece 抽查按比例**随机**抽人，杀「排后段永不抽查」 |
| hint 开源提示 | 反作弊组（`group_key='anticheat'`）全部非只读键的 hint 追加「出厂默认值随源码公开，人人可查；上线后请按本站情况调整」——主库实测命中 9 行 |
| 幂等性 | 全部 `ON CONFLICT DO NOTHING`，drill 库两轮重跑验证通过 |

### 2.4 红队工具（`scripts/redteam_probe.py`）

作弊者视角黑盒自查：R1 幽灵做种（port=0）/R2 裸监听/R3 只回握手/R4 伪造 piece
（自带三种 mock peer）/R5 速率超窗/R6 近零重置/R7 固定节拍（由单测覆盖）。
本机自测 ALL PASS（站内无种时 R1/R5/R6 自动 SKIP 而非假绿）。

## 五、一句话结论

**引擎公开性从「漏洞」变成组合优势：我们有物理验证（握手/bitfield/piece SHA-1），
站长有私有挂载点（调参/规则包/适配器）+ 官方红队工具——算法公开，密钥私有。**
