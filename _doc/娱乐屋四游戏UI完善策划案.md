# 娱乐屋四游戏 · UI 与玩法完善策划案

> 版本：v1.0 · 日期：2026-09-18
> 范围：`/games` 娱乐屋下的四个玩法 —— **刮刮乐 / 猜大小 / 九宫格抽奖 / 农场**（不含五子棋对战 `/gomoku`、趣味盒 `/fun`）
> 设计依据：Aurora「流光种子」设计系统（`apps/web/app/globals.css` 真实 token）+ 现有实现逐行盘点（`apps/api/src/games.rs`、`games_http.rs`、`apps/web/components/game-actions.tsx`、`app/(main)/farm/_inner.tsx`）
> 目标：**不动经济模型（EV 已审计锁定）、不新增运行时依赖**，把四个玩法从「能跑通的数字」做成「有手感、有反馈、有记忆点」的产品。

---

## 0. 一页结论

- **经济定位（2026-09-19 产品决策）**：FluxTorrent 是**通用 PT 建站系统**（可建成教育/影音/音乐/综合等任何站型），娱乐玩法**不携带任何站型特色**，且四玩法一律以**回收魔力**为目的 —— 期望回报全部 < 1：
  | 玩法 | 期望回报 | 回收率 | 说明 |
  |---|---|---|---|
  | 刮刮乐 | 0.66 | 34% | 档位可配（0109），单测锁 |
  | 猜大小 | **0.951** | 4.9% | 赔率 2x → **1.9x**（详见 §2 P0-1） |
  | 九宫格 | 0.725 | 27.5% | 权重表单测锁 |
  | 农场 | **0.90** | 10% | 产量 = 种子价 × 0.75，含 20% 双倍后 0.90 |
- **现状是「后端完备、前端缺位」**：经济管线（统一交易管线 / 幂等 / 行锁 / 限流 / EV 单测锁定）已经做得很扎实，但四个玩法在前端**只用了 emoji + 一行文字 + 一个按钮**表达，玩法的「核心动作」根本没做出来——刮刮乐没有「刮」、猜大小没有「开奖过程」、九宫格不是九宫格、农场没有田地。
- **硬伤必须先修**：① 猜大小 EV 恰为 1.0（零回收 + 可双向零风险对冲）；② 九宫格前端奖池文案与后端实现不符（前端 `100x`，后端最高 `50x`）；③ `0109` 参数键未被消费；④ 农场与即时赌局共用限流键；⑤ 农场作物名为教育站特色（已去特化）。
- **本方案给出**：统一「娱乐屋大厅 → 玩法专注页」信息架构 + 一套新增语义 token/组件 + 每个玩法的完整交互设计（含状态机、动效时序、ASCII 线框、接口契约）+ 后端最小改动清单 + 逐项验收标准。

### 0.1 站型无关纪律（通用建站系统前提）

| 纪律 | 说明 |
|---|---|
| **玩法不绑站型** | 四个玩法的规则、文案、道具命名与站型无关；教育/影音/音乐/综合站共用同一套。站型差异只体现在模块开关（`games` / `farm` 可独立关闭）。 |
| **命名用通用幻想系** | 农场作物 = 四叶草 / 星尘豆 / 云端瓜 / 月华参 / 日冕稻（0127 迁移统一下发），站长可在后台改名；不再出现「知识麦/学问瓜」这类绑定教育站的旧命名。 |
| **文案去特化** | 数据与文案里的「好学农场」「种下知识」「学习资料」等一律清理（0127 迁移 + i18n 三语）。 |
| **经济一律回收** | 所有玩法 EV < 1，且**不允许出现 EV = 1 的中性玩法**（中性玩法可被双向对冲，既无回收意义又鼓励刷局）。 |

|---|---|---|---|

**公共缺口（四个玩法都缺）**
- 无**余额实时反馈**：下注后顶部魔力不变（`userbar` 是 SSR 渲染，客户端无刷新）。
- 无**战绩/历史**：`spark_ledger` 有全部流水（`kind='game'`），但前端一局打完只剩一行文字，无「最近 10 局」。
- 无**限次剩余提示**：Redis `rl:games:{uid}`（60 次/小时）用完才报错，平时看不见。
- 无**统一反馈层**：各玩法各自 `setMsg` 一行小字；成功/失败/风控提示样式不统一。
- 无**加载骨架 / 失败重试 / 空态**：农场加载中是 `py-16 text-center text-sub` 一行字。
- 无**防沉迷软提示**：连续高频下注无任何提醒（审计已记 P2-7 限流在 Redis 故障下 fail-open）。

## 3. 设计目标与原则

| 原则 | 说明 |
|---|---|
| **只用 Aurora token** | 颜色取 `--sky/--sun/--coral/--mint/--candy/--indigo` 及 soft 面；圆角 `--r-*`；阴影 `--shadow-card/--shadow-hover`；标题 `--font-display`。**组件内禁止硬编码色值**（`globals.css` §7.6-1 纪律）。 |
| **零新增运行时依赖** | `package.json` 现在是纯 Next 15 + React 19 + Tailwind v4，无动画库。动效全部用 CSS `@keyframes` + `Web Animations API` + SVG，保持 bundle 干净。 |
| **核心动作必须做出来** | 刮刮乐要能刮、猜大小要能看数字跑、九宫格要能看灯跑、农场要能看作物长。UI 不是把结果画好看，是把**玩法过程**可视化。 |
| **服务端是唯一真相** | 前端动画只负责「表演已确定的结果」，绝不本地随机/本地算钱；动画期间禁用操作，结果以响应为准。 |
| **移动优先** | 主流程 375px 单手可达；触控目标 ≥44px；舞台区（视觉主体）居中且宽度 ≤420px。 |
| **结果必须可感知** | 输赢用「颜色 + 动效 + 飘字 + `aria-live` 播报」四通道，不只靠颜色（色觉无障碍）。 |
| **reduced-motion 一等公民** | 所有开奖动画在 `prefers-reduced-motion: reduce` 下直接跳到结果态（`globals.css` 已有全局降级，本方案组件另做逻辑分支，不是只靠 CSS）。 |
| **防沉迷是设计的一部分** | 余额条常驻、单局净额可见、连打 N 局弹「歇一会儿」软提示、净输超阈值给提示。**不阻断，只提醒**。 |

### 5.3 动效规范

| 场景 | 时长 | 曲线 | 备注 |
|---|---|---|---|
| 按钮按压 | 120ms | `ease-out` | `active:scale-[0.97]`，沿用现状 |
| 结果飘字 | 240ms 进 / 160ms 出 | `cubic-bezier(.22,.61,.36,1)` | 只动 `transform/opacity`，不触发重排 |
| 刮层刮开 | 实时（跟手） | — | `destination-out`，笔触 28px，DPR 缩放 |
| 数字跑道 | 1600ms | `ease-out` 减速（末段 400ms 明显减速） | 跑马灯的张力全在减速段 |
| 九宫格跑马灯 | 2400ms | 匀速 → 最后 600ms ease-out | 至少绕 2 圈再定格 |
| 九宫格翻牌 | 320ms | `ease-in-out` | `rotateY(180deg)` + `preserve-3d` |
| 农场生长/成熟 | 常态 4s 循环摇曳 | `ease-in-out` | 成熟才播，避免 6 块地一起动造成性能与注意力负担 |
| 收获飘字 | 600ms | ease-out 上浮淡出 | 双倍时金色 + 缩放 1.2 |

**reduced-motion**：组件内读 `matchMedia('(prefers-reduced-motion: reduce)')`，命中则**跳过动画直接渲染结果态**（跑道直接显示数字、灯阵直接点亮中奖格、田地不摇曳）。CSS 全局降级兜底但不能替代逻辑分支（否则刮层会永远刮不开）。

## 6. 玩法详细设计

### 6.1 刮刮乐（`/games/scratch`）

**玩法**：即开型。买一张 → 刮开涂层 → 出结果。保留现有赔率（EV 0.66），**不改数值**。

**交互改造核心**：把「点按钮出结果」换成「买卡 → 真刮 → 到达阈值自动开完 → 揭晓」。

**状态机**
```
idle → buying(请求中,卡面显示"??",禁用) → scratchable(涂层可刮)
     → revealing(刮开≥55% 或点"一键刮开") → result(揭晓+飘字) → idle
异常：buying 失败 → idle + toast；revealing 期间结果未回 → 骨架"开奖中…"，不揭晓
```

**界面线框**
```
┌──────────────────────────────────────┐
│ 💎 12,480  今日 +320   剩余 47 局     │ ← balance-bar
├──────────────────────────────────────┤
│         ┌────────────────────┐        │
│         │ ▓▓▓▓░░▓▓▓ ▓▓▓▓▓▓▓ │        │ ← canvas 刮层（金色闪粉 + 猫头鹰剪影）
│         │ ▓▓░░░░▓▓▓ ▓▓▓▓▓▓▓ │        │   已刮部分透出底层奖面
```

## 8. 公共系统

### 8.1 余额与限次（常驻可见）
- `balance-bar` 在三赌局页顶部常驻：`💎 余额` + `今日净收 ±N` + `剩余 N 局`。
- 数据来自扩展后的 `GET /games`（登录态），每局结束后重新拉取（不轮询）。
- 余额不足：下注按钮禁用 + toast「魔力不足，去做种赚点？」（跳转 `/my` 做种页的轻引导）。

### 8.2 战绩（三赌局共用）
- `history-strip` 展示近 10–20 局圆点（赢 mint / 输 sub / 平 tie / 大奖 sun），hover/tap 显示净额与时间。
- 数据源 `GET /games/history`，刷新即一致，跨设备一致。

### 8.3 防沉迷（软性）
- 连续 20 局内无停歇 → 顶部条「玩了 20 局啦，歇会儿再战？（做种收益更稳）」+ 一个「知道了」按钮（不阻断）。
- 今日净输 ≥ 5000 → 结果区附加一行「今日净输 N，娱乐有度」（阈值写入 `i18n`，不透出给他人）。
- 不做强制封顶（现有 `games_max_plays_per_hour` 已是硬风控）。

### 8.4 反馈层
- `use-toast()` 统一成功/失败/风控提示，替代各玩法自有的 `msg` 文本块；`role="status" aria-live="polite"`。
- 错误码走 `dict.errors[code]`（现状已有），网络错误走 `dict.common.networkError`。

## 11. 风险与边界

| 风险 | 处置 |
|---|---|
| Canvas 刮层在高 DPI / 暗色主题下糊或色偏 | DPR 缩放 + 涂层用 CSS 变量（`--sun/--sun-soft`）而非固定色；暗色下换涂层渐变 |
| 动画期间切后台/断网导致「刮开但无结果」 | `visibilitychange` + 超时（8s）自动揭晓为「网络异常，结果以账本为准」并引导看战绩 |
| 长动画诱导高频下注（赌博化体验） | 开奖动画上限 2.4s；不做「快速重复下注」按钮；防沉迷提示常驻 |
| 前端本地累积战绩会造成刷新丢失/跨设备不一致 | 战绩一律走 `/games/history`（`spark_ledger` 真相源） |
| 改了奖池展示会影响既有单测 | `jgg_expected_value_house_edge` 锁的是 `JGG_PRIZES`，改的只是下发链路，单测不动 |
| **不做的事** | 不新增赌法（老虎机/21点/轮盘）、不改任何 EV 与赔率、不做真人对战改造、不引入动画库（保持零新增运行时依赖） |

## 13. 链路加固记录（2026-09-19 实测发现并修复）

首轮落地后按「每条链路走一遍」做了深度复查，又修掉 7 处**功能性**缺口（不是样式问题）：

| # | 缺口 | 现象 | 修法 |
|---|---|---|---|
| 1 | **剩余局数口径错** | `/games` 的 `limit_left` 用「今日局数」推算，而真正限流的是 Redis `rl:games:{uid}`（INCR+EXPIRE 3600 滚动小时窗口）——两者不是一回事，显示的数字与实际限流不符 | 新增 `limit_used()` 直接读限流器计数；端到端断言 `limit_left == max(0, limit − redis_value)` |
| 2 | **路单按流水渲染** | 即时玩法每局写**两条**流水（下注负、派彩正），直接用流水画路单 → 一半是负一半是正、局数还翻倍，看起来像「输多赢少」 | 新增 `GET /games/rounds`（以「下注流水」为主体，按幂等键前缀 LEFT JOIN 该局派彩，返回 `bet/payout/net`），前端 `HistoryStrip` 改按局渲染（赢/大奖/平/输 四态） |
| 3 | **票价绕过单注上限** | 九宫格直接扣固定票价 100，不受 `games_max_bet` 约束 —— 站长把上限调到 100 以下仍能抽走 100 | jgg 先校验 `ticket <= max_bet` 再计数；端到端实测（把上限调到 50 → 拒绝 1002 → 恢复后可用） |
| 4 | **已买卡未揭示就离开** | 买卡（钱已扣、奖已开）后切后台/切走，回来对着半刮的卡不知道结果 | `visibilitychange` → 已买卡即自动开完 |
| 5 | **农场市场到点不自动刷新** | 倒计时走到 0 后行情不动，要手动 F5 | 监听 `next_refresh`，到点自动 `refresh()` + 余额刷新 |
| 6 | **农场配额显示错位** | 农场页顶部显示的是**即时赌局**的剩余局数（农场走 `rl:farm`，与赌局分开计数）——误导用户 | `/farm` 下发 `hour_limit/hour_left`，`BalanceBar` 支持 `limitText` 覆盖文案（"本小时可操作 N 次"） |
| 7 | **动作反馈跑出视野 / 错误太笼统** | 田地与行情很长，`ResultFlash` 在页面底部 → 点「收获」看不到反馈；错误统一显示「参数校验失败」，丢掉后端的具体原因 | 新增 `GameToast`（固定视口下方居中，3.2s 自动消，`aria-live`）；校验类错误（code 1002）直接显示后端 message |

另修两处体验细节：点空地选播种目标时**高亮该地块**（`aria-pressed` + ring，避免"点完不知道点的是哪块"）；九宫格开抽瞬间清掉上一局的高亮与中奖态（原本会残留到新结果返回）。

**本轮验证**：`cargo test games::` 10/10 ｜ `_v_games.py` **61/61** ｜ 无头 Edge UI **19/19 + console errors 0** ｜ hydration 五页 **0 错** ｜ `tsc` 0。

### 13.1 复查过的、确认没问题的链路

- 幂等：同键重放被拒且余额不变（防「首局没中 + 重试中了」的印钞口）
- 并发：农场播种/收获有行锁与 `ON CONFLICT`；九宫格/刮刮乐动画期间按钮禁用
- 限流：Redis 异常时 fail-close（不再静默放行）；农场与赌局分开计数
- 余额同步：每局/每次动作后刷新 `me`（`GET /games`）
- 展示与实现同源：奖池、赔率、票价、行情价全部由后端下发 —— 实测行情卡价 6,550 与播种实际扣款 6,550 完全一致
- 模块门控：`games` 三页 / `farm` 页各自独立开关（站长可只关农场）
- 无障碍：Canvas 刮层有 `role=img` + 一键刮开等价路径；结果/浮层 `aria-live`；GO 按钮含票价 `aria-label`
- reduced-motion：动画跳过、结果直接呈现（组件内逻辑分支，不只靠 CSS 降级）

## 14. 遗留项收口（2026-09-19 第二轮）

上一轮列的遗留三项已全部落地（迁移 `0131_play_param_fill.sql`）：

| 项 | 内容 | 默认值 | 后台可见 |
|---|---|---|---|
| 刮刮乐 10x 概率 | `games_scratch_ten_pct` —— 五档全可配（原先 10x 恒为余数） | 2% | ✅ |
| 农场每小时配额 | `farm_max_plays_per_hour`（代码早已在读，但缺 settings_meta 行 → 后台改不了） | 30 次 | ✅ |
| 作物有效期 | `farm_wither_days` —— 成熟后 N 天不收即枯萎；**0 = 永不枯萎** | 5 天 | ✅ |

同时补上策划案里承诺但未实现的两项：

1. **枯萎机制（§6.4 农产品有效期）**：过熟地块标记 `withered`，展示灰化 + 🥀 标签 + 「清理地块」；浇水被拒；收获作废（0 魔力）但**清空地块**让玩家能重种；写 `farm_harvests(amount=0)` 留痕便于运营统计浪费。
   - ⚠️ **存量数据影响**：该机制此前只有注释、代码从未实现，因此**升级后已超期的存量地块会立即变为枯萎**（实测本机 4 块 9 天前成熟的地块全部枯萎）。站长若不希望追溯历史，把 `farm_wither_days` 设为 `0` 即可关闭。
2. **一键收获**：多块成熟时出现「🌾 一键收获（N）」，逐块调同一 harvest 端点（后端幂等 + 行锁，重复点安全），单块失败不中断其余，汇总反馈走浮层。
3. **猜大小路单统计**：`近 20 局：中 W · 平 T · 不中 L · 命中率 P%`（基于按局聚合的战绩算，不含流水噪音）。
4. **防沉迷软提示（§8.3）**：本次会话 ≥20 局、或今日净输 ≥5000 时给一条可关闭的提醒（**不阻断**）。

> 运维提示：`farm_wither_days=0` 关闭枯萎；`games_bigsmall_win_mult` 上限锁 2.0（等于 1 时不再回收，见 §2 P0-1）。
