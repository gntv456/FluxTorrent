# 设置页全面收口方案（2026-10-30）

> 前置：注册面已收口（0434/0435，「注册与邀请」分区 18 键两卡）。本方案把同一套
> 判据推广到全站 539 个可见键。审计数据与分流结论见同日记忆
> `fluxtorrent-settings-audit-2026-10-30`。

## 目标（成功判据）

1. 发种/字幕门禁键归位单一分区，配置不再跨区跳转；
2. 全部分区有中文标签且左导航按稳定业务序排列（`settings_group_order` 全覆盖）；
3. 死键（全仓零消费者且非动态拼名）全部出清：设置页不再渲染任何"改了没反应"的卡；
4. A 类（功能在旋钮死）逐个处置：低风险接线或撤卡，C 类记入 backlog；
5. 每批落地后测试一批：schema 真机断言 + 三道门禁（fake_switch / 迁移链 /
   checksum）+ 常备审计（MB 台账删号 / MB4 棘轮下调），全绿才进下一批。

## 判据口径（全批通用）

- **死键**：`fake_switch_baseline.json` 基线 ∩ 当前可见键，且不属已知动态拼名族
  （`arule_*` 由 `review_auto.rs:239` format! 拼名；`seeding_*` 由迁移 0136
  `seeding_params()` 函数体读；`module_*` 前缀通用读取）。
- **归位**：只动 `site_settings.grp` / `settings_meta.group_key` /
  `card_order` 三个展示坐标，不动值、不动消费者代码。
- **摘键**：`DELETE settings_meta + site_settings` 两行同摘（0193/0434 先例）；
  `fake_switch_baseline.json` 不动（guard 只认 INSERT，墓碑机制）；但
  `pt_audit_mb_dead_setting_cards.py` 的 LEDGER 必须同步删号（0435 的
  tmp_invite_count 教训），MB4 棘轮 `MEASURED_CEIL` 按实测下调。

## 批次

### B1 发种门禁归位（迁移 0436）

把散在 5 个分区的发种/字幕门禁键归到 publishing 分区（该分区已有
`publish_credits_threshold` 孤键，语义正好），按动线三张卡：

- **发布门禁**（12 键）：upload_auto_approve_class / upload_title_pattern /
  upload_min_descr_len / upload_require_screenshots /
  upload_require_mediainfo / upload_dup_policy /
  upload_torrent_max_bytes / upload_deny_approval_deny_count /
  uploader_seed_enabled / uploader_seed_min / uploaderdouble /
  publish_credits_threshold
- **抓轨日志**（4 键）：logcheck_policy / logcheck_min_score /
  logcheck_max_kib / logcheck_gate_site_types
- **字幕审核**（3 键，孤儿 grp='' 一并收编）：subtitle_moderation /
  subtitle_bad_threshold / subtitle_ext_whitelist

留在原地的（有充分理由，不是遗漏）：

- `uploadtorrent` / `uploadsubtitle`（发种/发字幕的**奖励**数值）——留在
  bonus/行为奖励卡，与签到/回帖奖励同属"奖励面"；移走会把奖励卡拆碎。
- `upload_auto_promo_kind/days` / `upload_price_tax`（发种自动促销/税率）——
  留在 basic/经济卡，促销与计税是经济语义。
- `basic` 分区 `经济` 卡、`main` 分区 `上传限制` 卡清空后自然消失。

验收：schema 断言 publishing 三卡 19 键如上；torrent/torrent 卡不再含
upload_*/logcheck_*；三道门禁绿。

### B3 死键摘除·第一批：近乎全死分区（迁移 0438）

摘除三区死键（判据干净、无真键混杂风险）：

- authority：47 死键（保留唯一活键 staffmem）——NP 权限矩阵被自研
  authz/perm_key 取代（B 类）；
- security：13 死键（enable_two_step / enable_passkey_login /
  cheaterdet / cheater_detection_level / enable_attendance_captcha /
  use_challenge_response_authentication / login_secret_lifetime /
  guest_visit_type / loginattemptwhitelist / maxip / maxloginattempts /
  securelogin / securetracker）——2FA/Passkey 是用户级开关、登录锁定走
  Redis acctlock、探测阈值写死 SQL（A 类处置见 B5，卡先撤）；
- advertisement：6 键全死——广告功能从未实现（C 类，backlog 记档）。

分区本身保留（authority 还有 staffmem；security 还有 7 个活键；
advertisement 分区随全灭自然消失——由 group_key='广告' 的 main 分区 1 键

验收：schema 三区死键出清；MB 审计 LEDGER 删号 + MB4 基线下调（预计
