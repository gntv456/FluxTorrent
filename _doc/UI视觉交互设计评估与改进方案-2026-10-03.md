## 0. 一句话结论

**这个站的视觉设计不是"不好看"，而是"没有系统"。**

TIDE 主题的令牌层（`theme-tide.css`）质量相当高——语义位重映射清晰、注释里写明了纪律、圆角从 24/20/14/10 收敛到 18/14/10/6。但这套令牌**只覆盖了色彩层**，而项目在随后几个月里长出了 760 处硬编码色值、19 种圆角、34 种字号、47 个断点值、18 个 z-index 值。

结果是：**每一个"看起来不统一"的问题，都能追溯到"缺少某一层令牌"**。这不是审美问题，是工程问题。修完 P0 会有肉眼可见的改善，但真正的收益在于建立门禁，让它不再退化回去。

## 1. 三个"用户操作了但系统没响应"的 P0

这类问题最严重：用户付出了操作，系统没有反馈。这不是审美瑕疵，是功能缺陷。

### P0-1 深色模式完全失效（用户点月亮图标，配色一动不动）

**根因已定位到行：**

```
apps/web/app/globals.css:19   @import "./styles/theme-tide.css"   ← 在 base.css 之后
apps/web/app/styles/theme-tide.css:24-25
:root,                          ← ←← 就是这里
[data-theme="baozi"] {
  --surface-page: #f6f8fc;      /* 浅色 */
```

`base.css:126` 定义得**完全正确**的夜间令牌（`--surface-page:#0f1424` / `--surface-card:#1a2036` / `--ink:#e8eef9`）被 `theme-tide.css` 的 `:root` 块同特异性、后出现地全覆盖。

讽刺的是 `theme-tide.css:21` 的注释写着：

> 绝不触碰 `baozi-night` —— 夜间主题保持原样，回归必测。

**`:root` 就是触碰了。** 全文件 21 行 baozi-night 只出现 1 次，就是这句注释。注释与代码行为相反——这条纪律从来没被真正执行过。

**实测**：`data-theme="baozi-night"` + `localStorage=baozi-night` 状态下，`body` 背景是 `rgb(246,248,252)`，`--surface-page` = `#f6f8fc`，与浅色模式逐像素几乎无差别。

**连带伤害**：`arcade-sweet.css` 用的是 `[data-arcade="sweet"][data-theme="baozi-night"]` 双属性选择器（特异性 0,2,0）**会正常生效**——所以娱乐屋是站内唯一有深色表现的版块。用户会得到"娱乐屋是深色的、主站是浅色的"割裂感。

**修法（二选一，推荐 A）**：
- **A（1 行）**：`theme-tide.css:24` 摘掉 `:root,` 保留 `[data-theme="baozi"]`。风险：所有不带 `data-theme` 的页面（若有）会掉回 base.css 的旧令牌。
- **B（更稳）**：保留 `:root`，但在 `theme-tide.css` 末尾补一个 `[data-theme="baozi-night"]` 令牌回填块，把 62 处浅色覆盖的令牌在夜间重新赋值。工作量 62 行，但显式、可控、顺带补齐夜间缺失的令牌。

**验证**：`chk-theme.mjs` 断言 `document.documentElement.dataset.theme='baozi-night'` 时 `getComputedStyle(document.body).backgroundColor` 的亮度 < 40。

### P0-2 移动端种子列表每行露出砖红色块（像渲染破损）

**根因**：`torrent-row-card.tsx:47-56` 渲染了 `.trow-swipe__acts` 作为左滑操作层，而 `pages.css:3469-3490` 里：

```css
.trow-swipe__acts { position: absolute; top:0; right:0; bottom:0; display:flex; }
.trow-swipe__act  { width: 64px; background: var(--sky-deep, #0a3d6b); }
.trow-swipe__act.is-fav { background: var(--coral, #e11d48); }  /* ← 砖红 */
.trow-swipe__front    { position: relative; transition: transform .15s; }
```

`.trow-swipe__front` 靠 `position:relative` + 后写覆盖住 `.trow-swipe__acts`——但**卡片内容是透明背景**，所以砖红的操作层会**从卡片底下透出来**，贴在右缘。桌面端能看到行末的红色 ⬇ 箭头，移动端是一整块 64px 宽的砖红色块。

**这不是设计意图，是 z 轴打架。** 滑动操作层本该在 `translateX(100%)` 处待命，等 `useSwipe` 改变 offset 时才滑入。

**修法**：给 `.trow-swipe__acts` 加 `transform: translateX(100%)`（或 `right: -128px`），由 `useSwipe` 的 offset 驱动。顺手加 `background: var(--surface-card)` 给 `.trow-swipe__front` 兜底。

### P0-3 `/login` 底部提示框被裁且无滚动（内容永久丢失）

`layout.css:721-732`：

```css
.bz-login-card {
  min-height: 615px;              /* canvas */
  max-height: 563px;              /* card ← 上限写死 */
  overflow-y: auto;               /* 有滚动，但被 max-height 卡住 */
}
.bz-login-notice { font-size: 9px; line-height: 1.6; }  /* ← 9px！ */
```

`max-height: 563px` 在 900px 视口下让提示框溢出。实测 `document.documentElement.scrollHeight === 900`（等于视口高度），**页面不产生滚动条**，用户无法看到被裁掉的"连续 5 次登录失败将触发每分钟限流"、"本站为邀请制私有站"等关键提示。

**附带问题**：`font-size: 9px` 是全站最小字号，低对比度浅蓝，放在提示框里几乎不可读——而这是登录安全相关的必要告知。

**修法**：`max-height` 改用视口单位（`max-height: calc(100vh - 200px)`）；`.bz-login-notice` 字号提到 12px；短屏走 `@media (max-height: 760px)` 隐藏插画栏给内容让位。

### P0-4 CSS 语法错误：`var()` 变量名中间带空格（3 处，影响 3 个状态标签）

`pages.css:1924/1928/1936`：

```css
.fun-status--funny      { color: var(--baozi-orang e-dark); }  /* ← 空格 */
.link-status--pending   { color: var(--baozi-or ange-dark); }  /* ← 空格 + 拼写错 */
```

浏览器解析 `var(--baozi-orang e-dark)` 时会把 `--baozi-orang` 当变量名、剩下的 `e-dark` 当 fallback，**整条 `color` 声明直接失效**。效果是趣味盒的「好笑/爆笑」标签和链接的「待审」标签**没有颜色**，掉回继承色。

同时暴露：全局有 **11 个悬挂变量 / 24 处引用**（`--muted` 7 次、`--ease-out` 5 次、`--card` 2 次、`--tone`、`--panel`、`--accent-soft`、`--marquee-duration`、`--fill-2`、`--trow-cat` 等），全部无定义、静默回退到浏览器默认值（`initial` / `transparent` / `0s`）。

> 附注：勘察子报告称"18 个悬挂变量"含 `--baozi-orange` 等，**这条是误报**——`--baozi-orange` 在 `base.css:117` 和 `theme-tide.css:148` 都有定义。真实数字是 11 个 / 24 处，根因就是上面这 3 处空格拼写错导致的正则漏配。

**修法**：修 3 处拼写；11 个悬挂变量逐个决定是"补定义"还是"改引用"；加一个 CSS 变量门禁（见 §6）。

## 2. 全站设计系统现状：数据基线

### 2.1 令牌层

| 指标 | 实测 | 判读 |
|---|---|---|
| CSS 变量定义 | 165 个 / 377 处声明 | 数量充足 |
| 变量引用总数 | 1,873 处 | 使用面广 |
| 死变量（0 引用） | 40 个（24.2%） | 其中 33 个是 `@theme` 桥接变量（Tailwind utility 命中），真死变量仅 7 个 |
| **悬挂变量（引用但无定义）** | **11 个 / 24 处** | **P0，见上** |
| 硬编码色值 | **760 处 / 342 个唯一值** | 集中在 arcade-sweet(248) / arcade(155) / base(140) / pages(98) |
| 同义不同名冲突组 | 8 组 | 见下 |

**8 组同义不同名**（这是"换不统一"的直接原因）：
- `--ink` ≡ `--text-strong`（同值 `#1f2a44`）
- `--sub` ≡ `--text-muted`（同值 `#6b7a99`）
- `--line` ≡ `--border-soft`（同值 `#e3edf7`）
- `--surface-cream` ≡ `--surface-raised`（同值 `#fbfcfe`）
- `--brand-soft` ≡ `--sky-soft`
- `--grad-rainbow` ≡ `--ribbon`
- `--muted-soft` ≡ `--surface-sunken`（近似）
- `--accent-purple` ≡ `--indigo`（同值 `#0a3d6b`）

TIDE 主题自己的注释说"变量名不变、语义位换色"——但结果是 8 组变量指向同一批颜色。改主题时只改其中一组，另一组就成了脏数据来源。

### 2.2 尺度层：全面失控

| 维度 | 实测 | 判读 |
|---|---|---|
| **断点值** | **47 个唯一值 / 87 处引用** | 最严重。`base.css:266-271` 已写好映射表（"md ← 700/720/768/860/900"），但映射表只存在于注释里，87 处引用照旧 |
| **圆角** | 19 种 / 242 处；令牌化率 23.8% | 令牌 4 档{10,14,18,20}，硬编码 16 档。**最高频的 `8px`(50 次) 和 `999px`(78 次) 都无令牌** |
| **字号** | 34 种 / 582 处；**半像素占 20.6%** | 全 px、0 rem。TSX 被迫写 `text-[11px]`(176 次)、`text-[10px]`(54 次) 任意值对齐 |
| **间距** | 438 处声明，**非 4 倍数占 59.4%**（260 处） | 高频是 10px(64)、6px(38)、14px(34)——都在 8px 栅格之外 |
| **z-index** | 18 个唯一值 / 52 处，**0 个令牌** | `z-index:90` 同时承担 4 种浮层语义（hover卡 / 新闻弹窗 / 娱乐屋弹窗 / 奖池特效） |

**`pages.css`（81 KB、553 个选择器，全站最大）里 `prefers-reduced-motion` 出现 0 次**——而这是用户前庭障碍的真实需求。`motion-tide.css` 里有专门的动效文件，但页面级动效完全没做降级。

### 2.3 性能：娱乐屋拖累全站

`arcade.css`(55 KB) + `arcade-sweet.css`(68 KB) = **120.3 KB 全站加载**。

`globals.css:26,28` 把它们挂在**根 layout** 的 `@import` 链上，而 `games/layout.tsx` 不引 CSS。结果：**任何页面**（包括 `/login` `/upload`）都要下载并解析 120 KB 与娱乐屋无关的 CSS。

更麻烦的是 `arcade.css` 有 **307 个顶层选择器，其中 109 个（35%）是不带 `arc-/gc-/fp-/pp-` 任何命名空间前缀的裸类名**——它们会泄漏到全站，潜在污染其他页面的同名类。

## 4. 布局与信息架构问题

### 4.1 种子列表：表头无语义 + 300px 空白

看 `desk-torrents.png`——表头从左到右是「类型 / 标题 / ▣ / ⏱ / 💾 / 🌱 / 1 / ✅ / 操作」，其中 **6 列是无字图标或裸字符**。用户无法从表头判断哪列是什么。

数据行 6 个数字（`0 / 今天 / 50.0 MB / 1 / 0 / 1`）横向排开，**无列分隔、无对齐基准**，扫读极易串列。参考 PT 站（UNIT3D / Gazelle / NexusPHP）的通行做法是加列宽 + `title` 属性 + 窄屏降级为卡片（本站已有卡片模式，但表格模式仍是默认）。

列表下方 5 条数据撑不满 900px 视口，`y≈528` 到页脚 `y≈845` 之间是**约 300px 纯空白**——没有分页器、没有"加载更多"、没有空态引导。

### 4.2 种子详情：无栅格 + 5 种按钮样式

`desk-detail.png` 实测：详情页主容器只有一个 `width:1232` 的裸 div，**没有任何两栏栅格**（`.tsplit` 存在但未启用）。右侧 5 个统计块被绝对定位式摆成 **94px 宽的窄条**悬在页面右上，与左侧主区（800px）之间是大片空白。

- 海报是 **150×218 纯灰方块**，无图无图标，整页左侧 1/5 是一个巨大的灰色空洞
- 「魔力值奖励」6 个按钮横排**几乎溢出虚线框**
- 同页 6 个按钮出现 **5 种样式**（砖红下载 / 白底描边 / 蓝实心 / 金黄 / 白底描边），且**破坏性「删除」与普通「编辑」视觉权重相同**
- 「评论 (0)」是裸文字居中，**没有输入框、没有登录引导**——用户想评论不知道从哪下手
- 移动端操作区出现**完全空白的圆角块**（无文字无图标），是明确的渲染残留

### 4.3 `/my` 控制面板：字形缺失 bug + 卡片不齐

`desk-my.png` 亲眼可见：侧栏第 4 项只有一个**孤立的「、」字符**，没有文字没有图标。根因在 `usercp.tsx:28-36`：

```ts
export const USERCP_NAV: { key: UsercpTab; icon: string }[] = [
  { key: "overview", icon: "⌂" },   // ⌂
  { key: "personal", icon: "♙" },   // ♙
  { key: "fields",   icon: "✎" },   // ✎ ← 缺字形，渲染成「、」
  { key: "tracker",  icon: "⚙" },   // ⚙
  { key: "forum",    icon: "♧" },   // ♧
  { key: "security", icon: "⌾" },   // ⌾
  { key: "wishlist", icon: "☆" },   // ☆
];
```

七个图标全是**键盘符号 / 棋类字符 / 装饰字符**，不是语义图标。而且 `⚙` 在 `overview` 和 `tracker` 两处都用了（虽然 `overview` 的 `⚙` 在注释里，实际代码是 `⌂`）——**同一个符号承担两种语义**。

**同时这一项的 `fields` tab 在移动端是第 4 个显示项，且导航没有横向滚动/折叠机制**（`mob-my.png`：8 项只显示 4 项就被右缘切断，后 4 项不可达）。

其他：`分享率` 卡内 2×2 网格因高度差（`当前活动 5` 带副注 vs `上传量 1.00GB`）导致**同排卡片底边参差**；`最近登录 2026-10-03 23:55:02` 字号 20px **把整行卡片的垂直节奏撑爆**；`登录活动` 的描述文字溢出卡外。

### 4.4 `/upload`：控件高度 6 种混排 + 必填/选填无视觉区分

`desk-upload.png` 实测六种控件高度：**62px（.torrent 拖拽）/ 40px（标题输入）/ 62px（NFO）/ 62px（附件）/ 60px（MediaInfo textarea）/ 32px（价格）**。价格那个 32px 输入框在整页里明显矮一截，垂直节奏完全乱。

**必填与选填视觉完全相同**——`.torrent 文件`、`标题` 不写「可选」，`NFO/附件/MediaInfo` 写「可选：…」，但三者的虚线框、灰底、居中文案**样式完全一致**，用户必须逐字读占位符才知道必填还是选填。

`价格` 行：标签下输入框宽 110px，右侧 700px 全空，提示文字紧贴输入框右边。标签列固定 100px 与输入区 810px = **1:8 比例**。

移动端「提交发布」是 `position:fixed` 吸底条，**盖住「附件/截图」输入区下半部分**（文案被切在 `txt ≤ 8MiB` 处），无法滚动避开。

### 4.5 `/games`：hero 中间 320px 空白 + 孤行卡片

- hero 区宽 1080px，文字全挤在左侧 x=20–280，**右侧 x=600→1080 是纯渐变色块**（横向渐变的金色区暗示"这里该有东西"，空着更刺眼），只有最右端悬一个小小的「9 / 9 款玩法」
- 5 个玩法图标各 40×40，间距 68px，**图标比间距小一半**；图标与下方 12px 文字标签垂直间距 20px > 图标自身高度
- 「即时开奖」5 张卡排 5 列网格，**第 5 张（大转盘）孤立掉到第二行**，右侧留 3 张卡宽度的空白 → 改 3+2 居中
- 奖池区 20+ 个小方块，字号 **8–9px**，方块间无间隔，**视觉上是一条噪点带**
- 四条进度条（左端条长几乎一致接近满格）配 1479/618/618/1218 的数值，**条形长度与数值不成比例，传达了错误信息**
- 移动端「养成经营」第 2 行（宠物/钓鱼）**只露上半截就被视口裁掉**，且无「查看全部」入口

### 4.6 移动端浮层打架

实测三处 `fixed` 浮层各自为政、互不避让：
- `.filter-fab` 高级搜索 FAB：`[266,724] 108×44`，`z-index:45`，**直接压在种子卡标题与统计行之上**（`elementFromPoint` 命中自身）
- 底部导航：`fixed bottom-0`，高 57px，y=787
- 「发布」圆形按钮：半悬在导航条上沿，与「消息」「我的」**不在同一水平线**（y≈1008 vs y≈1015），并遮挡了「搜索」与「发布」之间的分隔

移动端顶栏 logo 在 390px 下宽 160px 字号 20px，**占顶栏 41% 宽度**（桌面端仅 12%），右侧四个控件挤在 180px 内。

### 4.7 `/admin`：空图表 + 被裁卡片

- 「14 天注水/养种趋势」是 **500×220 纯空白框**，只有左下角图例，无折线/无网格线/**无「暂无数据」空态文案** → 看起来是坏的
- 右侧 5 个指标卡排 2 列×3 行，**最后一行只有 1 张卡**，右侧空一格
- 「作弊探测 —」卡**没有边框和背景且高度被裁**（前三张 78px，第四张 ~50px），四卡底边不齐
- 侧栏折叠箭头在**已展开态仍指向右 `›`**（应 `˅`），箭头语义与实际状态矛盾
- 移动端 h1「管理组面板」与搜索框并排，**占位文字 `(Ctrl/⌘ + K)` 被右缘裁切**（只剩 `K`）

### 4.8 `/forums`：左栏承载 1 个导航项 + 500px 空白

左栏 **163px 宽、88px 高**的小卡只放了「综合交流」一项，其下方到页脚是约 500px 空白。整个左侧 1/5 版面承载一个导航项，右侧主栏挤 5 个版块。

**4 个 0 话题版块与 1 个有内容的版块视觉完全同构**（同样的 90px 高卡、同样样式），用户无法一眼分辨哪个版块有货。

hero 区四元素间距不等：搜索框 x≈272、标题块 x≈588、关注流 x≈800、发新主题 x≈940，**间隔 150/180/90px 三段不等宽**，整体节奏碎裂。

### 4.9 圆角与图标：两套语言混用

**圆角**：`radii` 采样证实**单个 `/torrents` 页面内就并存 6 种**——`999px`(胶囊)、`8px`、`6px`、`10px`、`0px`（直角）、`50%`（圆形）。全站 19 种，无令牌。

**图标**：三套混用
1. **彩色 emoji**（`📣📅🎪💠📝☁`，首页 6 处）
2. **单色线性 SVG/字体图标**（导航 🔵、统计 ↑↓）
3. **键盘符号/装饰字符残留**（`/my` 侧栏 `⌂♙✎⚙♧⌾☆` + 那个孤立的「、」）

第 3 类是明确的**字体降级失败**。

## 5. 空态设计缺失

「有内容时好看、没内容时垮掉」是通用系统最典型的短板。当前 5 处**既无空态文案也无加载占位**：

| 位置 | 现状 |
|---|---|
| `/torrents` 列表下方 300px | 无分页器 / 无「加载更多」 / 无空态 |
| `/admin` 趋势图 500×220 | 无「暂无数据」/ 无坐标轴 |
| `/torrent` 「还没有评论」 | 裸文字居中，**无输入框无引导按钮** |
| `/forums` 4 个空版块 | 与有内容版块视觉同构 |
| `/my` 「等级进度 —」 | 孤零零破折号，无「暂无等级」引导（而同排「成就徽章 0 枚」有副注「暂未有效徽章」，处理不统一） |

另：`/torrents` 右上角「列表 / 卡片 / 海报墙」（视图切换）与「20 50 100」（分页）**外观几乎相同、紧邻同一行、无分隔**，极易误点。

## 6. 改进方案：四层递进

改造按依赖顺序推进。**每层结束都能独立产生价值，不必等全部做完。**

### 第一层：止血（预计 0.5 天，约 60 行改动）

| # | 修什么 | 改哪 | 成本 |
|---|---|---|---|
| 1 | 摘掉 `theme-tide.css:24` 的 `:root` | 1 行 | 极低 |
| 2 | 修 `pages.css:1924/1928/1936` 变量名空格 | 3 处 | 极低 |
| 3 | `.trow-swipe__acts` 加 `translateX(100%)` + `.trow-swipe__front` 补背景色 | `pages.css:3469` | 极低 |
| 4 | `.bz-login-card` 的 `max-height` 改 `calc(100vh - 200px)`，`.bz-login-notice` 字号 9→12px | `layout.css:721/1120` | 极低 |
| 5 | `USERCP_NAV` 七个键盘符号 → 语义 SVG（`components/icons.tsx` 已有图标集，直接复用） | `usercp.tsx:28-36` | 低 |
| 6 | 11 个悬挂变量逐个补定义或改引用 | 3 个文件 | 低 |

**验证**：`chk-theme.mjs`（夜间模式亮度断言）+ 移动端种子列表截图复拍。

### 第二层：补齐缺失的令牌层（预计 2-3 天，新增约 300 行）

这是**解决"看起来不统一"的唯一根治路径**。当前只有色彩层有令牌，尺度层全靠硬编码。

**新增令牌（补在 `base.css` 的 `@theme` 块，与 Tailwind v4 对齐）**：

```css
/* 间距：8px 栅格为主，4 为半档 —— 覆盖现存 59.4% 的非 4 倍数 */
--sp-1: 4px;   --sp-2: 8px;   --sp-3: 12px;  --sp-4: 16px;
--sp-5: 24px;  --sp-6: 32px;  --sp-7: 48px;
/* 圆角：把最高频的 8px 和 999px 收进来 */
--r-xs: 4px;   --r-sm: 6px;   --r-md: 10px;
--r-lg: 14px;  --r-xl: 18px;  --r-pill: 999px;
/* 字号：消灭半像素，全站收敛到 9 档 */
--fs-xs: 11px;  --fs-sm: 12px;  --fs-base: 14px;  --fs-md: 16px;
--fs-lg: 18px;  --fs-xl: 22px;  --fs-2xl: 28px;  --fs-3xl: 36px;
/* z-index：18 个值收敛为语义 8 档 */
--z-base: 0;      --z-raised: 10;   --z-sticky: 30;
--z-nav: 40;      --z-fab: 45;      --z-dropdown: 50;
--z-overlay: 70;  --z-modal: 90;    --z-toast: 120;
/* 触控尺寸 */
--tap-min: 44px;
```

**合并 8 组同义变量**：`--ink`/`--text-strong`、`--sub`/`--text-muted`、`--line`/`--border-soft`、`--brand-soft`/`--sky-soft`、`--grad-rainbow`/`--ribbon`、`--accent-purple`/`--indigo`、`--surface-cream`/`--surface-raised`、`--muted-soft`/`--surface-sunken` → 各保留一个真源，其余改为 alias（`var(--text-strong)`）。

**启用断点映射表**：`base.css:266-271` 已写好 `md ← 700/720/768/860/900`，加一个 stylelint 规则把这 11 个野点标为 `warning`，分批收敛。

**娱乐屋 CSS 按路由加载**：`arcade.css` / `arcade-sweet.css` 从 `globals.css` 的根 `@import` 链移到 `games/layout.tsx`（Next.js 支持组件级 CSS import），**全站省 120 KB**；同时给 109 个裸类名加 `arc-` 前缀（用 `sed` 批量 + 逐一人工核对）。

### 第三层：组件与布局统一（预计 5-7 天）

**新建 `components/ui/` 基础组件层**（当前 `components/ui/` 目录是空的）：

- `<Button variant="primary|secondary|ghost|danger" size="sm|md|lg">` — 统一圆角/阴影/焦点环/最小触控尺寸，消灭「同页 5 种按钮样式」
- `<StatCard label value unit hint>` — 首页 4 张无标签统计卡、`/admin` 指标卡统一
- `<EmptyState icon title desc action>` — 5 处空态统一
- `<DataTable>` — 种子列表/字幕/管理端表格统一，**表头强制带文字或 `title`**
- `<Field label required error>` — `/upload` 表单统一，**必填/选填有视觉区分**，高度统一 40px
- `<Sheet>` / `<Modal>` — 复用已有 `modal.tsx` / `bottom-sheet.tsx`

**建立共享响应式栅格**（当前 93 个页面有 4 种容器宽度策略、详情页零栅格）：

```css
.bz-container { max-width: 1232px; margin-inline: auto; padding-inline: 16px; }
.bz-grid { display: grid; gap: 16px; grid-template-columns: minmax(0,1fr); }
@media (--bp-lg) { .bz-grid--split { grid-template-columns: minmax(0,1fr) 320px; } }
```

详情页右栏从 94px 窄条改成 320px 标准侧栏，启用已有的 `.tsplit` 网格。

**移动端浮层统一管理**（`apps/web/lib/overlay.ts`）：
- FAB 避开底部导航（`bottom: calc(57px + 12px)`）
- 「发布」圆钮与导航图标同一水平线
- 顶栏 logo 移到窄屏 20px 字号
- `/my` 侧栏加横向滚动或「更多」折叠

**图标统一**：抽 `components/icons.tsx` 为唯一来源（它已存在），删掉 emoji 与键盘符号；`/my` 侧栏、「两步验证」、Passkey 入口等统一。

### 第四层：门禁与动效降级（预计 1-2 天，长期收益最大）

**这是唯一能防止问题复发的投入。** 项目已有 `scripts/*.mjs` 门禁体系（`check_type_drift.mjs`、`line_limit_guard.mjs`、`i18n_guard.mjs` 等 20+ 个脚本），照同样模式加：

**`scripts/ui_design_guard.mjs`**（照 `check_type_drift.mjs` 的结构写）：
1. CSS 变量门禁：`var(--x)` 引用必须有定义（挡 11 个悬挂变量）
2. 硬编码色值门禁：`styles/*.css` 中 `#hex` 出现次数**只减不增**（基线 760），新文件从 0 起算
3. 断点门禁：`@media` 只允许 Tailwind 4 档（640/768/1024/1280），野点计数只减不增
4. z-index 门禁：只允许 9 个语义档
5. 圆角/字号门禁：硬编码值必须落在令牌内
6. 触控目标门禁：TSX 中可交互元素 `min-height < 44px` 报错

**ESLint 补规则**：`apps/web/eslint.config.mjs` 当前**只有 `next/core-web-vitals`，零样式规则**。加 `jsx-a11y` 核心 4 条：`control-has-associated-label`、`click-events-have-key-events`、`no-noninteractive-tabindex`、`label-has-for`。`label-has-for` 会一次性报出 400 处 `<label>` 缺 `htmlFor`。

**动效降级**：`pages.css`（553 个选择器，全站最大）补 `prefers-reduced-motion: reduce` 降级块，覆盖 `transition` / `animation` / `transform`。

**空态补齐**：5 处空态按「文案 + 图标 + 一个引导动作」三件套补齐；`/torrents` 补分页器或「加载更多」。
