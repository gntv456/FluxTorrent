## 1. 总体结论

**方向正确、地基扎实，但存在系统性的「教育站缺省」残留与若干前端漏网，且站长自定义能力在天花板处截断。**

具体分四句话：

1. **架构层已经对齐通用建站定位**：站型包（11 预置 + `custom_*` 自定义）、模块开关注册表
   （API 网关 fail-close / 页面守卫 / 导航过滤 / worker 跳过四处一致）、安装向导、生态商店
   （内容包四品类 + 适配器沙箱）、约 300 个设置键、分类/维度/标签全后台 CRUD——「站长选站型 →
   应用 → 微调 → 开站」的闭环是成立的，README 与总纲口径一致（`README.md:3`、总纲 §1.1）。
2. **但系统的「缺省形态」仍是教育站**：模块注册表缺省全开（`modules.rs:98-101`，仅 3 键默认关），
   全局共享的旧三列词表仍是「幼儿园/一年级/人教/部编」（`0001_init.sql:68-74`）——任何未显式落键的
   实例、任何未收敛的路径，都会退回教育站形态。这与「不偏向任何一类」直接冲突。
3. **前端有一批不消费模块开关的漏网点**：首页抽奖/娱乐板块、4 个无守卫页面（exams/myhr/endangered/teams）、
   详情页字幕面板、字幕评选榜、user-menu/footer 快捷链接——后端关了、前端还在展示，站长「关不掉」
   或关了之后留下报错残页。
4. **站长自定义能力在「数据层」很充分，在「结构层」截断**：维度/词表/标签/设置全可配；但用户自定义字段、
   分类层级、等级体系调整、公式结构、新页面类型必须改代码。对「轻松自定义需要的功能和字段」这一目标，
   种子侧已达标（受控维度可完全自定义），用户侧与结构侧仍是硬天花板。

另有一类**文档债**：早期文档（09-08 策划方案、vs NexusPHP 对比）仍以「教育垂直引擎」自我定位，
与后期通用化口径并存，未加头注声明口径已被取代。

## 2. 定位基准与符合度评分

### 2.1 定位基准

以《通用PT建站系统策划案.md》§1.1 的正式定位为准（本次审查目标与其一致）：

> **FluxTorrent = 开箱即用的通用 PT 建站系统**：站长选站型（或自定义）→ 应用站型包 → 微调开关与参数 → 开站。
> 官方镜像只发一份，所有站型差异由**数据与配置**表达，不 fork 代码。

三条硬约束（总纲 §10 纪律 D3 + 本次目标重申）：

- C1：不得偏向任何一个 PT 类型——缺省形态必须站型中立；
- C2：站长不改代码即可搭建任意类型 PT 站——功能开关、字段、词表、外观后台可配；
- C3：关闭的功能必须**四处一致**下线（导航 / 页面 / API / worker），不留残页与报错态。

### 2.2 分域符合度评分

| 域 | 符合度 | 一句话判定 |
| :--- | :--- | :--- |
| 站型包与切换机制 | ★★★★★ | 11 预置 + custom_* 另存，diff 预览、replace/merge、安装向导三入口齐全 |
| 模块开关体系 | ★★★★☆ | 四处一致性设计优秀；扣分在缺省值教育偏向 + 前端漏网（见 G1/G2） |
| 种子字段自定义 | ★★★★☆ | section_kinds/section_dict 维度完全可配；扣分在旧三列教育词表双轨遗留（G3） |
| 分类/标签体系 | ★★★★★ | 分类 CRUD+图标键、标签两层词表+分组+站型包联动，全部后台化 |
| 页面/文案/外观 | ★★★★☆ | FAQ/规则/公告/首页排版/菜单树可配；扣分在 CSS 令牌与页面类型不可配（G4） |
| 经济与规则可配 | ★★★★☆ | 300 设置键 + 7 参数做种公式 + 规则引擎；经济常量已参数化（0109 落地） |
| 站长结构层自由度 | ★★☆☆☆ | 用户字段/分类层级/等级体系/公式结构/新页面类型必须改代码（G4） |
| 生态扩展（包/适配器） | ★★★★☆ | 内容包+适配器已交付；适配器编写需开发者、规则/主题键白名单偏窄 |
| 文档口径一致性 | ★★★☆☆ | 总纲/README 已通用化；早期文档仍自称教育垂直引擎（G5） |

综合：**「能搭任何类型的站」已基本成立；「不偏向任何类型」在缺省值与遗留词表上不成立；
「轻松自定义字段」对种子成立、对用户与结构不成立。**

## 4. 不合理之处清单（分级）

> 分级口径：**P0 = 与定位直接冲突，任何新站长开箱即可感知**；P1 = 明显削弱「自由搭建/轻松自定义」；
> P2 = 口径债与体验毛刺。每项均附实证位置。

### G1【P0】系统缺省形态 = 教育站（C1 冲突的核心）

1. **模块缺省全开（教育站形态）**：`modules.rs:98-101` `default_on` 仅 showcase/social/contests
   三键默认关，其余 26 键缺省全开——注释自述「T3：= 当前教育站形态」。任何未显式落 `module_*`
   键的实例（新库未 apply 包、pack 未声明 modules、键被误清空），无论站长选了什么站型，
   都会得到一个「课本中心 + 绩效考核 + 考试 + 娱乐屋全开」的教育/娱乐复合站。
2. **站型矩阵未覆盖 general**：`0107:97-107` 只给 movie/music/anime/ebook/sports/game/software/
   documentary 八包播种模块矩阵；general（综合站，0119 起已是新站默认）没有行——综合站 apply 后
   的模块状态退回 0037 快照 + default_on 缺省，未按「综合站」口径收敛。
3. **全局旧三列词表是教育硬编码**：`0001_init.sql:68-74`，grades=「幼儿园…高三」、
   editions=「人教/部编/统编/苏教/北师大/外研/沪教」——这是**全局实体表，所有站型共享**。
   影视/音乐站的列表筛选参数恒绑定这三列（`torrents/list_noclamp_as.rs:212-214,277-279`），
   前端列表行与详情页规格网格消费的也是这套词表（`torrent-table.tsx:94-102`、
   `torrent/[id]/page.tsx:116-121,207-225`）。目前仅靠「无值则不显示」缓解——但「幼儿园/人教」
   作为系统词表存在于任何非教育站，本身就是偏向残留。
4. **产品叙事遗留**：早期核心文档仍以教育垂直自我定位并称之为「核心壁垒」
   （`_doc/FluxTorrent 策划方案.md` §1.1/§3.1；`_doc/FluxTorrent vs NexusPHP 功能对比.md` §1/§4），
   与 README/总纲的通用口径并存，无「口径已被取代」头注。

## 5. 整改方案

### R1【P0】缺省形态翻转：从「教育全开」到「核心最小集」

**目标**：任何未显式配置的实例，缺省得到一个**中立的通用站**（资源库/论坛/基础经济），而不是教育娱乐复合站。

**做法**：

1. **重定义 default_on 最小核心集**（`modules.rs`）：缺省仅开核心不可关面
   （torrents/forums/messages 等核心路径本就不在模块注册表内），注册表内键缺省一律改关
   （textbooks/jixiao/exams/games/farm/gomoku/contests/subtitles/preserve/resurrections/dressup/
   medals/bank/shop/…全部缺省关；social/showcase/contests 维持关）。
2. **哑变迁移**（新增 0178）：为**存量实例**把当前生效形态显式落成 `module_*` 键
   （读取现值/default_on 计算结果并 INSERT），保证「回归零伤」（总纲 §1.3 指标 3）——
   存量站长升级后行为不变；缺省翻转只影响「从未配置」的新实例。
3. **补齐站型矩阵**：`site_type_packs.modules` JSONB 为 11 个预置包全部补上完整 29 键快照
   （general=综合站口径：关 textbooks/jixiao/exams/farm 等，开 offers/requests/wishlist/subtitles 等
   品类无关面；movie 开 subtitles/preserve；music/lossless 开 subtitles 且 subtitle_kind=lyric…），
   并让 0107 矩阵口径与之一致。apply 后站长看到的开关状态 = 站型推荐值，而非教育缺省。
4. **契约测试更新**：modules.rs 契约测试补「缺省=关」断言；regression.py 补两条验收——
   干净库 apply lossless 与 game 后，分类/维度/模块/导航全部随站型变化且无教育功能在场（总纲 §1.3 指标 1）。

**工作量**：约 2–3 天（含矩阵设计与回归）。
**验收**：干净库不 apply 任何包 → 无课本/考核/游戏入口；apply 任意包 → 模块状态与该包矩阵一致；
存量库升级 → 行为零变化。

### R3【P1】旧三列词表退役（双轨归一）

**原则**：sections 体系是唯一未来；旧三列分三步退场，不做大爆炸。

   （非教育站清空 grades/editions 行、media 保留通用媒介词表或映射到 sections media 维）。

## 7. 长期纪律：防止再犯

在总纲 §10 纪律（D3「任何站型专属 if 进代码即违例」）基础上，本轮审查建议增补四条：

1. **缺省中立原则**：任何新模块键注册时缺省必须是「关」（或明确写入对应站型包矩阵），
   评审清单加一项「default_on 是否站型中立」。教育形态只是 11 个预置之一，不是系统缺省。
2. **四处于敛门槛**：新功能合并前必须同时过——API 网关映射、页面 requireModule、导航/入口
   mod() 过滤、worker 锁（若有后台任务）。只做后端开关不做前端消费的 PR 打回。
3. **词表单一真相**：任何面向站长的词表/维度只能进 sections 体系或受控字典表，
   禁止再向全局实体表塞品类词表。
4. **自定义能力预算**：每个大版本至少评估一次「本版新增的配置面是数据层还是结构层」，
   结构层需求（字段/层级/页面类型）不得静默用代码硬编码消化——要么排期 R4 类改造，要么在文档明示边界。
