# 第三方工具适配视角：对接需求与改进建议

> 立场：本报告以「PT 站点第三方工具适配开发者」的身份写成——即站在
> PT-Plugin-Plus / PT-depiler / cross-seed / Prowlarr / Sonarr·Radarr / MoviePilot /
> autobrr / IYUU / qBittorrent-RSS 这一侧的立场，评估「要接你的站，我需要你提供什么」。
>
> 方法：读源码定位实现 → 起本地栈真机打端点 → 与主流工具的真实契约逐条对照。
> 环境：本地 docker 栈（api 8080 / tracker 7070 / web 3000），库内 1 枚过审测试种。
> 日期：2026-10-02。

---

## 一、结论速览

站点已经埋好了三通道骨架（NP 兼容层 / 开放 API Token / Torznab），
**方向完全正确，且领先于多数自研站**。但从「工具真能跑起来」的角度看，
当前状态是 **"接口在、契约不到"**：形状像了，字段与语义还不够第三方工具消费。

一句话结论：**当前只有「用户信息类」工具（PTPP/pt_mate）能真正跑通；
「刷流类」和「媒体库类」工具全部卡在 P0 级契约缺陷上。**

| 级别 | 缺陷 | 谁被卡死 |
|---|---|---|
| **P0** | RSS 无 `<enclosure>`，`<link>` 指向网页 | qBittorrent RSS 自动下载 / autobrr / Flexget / cross-seed(RSS 模式) / PTPP 刷流 |
| **P0** | Torznab `caps` 根节点写成 `<torznab:search>`（应为 `<caps>`），无 `<searching>` | Prowlarr / Jackett 直接拒收索引器 |
| **P0** | Torznab item 缺 `<torznab:attr name="seeders|peers|infohash|downloadvolumefactor">` | Sonarr / Radarr 读到 0 做种、丢免费信息 |
| **P0** | Torznab 分类硬编码 `8000 Other` | Sonarr / Radarr 无法按媒体类型匹配 |
| **P0** | Torznab `t=tvsearch/movie` 及 `season/ep/imdbid` 被静默忽略 | Sonarr / Radarr 拿到未过滤结果 |
| **P1** | 兼容层/Torznab 强制 `seeders > 0` | 新种对工具不可见，冷启动期搜索恒空 |
| **P1** | 无 Token 化发种上传 API | PT-depiler / MoviePilot 自动发种 |
| **P1** | 登录端点只吃 JSON，拒绝 form-encoded | MoviePilot / autobrr 等按 NP `takelogin.php` 登录的工具 |
| **P1** | 兼容层不暴露 `info_hash` / `pieces_hash` | 辅种类工具（IYUU / cross-seed 精确匹配） |
| **P1** | NP 分类 `legacy_id` 全空、兼容层只返裸 id | 工具分类树错位、无法渲染标签 |
| **P1** | PTPP 收录模板缺 `passkey` 提取字段 | 用该模板提的 PR 装上即下载失败 |
| **P2** | 限流无 `Retry-After` / `X-RateLimit-*` | 第三方无法自适应退让 |
| **P2** | `compat/meta` 自描述缺 torznab/rss/open | 机器发现不全，工具集成时漏端点 |
| **P2** | 无 `getrss.php` / `details.php` / `takelogin.php` 别名 | 只认 NP 硬编码路径的老脚本无法零改造接入 |
| **P2** | 无 IRC announce；`/open/recent` 默认恒空且无 hash | autobrr 实时抓取、辅种反查均不可用 |

## 三、逐条详析

### P0-1｜RSS 不能用于刷流：无 enclosure，link 指向网页

**现象**
```xml
<item>
  <title>e2e-regression-seed e2e 15 MB · root</title>
  <link>http://localhost:3000/torrent/40</link>
  <guid isPermaLink="true">http://localhost:3000/torrent/40</guid>
  <pubDate>…</pubDate>
  <description>e2e · 15 MB</description>
</item>
```
没有 `<enclosure>`；`<link>` 是**站内详情页**，不是 `.torrent`。
`?linktype=dl` 与默认输出逐字符一致——读源码可知它其实是
**标题格式开关**（`dl`=标题带元信息，`page`=仅标题），与"下载链接"无关。

**证据**：`apps/api/src/rss_http.rs:150`（verbose 判定）、`:166-178`（item 拼接，全程无 enclosure）。
模块自注释 `rss_http.rs:4` 写着「刷流工具（RSS 阅读器/下载器）凭 URL 自动拉新种」——**与实现不符**。

**谁被卡死**：qBittorrent RSS 自动下载（拿到 HTML 页当种子解析失败）、
autobrr feed、Flexget `torrent:` 规则、cross-seed RSS 模式、PTPP 刷流。

**建议**：item 内补
```xml
<enclosure url="{api_base}/api/v1/compat/nexusphp/download.php?id={id}&amp;passkey={passkey}"
           type="application/x-bittorrent" length="{size}" />
```
并把 `<link>` 默认改为 download.php（保留 `linktype=page` 时指向详情页，兼容旧行为）。
`linktype` 语义建议重命名/文档化，别让它看起来像"链接类型"。

### P0-2｜Torznab caps 根节点非法

**现象**：`GET /api/v1/torznab` 返回
```xml
<torznab:search xmlns:torznab="http://torznab.com/schemas/2015/feed">
  <server …/><limits …/><categories>…</categories><search-fields>…</search-fields>
</torznab:search>
```
Torznab caps 的根必须是 **`<caps>`**，能力声明必须放在 **`<searching>`** 下，
`<search-fields>` 不是 caps 的元素。

**证据**：`apps/api/src/economy_http/recon.rs:42-53`（整段是硬编码字符串）。

**谁被卡死**：Prowlarr / Jackett 添加索引器时解析 caps 失败 → **直接拒收**。
这条不修，Torznab 通道对媒体库生态等于不存在。

**建议**：
```xml
<caps>
  <server version="1.0" title="…" url="/api/v1/torznab" />
  <limits max="100" default="50" />
  <searching>
    <search available="yes" supportedParams="q" />
    <tv-search available="yes" supportedParams="q,season,ep" />
    <movie-search available="yes" supportedParams="q,imdbid" />
  </searching>
  <categories><category id="2000" name="Movies" />…</categories>
</caps>
```

### P0-3｜Torznab item 缺 `torznab:attr`（Sonarr/Radarr 的命门）

**现象**：实测 item 里是裸标签
```xml
<size>15728640</size><seeders>5</seeders><peers>7</peers>
```
而 Torznab 消费方读的是 **属性**：`<torznab:attr name="seeders" value="5"/>`。
当前实现**只**在促销命中时才输出一条 `<torznab:attr name="tags">`（`recon.rs:142-147`），
seeders / peers / infohash / 免费倍率全都没有。

**证据**：`recon.rs:148-177`。

**后果**：Sonarr/Radarr/Prowlarr 显示 **0 做种**（判为死种）、无法做「优先免费种」策略。
cross-seed 也拿不到 infohash 做精确匹配。

**建议**：每条 item 补齐
`seeders` / `peers` / `size` / `category` / `infohash` / `grabs`
/ `downloadvolumefactor` / `uploadvolumefactor`。
其中免费倍率直接由 `promotion` 映射（free→0，50%→0.5，x2→1 且上传 2，x2free→0/2）——
**这是站点促销引擎的价值出口，不输出等于白做促销**。

---

### P0-4｜Torznab 分类硬编码 8000

**证据**：`recon.rs:47-48`（caps 只播 8000/8001）、`recon.rs:159`（每条 item 都写死 `Other`）。
数据库 `categories` 表有 10 个真实分类（电影/电视剧/音乐/游戏/软件/动漫/纪录片/电子书/体育/综艺），
但对外一律标 `Other`。

**后果**：Sonarr 拿到"电影"结果却被标 Other → 不匹配；Radarr 同理；用户手动加分类映射也没用。

**建议**：给 `categories` 表补 `newznab_id`（或启用已存在但**全为 NULL** 的 `legacy_id` 列），
按 Newznab 标准映射：电影 2000 / 电视剧 5000 / 音乐 3000 / 电子书 7000 / 其他 8000。
caps 与实际 item 用同一张映射表，避免两处漂移。

---

### P0-5｜Torznab 搜索模式参数被静默忽略

**现象**
- `?t=tvsearch&q=e2e&season=1&ep=1` → 返回结果与 `?q=e2e` **完全相同**
- `?t=movie&imdbid=1234567` → 同样不做 imdb 过滤

**证据**：`recon.rs:91-101` 只读取 `q` / `limit` / `offset` 三个参数。
`t` 从不解析，`season`/`ep`/`imdbid` 直接丢弃。
（对照：`compat/nexusphp/torrents.json` **已支持** `imdb` 参数并会转 `search_area=4`，
复用即可，`nexusphp.rs:95-105`。）

**后果**：Sonarr 按「剧集 + 季」搜索得到站内全部含关键词的种子，命中率与准确度崩塌。

**建议**：解析 `t` 并按模式路由；`tvsearch` 认 `season`/`ep`（落库侧可用标题/季集字段），
`movie` 认 `imdbid`/`tmdbid`；不支持的参数组合明确返回空结果集而非"忽略参数照常搜"——
**静默忽略比报错危险**（工具以为过滤生效了）。

### P1-1｜`seeders > 0` 硬过滤把新种藏起来

**现象**：同一枚过审种子，`seeders=0` 时 `torrents.json` 返回
`items:[] total_estimate:0`；改成 `seeders=5` 后立刻出现。

**证据**：`apps/api/src/torrents/list_noclamp_as.rs:87-90`（`include_dead` 为假则追加 `AND t.seeders > 0`），
兼容层（`compat_http/nexusphp.rs:106-112`）与 Torznab（`recon.rs:117-123`）都走这条路径。

**后果**：新站/冷启动期，第三方搜索**恒为空**。用户装好插件、配好 Token、
搜索框输入任何关键词都是"无结果"——他不会去读你的文档说"这是活种视图"，
他只会判定"这个站的对接是坏的"。**这是工具侧最容易被误判成故障的一条。**

**建议**：对外层（compat / torznab）默认放开 `include_dead`，或提供
`include_dead=1` / `alive=0` 显式参数并在 caps 中声明；站内列表维持现状不动。

---

### P1-2｜没有 Token 化的发种上传接口

**证据**：`_doc/开放API接入指南.md:62-66` 自列「路线图（未上线）」含 `POST` 上传端点；
兼容层无 upload 端点；现有 `publish_http/upload.rs` 是网页会话发种，Token 调不通。

**后果**：PT-depiler、MoviePilot 的**自动发种**链路整条不可用——
而"发种自动化"恰恰是 PT-depiler 这类工具的核心卖点（比搜索更黏人）。

**建议**：`POST /open/torrents`（multipart：`.torrent` + 元数据 JSON），
`scopes` 增加 `upload`，响应回 `{id, pieces_hash, info_hash, duplicate: bool}`。
按 `pieces_hash` 幂等（文档 §5 已推荐此口径，但当前**没有接口能校验它**，见 P1-4）。

---

### P1-3｜登录端点拒绝 form-encoded

**现象**
```
curl -X POST -d 'username=root&password=x' /api/v1/auth/login
→ HTTP 400 {"code":1002,"message":"参数校验失败: Content type error"}
```
**证据**：`apps/api/src/auth_http/login.rs:18` 绑的是 `web::Json<LoginReq>`。

**后果**：按 NexusPHP `takelogin.php` 习惯用表单登录的工具（MoviePilot 站点定义、
autobrr 的登录模式、部分老脚本）无法建立会话 → 拿不到 passkey → 全线失败。

**建议**：兼容 `application/x-www-form-urlencoded`（actix 可同时挂 `web::Form` 分支）；
更省事的做法是在 compat 层加一个 `takelogin.php` 形式的薄壳。
另建议提供 `POST /open/session`（Token 换短期 Cookie），让浏览器类工具免去账号密码。

---

### P1-4｜不暴露 `info_hash` / `pieces_hash`，辅种与查重无法实现

**证据**
- `compat/nexusphp/torrents.json` 字段（`nexusphp.rs:125-143`）无 hash
- `compat/nexusphp/torrent/{id}.json`（`nexusphp.rs:198-212`）无 hash
- `GET /open/recent`（`openapi_http/open.rs:39-47`）只返 `id/name/description/size/published_at`
- 且 `open.rs:21-30`：站点默认 `guest_policy=all_private` → **该端点直接返回空数组**

**后果**：`_doc/开放API接入指南.md:52-56` 写着「批量反查：`/open/recent` 拿最新 50 条」
和「先按 `pieces_hash` 查重」——**这两句话在当前实现下都无法执行**：默认配置下端点返回空，
且即使放开也不含任何 hash 字段。文档承诺 > 实现能力，第三方照着做必然踩空。

**建议**：三处（兼容列表 / 详情 / `open/recent`）都补 `info_hash`（本站主键之一）与
`pieces_hash`；`open/recent` 增加分页与 `seeders`；
文档与实现二者改其一——建议改实现，hash 是辅种生态的通用语言。

---

### P1-5｜分类只返裸 id、`legacy_id` 全空

**证据**
```sql
select id,name,legacy_id from categories;  -- 10 行，legacy_id 全 NULL
```
兼容层输出 `"category": t.category_id`、`"medium": t.medium_id`（`nexusphp.rs:134-135`）——
**只有数字，没有名称**。实测样本返回 `"medium": null, "promotion": null`。

**后果**：工具无法渲染"电影/Blu-ray/2xFree"这类标签，必须为每个站自备映射表；
期望 NP 4xx 分类 id 的工具（按 NexusPHP 惯例 401=电影、402=电视剧）拿到 `1..10` 直接错位。

**建议**：补 `legacy_id` 种子数据并让 compat 层输出 `category`(NP id)，
同时**追加**（不替换）`category_name` / `medium_name` / `promotion_name` 字段。

---

### P1-6｜PTPP 收录模板缺 `passkey`

**证据**：`.research/ptpp-config-template/config.json:25` 下载模板用 `$passkey$`，
但 `:28-43` 的 `selectors.userBaseInfo` 里**没有任何 passkey 提取字段**。
插件拿不到 passkey → 拼出 `download.php?id=40&passkey=` → 下载 401。
另外 `:7` 的描述把站点写死成「教育垂直 PT」，与本系统"中立通用站型"定位不符；
`:11` 只列 1 条等级，实际等级由站点自配。

**建议**：`userBaseInfo` 增加 `passkey: { selector: ["data.passkey"] }`
（取自 `/compat/nexusphp/user.json`），并修正描述与 `levelRequirements`。

### P2 级（不阻断，但影响覆盖率与体验）

| # | 问题 | 证据 | 建议 |
|---|---|---|---|
| P2-1 | 429 无 `Retry-After`，正常响应无 `X-RateLimit-*` | 1 req/min 的 Token 第二次即 429，响应头空 | 429 带 `Retry-After`；成功响应带 `Limit/Remaining/Reset` |
| P2-2 | `compat/meta` 自描述只有 6 项，不含 torznab / rss / open / downloads | `compat_http.rs:26-48` | 补全 + 增 `capabilities` 段，让工具能自动发现能力 |
| P2-3 | 无 NP 别名路径 | 无 `getrss.php` / `details.php` / `userdetails.php` / `takelogin.php` | 加薄别名转发（成本极低，救活一批只认硬编码路径的老脚本） |
| P2-4 | 无 IRC announce | 全仓无 IRC 实现（09-28 策划已明确不做） | 不一定要做 IRC；提供 `GET /open/announces?since=<cursor>` 长轮询或 HTTP announce 推送（`docs/ops/events.md` 已有 webhook 底座）即可让 autobrr 类工具实时抓种 |
| P2-5 | Tracker 仅支持 compact | `apps/tracker/src/peers/bencode.rs:13-48` | 视情况支持 `?compact=0` 兜底老客户端 |
| P2-6 | `class` 返数字、`ratio` 在 downloaded=0 时返 `-1.0` | 实测 `user.json` | 追加 `class_name`；ratio 用 `null` 或 NP 惯例 `inf`，别用 `-1`（工具会当负数显示） |
| P2-7 | Token 180 天固定、不可续期 | `openapi_http.rs:184` | 加 `POST /me/tokens/refresh` 滚动续期，或到期前在响应头预警——NAS 长期运行的工具会静默断连 |

## 四、对接需求清单（Request for Integration v1）

以下是我方（第三方工具侧）希望站方**明确承诺**的最小能力集，按优先级排列。
每条给出验收标准，满足即可在兼容矩阵里标 ✅。

### P0 —— 不满足则工具无法工作

| ID | 需求 | 验收标准 |
|---|---|---|
| R-01 | RSS item 必带 enclosure 直链 | `curl /rss/{pk} \| grep -c "<enclosure"` ≥ item 数；qBittorrent RSS 能直接下载 |
| R-02 | Torznab caps 合规 | Prowlarr「测试索引器」通过；根节点为 `<caps>`，含 `<searching>` |
| R-03 | Torznab item 带 `torznab:attr` | Sonarr 结果显示正确做种数与免费标记 |
| R-04 | Torznab 分类映射 Newznab 标准 | Radarr 搜"电影"能命中站内电影分类 |
| R-05 | 支持 `t=search/tvsearch/movie` + `season/ep/imdbid` | Sonarr 按季搜索命中正确 |

### P1 —— 不满足则覆盖度与自动化能力残缺

| ID | 需求 | 验收标准 |
|---|---|---|
| R-06 | 对外层默认包含零做种新种（或提供开关） | 新发种后 1 分钟内可在 `torrents.json` / Torznab 搜到 |
| R-07 | Token 化发种上传 | `POST /open/torrents` 上传成功并回 `pieces_hash`，重复上传幂等 |
| R-08 | 登录兼容 form-encoded（或 `takelogin.php` 形状） | 表单登录返回 200 + 会话/passkey |
| R-09 | 列表/详情/`open/recent` 暴露 `info_hash` 与 `pieces_hash` | 辅种工具可按 hash 精确匹配 |
| R-10 | 分类/媒介/促销在 compat 层同时给 id 与名称，`legacy_id` 落数据 | 工具无需自备映射即可渲染标签 |

## 七、NP 兼容的安全评估（2026-10-02 追加）

> 起因：修复过程中被问「兼容 NP 会不会有安全问题」。
> 结论：兼容层本身不引入新的**漏洞类别**，但它把 NP 生态「凭据放进 URL」的既定习惯
> 带了进来；而实现过程中暴露出 **7 个真实的权限/节流/缓存缺口**，均已修复。

### 7.1 S-1｜`scopes` 只落库不校验（最严重）

`api_tokens.scopes` 从 0069 起就写库，但 `require_token` 从不读它。
后果：一枚声明 `["read"]` 的 Token（默认值）**可以调用任何后增的写端点** ——
包括本次新增的 `POST /open/torrents`。用户为了「给媒体库读数据」签的 Token，
一旦泄露就等于交出了发种能力。这是「用户授权得比他想给的更多」，属于权限模型漏洞。

**修法**：`require_token` 回传 `scopes`；新增 `require_scope()`；`/open/torrents`
强制 `require_scope(tk, "upload")`（不满足 → 403）；签发时做白名单校验
（未知 scope 报错而非静默接受）。默认仍是 `read`，需显式勾选才能发种。

### 7.2 S-2｜passkey 类端点零限流

`download.php` 有限流（30/min），但 `/rss/{passkey}`、`getrss.php`、
`userdetails.php` **完全没有**。一枚泄露的 passkey 可以无限次拉订阅源与账号数据
（打库 + 放大信息面），且没有任何「异常访问」信号。

**修法**：新增统一的 passkey 维度限流（桶 = `sha3(passkey)` 前 16 位，60s 窗口，
30 次/分钟，Redis 故障 fail-close 与 `http::throttle` 同口径），
`/rss/{passkey}`、`getrss.php`（透传到目标端点）、`userdetails.php` 全部接入。

### 7.3 S-3｜表单登录引入 login CSRF

为兼容 NP `takelogin.php` 而接受 `application/x-www-form-urlencoded` 后，
**表单 POST 不触发 CORS 预检** —— 任意站点都能用一个 `<form>` 把访客浏览器
「登录成攻击者的账号」，之后访客的浏览与流量全记到攻击者名下（洗白账号 / 套取行为）。

**修法**：只对**表单**路径加 Origin 闸（JSON 路径由 CORS 预检天然覆盖，不动自家前端）：
无 `Origin` → 放行（curl / 脚本 / 移动端）；`Origin` 与本站 `Host` 同源或在
`CORS_ORIGINS` 白名单内 → 放行；其余（含 `Origin: null` 的沙箱 iframe）→ 403。

### 7.4 其余四项

| 编号 | 问题 | 影响 | 修法 |
|---|---|---|---|
| S-4 | 凭据类响应未禁缓存 | `.torrent` 内嵌本人 announce(passkey)、RSS 的 enclosure/link、用户信息都带 passkey；CDN/反代一旦缓存就可能把甲的凭据发给乙 | 相关响应统一 `Cache-Control: private, no-store, max-age=0`（download.php / 凭证下载 / RSS / user.json / userdetails.php / ptppUserInfo / Torznab / 发种响应） |
| S-5 | 发种复用 Token 的 60 req/min | 60 个种子/分钟足以灌爆审核队列 | 发种独立限流 20 次/分钟/用户 |
| S-6 | 别名把 passkey 拼进 `Location` 头前未校验形状 | 畸形输入进响应头（防御纵深） | 严格校验（32 位小写字母数字），非法直接 401；顺带收紧 `/rss/{passkey}` 原有的"只查长度" |
| S-7 | `last_used_at` 从未更新 | `UPDATE ... $2` 漏绑被 `let _ =` 吞掉 → 面板看不出 Token 何时被用过，泄露后无法判断 | 补上绑定 |

### 7.5 复核确认「已经做对」的部分

- **Token 发种没有绕过权限**：复用网页发种同一条核心（`torrent.upload` 权限、
  被拒禁发阈值、过审/免审规则、`charge_for_download` 扣费），拿到 Token 也拿不到
  超出该用户当前等级的能力；`class_id` 实时读库，降级/封禁立即生效。
- 兼容层与开放 API 全部要求 Token；passkey 类端点只暴露"本人"数据。
- 查询参数全部走绑定（无 SQL 注入面）；`title_like` / `search` 经 `esc_like` 转义。
- 别名只把**原始（百分号编码的）** query string 搬进 `Location` —— 无法注入 CRLF。
- IP 黑名单、tracker 的 UA/peer_id 名单、passkey 轮换即时失效、封禁用户 Token 立即失效，均在位。

### 7.6 固有风险（NP 设计自带，兼容层消不掉，只能文档化）

1. **passkey 出现在 URL**（`/rss/{passkey}`、`getrss.php?passkey=`、
   `download.php?passkey=`、`/announce/{passkey}`）→ 会进入
   反代/actix 访问日志、浏览器历史、Referer、截图与分享链接。
   这是 NP 生态的整体事实，工具也按此设计。**缓解**：HTTPS + 日志访问受控 +
   定期轮换 passkey（改密会自动轮换并即时失效 tracker 缓存）。
2. **`?apikey=` 让 Token 进 URL** → 同上。Prowlarr 等只支持 query 传参，
   属必要妥协；**建议优先用 `Authorization: Token` 头**。
3. **Token = 批量导出能力**：兼容层列表、`/open/recent`(200/次)、
   `/open/announces`(200/次)、Torznab(100/次) 都可用 Token 拉。
   ⚠️ 本次把 `/open/recent` 从"默认恒空"改为"对有 Token 的成员返回"、
   并把对外列表默认放开零做种后，**站长需要知道：成员可以批量导出目录**。
   这与站内浏览页的可见度一致（会员本就能看列表），且被限流封顶；
   若站长要收紧，建议加一个「开放数据端点」总开关，而不是退回"恒空"。
4. **无 OAuth / 设备码**：Token 是长期 Bearer，泄露即长期可用。
   现有补偿：180 天有效期 + 可撤销 + 可续期 + scope 面收窄。

### 7.7 建议站长做的三件事

1. 生产环境显式设置 `PUBLIC_SITE_URL` / `PUBLIC_API_URL` / `CORS_ORIGINS`。
   否则 RSS/Torznab 里的链接按请求 `Host` 拼 —— Host 头可控时会污染对外链接。
2. 反代层对 `/api/v1/` 关闭响应缓存（我们已发 `no-store`，属双重保险）。
3. 访问日志脱敏：`passkey=` / `apikey=` 掩码，避免"日志 = 凭据库"。
