> 定位目标：**站长不改代码能搭出自己的站**。B 批解决的是「面板都在，但面板能表达的粒度小于自由搭建所需」。

## 一、问题重述（已核实）

| 层 | 现状 | 结构证据 |
| :--- | :--- | :--- |
| L3 内容字段 | 只能表达**单选枚举**，值必须是预置 dict_id | `0085_section_kinds.sql:5-9` 只有 `kind,label,sort` |
| L3 多值 | **结构上不可能**——主键 `(torrent_id, kind)` 限一条 | `0063_admin_p3_suite.sql:62-66` |
| L3 写入口 | 类型锚死为 `HashMap<String, i64>` | `publish_http/upload_sections.rs:25` |
| L4 模式 | 7 个固定布尔列，自建维度永远 `_ => true` 不受管 | `0063:32-42`、`section_public.rs:69-78` |
| L4 层级 | `parent_id` 建了但不下发 | `0188` vs `staff_http/sitetype.rs:36`（只 SELECT 四列） |

**对照**：用户侧 `0186_user_fields.sql` 已有完整六类型系统（text/number/select/multiselect/date/bool + required + options + visibility），且 `auth_http/user_fields.rs:33-91` 的 `validate_value` 是现成校验器。**内容侧不是缺能力，是缺「把已有能力铺过去」。**

## 二、设计原则

1. **一套字段类型系统，两处消费**。内容侧与用户侧共用类型语义与校验器，不另起炉灶。
2. **向后兼容优先**。存量 `torrent_sections`（dict_id 引用）继续可用、继续被筛选，不做破坏性迁移。
3. **值域与引用域分离**。枚举值仍走 `section_dict`（保留既有级联语义：删选项→清引用）；自由值（文本/数字/日期）存自身。
4. **可扩展性留在数据行，不留列名**（直接回应 R2 根因）。

## 三、数据模型

### 3.1 `section_kinds` 扩列（0085 平行升级）

```sql
ALTER TABLE section_kinds
    ADD COLUMN IF NOT EXISTS field_type TEXT NOT NULL DEFAULT 'select'
        CHECK (field_type IN ('select','multiselect','text','number','date','bool')),
    ADD COLUMN IF NOT EXISTS required   BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS multiple   BOOLEAN NOT NULL DEFAULT FALSE,  -- 多值（非枚举亦可）
    ADD COLUMN IF NOT EXISTS icon_key   TEXT,
    ADD COLUMN IF NOT EXISTS bg_color   TEXT,
    ADD COLUMN IF NOT EXISTS enabled    BOOLEAN NOT NULL DEFAULT TRUE;
```

- 默认 `field_type='select'` ⇒ **存量 9 维零语义变化**。
- `options` 不新增列：枚举选项仍在 `section_dict`（该表已有 kind/name/sort/mode_id，是「行」不是列，符合原则 4）。

### 3.2 值表改造（关键决策）

**选 A：原位升级 `torrent_sections`**，新增自由值列 + 放开单值约束。

```sql
ALTER TABLE torrent_sections
    ADD COLUMN IF NOT EXISTS value      JSONB,   -- 自由值（text/number/date/bool）；枚举仍走 dict_id
    ADD COLUMN IF NOT EXISTS ordinal    INT NOT NULL DEFAULT 0;  -- 多值序号

-- 主键 (torrent_id, kind) → (torrent_id, kind, ordinal)
ALTER TABLE torrent_sections DROP CONSTRAINT torrent_sections_pkey;
ALTER TABLE torrent_sections ADD PRIMARY KEY (torrent_id, kind, ordinal);

-- dict_id 由 NOT NULL 放宽（自由值行无 dict 引用）
ALTER TABLE torrent_sections ALTER COLUMN dict_id DROP NOT NULL;

-- 约束：枚举行必须有 dict_id，自由值行必须有 value
ALTER TABLE torrent_sections ADD CONSTRAINT torrent_sections_value_or_dict
    CHECK (dict_id IS NOT NULL OR value IS NOT NULL);
```

**为什么选 A 不选 B（新表平行）**：
- 既有 9 处消费面（详情/列表筛选/RSS/批量/包导出/后台）**零改动**即可继续读到枚举行（`ordinal=0` 语义同旧）。
- 选 B 会让「按维度筛选」在两张表间做 UNION，list 查询与 count 同套谓词的纪律（记忆里明确写过 count 与列表必须同套谓词）会被破坏。
- 迁移成本：存量行 `ordinal` 默认 0，主键约束自然满足。

### 3.3 `category_modes` 改关联表（回应 R2 的「7 个布尔列」）

```sql
-- 新的 (mode_id, kind) 关联表；旧 7 列保留一个发布周期做兼容，读取侧切到关联表
CREATE TABLE IF NOT EXISTS mode_kinds (
    mode_id INT NOT NULL REFERENCES category_modes(id) ON DELETE CASCADE,
    kind    TEXT NOT NULL REFERENCES section_kinds(kind) ON DELETE CASCADE,
    visible BOOLEAN NOT NULL DEFAULT TRUE,
    PRIMARY KEY (mode_id, kind)
);
-- 从旧 7 列回填（7 个 show_* 映射到对应 kind）
INSERT INTO mode_kinds (mode_id, kind, visible)
SELECT m.id, k.kind, m.visible FROM category_modes m
CROSS JOIN LATERAL (VALUES
    ('source', m.show_source), ('medium', m.show_medium), ('codec', m.show_codec),
    ('audio_codec', m.show_audio_codec), ('standard', m.show_standard),
    ('processing', m.show_processing), ('team', m.show_team)
) AS k(kind, visible) ON CONFLICT DO NOTHING;
```

- 读取侧 `section_public.rs:69-78` 从「按 kind 名 match 7 个列」改为「查 `mode_kinds`」⇒ **自建维度可纳入模式管辖**。
- 缺行语义：`(mode_id, kind)` 无行 ⇒ 视为可见（与现状 `_ => true` 一致，不改行为）。

### 3.4 `categories` 排序与下发

```sql
ALTER TABLE categories ADD COLUMN IF NOT EXISTS sort INT NOT NULL DEFAULT 100;
```
- `site-profile`（`staff_http/sitetype.rs:36`）SELECT 补 `parent_id, mode_id, sort`；前端 `lib/site-profile.ts` 类型同步。
- 排序从 `ORDER BY id` 切 `ORDER BY sort, id`；**存量行 sort=100 相同 ⇒ 退化为 id 序，行为不变**。

## 五、分批与风险

**B1（数据模型，本批核心）**：3.1 + 3.2 + 3.3 + 3.4 迁移；存量兼容性验证（枚举行行为零变化）。
**B2（写读链路）**：消费面 1/2/3/5 + 管理面板 9。
**B3（协议与运营面）**：4/6/7/8 + RSS/后台列表。

**风险**：
- ⚠️ 主键变更会锁表。开发库 205 表规模可忽略；**站长存量库需评估**——建议迁移内加 `LOCK` 说明与执行时长提示。
- ⚠️ 开工前必须查 `_sqlx_migrations` 最大号避让（0193 已占用，下一号 0194 起）。
- ⚠️ `sync_legacy_columns`（`upload_sections.rs:77`）反向落旧三列的语义要保持：新自由值维度不参与旧列同步。

## 六、开口项（已拍板 2026-09-25）

1. **范围**：**先做 B1（数据模型），验证存量兼容后续推 B2/B3**。
2. **3.2 选 A**：原位升级 `torrent_sections`。
   - **已实测验证**（临时表预演）：存量行 `ordinal=0` 下主键 `(torrent_id,kind,ordinal)` 自然满足；
     同一 `(torrent_id,kind)` 可并存 `ordinal=0`（枚举）与 `ordinal=1`（自由值）；`dict_id` 放宽为可空、
     `CHECK (dict_id IS NOT NULL OR value IS NOT NULL)` 正确挡下空值行。
3. **`category_modes` 旧 7 列**：**本批保留不删**，读取侧切到 `mode_kinds` 关联表。回滚容易。
4. **筛选语义**：**全类型都支持**（站长选定，比建议激进）。
   - 枚举/多选：复用现有 dict 筛选机制。
   - 文本：`ILIKE '%…%'` 模糊匹配。
   - 数字：范围查询（`from`/`to`）。
   - 日期：范围查询（`from`/`to`）。
   - 布尔：真/假/不限三态。
   - ⚠ **承重约束**：`torrent_http/list.rs` 的列表查询与 `count` **必须同套谓词**
     （记忆中的既有纪律）——自由值筛选条件要在两处用同一构造器生成，不可各写一遍。
   - ⚠ 自由值筛选涉及 `torrent_sections` 自连接/EXISTS 子查询，需在 B1 迁移里预建
     `(kind, value)` 与 `(kind, ordinal)` 索引，避免列表查询退化。

## 七、B2 详细设计（写读链路）

### 7.1 共享校验器（先做，其余都依赖它）

把 `auth_http/user_fields.rs:33-91` 的 `validate_value` 提到公共模块，两处共用：

```
apps/api/src/fields/mod.rs          ← 新建
    pub fn validate_value(field_type, options, v) -> Result<(), String>
```

- 内容侧（`upload_sections.rs`）与用户侧（`auth_http/user_fields.rs`）都调它
  ⇒ 类型语义天然一致，不会两边漂移。
- 内容侧 `options` 取自 `section_dict`（枚举维度），用户侧取自 `user_field_defs.options`。
- **只搬不改语义**：搬完先让用户侧现有测试（若有）与 e2e 不变。

### 7.2 写入侧：`upload_sections.rs`

现状（`upload_sections.rs:25`）：
```rust
let map: HashMap<String, i64> = serde_json::from_str(json)?;   // 只能单选枚举
```

改为结构化条目，**同时兼容旧格式**：
```jsonc
// 旧格式（存量客户端）——枚举单选，继续支持
{ "media": 5, "codec": 7 }

// 新格式——按 field_type 表达
{
  "media":   { "dict_ids": [5, 8] },        // 枚举多选（multiple=true）
  "isbn":    { "text": "978-7-111-xxxx" },  // text
  "pages":   { "number": 320 },             // number
  "pubdate": { "date": "2024-05-01" },      // date
  "inprint": { "bool": true }               // bool
}
```

解析策略：值若是 JSON number ⇒ 旧格式（枚举单选）；若是对象 ⇒ 新格式。
**判据在值的 JSON 类型上，不靠参数名**，兼容面最广。

校验：
1. `kind` 存在于 `section_kinds` 且 `enabled`（B1 新列）。
2. 值形状匹配该 kind 的 `field_type`（走 7.1 共享校验器）。
3. `multiple=false` 的维度，`dict_ids` 长度 ≤ 1 ⇒ 否则 400。
4. `required=true` 的维度缺值 ⇒ 400（**新增能力**，四审 P1 说现状无必填概念）。
5. 整体校验后再写（保持现有「任一非法就一条不写」的纪律，见 `upload_sections.rs:12-16` 注释）。

写入：按 `ordinal` 递增（枚举 0..n，自由值同样按序），枚举行写 `dict_id`、自由值行写 `value`。
`sync_legacy_columns` 保持只对 media/grades/editions 三旧列生效（`section_pred.rs:17-21` 的 `LEGACY_DIMS`）。

### 7.3 读取侧：详情 `torrents/detail.rs:123-141`

现状 `JOIN section_dict d ON d.id = ts.dict_id` ⇒ **自由值行会被内连接丢掉**。

改为：
```sql
SELECT ts.kind, ts.dict_id, ts.value, ts.ordinal,
       d.name, COALESCE(k.label, ts.kind) AS label,
       COALESCE(k.sort, 999) AS sort, k.field_type
  FROM torrent_sections ts
  LEFT JOIN section_dict d ON d.id = ts.dict_id     -- ← LEFT：自由值行无 dict
  LEFT JOIN section_kinds k ON k.kind = ts.kind
 WHERE ts.torrent_id = $1
 ORDER BY sort, ts.kind, ts.ordinal
```

输出形状（**向后兼容**：旧字段 `dict_id/name/label/sort` 全保留）：
```jsonc
"sections": {
  "media": { "dict_id": 5, "name": "BluRay", "label": "媒介", "sort": 10,
             "field_type": "select", "values": [ /* 多值：全量有序数组 */ ] },
  "isbn":  { "dict_id": null, "name": "978-7-111", "label": "ISBN", "sort": 100,
             "field_type": "text", "values": [...] }
}
```
- 单值维度 `name` 即该值（同旧）；多值维度 `name` 取首个、`values` 给全量。
- 前端旧消费点读 `name` 无感；新消费点读 `values`。

### 7.4 列表读取 `list_noclamp_as.rs:194-199`

`sec_names` 的 `JOIN section_dict x` 同样是内连接 ⇒ 自由值维度在列表**零显示**。
改 `LEFT JOIN` + `COALESCE(x.name, ts.value::text)`，多值聚合按 `(kind, ordinal)` 排序。

### 7.5 后台批量 `admin_p3_http/torrent_batch.rs`

`change_sections`（`:211`）已存在，B2 扩展为接受 7.2 的新格式。
- 权限与校验复用 `upload_sections.rs` 的解析函数（**同一实现，不复制**）。
- 批量替换语义：整维度覆盖（DELETE 该 kind 全部行 + 按新值重插），与现状一致。

### 7.6 管理面板 `admin-sections-kinds.tsx`

- 列表加列：`field_type` / `required` / `multiple` / `enabled`。
- 新建/编辑表单加：字段类型选择器（六类型）+ 必填开关 + 多值开关 + 启用开关。
- **类型不可改**（已建维度改类型会让存量值语义失效）⇒ 编辑态禁用该控件，或改类型时强提示。
- 枚举类型才显示「字典项」入口；其余类型不显示（避免无意义的空选项列表）。

### 7.7 管理端「在用量」守必须覆盖自由值行 ⚠

`section_kinds.rs:159-166` 的删除守卫：
```sql
SELECT count(*) FROM torrent_sections ts JOIN section_dict sd ON sd.id = ts.dict_id
 WHERE sd.kind = $1
```
**`JOIN` 导致自由值行（`dict_id IS NULL`）不计入** ⇒ 站长删一个只被自由值使用的维度会**静默删数据**。
改为不依赖 dict：
```sql
SELECT count(*) FROM torrent_sections WHERE kind = $1
```
B1 的 `(kind, ordinal)` 索引正好命中。

### 7.8 模式关联表接入（B1 已建表，B2 切读取）

`section_public.rs:65-79` 的 `allows()` 改为查 `mode_kinds`：
```sql
SELECT kind, visible FROM mode_kinds WHERE mode_id = $1
```
- 拿不到 `mode_id`（未传 category_id）⇒ 全部可见（同旧）。
- 有 `mode_id` ⇒ 无该 kind 行 = 可见（与旧 `_ => true` 一致），有行则按 `visible`。
- 旧 7 列本批仍保留（读取侧不再读它）。
