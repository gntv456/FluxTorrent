## 2. 总体结论

### 2.1 结论摘要

**核心结论：后端 API 覆盖度较高，但「前端 UI 入口」是系统性短板，导致大量已实现功能对终端用户不可达。**

项目存在一种典型的「**API 完成 ≠ 功能可用**」风险：后端 175 个路由中有 **58 个（33%）从未被前端调用**，其中多个属于核心治理链路（H&R 免罪、申诉处理）与核心业务闭环（站免池捐赠、绩效考核）。这些功能在文档中被标记为「✅ 已完成」，但真实用户无法在界面上使用。

### 2.2 缺陷统计

| 等级 | 数量 | 说明 |
|---|---|---|
| **P0** | **0** | 未发现资金/流量账目错误或安全绕过类致命缺陷 |
| **P1** | **7** | 核心功能缺失或业务链路断裂，无替代路径 |
| **P2** | **12** | 功能有后端无 UI、死链、文档与代码不符 |
| **P3** | **5** | 死代码、体验优化、非阻断增强 |
| **合计** | **24** | |

### 2.3 覆盖率评估

| 维度 | 覆盖率 | 说明 |
|---|---|---|
| NP 核心 PT 功能（发种/下载/浏览/搜索/评论/收藏） | **~90%** | 主体完整 |
| NP 社区功能（论坛/短讯/好友/勋章/喊话） | **~85%** | 缺论坛投票、版主工具 |
| NP 治理功能（H&R/审核/举报/申诉/封禁） | **~70%** | 后端齐，UI 缺 H&R 免罪与申诉处理 |
| NP 后台管理（53 Resource 口径） | **~45%** | Dev 版，仅覆盖高频管理面 |
| NP 辅助/生态功能（搜索建议/图床/附件/考试/OAuth/多 passkey） | **~15%** | 基本未移植 |
| **端到端用户可用率（有 UI 入口）** | **约 67%** | 175 路由中 117 个有前端调用 |

> **总体判定**：后端功能覆盖达 NP 核心面的约 **80%**，但**用户实际可用功能覆盖率仅约 67%**。差距全部来自 UI 入口缺失。

| 等级 | 判定口径 |
|---|---|
| **P0 致命/阻塞** | 资金或流量账目错误、安全绕过（越权/鉴权失效）、数据丢失风险 |

## 12. 审查结论

1. **移植完整性**：核心 PT 链路（发种/审核/下载/计费/评论/收藏/搜索/RSS）移植完整，H&R 结算逻辑经代码验证**实现正确且幂等**。但**种子编辑/删除、用户公开主页、peer 与下载记录、NFO** 四项 NP 基础能力缺失，构成 P1。
2. **功能可用性（本次最大风险）**：后端 175 路由中 **58 个（33%）无任何前端调用**，其中 **H&R 免罪、申诉处理、站免池捐赠、绩效考核** 属核心业务闭环断裂——功能"存在"但用户与 staff 均无法使用。端到端可用率约 **67%**，显著低于文档宣称的完成度。
3. **UI 入口完整性**：发现 1 处硬死链（`/users/{id}`）、1 处自指死链（2FA 启用按钮指向当前页）、5 个死代码组件；导航覆盖基本完整，主要问题在"功能已实现但未挂入口"。
4. **业务逻辑**：未发现 P0 级账目或安全缺陷；2 项待改进（H&R 未区分免费种子、免罪方式单一）。
5. **文档可信度**：`功能对比.md` 存在**系统性夸大**，"建列/预留"被记为"已实现"，§3 矩阵与 §4 结论自相矛盾。**该文档不可作为验收依据**，建议按 §7 逐条修正。
6. **测试体系**：前端零测试、后端单测不覆盖业务链路，是 UI 入口类缺陷长期未被发现的根本原因；建议将"路由↔前端调用"对称性检查纳入 CI 门禁。
