# 标签体系重构：业界调研与开发策划案

> 起因：用户提出「标签很多地方不合理，需要重新梳理调整规划，先研究市面上同类项目，对比分析，写出详细开发策划案」。
> 本文三部分：**现状全景盘点**（代码级证据）→ **业界调研**（NexusPHP / UNIT3D / Gazelle / Danbooru / TMDB / 各 PT 站实践）→ **目标架构与分批实施计划**。
> 调研时间：2026-09-23。行号以当日 master（31624b1）为准。

---

## 0. 一页摘要

**现状一句话**：标签子系统 = 一张通用字典 `tag_dict`（scope 分 torrent/forum 两域）+ 两张关联表 + 一列冗余布尔 `torrents.official_tag`；预设列表制（无自由文本，方向正确），但**发布/详情/批量三个打标入口校验口径不一致、官种双口径无同步、列表页不回显标签、搜索只能单选、种子侧不消费字典样式、站型切换不换标签集**。

**业界一句话**：NexusPHP v1.6+ 也是受控词表 + checkbox + 特殊标签权限门控；Gazelle（PT 圈最成熟标签治理）靠「规范形式 + 别名 + 官方白名单 + 投票 + 批量修正」五件套存活十余年；UNIT3D 2020 年删掉了无人治理的 tags 表退化为扁平 keywords——**无治理的标签系统维护成本高于价值，受控词表是 PT 站的正确选择**。

**本方案方向**：不推翻受控词表制，分三阶段收敛——

| 阶段 | 主题 | 一句话内容 |
|---|---|---|
| **P0** | 口径收敛与缺陷修复 | 统一三入口校验、修 id 竞态、补 FK/CHECK、清死键、接通 aggregate initial |
| **P1** | 查询与展示强化 | 标签多选搜索（any/all）、列表行回显标签、渲染口径统一、使用计数、编辑表单补标签 |
| **P2** | 体系升级 | 通用标签层（首发/官种/禁转/国语/中字/DIY 跨站型共享）、标签分组（属性/内容）、分区绑定 mode 接通、站型专属 tag packs 联动、官种口径物化收敛 |

**关键裁决**（详见 §3）：分辨率/编码/来源/媒介归 **sections 六维字段**，标签只放作品级轻量徽标；「免费」标签与促销系统职责重叠应移除；官组/字幕组不做标签，走独立维度；`official_tag` 列保留为物化口径但写入统一收口。

### 1.2 数据流现状

```
[种子域]
发布: upload-form checkbox(≤12, 过滤official) → POST /torrents?tags=[id...]
      → store_sections_tags 校验(存在/enabled/scope/official仅staff) → INSERT tags
详情打标: TorrentTags 点击 → PUT /torrents/{id}/tags → tag_torrent(作者或staff)

展示: 详情页 TorrentTags(0159 默认只显已选, 前端固定 palette 四色)
      ← /aggregate 已内嵌 tags 但详情页没传 initial，仍二次请求

[论坛域（独立闭环，健康）]
发帖 ≤5 → attach_topic_tags 校验 scope=forum → topic_tags
消费: 版块筛选条 + 主题行 TagChip(消费字典样式列)

[旁路]
torrents.official_tag 由求种转正写入，与「官种」标签(id=3)无同步
```

## 2. 业界调研

### 2.1 NexusPHP 核心实现（源码级，xiaomlove/nexusphp@1.10.2）

**数据模型**：`tags` 表（name unique、color/priority、padding/margin/border_radius/font_size、`mode` 分区绑定、description）+ `torrent_tags` 多对多。v1.5 经典版完全没有 tags 表（只有 sources/media/codecs/standards/processings/teams/audiocodecs 分类法）——**标签是 v1.6 引入的新机制，与老分类法并行**，v1.6 前用位掩码列，官方给了迁移命令。

**官方 seed 7 标签**：禁转(7,#ff0000)/首发(6,#8F77B5)/官方(#0000ff)/DIY(#46d5ff)/国语(#6a3906)/中字(#006400)/HDR(#38b03f)——带优先级与颜色，priority 越大越靠前，列表显示顺序受它影响。

**发布填写**：`renderCheckbox` 复选框渲染预设列表，**用户无法自造标签**；按分区 searchbox mode 过滤（`mode in [0, searchBoxId]` = 全局标签+本分区专属，v1.8.0 起）；特殊标签对无 `torrent-set-special-tag` 权限者不可见+提交二次拦截。

**搜索**：`torrents.php?tag_id=` 单选 join 过滤；搜索框下方渲染彩色标签过滤行（点击即筛，类 tag cloud 内嵌列表页）；`searchbox.require_tags` 可配置「进入本列表必须含某标签」——各站「官组区/首发区」的聚合列表机制。

**官方标签机制（重要）**：`bonus.official_tag`（官种标签）与 `bonus.zero_bonus_tag`（零魔标签）在站点设定里指认，**标签驱动魔力公式**（官种加成系数、零魔体积折算）——标签不只是展示，是激励钩子。

**管理工具链**（v1.7.x 系列逐步补齐）：批量设置标签（附加 or 同步替换，v1.7.27）、按标签统计种子数 + 一键分离某标签全部种子（v1.7.24，脏标签清洗）、Filament 后台全量 CUD + TagPolicy 限管理员。

### 2.3 UNIT3D / Gazelle / 公开站 / 内容平台

**UNIT3D（BHD/BLU 在用）——前车之鉴**：2017 年曾有 `tags`+`tag_torrent` 多对多，**2020-07 整体删除**，退化为无治理的 `keywords`（torrent_id+name，trim+大小写去重即存，无词表无补全），且社区无人做插件补齐。结构化维度则很完整：categories/types/resolutions/regions(243 个)/distributors 独立表+下拉+facet；free/doubleup/highspeed 全是 torrents 布尔列。**结论：无治理的标签系统维护成本高于价值。**

**Gazelle（RED/OPS，PT 圈最成熟标签治理）——目标形态参考**：
1. **规范形式先行**：`sanitize_tag()` 强制小写、仅 `a-z0-9.`、点号分词——唯一键因此可靠；
2. **标签挂作品(group)而非种子**：同专辑多版本共享一组标签；
3. **官方标签白名单**：TagType 只有 genre/other；autocomplete 只收录 `Uses>700 OR genre`——**低频长尾标签存在但对输入提示不可见**，这是词表防爆的关键阀门；
4. **别名双端重写**：输入时即时重写、搜索时重写查询（不迁移存量）；
5. **投票**：新标签初始 +3，up=+2/down=+1 非对称，每人每方向一票；
6. **版主 merge/rename 批量工具 + group_log 审计**；
7. **官方规则明确了字段/标签分界**：*"Only tag information on the album itself — not the individual release. Tags such as `v0`, `eac`, `vinyl` are strictly forbidden."*——**作品级属性做标签，发布版本级属性（编码/介质/抓轨软件）做结构化字段**，而 Format/Encoding/Media 恰好是封闭下拉，双轨咬合。

**nyaa.si**：无标签表，两级分类 + TRUSTED/REMAKE 等位标志。**Danbooru**：tag_aliases（批准时物理迁移）+ tag_implications（打 A 自动加 B，递归 CTE 展开）+ 五类标签类别（meta 类对应「描述资源本身」的标签）+ 论坛 BUR 工单化治理 + 自动退休不活跃关系。**TMDB**：genre（固定小集合）与 keywords（全站受控词表）分层；`with_keywords` 逗号 AND / 竖线 OR——内容平台过滤语法的事实惯例。

### 2.4 归纳：五条设计定律

1. **先立「字段 vs 标签」分界线，再谈标签系统**。三份独立证据（Gazelle 官方规则、UNIT3D 结构化表、Danbooru meta 类）指向同一条线：分辨率/编码/来源/地区/发行商做封闭枚举字段（可 facet）；标签只承担作品级主题与轻量徽标；促销/状态一律布尔或枚举字段。
2. **受控词表是 PT 站的正确选择**。NP checkbox-only 原厂如此，Gazelle 用「白名单+使用门槛」控制自由层。我们的现状（预设 id 列表制）方向正确，**不需要引入自由文本+投票全家桶**，需要的是把受控词表自身的工程债还清。
3. **治理闭环最小集**：规范形式（我们天然有=id 制）→ 建词防重（已有 name UNIQUE）→ 近义词不建词（运营纪律+后台提示）→ 使用计数（缺失）→ 批量修正工具（已有雏形）→ 操作审计（详情页打标已有 audit，批量缺）。
4. **标签即列表**：NP 的 `require_tags` 用标签圈出聚合列表（官组区/首发区），标签云点击即筛是通用形态。
5. **标签可驱动激励**：NP 官种/零魔标签接入魔力公式——标签系统与经济系统有天然接口，值得预留。

## 3. 设计原则与口径裁决

结合我们特有的两个约束：**多站型**（site_type 切换整套分类/模块）与**已有 sections 六维体系**（section_kinds/section_dict 承担媒介/来源/编码等标准字段）。

### 裁决 1：字段 vs 标签的归属线

| 信息 | 归属 | 理由 |
|---|---|---|
| 媒介/来源/编码/分辨率/地区 | **sections 六维**（现状已如此） | Gazelle/UNIT3D 定律：发布版本级属性做字段 |
| HDR/DV/杜比视界 | **sections**（若对应维度缺枚举值则补枚举值，不开标签口子） | TTG 把 HDR 系列做成标签是历史包袱，pt_mate 被迫维护映射 |
| 首发/禁转/官组/国语/中字/DIY/完结 | **标签**（attribute 组） | NP 原厂口径；轻量徽标+多选 |
| 官方/官种 | **标签 + 物化列**（见裁决 3） | 激励钩子（魔力/促销联动）+ 列表覆盖索引性能 |
| 免费/促销 | **促销系统（promo），从标签集移除** | 职责重叠：NP 中免费是促销字段；标签「免费」与 promo 状态漂移必然发生 |
| 合集/带答案/题材主题 | **标签**（content 组） | 作品级内容特征 |
| 字幕组/压制组 | **不做标签**（独立维度，另案） | 0138 已废弃 kind='team' 思路；M-Team 官组=teams 维度的实践佐证；先维持 `subtitles.author_name` |

### 裁决 2：保持受控词表制，不引入自由文本与投票

理由：§2.4 定律 2。Gazelle 五件套是为「自由打标」付出的治理成本；我们既然是 id 制，脏数据源头已断，剩下的债是**一致性与消费端**（§1.3 清单），不是词表失控。别名/蕴含机制**不做**——受控词表下近义词靠「不建词」纪律解决，成本远低于维护 alias 体系。

### 裁决 3：官种双口径收敛——物化列保留，写入统一收口

`official_tag` 进了列表覆盖索引（`0001:117`），改成实时 JOIN tags 表会伤列表性能；而 0145 教训（内存：派生值须纯覆盖+动态 JOIN 不可单路径物化）要求**所有写入路径走同一函数**。方案：抽 `set_torrent_tags` 统一服务函数，内部维护「打/摘 official-kind 标签 ⇄ 同步 official_tag 列」的双向一致性；求种转正 `offers.rs:173` 改走该函数。列上的口径命名同步理顺（列=官种语义，列表徽标文案与 i18n 对齐）。

### 裁决 4：样式口径统一——种子侧也消费字典样式列

论坛 TagChip 已实现 inline style 消费（`forum-bits.tsx:39-63`），种子详情的固定 palette 四色（`torrent-tags.tsx:142-151`）改为复用同一 TagChip 组件/口径；字典样式列留空时回落现有默认色。后台所见即所得，两侧一致。

### 裁决 5：站型联动——通用标签 + 站型专属 tag packs

**用户裁决（2026-09-23）：首发、官种、禁转、国语、中字、DIY 六个为通用标签，所有站型共享。** 这与 NP 原厂 seed 口径一致（7 标签里占了 6 个，只差 HDR——HDR 我们归 sections）。

据此把词表拆成两层：

| 层 | 内容 | 随站型切换 |
|---|---|---|
| **通用层（global）** | 首发、官种、禁转、国语、中字、DIY | ❌ 永不重建，所有站型可见可选 |
| **站型专属层（per-pack）** | education：官方、合集、带答案；movie：完结、合集、导演剪辑；game：官方汉化、DLC 完整；anime：官译、剧场版、合集…… | ✅ 随 pack_apply 重建（引用保护） |

落库方案：`tag_dict` 加 `scope_layer TEXT NOT NULL DEFAULT 'pack'`（取值 `global` / `pack`），不另建表——字典就几十行，加列比加表 + 视图 JOIN 简单，且后台管理页只需多一个下拉。通用层六件套由一条基线迁移 INSERT（`ON CONFLICT (name) DO NOTHING`，幂等）。

`pack_apply.rs` 重建流程（比照 sections 的重建+引用保护模式 `pack_apply.rs:172-182`）：
1. 重建时**只处理 `scope_layer='pack'`** 的 torrent 域标签：删除未被引用（tags/topic_tags 无关联行）的站型专属标签，插入新 pack 的标签集；
2. **`scope_layer='global'` 全程不触碰**——这是「切站型不丢通用标签」的硬保证，比纯引用保护更强（引用保护只保在用的，通用层连没在用的也保）；
3. forum 域标签不受站型影响；
4. apply 前后输出词表 diff 日志（比照 sections 做法）。

各站型标签集修订版：

| 站型 | 通用层（共享） | 站型专属层 |
|---|---|---|
| 全部 | 首发、官种、禁转、国语、中字、DIY | — |
| education | ↑ | 官方、合集、带答案 |
| movie | ↑ | 完结、合集、导演剪辑 |
| game | ↑ | 官方汉化、DLC 完整、合集 |
| anime | ↑ | 官译、剧场版、合集 |

> 注：「官方」（education 特有，官方出品口径）与「官种」（通用层）语义不同，前者留站型层；原「免费」标签退役（裁决 1）。

## 4. 目标架构

### 4.1 数据模型改造（迁移 0160 起，编号以实施时下一个空闲为准）

```sql
-- 0160_tag_gov.sql（P0）
ALTER TABLE tags ADD CONSTRAINT fk_tags_dict
  FOREIGN KEY (tag_id) REFERENCES tag_dict(id) ON DELETE CASCADE;  -- 补 FK，对齐 topic_tags
ALTER TABLE tag_dict ADD CONSTRAINT chk_tag_scope CHECK (scope IN ('torrent','forum'));
ALTER TABLE tag_dict ADD CONSTRAINT chk_tag_kind  CHECK (kind IN ('plain','official'));
CREATE SEQUENCE tag_dict_id_seq OWNED BY tag_dict.id;             -- 修 max(id)+1 竞态
-- id 已是手工 INT：setval 到 max(id)，新增改用 nextval

-- 0161_tag_group.sql（P2）
ALTER TABLE tag_dict ADD COLUMN "group" TEXT NOT NULL DEFAULT 'attribute';
  -- 'attribute' 属性类(首发/官种/禁转/国语/中字/DIY/完结) | 'content' 内容类(合集/带答案/题材)
ALTER TABLE tag_dict ADD COLUMN scope_layer TEXT NOT NULL DEFAULT 'pack'
  CHECK (scope_layer IN ('global','pack'));                        -- 通用层/站型层（裁决 5）
ALTER TABLE tag_dict ADD COLUMN usage_count BIGINT NOT NULL DEFAULT 0;  -- P1 维护
-- 通用六件套幂等入库（同名已存在则仅标记为 global，如官种 id=3）
INSERT INTO tag_dict (name, kind, scope, scope_layer) VALUES
  ('首发','plain','torrent','global'), ('官种','official','torrent','global'),
  ('禁转','plain','torrent','global'), ('国语','plain','torrent','global'),
  ('中字','plain','torrent','global'), ('DIY','plain','torrent','global')
ON CONFLICT (name) DO UPDATE SET scope_layer = 'global';
DELETE FROM tag_dict WHERE name='免费' AND id=2 AND NOT EXISTS
  (SELECT 1 FROM tags WHERE tag_id = tag_dict.id);                -- 移除「免费」标签(有引用则跳过并人工处理)
```

`mode_id` 接通（P2）：`GET /tags-dict?section=` 或发布表单按当前分区传 mode，词表查询改 `WHERE (mode_id IS NULL OR mode_id = $1)`——NP「全局+分区专属」口径。

### 4.2 写入口径统一（P0 核心）

抽公共函数 `tags::apply_torrent_tags(tx, torrent_id, tag_ids, actor)`（放 `apps/api/src/torrents/manage.rs` 或新 `tags.rs` 模块）：

- 校验：存在 + enabled + scope='torrent' + official-kind 需 class≥90（批发时降为：official 需操作者是 staff——批量入口本身就是 staff）；
- 写入：`INSERT ... ON CONFLICT DO NOTHING`；
- **同步钩子**：涉及 official/官种标签时同事务更新 `torrents.official_tag`；
- 审计：全部入口记 audit（批量入口补上）。

三个入口改调它：`upload_sections.rs:67-113`（发布）、`torrents/manage.rs:150-194`（详情页）、`torrent_batch.rs:135-162`（批量）。求种转正 `offers.rs:173` 改调它（打官种标签而非裸写列）。

### 4.3 查询能力（P1）

- `tag_id` → `tag_ids`（复数，逗号分隔）+ `tag_mode=any|all`，完全比照 promo 多选的既有套路（`query.rs:148-172` norm_promo 的解析/绑定模式照抄）；SQL 改 `= ANY($n::int[])`（any）或多个 EXISTS（all）；保留 `tag_id` 单数兼容旧链。
- 计数：`GET /admin/tags-dict` 返回 `usage_count`（`tags`/`topic_tags` 两表 UNION 计数，或维护列——量级小（字典几十行），直接子查询即可，不维护列，避免双写）；后台列表加「种子数/帖子数」列与排序，提供「查看引用」「一键分离」（NP v1.7.24 口径：列出引用并支持批量摘除）。

### 4.4 展示统一（P1）

- **列表行回显**：`torrent-table.tsx` / `torrents-cards.tsx` 行内加标签徽标（最多前 2-3 个 + overflow 计数，按字典 sort 排序，official 优先）；列表 SQL 随行 `json_agg` 标签（比照论坛 topic.rs:104-107 的随行回显模式）；列宽敏感——徽标只显 name 不显删除入口。
- **详情页**：`page.tsx:188` 把 aggregate 里的 tags 传给 `<TorrentTags initial={...}>`，消掉二次请求；无已选标签时整区折叠为一行「＋加标签」入口而非「空区+全部标签按钮」。
- **TagChip 统一**：种子侧复用论坛的样式消费口径，删前端 palette。
- **编辑表单**：`torrent-manage.tsx` + `PUT /torrents/{id}` 补 tags 字段（走统一函数，作者本人或 staff 校验同详情页）。
- **chips 降级**：字典失败时显示「标签#id」而非裸数字，并给出错误态而非静默空列表。

### 4.5 i18n 清理（P0）

删三语 `torrTags2.filterRow` 死键（无组件引用）；后台/前台所有标签名渲染一律来自字典（DB 数据不是 UI chrome，参照管理端 i18n 策划案 §3.2a 的既定结论）。

### 4.6 站型联动（P2）

`site_type_packs` 增加 `tags` 数据节（只含站型专属层的标签集）；`pack_apply.rs` 重建流程加一步：**只重建 `scope_layer='pack'` 的 torrent 域标签**（引用保护），`scope_layer='global'` 六件套全程不触碰，forum 域不受影响——规则详见裁决 5。各站型标签集见裁决 5 的修订版表格（实施时按站型策划再校）。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| `tags` 补 FK 时存量孤儿行导致迁移失败 | 迁移先 `DELETE FROM tags tg USING tag_dict d WHERE ... 不存在` 清孤儿（0138 有先例），再加约束 |
| 删「免费」标签误伤在用数据 | 迁移带引用检测，有引用则跳过并输出清单人工处理（裁决 5 同款保护） |
| `official_tag` 同步函数漏写入口 | 全仓 grep `official_tag` 建写入点清单收进验收脚本；新入口 lint 层面无约束，靠 audit_log 巡检 |
| 列表行加徽标导致行高/折行回归 | 项目有 300 行/80 列门禁与 admin-tasks-table 折行先例；验收含行高断言 |
| 站型 apply 重建标签丢手工词/丢通用标签 | `scope_layer='global'` 在 apply 流程中硬性不触碰（比引用保护更强）；pack 层引用保护 + apply 前后词表 diff 日志（比照 sections 172-182） |
| 多选筛选 SQL 退化为多次子查询 | any 用 `= ANY(array)` 单谓词；all 用固定数量 EXISTS；复用 0151 索引；50 万级数据先 expPLAIN 后合入 |
