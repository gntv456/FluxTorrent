## 0. 一页结论

**三个岔路按推荐口径取定**（用户以「继续」授权按推荐推进；任一条改的是参数，不是结构）：

| 岔路 | 取定 | 理由 |
|---|---|---|
| ① 抽取货币 | **独立券（gacha_ticket），spark 不可购买、不可转让** | `spark_balance` 是上传/做种的劳动凭证，随机发放带真实价值的东西等于给站点经济开印钞口；分轨后保底爬坡不会变成确定性印钞 |
| ② 卡本体 | **站点实体卡**（绑制作组/发布者/板块等站点自有维度） | 图鉴同时是站点档案馆，抽到→去发源，反哺做种；不靠原创 IP 立绘，美术量可控 |
| ③ 范围 | **抽卡 + 图鉴 + 碎片合成最小闭环** | 赛季/外观商店、经济类奖品全部后置 |

**批次**：G31-A（骨架 + 只读公示面）→ G31-B（抽取与账本闭环）→ G31-C（合成／升级／后台）。每批可独立验收，B 批之前不产生任何玩家可见的抽取行为。

**本方案最重要的一条不是 UI，是守卫口径**：返还率门禁**必须按含保底的综合概率算，不能按表定概率**。保底会把概率从低档搬到高档，实测同一池子表定 91.6% 而含保底 105.8% —— 按表定算会放行一个实际在倒灌经济的卡池。详见第 6 节。

**已完成的样张层**（`.workbuddy/`，gitignored，未入库）：六页 HTML + 一份共享层，全部实测结论见第 2 节。它们是本方案的证据来源，也是 G31-A/B/C 的视觉与交互规格书。

## 1. 经济红线（先于功能）

1. **奖品表 90% 非经济**：收藏、外观、称号、主页展示权。带真实价值的（做种加速、免考核周、上传额度）**第一批全部不做**。
2. **两种新货币各自建账本，形状照 `spark_ledger`**：行锁 + `idempotency_key` + `balance_after` + 同事务写流水。娱乐屋现有 `kind='game'` 口径沿用，抽卡用 `kind='gacha'`、`ref_type` 按池分。
3. **碎片有双重身份 ⇒ 合成价不是独立运营参数**。碎片既是奖池产出又是合成/升级货币，其价值由「玩家能换到的最好东西」倒推：
   `shardValue = max(prize_value / synth_shards, prize_value · lv_gain / 升级总价)`
   压低合成价 ⇒ 碎片单价抬高 ⇒ 重复折算与碎片奖池同时升值，而卡片 `prize_value` 一个字没改。**这是绕过只看卡片价值的 EV 守卫的后门，已在样张里一键复现**（sv 0.938→3.750，返还率 96.8%→202.8%）。
4. **守卫卡 `max(新手口径, 毕业口径)`**。图鉴满后每次抽到卡都只按最优兑换价折算，毕业口径在 sv 高时会反超新手口径。
5. **卡牌等级只改卡面与图鉴权重，不给任何站点经济加成**；升级消耗递增（`lv_cost_each × 当前等级`）。

## 2. 样张层已实测的结论（方案的判据出处）

| 结论 | 证据 |
|---|---|
| 稀有度视觉必须行表下发，前端不持色表 | 同一份 frame SVG + 徽记模板，5 张卡只换 `--r-*` token ⇒ 5 个不同 `--r-frame`，实测成立 |
| 虹彩在深色卡底上必须 `mix-blend-mode: screen` | `overlay` 把 conic 彩虹压成一片灰；换 `screen` 才出棱光。**只有浏览器量得出来，AI 样图看不出来** |
| 材质参数至少两个量：`foil` + `foil_mask` | 高 foil 会连主图对比度一起吃掉，需把虹彩限制在卡框与背景环 |
| 程序化 SVG 撑得住卡框，撑不住主图的绘画体积 | 卡框/材质/光柱/星座 100% 程序化可达；主图仍需 3–5 张可复用模板（AI 出图 + 人工修） |
| 网格档必须降 LOD | 60 张卡各带一份 SVG 渐变 defs 会让首屏节点数爆；渐变 id 还须按实例命名空间，否则跨卡串色 |
| 演出类组件的**终态必须能脱离动画成立** | 曾把落点交给 `animation … forwards`，动画不跑卡就永远停在背面 |
| `prefers-reduced-motion` 分支 = 低配/弱网/玩家主动关演出的同一条降级路径 | 实测直落结果、演出层 `display:none`、卡 `opacity:1` |
| 10 连演出 ≈ 4.5s ⇒ 「跳过」是必需功能，且必须落到**完整结果**而非快进 | 阶段机 `idle→overture→burst→reveal→result` 全序列实测；跳过时迟到定时器被清 |
| 悬念靠两个零美术机制 | 流星颜色取**整批最高稀有度**（非逐张）；最高稀有度那张**压轴 + 多停 ~430ms** |
| dud 不配占用悬念时间 | 逐张节奏按产出分档 `miss 55 / shard 130 / card 170ms`；压轴放大只给 rank≥3 |
| 图鉴的「已获得」必须与持有数解耦 | 分解重复卡后 `lit_at` 不清，实测 `everStillLit: true` |
| 定向价 : 分解值 需逐档体检（<4 告警） | 合成价既然是逐卡独立参数，比值就不能靠一个全局系数派生 |
| 失效绑定必须在控件里保留显示 | 切站型后 select 选项集不含存量值 ⇒ 浏览器渲染成「未选」，一保存就静默清空。正解：以 `disabled` 选项保留原值 |
| 阻断原因不能只躺在某个 pane 里 | 顶栏常驻「N 项阻断 · 首条原因」并可点击直达出错页 |
| 硬保底可以是纯装饰 | 默认参数下软保底爬坡先饱和，实测最大间隔 63 抽、硬保底 65 **触发概率 0.009%**。后台须显示触发概率而非沉默 |
| 包载荷形状可验偏向 | 解析走树：颜色字面量**只出现在 rarities 段**，`cards` 段 0 色，卡键只有 `key/name/rarity/section_kind/entity_ref` |
| 「清单只能有一份」同样适用于样张 | 六页的卡面、token、DP、PRNG 已收进 `gacha-shared.js` + `gacha-card.css`；四处（索引/后台/模拟器/公示）给同一个综合出金率 **3.3875%** |

**样张清单**：`gacha-index.html`（入口 + 实时自检）、`gacha-card-demo.html`、`gacha-pull-demo.html`（含 0–180° 翻牌定格）、`gacha-album-exchange-demo.html`、`gacha-admin-demo.html`（6 pane）、`gacha-sim-demo.html`（定种子蒙特卡洛 + 精确 DP 互验 + 一键复现后门）、`gacha-disclosure-demo.html`；共享层 `gacha-shared.js` / `gacha-card.css`；AI 样图 `gacha-mocks/`。

## 3. 表结构（迁移 0226–0234）

设计约束：**机制进代码、内容进包、视觉与经济参数走行表**；产出类型用判别列而不是并列固定列；两种新货币各建账本。

```sql
-- 0226 材质 token（照 medal_rarities 0143 先例）。前端不得再持任何稀有度色表。
gacha_rarities(
  key        text PRIMARY KEY,              -- 'R','SR','SSR','UR','LR'，可增删
  label      text NOT NULL, sort int NOT NULL,
  stars      smallint NOT NULL,
  gold_rank  smallint NOT NULL DEFAULT 3,   -- 「出金」阈值是数，不是枚举
  frame text, frame_hi text, glow text, bg1 text, bg2 text, ink text,
  foil       numeric(4,3) NOT NULL DEFAULT 0,
  foil_mask  text NOT NULL DEFAULT 'art'
             CHECK (foil_mask IN ('art','frame','none')),  -- 值集合由守卫对账 CSS 类名
  enabled    bool NOT NULL DEFAULT true)

-- 0227 卡定义。「系列」不新建词表，直接绑站点已有的维度体系。
gacha_cards(
  id           bigserial PRIMARY KEY,
  key          text UNIQUE NOT NULL,        -- 包内稳定标识，供 apply 幂等
  name         text NOT NULL,
  name_i18n    jsonb NOT NULL DEFAULT '{}',
  rarity       text NOT NULL REFERENCES gacha_rarities(key),
  series_kind  text,                        -- 绑 section_kinds.kind，可空
  series_value bigint,                      -- 绑 section_dict.id，可空
  entity_table text,                        -- 来源表名：不把实体类型冻成列
  entity_ref   text,                        -- 'E-1042' / 'U-8841'
  art_asset    text,                        -- attachments.sha256
  synth_shards  int NOT NULL DEFAULT 0,     -- ★站长按「每张卡」配的合成价
  dupe_shards   int NOT NULL DEFAULT 0,
  lv_max        smallint NOT NULL DEFAULT 1 CHECK (lv_max >= 1),
  lv_cost_each  int NOT NULL DEFAULT 0,
  lv_gain       numeric(4,3) NOT NULL DEFAULT 0,
  enabled bool NOT NULL DEFAULT true, sort int NOT NULL DEFAULT 0)

-- 0228 卡池
gacha_banners(
  id bigserial PRIMARY KEY, key text UNIQUE NOT NULL, name text NOT NULL,
  kind text NOT NULL CHECK (kind IN ('standard','limited','newbie')),
  starts_at timestamptz, ends_at timestamptz,
  up_card_id bigint REFERENCES gacha_cards(id),
  ticket_cost int NOT NULL, ten_cost int NOT NULL, daily_free int NOT NULL DEFAULT 0,
  pity_soft int NOT NULL, pity_hard int NOT NULL CHECK (pity_hard >= pity_soft),
  pity_ramp numeric(5,3) NOT NULL DEFAULT 0,
  pity_inherit bool NOT NULL DEFAULT true, pity_reset bool NOT NULL DEFAULT true,
  guarantee_up bool NOT NULL DEFAULT false, up_ratio numeric(4,3) NOT NULL DEFAULT 1,
  enabled bool NOT NULL DEFAULT true)

-- 0229 奖池行：三类产出一张表，不建 card_value / shard_n / miss_w 这种并列固定列
gacha_pool_rows(
  id bigserial PRIMARY KEY,
  banner_id bigint NOT NULL REFERENCES gacha_banners(id) ON DELETE CASCADE,
  output_type text NOT NULL CHECK (output_type IN ('card','shard','miss')),
  rarity  text REFERENCES gacha_rarities(key),
  card_id bigint REFERENCES gacha_cards(id),
  weight  numeric(8,3) NOT NULL CHECK (weight >= 0),
  prize_value numeric(10,2) NOT NULL DEFAULT 0,
  shards int NOT NULL DEFAULT 0, sort int NOT NULL DEFAULT 0,
  CHECK ((output_type='card'  AND rarity IS NOT NULL)
      OR (output_type='shard' AND shards > 0)
      OR  output_type='miss') )

-- 0230 抽取券（与 spark 分轨）+ 账本，形状照 spark_ledger
gacha_ticket_balance(user_id bigint PRIMARY KEY REFERENCES users,
                     balance int NOT NULL DEFAULT 0 CHECK (balance >= 0))
gacha_ticket_ledger(id bigserial PRIMARY KEY, user_id bigint NOT NULL, delta int NOT NULL,
  kind text NOT NULL, ref_type text, ref_id bigint,
  idempotency_key text UNIQUE, balance_after int NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now())

-- 0231 碎片账本（同上形状）
gacha_shard_balance(user_id bigint PRIMARY KEY,
                    balance int NOT NULL DEFAULT 0 CHECK (balance >= 0))
gacha_shard_ledger(id bigserial PRIMARY KEY, user_id bigint NOT NULL, delta int NOT NULL,
  kind text NOT NULL, ref_type text, ref_id bigint,
  idempotency_key text UNIQUE, balance_after int NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now())

-- 0232 持有与图鉴。lit_at 一旦写入不因分解而清 —— 「图鉴只增不减」落在列上
gacha_user_cards(
  user_id bigint NOT NULL, card_id bigint NOT NULL REFERENCES gacha_cards(id),
  held int NOT NULL DEFAULT 0 CHECK (held >= 0),
  lv   smallint NOT NULL DEFAULT 1 CHECK (lv >= 1),
  lit_at timestamptz NOT NULL, first_source text NOT NULL,
  PRIMARY KEY (user_id, card_id))

-- 0233 抽卡流水：公示、导出、对账的唯一真相
gacha_draws(
  id bigserial PRIMARY KEY, user_id bigint NOT NULL, banner_id bigint NOT NULL,
  seq int NOT NULL, drawn_at timestamptz NOT NULL DEFAULT now(),
  output_type text NOT NULL, rarity text, card_id bigint, shards int NOT NULL DEFAULT 0,
  pity_at int NOT NULL, was_pity bool NOT NULL DEFAULT false, is_new bool NOT NULL DEFAULT false,
  seed bigint NOT NULL,                 -- 落库以便事后复核
  idempotency_key text NOT NULL,        -- 一次请求 N 行共用
  UNIQUE (idempotency_key, seq))

-- 0234 定向兑换。限次直接落在唯一键上，不靠代码记
gacha_exchanges(
  id bigserial PRIMARY KEY, user_id bigint NOT NULL, card_id bigint NOT NULL,
  season_key text NOT NULL, shards_spent int NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, card_id, season_key))
```

**必须先抽出来的一层**：把样张 `gacha-shared.js` 里的 `composite() / economics() / rng()` 提成 **`packages/gacha-math/`**，TS（前端公示）与 Rust（守卫 + 运行时预检）各写一份实现并配**逐条镜像用例**（照 L7 术语表那次 Rust / vitest 互验的先例）。不这么做，「四处同源」一进真代码就破。

## 5. 批次划分与验收断言

### G31-A 骨架 + 只读公示面（0228–0229 + `packages/gacha-math/` + 模块键八处）——✅ 2026-09-27 完成

接口：`GET /gacha/rarities`、`/gacha/banners`、`/gacha/cards`、`/gacha/banner/{id}/rates`（**同时返回表定与综合两列**）。前端公示页（样张⑥骨架：双列概率表+出金率/保底周期/硬保底概率/最差返还率脚注，色 token 全部来自 rarities 行表）。**实证**：端点↔向量逐位一致（goldComp 3.3875%、comp 七行、ratioWorst 96.76%、svFrom=synth:LR）；8081 实例对拍脚本全过；模块关闭三处同时消失（API 404/4101、nav 条目消失、页面空态 🚧）；module_keys 三方 31/31；gacha_math_guard 真库快照 1 池绿；i18n/行宽门禁本批文件零违规。坑：module flags TTL 30s（开关切换后验证须等 ≥32s）；COALESCE(lv_max) 是 INT2 需 `::int` 对齐元组；迁移编号避让并行会话（0227 captcha → 取 0228/0229）。

断言：
- 公示页七行概率与 `economics()` 逐位一致，`Σ comp == 1`（精度 1e-9）；
- 模块关闭后**前台入口、后台菜单条目、路由三处同时消失**（反向验「后台导航不随模块开关闭合」那个老缺陷）；
- **未登录访问公示页的口径当场定死**：`attachments` 的 `GET` 要登录 ⇒ 卡图在匿名态拿不到。要么公示页要求登录，要么给卡图单开一条匿名可读路径。这条不决定就会在装机验收时炸；
- 新增维度/稀有度行不触发任何 schema 变更（加一档只 INSERT）。

### G31-B 抽取与账本闭环（0231–0232）——✅ 2026-09-28 完成

`POST /gacha/draw {banner_id, count(1~10), idempotency_key}`：事务内 `FOR UPDATE` 行锁扣券 → 服务端逐次 roll（`gacha_http/roll.rs`，与 simulate 同式，行种子=批种子+seq 落库）→ 写 `gacha_draws`（pity_at/was_pity/is_new）→ 碎片聚合一批一行入账 → upsert `gacha_user_cards`（lit_at 只 INSERT 写，ON CONFLICT 只加 held）→ 返回结果序列 + 双余额。**运行时守卫**：每请求现算 `ratio_worst`，>100% → 409/4102 `PoolGuard`（errors.rs 新变体）+ tracing::error 告警——**e2e 实证直改库也拦**。重构纪律：`pool.rs` 单源 load_pool（rates/draw 共用，card_ids 平行向量）+ `prior_draw_rows` 幂等重放读。

**e2e 13/13**：幂等重放同批不扣券｜券不足 400+文案｜lit_at 不重写｜held=抽中卡数｜并发 20 全 200 恰扣 500｜账本连续三段查（调整/并发/10 万抽后 balance_after−LAG−delta 零断行）｜10 万抽出金率 **3.3560%**（公示 3.3875%，偏差 −0.0315pp）｜**直改库抬 prize_value → 409/4102**。crate 内测试 10/10（gacha_math 7 + roll 3：MC 收敛/硬保底必金/pity_at 口径）。坑：e2e 调余额必须「流水行+余额」成对（裸 UPDATE 自破连续性）；重放 key 复用会掩盖券不足断言。staff 发券端点留 G31-C 后台 pane（e2e 用 psql 成对入账）。

断言：
- 同 `idempotency_key` 重复提交只出一批；
- 并发 20 路抽取不超发不双扣，`balance_after` 逐条连续可核；
- 券不足返回 400 且**文案是原因而不是 500**（照 23503→400 那批的口径）；
- 抽 10 万次实测出金率落在公示综合概率的抽样误差内（样张实测偏差 −0.41%）；
- 分解重复卡后 `lit_at` 不清、图鉴不暗。
