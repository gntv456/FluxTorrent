# 反 AI 味设计门

**slop = 条件反射做出的选择，而不是为这个产品做的选择。**
一个元素如果原封不动搬去毫不相干的产品还成立，它大概率是 slop。

## 判据（命中才flag，不搞品味打分）

1. **可迁移性**：这个渐变/圆角/徽标换个 logo 就能用在别的站？→ 没有产品语境
2. **生成模式复读**：又是「三个等宽卡片+图标+一句话」？→ 模板复读
3. **与本仓设计系统打架**：颜色不走 TIDE 令牌、圆角/阴影自造数值？
4. **零信息量**：摆在那但不解释任何关系、状态或因果？

## 本仓铁律（在通用判据之上）

- **每个角标/数字都来自后端真实数据**。假数字（"3 张免费"）哪怕好看也
  是 P1——2026-10 审计已清过一轮，别再引进
- TIDE 令牌先行：新颜色先查 `--sky/--mint/--sun/--coral/--candy` 有没有
  能用的，自造 hex 需要理由
- emoji 图标是本仓口径（零资源依赖），不为此 flag；但 emoji 与 SVG
  图标混用要有一致规则（ArcadeGlyph 有 SVG 集就优先 SVG）
- 文案必须走 dict 三语键，硬编码中文进 tsx 直接红门禁

## Removal Test

1. 说出可疑元素与它的职责
2. 心里删掉它
3. 信息/功能无损 → 删；有损 → 在既有系统内做**最小修正**，不另起炉灶

## 边界

- 不给具体技法贴 slop 标签（渐变本身不是罪，无语境的渐变才是）
- 不用「中性模板」去洗掉产品已有的独特选择
- 清理时不新增依赖
- 核验看**渲染结果**（浏览器/截图），只读源码查不出 slop
