## 0. 执行摘要

**一句话结论**：FluxTorrent 已经不是「界面不好看」的问题，而是**「功能深度 9 分、任务效率 6 分」的结构性错配**——设计系统与视觉资产很扎实，但首屏信息架构、发现效率、新用户上手路径和密度控制没有随功能数量同步成长。

### 0.1 体验评分（本轮口径，10 分制）

### 0.2 三个最高杠杆点（先做这三件，投入产出比最高）

1. **首页信息架构重排**（A1）：把「签到日历」从首屏主位降级为一条 compact 签到带，把「最新资源 + 我的进度 + 下一步动作」顶到首屏。成本：1 个板块配置 + 1 个新组件；收益：所有用户每天看到的第一个画面从「工具」变回「内容」。
2. **资源库分面发现**（A2）：从「搜索框 + 空态」升级为「分类 chips + 常用筛选 + 保存搜索 + 结果预览」。PT 站的核心价值是「找得到」，不只是「搜得到」。
3. **新用户 5 分钟上手**（A3）：把已有 `/me/onboarding` 数据（account-health 页已在消费）搬到首页首屏，做成可跳过的三步任务卡。这是转化与留存的根，不是锦上添花。

## 2. 现状诊断：现状界面里真正的问题

### 2.1 首页：首屏主位被低价值工具占用（P0-架构）

**观察**（`design-system/_desk-home.png`，1440×900）：
- 首屏从上到下依次是：社区新鲜事（公告 + 蓝色占位海报）→ **签到得魔力日历（整块约占 420px 高）** → 聊天室。
- 签到日历展示 30 天的「未签」格子，真正有用的信息只有「今日已签到 / 连续 1 天 / +10 魔力」三项，却占据近半屏。
- 「最新种子海报墙」在源码里存在（`app/(main)/page.tsx` 的 `PosterRibbon` / `LatestPosters`），但在真实空数据环境下退化为「主题化占位色块」，首屏看不到实质内容。
- 聊天室在页面底部，标注「15 秒自动刷新」——低优先级、高干扰的模块被放在了用户必经路径上。

**问题本质**：PT 用户打开首页的意图排序通常是「我该做什么 / 有什么新资源 / 我的站点状态」，而当前排序是「公告 / 签到 / 聊天」。签到是每日一次、5 秒完成的动作，不该按「月度日历」的体量占用空间。

**代价**：新用户看不到「下一步该干什么」；老用户每次都要滚过日历才能看到内容；首屏「信息密度低但视觉噪音不低」。

**优化方向**：见方案 A1（§3.1）。

### 2.2 资源库：有搜索，没有「发现」（P0-任务）

**观察**（`_desk-torrents.png` 与视觉回归 `baozi-torrents-win32.png`）：
- 顶部是「范围 + 关键字 + 匹配模式 + 给我搜 + 设置」，功能完整；
- 第二行只有「共 0 个种子 / 列表·卡片·海报墙 / 20·50·100 / 快捷键提示」；
- 无数据时是一大片空白 + 一个小图标 + 「查看全部（含断种）」，**没有分类 chips、没有热门筛选、没有保存搜索、没有推荐内容**。

**问题本质**：这是「数据库查询界面」而不是「资源发现界面」。对 PT 站而言，用户往往「不知道要搜什么」，分面浏览（分类 / 分辨率 / 年代 / 大小 / 活种）比精确搜索更高频。

**代价**：冷启动期或筛选过窄时，用户看到空白就离开；老用户的重复筛选条件无法复用。

**优化方向**：见方案 A2（§3.2）。

### 2.3 新用户没有「第一步」（P0-转化）

**观察**：
- `account-health` 页有 `onboarding-card` 与 `/api/v1/me/onboarding` 数据，说明后端已具备「新手进度」能力；
- 但首页、资源库、种子详情页都没有消费这份数据；新用户第一次登录后看到的是与老用户完全相同的「公告 + 日历」。
- `docs/user/01-join.md`、`02-survival.md` 等文档存在，但文档不是产品内引导。

**问题本质**：PT 的新用户门槛天然高（客户端、passkey、比例、H&R、做种），如果产品内不主动给路径，流失发生在前 10 分钟。

**代价**：注册转化虽有，但「注册后 7 日首种率」大概率偏低（建议后续埋点验证）。

**优化方向**：见方案 A3（§3.3）。

### 2.4 个人中心：指标很多，但没有「健康度叙事」（P1）

**观察**（`baozi-me-win32.png`）：
- Hero 是通用头像占位 + 「站长」徽标；下面是 5 张等权统计卡：上传量 / 下载量 / 分享率 / 魔力值 / 做种收益。
- 再往下是一行「宠物:Lv.1 · 史莱姆」的空挂件（只有一个小圆圈），紧接着 9 个页签（个人中心 / 发布种子 / 当前做种(0) / 当前下载(0) / 完成种子(64) / …）。
- 「下一级进度」卡片内容是「已达最高等级」；「佩戴勋章」是「暂未佩戴勋章」的虚线空框。
- 账号信息、传输与做种、连接信息、更多资料以密集的键值行 + 虚线分隔铺开。

**问题本质**：信息是「系统有什么就显示什么」，而不是「用户关心什么就先给什么」。PT 用户最关心的是**账号健康度**（分享率是否安全、H&R 是否清零、做种是否活跃），而不是绝对的上传总量。

**代价**：关键风险信号被淹没在 20+ 个同名数据行里；空挂件（宠物）与空徽章框制造「没做完」的观感。

**优化方向**：见方案 B3（§3.7）。

### 2.5 管理后台：长文本导航 + 移动端审核风险（P1）

**观察**（`_desk-admin.png`）：
- 左侧是约 22 项纯文字菜单，按「总览 / 审核队列 / 种子审核 / 举报处理 / 用户申诉 / 作弊探测 / HR&R 管理 / 用户 / 上传者 / …」纵向排列；无图标、无分组折叠、无待办数量徽标（只有顶部「99 站长」标识）。
- 主区「待办队列」四张卡全是 0，「站点数据」六张卡，接着「最近操作」审计流水。整体是可用的，但**「审核队列」的入口在左侧第 2 项，却没有数量提示**，当有 14 条待审时用户不会第一时间看到。
- 11-03 审计已修 375 下审核队列横向溢出；但管理端在 375 仍然是「抽屉 + 长列表」的降级形态，审核动作效率未针对拇指优化。

**优化方向**：见方案 B4（§3.8）。

### 2.6 跨主题与密度：令牌对了，消费点仍要收口（P1）

**观察**：
- 令牌层很扎实（`--tap-min:44px`、`--focus-ring`、`--text-*` 五阶、明暗双套），11-03 的低对比与级联问题已修；
- 但仍有「语义对」缺失的迹象：例如成功/警告/危险的 soft 底配套色在明色主题下成组偏浅（既有审计记录 17/25 组 <AA，后续已部分清偿）；实心按钮所需的是 `--accent-surface + --accent-on` 这样的**成对语义令牌**，而不是组件各自 `bg-sky text-white`。
- 全站没有「舒适 / 紧凑」的用户可选密度：个人中心、后台表格是 10–12px 密集行；首页与空态是 40–80px 大留白。同一用户在两种场景下都需要不同密度，目前只能被动接受。

**优化方向**：见方案 B1（语义令牌）与 B2（密度系统）。

## 3. 优化方案（按优先级与依赖排序）

### P0-A1 首页信息架构重排 ⭐ 最高杠杆

**目标**：首屏 1 屏内回答三个问题——「我现在怎么样 / 有什么新资源 / 我下一步做什么」。

**改版结构（桌面 1440）**：

```
┌─ 站点头部（保持不变）───────────────────────────────┐
├─ 置顶促销条（有则显示）────────────────────────────┤
├─ 我的 PT 驾驶舱（新，约 180px）
│  问候 + 等级进度条 + 4 个健康指标（分享率/H&R/做种/魔力）
│  ＋ 主CTA「去搜种」  ＋ 次CTA「发布资源」  ＋ 签到按钮（compact）
├─ 最新资源（前置，海报墙 12 张，含分类角标与活种数）
├─ 两栏：左「社区动态/公告」  右「快速导航 + 任务卡」
└─ 站点数据 / 聊天室（下移或可折叠）
```

**关键设计决策**：
- 签到：首屏只保留「签到 + N 天连续 + +10 魔力」的**单行带**（高度 ≤56px），完整日历移至 `/checkin` 页或点击展开的 popover。源码已有 `checkin` 模块与路由，零新增后端。
- 海报墙：即使无真实海报，也不要用纯色块「假装有内容」——改为**分类引导卡**（电影/剧集/纪录片/动漫/音乐…），点击直达 `/torrents?category_id=…`，把空态变成导航。
- 首页板块顺序已有 `home_layout` + `parseHomeLayout` 机制（`components/home-layout.tsx`），**新结构应通过配置落地，而不是写死 JSX**，既保留站长自定义能力，又便于灰度 A/B。

**验收**：首屏 900px 内可见「资源卡片 ≥ 6 张」且「签到动作 ≤ 1 次点击」；移动端首屏可见驾驶舱 + 至少 2 张资源卡。

**落点**：`app/(main)/page.tsx`、`components/home-sections.tsx`、`components/home-data.ts`、`app/styles/home-mobile.css`、`scripts/home_sections_guard.mjs`（板块键需同步登记）。

### P0-A2 资源库分面发现升级

**目标**：把「查询界面」变成「发现界面」，同时不破坏现有 URL 参数契约。

**改版要点**：
1. **分类 chips 行**（搜索框下方）：全部 / 电影 / 剧集 / 纪录片 / 动漫 / 音乐 / 游戏 / 软件 / 教育…（取 `profile.categories` 顶级分类），多选/单选按现有 API 语义；chips 自动换行（UI/UX 规则：Chip Collection Reflow），不裁切标签，超出用「+N」展开。
2. **快捷筛选行**：分辨率（4K/1080p/720p）、年代、体积（<1GB / 1–10GB / >10GB）、只看活种、官种/非官种。以 URL query 同步状态，保证可分享、可后退（Deep Linking 规则）。
3. **保存搜索**：当前条件可命名保存，列入用户中心「我的筛选」；重复访问一键恢复。
4. **结果区**：默认列表视图保留；卡片/海报视图补「种子数 + 活种数 + 最近更新」。空态按「全站无资源 / 筛选过窄 / 搜索无结果 / 仅死种」四态给不同文案与 CTA（其中「筛选过窄」主 CTA 是「清空筛选」，不是「发布资源」）。
5. **搜索建议**：输入时下拉提示热门词 / 分类 / 字幕组，键盘 `/` 与上下键已有基础，沿用。

**验收**：从首页进入资源库到「点开一颗目标种子」的中位步骤 ≤ 3；筛选状态可通过 URL 完整复现；空态四态文案各有专属 CTA。

**落点**：`app/(main)/torrents/_parts/torrents-table-view.tsx`、`components/torrent.tsx`、`components/ui/pager.tsx`(?) 与新 `components/ui/filter-chip-bar.tsx`、`i18n/*`、`lib/nav-menu.ts`（分类来源已具备）。

### P0-A3 新用户 5 分钟上手卡

**目标**：用已有的 `/api/v1/me/onboarding` 数据，在首页首屏给出「可跳过、可回看」的三步任务。

**三步内容**（文案示意）：
1. 下载并安装 BT 客户端 → 链接到「客户端推荐」页（`clients`）
2. 用 passkey 导入种子 → 链接到「种子详情 / 下载」
3. 保持做种 24 小时 → 链接到「我的做种」并展示进度

**交互规范**：首次登录展示，可「跳过」（写用户偏好，不再强制）；任何时候可从首页「新手任务」入口重新打开；每步完成有即时勾选反馈（`ActionFeedback` 原语）与魔力奖励提示（若后端已配置）。

**验收**：新用户首访首页可见任务卡；跳过后再不自动弹出；三步均可从卡片直达对应页面。

**落点**：`components/home-sections.tsx`、新 `components/onboarding-card.tsx`、`i18n/*`、`lib/user-pref` 相关用户偏好（46 项偏好体系已存在，需新增一个键并过 `user_pref_guard`）。

### P0-A4 空态语义化（与 A2 配套）

四态模型（已实现「搜索无结果」，其余三态补齐）：

| 场景 | 标题 | 主 CTA | 次 CTA |
|---|---|---|---|
| 全站无资源（冷启动） | 这里还空空的，来种下第一颗种子 | 发布资源 | 看新手指南 |
| 筛选过窄 | 没有符合当前筛选的资源 | 清空筛选 | 放宽条件（删掉分辨率/体积） |
| 搜索无结果 | 没有找到与「{q}」匹配的种子 | 清空搜索 | 换关键词 / 查看热门 |
| 仅死种 | 这里的资源暂时无人做种 | 查看全部（含断种） | 发布资源 |

**规范**：所有空态统一用 `EmptyState` 原语 + `tone` 区分语义；禁止用危险色（`--coral`）当「发布」主 CTA（11-03 已修，需防回潮）。

### P1-B1 语义令牌成对收口

**新增令牌（明暗双套，写进 `base.css` 令牌层）**：

```css

  /* 实心主操作：成对出现，禁止单独消费 bg-sky + text-white */
  --accent-surface: #0f62c4;   --accent-on: #ffffff;
  --accent-surface-hover: #0d4fa0; --accent-surface-active: #0a3d80;
  /* Hero 专用（山海经金箔底需深字） */
  --hero-bg: linear-gradient(...); --hero-on: #0e1b2a;
  /* 状态色 soft 底成对 */
  --success-soft: ...; --success-on-soft: #167c63;
  --warning-soft: ...; --warning-on-soft: #936800;
  --danger-soft:  ...; --danger-on-soft:  #d60000;
}
[data-theme="shanhaijing"] {
  --accent-surface: #2c7a64; --accent-on: #ffffff; /* ≈5.2:1 */
  --hero-on: #101914;
}
```

**配套门禁**：在 `scripts/design_cov_guard.mjs` / `ui_design_guard.mjs` 增加「成对令牌」规则——凡出现 `--accent-surface` 必须同作用域有 `--accent-on`；禁止组件层出现 `bg-sky text-white` 组合（棘轮只许降）。这能把 11-03 的 P1-1/P1-2 类问题从「靠人记」变成「机器挡」。

### P1-B2 用户可选密度系统

**机制**：在 `<html>` 上加 `data-density="comfortable|compact"`（默认 comfortable），令牌随档切换：

| 令牌 | comfortable | compact |
|---|---|---|
| `--space-row` | 16px | 8px |
| `--font-min` | 12px | 11px（不低于 11，防 11-03 P1-6 回潮） |
| `--tap-min` | 44px | 44px（**不随密度降级**，触控底线） |
| `--card-pad` | 20px | 12px |
| `--section-gap` | 24px | 12px |

- 用户设置新增「界面密度」开关（写入现有用户偏好体系，过 `user_pref_guard`）。
- 表格/列表组件在 compact 档启用 `line-height` 与 `padding` 收缩，但**触摸目标不缩**。
- 移动端自动跟随 comfortable（屏幕小但手指不小）。

**验收**：切换密度后，个人中心与后台表格行数在同屏内提升 ≥ 30%；所有可点元素仍 ≥44px；10px 以下文字零命中。

### P1-B3 个人中心重构：从「数据罗列」到「健康叙事」

1. **Hero**：替换通用头像占位为真实头像（已有 `avatar_url`）；用户名 + 等级 + 注册天数 + 进度条（若无下一级则显示「已达最高」但保留成就进度）。
2. **健康指标前置**：把「分享率 / H&R 未处理 / 做种数 / 魔力值」做成 4 张带状态色的健康卡（正常绿、警告黄、风险红），上传总量降为次要信息。
3. **移除/补齐空挂件**：宠物模块若无内容则隐藏（`profile.modules.pet` 已有模块开关），徽章空态改「去勋章墙看看」的可点入口而不是虚线空框。
4. **页签收敛**：9 个页签按「概览 / 我的资源 / 社区 / 成长」四组二级收纳，默认展示概览；数量角标保留。
5. **表格密度**：使用 B2 的 `--space-row`，并为「近期发布」补体积、活种、更新时间三列（当前只有名称与体积）。

### P1-B4 管理后台导航与审核效率

1. 左侧菜单加 **分组标题 + 线性图标 + 折叠**（复用 `components/icons` 的 SVG 图标，禁止 emoji）；当前项用 `--accent-surface` 浅底 + 左侧 3px 指示条（Active State 规则）。
2. 「审核队列 / 举报处理 / 用户申诉」显示**待办数量徽标**，数量来自现有 `admin/staffpanel` 数据，零新增请求。
3. 审核操作行：移动端 `flex-wrap`，文字占满一行、按钮独占一行，按钮 `min-height:44px`（11-03 已修溢出，本条是效率增强）。
4. 403/权限态：专用空态（图标 + 「需要 staff 权限」+ 返回入口），不渲染数据面板（11-03 P1-7 已修，纳入回归清单防回潮）。

### P1-B5 暗色 Elevation 模型

统一 4 级表面：`--surface-0`（页面）→ `--surface-1`（卡片）→ `--surface-2`（悬浮/下拉）→ `--surface-3`（弹层），每级配 `--border-*`。当前暗色页面（`baozi-night-top-win32.png`）大面积是同一深蓝，层级靠细线区分，扫读时「哪些是可交互面板」不够直觉。用轻微明度差 + 1px 边框建立层级，不改品牌色相。

### P2-C1 娱乐模块聚合

`lib/nav-menu.ts` 的「娱乐」组目前含 games / gacha / farm / gomoku / contests 等 5+ 入口，与核心工具在「更多」里并列。建议在「更多」中收成一个「娱乐屋」二级入口，进入后再分游戏；核心任务（搜种 / 发布 / 做种 / 消息）保持一级直达。收益：降低新用户的选择过载，同时不影响老玩家路径（原路由不删，只做导航聚合）。

### P2-C2 详情页「追更 / 相似推荐」

竞品对比（`docs/ops/flux-vs-peer-a.md`）指出对方在 Media→Series→Members→Versions 强模型上领先。我们不一定要重建数据模型，但可以在种子详情页补轻量区块：「同系列其他版本」「同字幕组其他作品」「看过此资源的人也看」，用现有 `torrent-related` 组件扩展，提升发现深度与停留。

### P2-C3 动效与微交互规范

- 统一时长：微交互 150ms、面板进出 200–300ms、页面转场 ≤300ms，全部走 `--motion-*` / `--tide-*` 令牌（现有 43 处散落时长棘轮只许降）。
- 按压反馈：所有卡片/按钮/chip 加 `active:scale-[.98]` 或背景变化（Active States 规则）。
- 快速切换 chip 时取消在途动画，直接落最终语义态（Cancellable State Transitions 规则）。
- `prefers-reduced-motion` 全量兜底（现有 15 个文件覆盖，新增组件必须跟进）。

### P2-C4 体验度量闭环

定义并埋点 5 个体验指标，进 `docs/design/metrics-log.md`：

| 指标 | 定义 | 目标 |
|---|---|---|
| TTFV（Time To First Value） | 登录后首屏出现可用资源卡的时间 | < 1.5s |
| 首次搜到种耗时 | 新用户从首页到打开第一颗种子的中位时长 | < 90s |
| 空态退出率 | 进入空态后 10s 内离开的比例 | 下降 30% |
| 签到完成率 | 日活用户中当日签到比例 | 提升 10pp |
| 审核处理时长 | 后台从进入队列到完成审批的中位时长 | 下降 25% |

## 6. 验收与可用性测试

### 6.1 定量门槛

- 明暗双主题：正文对比 ≥4.5:1，大字 ≥3:1；`check_dark_contrast` 零回潮。
- 触摸目标：全站可点元素 ≥44px（除表格内部密集操作可用 36px 但需间距 ≥8px）。
- 空态：四类场景文案与 CTA 各自独立，无「发布资源」误用。
- 键盘：Tab 顺序符合视觉顺序；弹层焦点陷阱；`/` 快捷键不回归。
- 性能：LCP/INP/CLS 不劣化（本机模拟档仅看方向，生产域看绝对值）。

### 6.2 定性测试脚本（建议 5 名新用户 + 3 名老用户）

1. 新用户：注册 → 首页 → 说出「你现在该做什么」（检验 A3 是否清晰）。
2. 找种任务：「找一部 2024 年 4K 纪录片」→ 记录步骤数与耗时（检验 A2）。
3. 签到任务：找到并今日签到（检验 A1 compact 带的可发现性）。
4. 健康度判断：看个人中心 10 秒后复述「我的账号有没有风险」（检验 B3）。
5. 后台审核：给定 3 条待审，完成通过/拒绝（检验 B4）。
