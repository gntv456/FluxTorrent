> 方法：源码走查（`apps/web` 814 个 tsx）+ 4 条真实用户路径并行评审 + 门禁脚本复跑 + 关键结论逐条复核。

## 0. 一句话结论

**FluxTorrent 的「地基」（设计系统原语、a11y 基建、错误页、加载态）已经建得比多数同类项目好；
但「上层」（原语的实际落地率、跨组件状态同步、不可逆操作的确认与撤销）几乎是空的。**
结果是：**界面看起来是完整的，玩起来处处是「点了没反应 / 数字是错的 / 明明成功了却像失败 / 出错了回不去」**。

量化口径（本次实测）：

| 指标 | 实测 | 说明 |
| :--- | ---: | :--- |
| 原生表单控件 / 覆盖文件 | 806 / 233 | 全站表单规模 |

## 1. 五个问题的总判定

| # | 问题 | 判定 | 最典型的一条 |
| :-- | :--- | :--- | :--- |
| 1 | 玩家此刻最需要知道什么？ | **不及格** | 签到页「累计签到」显示的是**近 30 天**的天数；列表里**断种的种子没有任何标识** |

## 2. 根因：不是没有设计系统，是设计系统没被使用

`apps/web/components/ui/README.md` 把反馈协议写得很清楚：
「编程式反馈的唯一形态」「错误需要占位而不是浮层」「失败可诊断：request_id 芯片（必附）」「可撤销操作：直接执行 + toast.optimistic 回滚更好」。

**协议是对的，落地是空的。** 于是出现三类系统性缺陷：

### 2.1 原语在，但页面不走原语 → 反馈形态 179 种
- 59 处 `toast.error` 里只有 5 处带 `requestId`，0 处带 `action`：设计文档承诺的「可诊断 + 可补救」几乎不存在。
- `toast.error` 默认 5 秒自动消失（`ui/toast.tsx:89`），而**错误恰恰是玩家需要记住的那一类**；全站 0 处使用 `duration: 0`。
- 806 个表单控件里只有 13 处走 `<FormField>`，所以 `aria-describedby` 错误关联、字段级红字、label 关联**基本全站缺席**。
- `<FieldErrors>` 的「点字段名聚焦对应控件」（`ui/form-field.tsx:146-148`）在真实表单里是死链：发种表单的输入只有 `name` 没有 `id`（`upload-form-files.tsx:132-140`）。

### 2.2 组件之间不互相知道对方改了数据 → 「操作完看不到结果」
- 商店买券：`shop/page.tsx:56` 与 `:64` 是两个互不相干的组件，`VoucherPanel` 只在 mount 时取一次数（`voucher-panel.tsx:82-84`）。
- 抽卡后「我的卡册」的券余额不刷新（`GachaDraw` 更新自己的 `bal`，`GachaAlbum` 另持一份 `me`）。
- 领取任务扣了报名费，任务页 hero 的「当前魔力」还是旧数（`tasks/page.tsx:17-23` 是 RSC 一次性 prop）。
- 短讯点开一封信 → `setRows(null)` → 整张列表塌成骨架再弹回来，同时勾选被清空（`message-center.tsx:73-77`）。

### 2.3 没有「撤销 / 重试 / 二次确认」这一层
- 全站只有 1 处 `toast.optimistic`，0 处 toast 带 `action`。
- 领取任务扣 3~10 万魔力、锁 30 天、失败扣罚，**一键无确认、无撤销**（`task-board-sections.tsx:99-117`）。
- 投票、下载、发种等花钱/不可逆动作没有成本前置说明与二次确认。

## 3. 按五问列出的问题清单

### 问 1｜玩家此刻最需要知道什么？（信息层级）

#### 【P0】【已复核】签到页「累计签到」显示的是近 30 天，不是累计总天数
连签 483 天的老玩家在 `/checkin` 看到「累计签到 30」。
- `apps/api/src/economy_http/checkin/status.rs:120-133` — 响应体只有 `recent`/`heatmap`/`streak`，**根本没有 `total_days`**；`recent` 是 `date >= current_date - 30 days`。
- `apps/web/components/checkin-page.tsx:159-163` — `s.total_days ?? s.recent?.length ?? 0`，于是永远等于近 30 天记录数。
- 对照首页口径正确：`apps/api/src/http/home_attendance.rs:87` 用全量行数。
- **改**：后端 `GET /attendance` 补 `"total_days": (SELECT count(*) FROM attendance WHERE user_id=$1)`；前端直取。补齐前把标签降级为「近 30 天签到」。

#### 【P0】【已复核】列表里的「断种」种子没有任何视觉标识（行级语义类全部无 CSS）
PT 站里「还有没有人做种」是玩家判断要不要点的**第一信息**。桌面表格、卡片墙、列表卡片三处都加了 `torrent-dead` 类，但 **全站 45 个 CSS 文件里没有任何一条 `.torrent-dead` 规则**。
- 加类处：`components/torrent-table.tsx:123`、`app/(main)/torrents/_parts/torrents-cards.tsx:208,268`。
- 同样悬空的还有 `torrent-official`（官种）、`torrent-sticky`（置顶）、`pro_free/pro_2up/pro_50pct/pro_30pct`（促销 DOM 契约，`torrent-table.tsx:42-61`）。
- 做种数字列本身也没有零值特判：`components/torrent-table-nums.tsx:31-32` 只有 `seed-arrow` 类，而 `.seed-arrow` 仅在 `.userstat` 作用域下有样式（`app/styles/layout.css:450`）。

### 问 2｜玩家此刻最需要做什么？（行动引导）

#### 【P0】【已复核】筛选面板会偷偷把「仅活种」变成「含断种」，且没有任何 chip 可回退
后端缺省是**仅活种**（`apps/api/src/torrent_http/list.rs:46`「存活三态：缺省=仅活种 0=全部 1=仅活种 2=仅断种」），
但前端高级面板的「存活」radio 在 `alive` 缺席时**默认选中「全部(0)」**：
- `app/(main)/torrents/_parts/torrents-adv-groups.tsx:148` — `chipLabel("alive", v, label, (sp.alive ?? "0") === v, "radio")`。
- 整个高级面板在同一个 `<form action="/torrents" method="get">` 里（`_parts/torrents-search-box.tsx:72`），`<details>` 折叠不影响提交。
- `alive=0` **不生成 chip**（`_parts/torrents-chips.ts:70-71` 只处理 `alive=1/2`）。
- **后果**：① 面板显示「存活：全部」而列表其实是仅活种 → **面板在撒谎**；② 玩家点一次「给我搜」/「应用」，URL 带上 `alive=0`，断种全涌进列表，**零提示、零 chip、无法察觉也无法退回**。
- **改**：radio 默认改「仅活种(1)」或把「全部」的 value 置空串并在 page 侧视作缺省；`torrents-chips.ts:70` 补 `alive=0` 的 chip。

#### 【P0】【已复核】体积筛选框是 number 类型，带单位的值静默失效或静默错筛
- `_parts/torrents-adv-groups.tsx:65-85` — 体积区间用 `type={date ? "date" : "number"}`，而 placeholder 明说支持 `500MB / 1.5GB / 2TB`（`i18n/zh-CN.ts:1202-1204`），分面 chip 产出的也是带单位字符串（`_parts/torrents-facets.tsx:149-153`）。
- number 输入框的 value sanitization 会把 `"1GB"` **直接清空** → 提交时不发送该参数 → **体积筛选整条消失**；若用户填裸数字，后端按**字节**解析（`apps/api/src/torrent_http/query.rs:183-213`）→ 阈值 2 字节 → 等于没筛。
- **改**：体积两框改 `type="text" inputMode="decimal"`，值保留带单位字符串，与后端 `parse_size` 同口径。

#### 【P1】【已复核】详情页头部主行动不唯一：下载 / 心愿单 / 感谢 / 更多操作 四枚同级
- `components/torrent-detail-head.tsx:163-208` — 两行四枚按钮样式完全相同（药丸），而真正高频的「收藏此种」（按 id 的 bookmark）被塞进「更多操作」（`components/torrent-social.tsx:171-185`）。
- 「心愿单」是**关键词型**订阅（`components/wishlist.tsx:37-99`），和收藏完全不是一回事，却摆在最显眼位置。
- **改**：头部行 1 只留「下载种子」（实心主色）+「收藏」；心愿单挪进更多操作。

#### 【P1】【已复核】移动端底部操作条的「收藏」实现成了心愿单，和桌面不是同一件事
- `components/torrent-actionbar-mount.tsx:57-66` — favorite 走的是 `POST /api/v1/wishlist`（关键词型）。
- `app/(main)/torrent/[id]/page.tsx:365-368` — 标签直接把 fav 绑到它。
- 桌面收藏是 `PUT /torrents/{id}/bookmark`（`components/torrent-social.tsx:171-185`）。
- **后果**：手机点了收藏，桌面收藏列表里没有它，反之亦然；重复添加被后端按 (user,keyword) 唯一拦掉，错误 toast 只说「参数校验失败」。
- **改**：移动端 favorite 改调 `/torrents/{id}/bookmark`，心愿单另起一枚独立按钮。

#### 【P1】【已复核】领取任务要扣报名费、30 天不可取消，却是一键无确认
- `components/task-board-sections.tsx:99-117` — 点击直接调用认领，无 `ConfirmDialog`；后端同事务扣费（`apps/api/src/ops_http/task_overview.rs:206-227`）。
- 规则明写「领取后不能由用户取消」「报名费领取时扣除」（`i18n/zh-CN.ts:1312,1315`）。

## 5. 建议补的门禁（把这次的人工结论变成 CI 规则）
