# 产品评审与整改报告 · 第四轮（2026-11-19）

> 视角：资深产品经理。本轮不再堆叠新功能，而是从「用户权利」「承诺一致性」「并行开发下的回归」三个维度找缺口，发现 3 项并全部落实。

## 一、发现与整改

### P0-1 账号数据不可携带：用户只能导出本地足迹，拿不到站点持有的数据

- 现象：`/account-health` 有「我的使用足迹」导出，但那只是浏览器本地的行为记录；站点持有的资料、统计、偏好、邀请、收藏等无任何导出方式。
- 风险：数据可携带是成熟社区的基本权利，用户换站/备份/申诉时拿不到自己的数据；站内既有的 `/me/*` 只读端点已具备数据，缺的只是产品出口。
- 整改：新增 `components/account-data-export.tsx`，挂在 `/account-health`，点击后并发读取 12 个既有只读端点，打包成 `flux-account-data/v1` JSON 下载。
- 关键纪律：不含密码、passkey、令牌与登录会话；单端点失败如实写入 `errors`，不伪造空数据；只读、按需、不上传第三方。四语文案入 `dict.uxOpt`，日语在 `ja.ts` 覆盖。

### P1-1「查看已过期」求种筛选是死标签：永远查不到数据

- 现象：前端 `request-board.tsx` 有 `filterIng`（文案「查看已过期」），后端 `request_list` 用 `r.status = 2` 过滤，但**全仓库没有任何写入 status=2 的代码**；同时行渲染又写了 `status === 2 ? 已过期`，等于一个永不出结果的入口。
- 整改：不再依赖不存在的状态列，改为**派生口径**——未完结且创建超过 30 天（与站内求种位 30 天兜底同口径）即视为过期。列表返回时把派生状态映射为 2，前端原有的「已过期」标记自动生效；`ing` 筛选同步改为派生条件。
- 一致性：过期单不再接受加价与应种（后端 `bid.rs` / `requests.rs` 同步守卫），避免 UI 标了过期、API 仍可操作的分裂。零迁移、零新表。

### P2-1 并行开发下日语覆盖会悄悄退化

- 现象：上一轮完成 188/188 段全译后，另一会话在 `zh-CN.ts` 新增 `profileStats` 段；段级覆盖立即出现缺口，且 β 标记已移除，退化不再有显式提示。
- 整改：`ja.ts` 显式覆盖新段并补齐译文；保留 `scripts/ja_coverage.mjs` 作为可随时执行的门禁前检查（本轮实测 189/189，missing 0）。
