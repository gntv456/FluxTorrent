# 产品评审与整改报告 · 第五轮（2026-11-19）

> 视角：资深产品经理。本轮从「指标是否真的被看见」入手，发现北极星指标只写在文档里、产品内无处可看；同时借这次机会纠正了一处分层违规苗头。

## 一、发现与整改

### P0-1 北极星指标 MASU 从未在产品内可见

- 现象：`docs/product/产品指标体系.md` 把 MASU（月活做种用户）定为北极星，管理后台也有 WAU、做种健康度、14 天趋势，但**没有任何地方显示 MASU、MAU 或做种渗透率**。站长无法用产品本身判断「本月做种的人变多还是变少」，指标只活在文档里。
- 整改：
  - 后端 `/admin/overview` 新增 `masu` / `mau`：MASU = 30 天内仍有做种 announce 的去重用户（`snatches.last_seen_at` + `seeding`，命中既有部分索引），MAU = 同期活跃用户；老后端缺字段时前端按 0 降级。
  - 前端管理总览在 WAU 旁新增 MASU / MAU / 做种渗透率三格与口径说明，四语文案入 `dict.uxOpt`。
- 架构纪律：SQL 不落在 H 层。取数封装进 `repo/admin_metrics.rs`，`overview.rs` 只调 repo 函数——分层门禁从 7 处 SQL 回落到 5 处基线，没有靠放宽基线蒙混。

### P1-1 指标口径不一致的隐患

- 指标体系把 MASU 定义为「月度活跃做种用户」，但仓库里同时存在「做种数」「活种率」「WAU」多个近似口径，容易被误读为北极星。
- 整改：前端明确标注口径与分母（渗透率 = MASU / MAU），并在报告与指标文档中固定同一句定义，避免后续各做一套。
