# FluxTorrent 运营整改报告（2026-11-19）

> 视角：资深运营团队。方法：以 CI 门禁为验收标准的工程健康度审计 + 仓库卫生盘点。
> 与既有五轮产品评审互补——产品功能面已清零，本轮聚焦「工程与交付面」的真实红灯。
> 所有整改均已落盘，并逐项以门禁/编译命令复验。

## 一、总评

项目产品质量已相当成熟（11 种站型、45 个 worker 任务、33 项静态门禁、
五轮产品整改清零）。但本轮审计发现：**交付面存在两处 CI 红灯，
且仓库卫生与资产入库存在结构性漏洞**。这些不是功能缺失，而是
「本地能跑、CI 会红 / 干净克隆拿不到」的交付风险。本轮全部修复。

## 二、发现的不足（按严重度）

### A.【P0】CI 红灯：文件膨胀门禁 5 处违规

| 文件 | 问题 | 根因 |
| :-- | :-- | :-- |
| `apps/web/components/global-search.tsx` | 313 行 > 300；1 行 94 列 | 搜索弹窗四态逻辑与类型定义同文件 |
| `apps/web/components/nav-drawer.tsx` | 302 行 > 300 | useMemo/setOpenIds 尾行拆行 |
| `apps/web/components/request-board.tsx` | 368 行 > 基线 358；3 行超宽 | 多轮功能叠加，只增不减 |
| `apps/web/components/site-news-banner.tsx` | 1 行 90 列 | Link 属性单行堆叠 |
| `apps/api/src/content_http/requests.rs` | 309 行 > 300 | 两处完全相同的 10 元素元组声明 |

**风险**：`build-test.yml` 与 `scripts/ci_local.sh` 均跑该门禁，红灯意味着
PR 无法合入、发版构建被卡；「本地绿、远端红」会拖垮交付节奏。

### B.【P0】CI 红灯：设计令牌退化 2 处

- `components/pwa-install-bar.tsx:61` 直写 `bg-sky-deep`
- `components/request-board.tsx:359` 直写 `bg-sky`

**风险**：语义色类绕过 `var(--tone-*)`，明暗主题切换时按钮配色不跟随，
是可访问性与品牌一致性的回退。设计门禁按行号登记，新增即红。

### C.【P1】后端校验详情未本地化（存量 2 条）

- `该求种已过期`（requests.rs）、`该求种已过期，无法加价`（bid.rs）
  未进 `validation_details.tsv`，且不在基线内 → `validation_i18n_guard` 红灯。

**风险**：英文站用户看到裸中文错误；CI 里该门禁长期失效未被发现。

### D.【P1】仓库卫生：约 500MB 临时归档 + 忽略规则漏洞

- 根目录 `srcv9.tgz`(194MB)、`websrc.tgz`(152MB)、`websrc2.tgz`(152MB)
  均为 gzip 源码快照，未被任何规则忽略，一次 `git add -A` 即全部入库。
- `=/nul/` 为命令行重定向残留空文件。
- 现有 `/_*.txt|json|py|...` 规则只覆盖根目录且漏了 `.rs/.b64/.md`；
  `/_doc/` 声明「绝不入仓」但 `!_doc/` 后又无 `/_doc/**` 兜底，
  子目录里的 `.ts/.mjs/.md` 仍挂在未跟踪区。

### E.【P1】有价值资产漏交

`docs/product/` 9 份产品评审/指标报告、`docs/ux/` 2 份诊断方案、
`scripts/ja_coverage.mjs`（日语 188 段覆盖率校验）均未在版本控制中。
本地容器从工作区构建一切正常，干净克隆/CI 拿快照直接缺件——
这正是仓库既有「漏交文件守门」要防的场景，但它只查被引用文件，
查不到这些孤立文档与脚本。

### F.【P2】rustfmt 模块声明失序

`apps/api/src/repo/mod.rs` 中 `pub mod admin_metrics;` 排在字母序之外，
`cargo fmt --check` 会将其重排（CI 格式门禁隐患）。

## 三、整改落实明细

| 不足 | 整改动作 | 验收标准 |
| :-- | :-- | :-- |
| A | 类型外移新模块 `global-search-types.ts`；提取 `RequestTuple` 别名消除重复；压缩非空 JSX 尾行；断行超宽属性 | 5 文件均 ≤300 行、零新增超宽 |
| B | 两处色类改 `bg-[var(--sky-deep)]` / `bg-[var(--sky)]`，属性超宽改字符串拼接 | design palette 零新增 |
| C | 按三列 TSV 格式补入繁中/英译文 | 校验门禁 OK、覆盖率 33.5%→33.7% |
| D | `.gitignore` 补 `*.tgz / tree.json / = / nul / _*.rs/.b64/.md / .pnpm-store / _doc/**`；删除 `=` | 未跟踪垃圾从 git status 消失 |
| E | `git add` 12 份文档 + 校验脚本（暂存待提交） | 资产进入版本控制 |
| F | `cargo fmt --all` 重排模块声明 | fmt --check 通过 |

**基线纪律**：行数与设计门禁仅用 `--touch` 定向收缩本次改动的两个文件，
未使用 `--update` 全量重算，避免把并行会话的违规一并洗白。

## 四、验证结果

- 33 项静态门禁（行数/设计/i18n/分层/路由/卫生/契约/迁移/安全等）：**全绿**
- `pnpm exec tsc --noEmit`：**0 错误**
- `cargo fmt --all --check`：**通过**
- `cargo check --workspace --all-targets`：**0 错误**（198 条存量 warning，非本次引入）
- `cargo test --workspace`：**106 passed / 0 failed（全 workspace）**

## 五、防复发建议

1. **门禁红灯必须在 PR 内修复**：`--update` 只允许在确认无并行改动时由维护者执行，
   日常一律 `--touch` 定向落账。
2. **大文件入库前过一遍 `git status --short`**：`*.tgz` 已入忽略表；
   新增文件类型若不在表内，先补规则再 `add`。
3. **新静态校验串同步进译文表**：CI 门禁已生效，开发者首次遇到红灯时
   应补 `validation_details.tsv` 三列，而不是跑 `--update` 洗白。
4. **设计系统色类零直写**：新组件统一用 `var(--tone-*)` / Badge tone，
   设计门禁已按行号锁死新增。
5. **文档即资产**：产品决策记录（`docs/product/`）与校验脚本必须随代码入库，
   否则干净克隆无法复现决策与门禁。
