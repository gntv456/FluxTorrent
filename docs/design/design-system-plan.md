## 0. 设计意图（为什么做、做到什么算成）

### 0.0 北极星：现代自部署 PT 基准（v3 新增）

七站横评（§11.5）看的是"同行怎么做"，北极星回答"下一代该怎么做"。**NP 的形态是历史存量，不是我们的天花板**——同类站 的 18 项平铺、Audiences 的数据条都是 2010 年代服务器渲染的产物；同类站 也只是"把传统形态做整洁"，没有定义新形态。我们栈的现代化程度（Next.js 15 App Router / RSC / Rust actix / SSE）已经在同行之上，缺的是把这栈的能力**兑现成用户体验**。三个兑现方向：

| 支柱 | 含义 | 我们已有的底子（不是从零开始） | 兑现路径 |
|---|---|---|---|
| **性能强** | 首屏快（SSR+流式）、翻页快（缓存+预取）、交互快（乐观更新） | RSC 默认服务端渲染、`output: standalone`、SSE 未读流已上线 | §12 性能预算表：Core Web Vitals 全绿 + 接口 P95 + 缓存分层 |
| **UI 好** | 设计系统驱动的一致性、暗色一等公民、站型主题化个性 | Aurora 令牌 265 变量明暗双套、M1-M4 移动端、55 种站型参数化 | 本方案 §2-§6 全部；主题注册表扩多主题（IA-3） |
| **工程先进** | 类型安全全链路、契约驱动、门禁护城 | domain-types 包、check_type_drift、四件门禁 | §10 流程 + **姊妹篇 `docs/design/frame-plan.md`（FRAME-PLAN-01）**：契约五步走（路由清单→错误码注册表→utoipa 分域→前端类型生成）+ 分层宪法（H/S/D/R/C 五层禁 import）+ 用例函数化根治双入口 |

**现代性的五条判据**（区别于"NP 换皮"的自我检验，每条都有反面教材）：
1. **无白屏导航**——RSC 流式让页面切换有即时反馈（反面：NP 全页刷新、同类站 SPA 换页白屏）；
2. **暗色不是补丁**——令牌双轨制（`[data-theme]` 切换变量而非 filter 反色），对比度按暗色单独校准；
3. **键盘与读屏可用**——搜索 `/` 快捷键、Esc 关弹窗、焦点可见（反面：六站实测无一有跳主内容链接之外的键盘方案——我们已有 SkipLink 约定）；
4. **实时性**——未读 SSE 已上线；后续站内信、审核状态变化走同一条推送思路（反面对手：全轮询）；
5. **失败可诊断**——错误展示带 request_id（§3.2 ErrorPanel），用户报障自带线索（反面：NP 的"操作失败"三字）。

### 0.2 设计意图（四条，每条都有"不做什么"的边界）

**意图一：反馈有协议，而不是各有各的反馈。**
用户在任何一个页面做任何一个写操作，反馈的形态（成功/失败/进行中/部分成功）由系统决定，不由页面作者决定。页面只声明语义（"保存了"），不手写呈现（alert/刷新/静默三选一的现状正是没有协议的症状）。
*不做什么：不做全局状态管理库（redux/zustand），toast 用轻量事件订阅即可——327 个组件文件经不起一次大迁移。

**意图二：令牌是单一真源，代码里不许出现颜色。**
Aurora 六色令牌体系（base.css 已有 265 个变量声明 + 兼容层 `--brand-*` 别名）就是真源。达标 = 组件/页面代码中的硬编码 hex 归零（娱乐屋 SVG 皮肤资产例外，见 §6 豁免口径）。
*不做什么：不换设计语言、不重做视觉——Seedlight Aurora 体系保留，夜间主题的令牌切换机制（`data-theme`）保留，只做"未接线的部分接线"。

**意图三：覆盖可度量，欠账可见、可还、可防新增。**
"成熟"不是形容词，是四个数字：路由加载态覆盖率、原语采用率、令牌覆盖率、a11y 骨架覆盖率。每个数字有脚本可算、进 CI 门禁、只许升不许降（同 line_limit_guard 的"只许瘦不许胖"哲学）。
*不做什么：不追求 109 个页面一次迁完——按流量分层，P0 十页达标即宣布系统成立，其余页面按"触碰即迁移"纪律渐进。

**意图四：门禁护城，防止第 N 个功能又绕过系统。**
每次新功能上线，设计系统不为它破例。新代码过不了覆盖率门禁就进不了 master——这是对标报告 §12"体量超过工程纪律承载"的诊断在 UI 层的解药。
*不做什么：不给人添负担——门禁只管增量（新文件/新行），存量按页面分层渐进清偿，不做一次性大爆炸迁移。

### 0.3 非目标（明确不做）

- 不引入第三方组件库（shadcn/MUI/AntD）——327 个存量组件 + 已有 CSS 体系（17 个域样式文件、17294 行）改造成本高于自建原语层；
- 不做视觉重设计——令牌层已承载设计语言；
- 不动后端契约与 API 形态（另属契约工程线）；
- 娱乐屋（games）的美术资产不做令牌化改造（SVG 皮肤是内容不是 chrome，见 §6）。

## 2. 分层架构（目标形态）

```
┌─ L4 页面层（109 page.tsx）——只做数据编排与语义声明
├─ L3 模式层（patterns）——搜索结果页/列表页/表单页/详情页的页面级组合约定
├─ L2 原语层（components/ui/*）——本方案的核心交付，纯展示+交互，无业务
├─ L1 令牌层（base.css）——色/字/距/角/影/焦点/断点/动效，唯一真源
└─ L0 守护层（scripts/*guard.mjs + CI）——覆盖率度量与门禁
```

关键约束（自上而下）：
- L4 **禁止** import L1（页面不许直接碰 CSS 变量/hex/Tailwind 色类——通过 L2 或既有语义 class）；
- L2 **禁止**包含业务词汇（torrent/bank/medal…），原语只认 size/tone/variant 这类设计词汇；
- L2 组件全部 i18n（四语），全部键盘可达，全部带 `role`/`aria-*` 语义；
- 新原语文件 ≤300 行（既有门禁），样式统一进 ui.css 复用令牌。

## 3. 原语层清单（L2 核心交付，12+ 件）

设计词汇先行——所有原语共享同一套 **tone（brand/neutral/success/warn/danger）× size（sm/md/lg）** 矩阵，与 Aurora 六色的映射在令牌层完成（tone 不直接写色值）。

### 3.1 反馈通道（意图一的主角）

| 原语 | API 骨架 | 替代的现状 |
|---|---|---|
| **Toast 系统** | `<ToastProvider>`（根布局一次挂载）+ `toast.success/error/info(msg)` 编程式调用；自动叠放、`role="status"` + `aria-live="polite"`、danger 用 assertive；5s 自动消失可悬停延长；移动端从顶部下滑 | 各页面的 alert/静默/局部实现（收编 admin-user-detail 与 game-kit-feedback 两孤岛） |
| **ActionFeedback** | `<ActionFeedback state="busy\|ok\|fail" />` 行内三态（按钮内 spinner→✓→✗ 或文本行），替代手写"提交中…" | 各表单 20+ 处手写 loading 态 |
| **ConfirmDialog** | `<ConfirmDialog tone danger\|neutral onConfirm>` 焦点陷阱 + Esc + 点击遮罩语义（复用 `lib/use-focus-trap.ts`）；危险操作红色确认 + 二次输入（删除类） | 各处手写 confirm/window.confirm |
| **BusyLabel** | `<BusyLabel label busy>` 文本+spinner 组合 | 手写"加载中"散句 |

### 3.2 数据四态

| 原语 | 说明 |
|---|---|
| **EmptyState**（已有） | 补 tone/图标协议；已有 4 处引用迁入统一 props |
| **Skeleton**（已有） | 扩 `SkeletonBlock variant="text\|media\|table\|form"` 四预设，配 loading.tsx 模板 |
| **ErrorPanel** | `错误码 + request_id + 重试按钮 +（dev）折叠堆栈`；与后端错误信封 `{code,message,request_id}` 对齐——request_id 一键复制，用户报障能附上 |
| **StatePanel** | 四态路由器 `<StatePanel loading error empty children>`——页面用它声明四态，内部调度上面三件；**这是消灭"三态各自手写"的关键件** |

### 3.3 表单协议

| 原语 | 说明 |
|---|---|
| **FormField** | label + 输入 + hint + error 四槽位统一布局；error 关联 `aria-describedby`；必填标记协议 |
| **FieldErrors** | 与后端 FieldErrors（`errors.rs` 的 fields map）**结构化对齐**：`<FieldErrors fields={{field: [msgs]}}>` 直接渲染后端校验错——前后端校验口径单一真源 |
| **SubmitButton** | 表单提交生命周期封装（idle→busy→done/fail 与 ActionFeedback 联动；防双击；键盘提交） |

### 3.4 布局与导航

| 原语 | 说明 |
|---|---|
| **PageHeading** | 标题/副题/操作区三槽；`<h1>` 唯一性由它保证（对齐报告"主标题归一"整改） |
| **DataPager** | 分页统一件（与后端 page/per_page 契约对齐）；键盘翻页、页码 aria-current |
| **PosterImage**（已有） | E 批交付，纳入清单管理 |

### 3.5 a11y 基建（非组件，是约定）

- **SkipLink** 全站唯一 `<main id="main-content">` 锚点（layout 一次）；
- **useFocus/键盘导航**约定进 lint（onKeyDown 必须与 onClick 成对出现于交互元素——9 处存量在阶段五清）。

### 3.6 动效协议（轻量）

令牌层补 `--motion-fast/normal/slow` + `prefers-reduced-motion` 全局短路（一行 media query）——动效只允许引用令牌时长，禁止散落 transition。

## 4. 路由级加载与分割策略

### 4.1 loading.tsx 铺设（不是 109 个全铺）

RSC 数据页的加载态由 Next 自动触发。铺设范围按"数据路由"判定：
- **P0（10 页）**：种子列表/种子详情/发种/消息收件箱/论坛列表/论坛主题/搜索/用户中心概览/排行/通知中心——每页一个 loading.tsx（Skeleton 四预设组合，≤30 行/文件）；
- **P1（约 20 页）**：银行/娱乐屋/勋章/成就/求种/订阅/收藏/好友等次频数据页；
- **其余**：静态或轻数据页不铺（避免无意义闪烁），由"触碰即迁移"纪律覆盖。

### 4.2 代码分割（`next/dynamic` 选点）

只对**重组件**做分割，预选清单（按构建产物体积核）：
- 娱乐屋游戏画布（fishing-pond 26 hex 的 SVG 系——game 目录 ~100 hex 的皮肤资产随包分割走懒加载）
- BBCode 富渲染器（bbcode.tsx 208 行）
- 管理台重表格（admin-user-detail 等）
- markdown-lite 渲染器
每处分割必须带 `loading:` 骨架参数（禁止白屏）。目标：首屏 JS 净减 ≥15%（以 next build 产物对比验收）。

## 10. 开发流程规范（成熟设计团队的工作方式）

> 本节回答"一个功能从想法到上线，怎么走才不会绕过设计系统"。它是 §5 门禁的**人文前置**——门禁是底线，流程是日常。

### 10.1 设计宪章（每条都可判对错，评审时逐条过）

1. **令牌先行**：任何新视觉决定先问"这个值该进令牌层吗？"——色/字/距/角/影/动效时长 six 项，页面代码里出现即错（§5.2 门禁强制）。
2. **语义先于样式**：组件 API 用语义词汇（tone/size/variant/state），禁止把视觉参数（颜色值/像素宽）当 props 透传——调用方表达"这是什么"，不表达"长什么样"。
3. **原语无业务词汇**：components/ui 里出现 torrent/bank/medal 等领域名词即打回（§2 L2 约束）。
4. **四态是默认配置**：任何承载数据的 UI，提交时就该答得上"加载中/空/错/成功各长什么样"——答不上=设计未完成（DoR 检查项）。
5. **a11y 与 i18n 是验收项不是加分项**：键盘不可达、文案未三语，等同功能缺陷（进 PR 清单）。
6. **增量不欠新债**：存量欠账按阶段清偿，但新代码零豁免——"这次先赶进度"不成立，门禁会拦（§5.1 只许向好）。

### 10.2 需求到上线的六步流（Design Flow）

```
① 设计提案 → ② 设计评审 → ③ 实现自检 → ④ PR 清单 → ⑤ 合并部署 → ⑥ 度量回收
```

| 步骤 | 产出物 | 通过条件 |
|---|---|---|
| ① 提案 | 一段话意图 + 状态清单（四态各一句）+ 涉及原语清单（复用哪个/缺哪个） | 缺原语时先立"原语工单"，不带病提案 |
| ② 评审 | 针对宪章 6 条 + tone×size 矩阵适配性 + 是否触碰 L4→L1 禁令 | 评审不过**不开工**（阶段一的 toast 协议评审即此规格） |
| ③ 自检 | 本地全门禁绿（line_limit/i18n/design_cov/ui_design 四件套）+ P0 页视觉自查（明暗双主题） | 自检不过不提 PR |
| ④ PR | §10.3 清单逐项勾选；截图（涉及视觉时明暗各一） | 清单未勾全不进 review |
| ⑤ 合并 | CI 全绿（含 design_cov_guard 只许向好断言） | squash/常规按仓内现行约定 |
| ⑥ 度量 | design_cov_guard 数字变化写进 PR 描述（"路由覆盖 62%→64%"） | 指标恶化即回滚或补迁移 |

### 10.3 PR 评审清单（UI 类改动的固定模板）

```markdown
- [ ] 新 UI 用了 components/ui 原语（或说明为何不适用）
- [ ] 无新增硬编码 hex / 裸像素断点 / 散落 transition（games 豁免除外）
- [ ] 数据 UI 四态齐全（loading/empty/error/success 各有交代）
- [ ] 键盘可达（Tab 顺序/Esc/Enter）；焦点环可见
- [ ] 文案三语齐（ja 走回落）；aria 语义到位
- [ ] 错误路径带 request_id 展示（若涉及失败态）
- [ ] 移动端断点抽查（4 档语义令牌之一，无新裸断点）
- [ ] design_cov_guard 四数字无恶化
```

### 10.4 并行与移交纪律（对本仓多会话现实的适配）

- 设计系统工作按阶段开独立 PR 线，**只 add 自己的文件清单**（仓内既有多会话纪律延续）；
- 原语 API 变更（改 props/语义）须在 PR 描述列全调用方清单并同批迁移——禁止"先改接口后补调用"；
- 每阶段收尾在 `docs/design-system.md` 的"原语目录"同步登记（阶段六起此文件即单一登记点，防止目录与实现漂移）。

### 10.5 节奏与回顾

- 每阶段结束跑一次四指标快照存档（`docs/design/metrics-log.md`，数字+日期+对应 PR），形成可回溯的改善曲线；
- 阶段三/四（主体迁移期）每半周人工走查一个 P0 页的完整动线（不只看静态态）——键盘走查与真机移动端各一次；
- 达标（§9 全绿）后流程不撤：门禁永久在 CI，宪章进 CONTRIBUTING 前端节，新成员按 §10 六步流上手。

## 11. 信息架构与导航（第五维差距：对方常态直显，我们折叠成瘾）

> 2026-10-13 深夜补充。基于 同类站 站内实测（登录态走查 /home、/browse）与本仓逐文件审查——对标报告 §1 只覆盖了"组件与令牌"层，IA（信息架构）层还有一组结构性差距，本节收编进策划案，避免阶段三迁移时按错误的结构铺 loading。

### 11.1 实测差距五件（全部 file:line 可查）

| # | 维度 | 同类站 实测 | 我们现状 | 差距定性 |
|---|---|---|---|---|
| 1 | 主导航密度 | 4 项（首页/浏览/论坛/求种）+ 搜索 + 上传 + 个人状态栏 = 7 元素，零下拉 | 一级 5 项 + 「更多 ▾」5 组**约 39 项**（nav-menu.ts:83-201，发现组独占 12），全站入口约 44 个 | 失衡：顶栏折叠 vs 下拉爆炸并存 |
| 2 | 个人状态栏 | 上传/下载/积分/未读**常态直显**于顶栏 | 全部收进头像弹窗 1 击深（user-menu.tsx:243-269） | 高频信息被折叠 |
| 3 | 主题选择器 | 顶栏原生 select 四选项（Minimal/奶油红/黑红/**自适应跟随系统**） | 二值日夜 toggle（theme-toggle.tsx:13 `Theme = "brand" \| "brand-night"`），无第三主题无跟随系统档 | 主题注册表要先扩（令牌层→IA 层衔接点） |

### 11.2 信息架构意图（第五条设计意图）

**意图五：高频信息常态直显，低频功能按需收拢——密度由数据决定，不由"塞得下"决定。**
顶栏是全站最贵的不动产：搜索、未读、身份态（等级/数据摘要）这类"看一眼就走"的信息不该藏进弹窗；而 39 项下拉是"全都重要=全都不重要"的症状。
*不做什么：不砍功能——44 个入口一个不删，只重排层级（一级 5 项保持、发现组拆分降层、个人数据条直显）；站长自定义菜单（customNav，nav-menu.ts:36-57）机制保留。

### 11.3 落地项（并入 §7 阶段计划）

### 11.4 列表页范式结论（不改策划案主体，只记录判断）

对方「三布局（紧凑/宽松/网格）+ 折叠筛选 + 每页数量」三件套我们**不缺**（TORRENT_VIEWS 三形态 torrents-utils.ts:48-52、details 折叠面板 torrents/page.tsx:130-180、PAGE_SIZES 与服务端对齐）；真差距是筛选体量——对方"更多筛选"约 8-10 控件，我们展开是 5 组 18 卡 30+ 控件。处置：**不裁剪**（NP 复刻是我们的兼容资产），但阶段三给折叠面板补「已选 N 项」计数徽标 + 一键收起，把 30+ 控件的认知负担压到折叠态摘要层。

2. **个人数据呈现：直显与收纳之争（2026-10-13 复议结论）**。初判「NP 四站全量直显 ⇒ 直显是必须项」过重——那四站是**十年以上 NP 肌肉记忆的老站存量用户**，直显是他们不动的理由，不是新站该抄的理由；且我们数据维度远多于它们（银行/娱乐屋/勋章/成就/绩效），全量平铺必成仪表盘病。**定稿：头像弹窗为主形态 + 未读 SSE 角标（已上线）+ 可选魔力 chip + 消费页余额直显**；NP 式数据条降为后台可选布局。横评表保留原始观察，此条为修正后结论——评审记录示范了「证据 → 判断 → 复审」的完整轨迹。
3. **版本号页脚直显三站可见**（SUNNYPT v0.0.24 / 同类站 API 13.12 / mTower Powered by mTorrent）——IA-5 是行业惯例，不是小聪明。

## 12. 性能预算与测量（v3：北极星"性能强"支柱的落地）

> UI 好不好可以评审，性能好不好只能测量。本节把"性能要强"变成预算表——超预算即门禁挂，同 §5 覆盖率门禁一个哲学。

### 12.1 预算表（阶段三起进 CI）

| 指标 | 预算 | 测量方式 | 现状基线 |
|---|---|---|---|
| LCP（种子列表页，4G 节流） | ≤ 2.5s | Lighthouse CI（P0 十页轮换） | 待阶段三建基线 |
| INP | ≤ 200ms | 同上 | 待建 |
| CLS | ≤ 0.1 | 同上（骨架与实体尺寸一致是根治手段，§3.2 Skeleton 预设的价值） | 待建 |
| 首屏 JS（路由 entry） | 较基线只降不升 | `next build` 产物 diff 进 PR | 阶段四建基线（§4.2 的 -15% 目标即首个断言） |
| 接口 P95（页面数据链） | ≤ 500ms（本机） | e2e 冒烟埋点（既有 e2e 框架扩展） | 待建 |
| 重复请求 | 页面数据链无重复 fetch | RSC 请求去重审查（React `cache()` 既有范式，site-profile.ts:145 已示范） | 待查 |

### 12.2 快的三个来源（按杠杆大小排序）

1. **少发**：RSC 请求合并与 `cache()` 去重（框架能力，改造在数据层不在 UI 层——与契约工程线协同）；
2. **少传**：流式渲染（`loading.tsx` 铺设本身就是流式的入口）+ 重组件分割（§4.2）；
3. **不等待**：乐观更新协议（Toast 系统的 `optimistic` 变体：提交即反馈、失败回滚提示）进阶段二表单协议——收藏/点赞这类轻写操作从"等接口"变"即时"。

### 12.3 边缘与缓存（远期项，记而不排期）

静态资源走 CDN 是部署层能力（compose 已支持反代）；RSC 响应的增量缓存（`revalidateTag`）依赖数据层稳定后才有意义——挂到契约工程线完成后复评，本方案不虚列。
