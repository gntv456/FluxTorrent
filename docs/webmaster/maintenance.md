# 维护模式（一键停站维护）

> 升级数据库、换域名、处理突发事故时，你需要把站临时关起来——但又不能把正在做种的用户打断。维护模式就是为这个场景设计的：**普通会员看到维护页，管理组照常使用，做种与下载完全不受影响**。
> 版本要求：v0.5.12 起。不懂的词查 [术语小词典](glossary.md)。

## TL;DR（赶时间看这版）

1. 后台「站点设定 → **运维**」卡 → **维护模式** 切到「维护中」→ 保存。全站即刻进入维护态。
2. 干完活 → 切回「运行中」→ 保存。普通会员刷新后最长 1 分钟内恢复访问。

就这两个动作。下面是你需要知道的边界行为。

## 什么会被拦、什么不会

| 面 | 维护期间的行为 | 为什么这么设计 |
| :--- | :--- | :--- |
| 普通会员的页面 | 一律 302 到 `/maintenance` 维护页 | 站点状态对会员透明，避免半可用造成的困惑 |
| 普通会员的 API | 503 + 错误码 4104（信封三语文案） | 反代/监控看到的是标准 5xx，不会误判健康 |
| **Tracker 汇报（announce）** | **照常工作** | 打断全站 peer 的做种，恢复后 H&R、魔力结算全是事故 |
| **RSS / getrss / torznab** | **照常工作** | 下载器订阅不断粮，维护结束自动追新 |
| 管理组（等级 ≥90） | 照常全功能访问，顶部显示黄色横幅提醒「站现在对外是维护态」 | 你得能进后台干活、随时关闭 |
| 登录/登出/改密 | 可用 | 管理组成员要能登进来 |
| 健康探针（/health /ready） | 可用 | 编排系统不能把维护态判成宕机重启 |

「做种不受影响」这件事**写进了维护页文案**——会员看得到，不会慌着去卸载客户端。

## 三个配置键（后台「运维」卡）

| 键 | 类型 | 说明 |
| :--- | :--- | :--- |
| `maintenance_mode` | 下拉 | 「运行中」/「维护中」。唯一必需的开关 |
| `maintenance_message` | 文本 | 自定义维护公告（支持换行）。留空用默认文案「站点正在升级维护，暂停对外服务」 |
| `maintenance_until` | 文本 | 预计恢复时间，RFC3339 格式（如 `2026-11-06T06:00:00+08:00`）。**填了维护页才显示倒计时**；留空不显示——不承诺做不到的时间 |

倒计时到期后显示「恢复中…」而不是负数；时间格式填错后端直接拒收（不显示倒计时），不会渲染出一段错乱时间。

## 生效与恢复的时间线

- **开启即时生效**（API 侧开关缓存 30 秒，后台保存走的是主动失效通道，保存即生效）；
- **关闭后 web 侧最长 60 秒恢复**——站点档案有 60 秒缓存（性能设计），期间部分会员仍看到维护页，刷新即可。计划内的维护建议在公告里把恢复时间写宽 1 分钟。

## 常见问题

**问：维护期间会员的下载会断吗？**
不会。Tracker 与 RSS 刻意不拦。已经加载的种子页可能打不开，但客户端的做种/下载汇报照常计费。

**问：我在维护期间把管理组密码忘了怎么办？**
登录、登出、改密三个口在维护中仍然开放——先用管理组账号登进来（没登出过的话直接进后台），再走 [故障排查](troubleshooting.md) 的重置流程。

**问：API 返回的 4104 是什么？**
维护模式的专用错误码（HTTP 503）。第三方工具（如 PT-Plugin-Plus）收到 4104 应提示「站点维护中」而不是当成 bug。错误码注册表见仓库 `docs/api/error-codes.md`。

**问：能不能只拦部分功能？**
维护模式是全站一刀切。只想关某个功能域（论坛/商店/娱乐屋）用 [模块开关](../customize/modules.md)，两者正交：维护模式管「站开着吗」，模块开关管「功能开不开」。
