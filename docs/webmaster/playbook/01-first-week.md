# 开站第一周

> 前提：安装向导已完成、[launch-checklist](../launch-checklist.md) 已过。
> 本篇按时间线给出第一天的动作与第一周的节奏。

## 第 0 天：自己先把全链路走一遍

用测试账号（后台「用户管理 → 新建」）完整走：注册登录 → 下载种子（确认
announce 地址公网可达）→ 做种一小时（确认时魔入账，`/me/sparks` 可查）→
发一个种子（确认审核流，若开启）→ 发一条论坛帖。**站长没走通的链路，
用户第一天就会踩。**

同时确认三件事在跑：

- worker 任务面板（后台「任务」）无红色失败项；
- `docker compose --profile monitoring up -d` 后 Grafana 面板有数据；
- `scripts/backup.sh` 已挂 cron 且 `restore.sh --drill` 演练过一次。

## 第 1-3 天：种子先行，用户后到

**空站放用户进来是最大的运营事故**——新用户面对零种子的站只会流失。顺序：

1. 管理组先传 20-50 个种子打底（覆盖主分类；站型包已给分类词表）；
2. RSS 转载工具（若启用）开跑，把外部资源引到候选区；
3. 首批邀请控制在 10-20 人（见[邀请策略](04-invites.md)），优先拉会做种的老手；
4. 首周开全局 2xFree 促销（见[促销编排](02-promotions.md)），降低首月生存压力。

## 第 4-7 天：立规矩、看仪表

- 规则页/FAQ 用后台「自定义页面」建好并挂导航（模板已带，改数值即可）；
- 每天看一次后台「经济仪表」：首周做种时魔产出是否远超商品消耗
  （首周用户以攒魔力为主，轻度通胀是正常形态）；
- 第一次作弊巡检（见[巡检篇](05-anticheat.md)）：账号不多时逐个过一眼
  「IP 检查」与「客户端名单」，把基线立起来；
- 如选了考核淘汰制模板，确认第一批考核任务的截止时间合理
  （默认口径见[考核篇](03-exam-hr.md)），别让首批用户全卡在考核上。

## 常见第一周翻车点

| 症状 | 根因 | 处置 |
|---|---|---|
| 用户报告"下载不动" | announce 还是 127.0.0.1 | 站点设定改公网地址，重新分发种子 |
| 找回密码没邮件 | SMTP 未配 | 后台「邮件」配置 + 测试发信 |
| 用户下载完不统计 | 未做种/客户端未回传 | 确认 tracker 端口（HTTP 7070/UDP 6969）公网放行 |
| 魔力数字异常大 | 签到/里程碑参数被改 | 经济仪表对收支平衡表（见考核篇附录） |
| 新用户全被考核卡死 | 模板阈值对新站过严 | 后台「考核内容」放宽首批任务量 |
