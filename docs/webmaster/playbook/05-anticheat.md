# 防作弊日常巡检

> 内置反作弊是"作弊探测四件套 + agent 黑白名单 + IP 工具"的组合。
> 本篇给一套可直接执行的巡检节奏（周巡检 30 分钟口径）。

## 内置能力地图

| 工具 | 位置 | 看什么 |
|---|---|---|
| 作弊探测 | 后台「反作弊」 | cheat_audit（行为异常）/ multi_ip（多账号同 IP）/ highspeed（速度异常）/ leak_scan（泄漏扫描）四件套的产出 |
| IP 检查 | 后台「IP 检查」 | 任意 IP/用户名 → 同 IP 账号列表、登录轨迹 |
| 客户端名单 | 后台「客户端」 | agent 黑白名单（BitComet 之类劣迹客户端直接拒） |
| 测试 IP | 后台「testip」 | 封禁规则的命中测试（配了 IP 段后验证没误伤） |
| 登录失败 | 后台「暴力破解」 | 登录失败锁定记录（5 次/15 分钟口径） |
| 审计日志 | 后台「审计」 | 全部管理动作留痕（谁封的、何时、什么理由） |

## 周巡检清单（30 分钟）

1. **四件套产出**过一遍：只看新增条目；`multi_ip` 命中先看是不是家庭 NAT
   （同 IP 2-3 个账号 + 不同设备指纹大概率是家人），别上来就封；
2. **速度异常**对照做种体积：上传速度常年 > 100MB/s 且做种量小的，基本是
   盒子（seedbox）——盒子是否违规取决于站点口径，规则页要有明示；
3. **新注册账号 7 日观察**：注册当天下载量 > 500GB 的（新手不可能），
   结合 IP 检查看是否老号马甲；
4. **客户端分布**：黑名单客户端还在出现 = tracker 侧拦截没生效，去
   「客户端规则」核对（agent_block 死信在后台「运行日志」有告警）；
5. **封禁动作走规范**：能自助解封的（首次宽恕）让用户走自助；申诉通道
   （后台「申诉」）待处理清零；**所有封禁写理由**——审计日志是三个月后
   你自己复盘的唯一依据。

## 封禁的分级实践

| 级别 | 动作 | 适用 |
|---|---|---|
| 轻度 | 警告（通知当事人） | 首犯、情节轻（H&R 累积、客户端违规） |
| 中度 | 限制下载/降级 | 屡犯、考核作弊 |
| 重度 | 封号（status=2） | 买卖账号、恶意破坏、泄漏内容 |
| IP 级 | ip_bans | 爬虫、撞库源（先 testip 验证误伤） |

内置纪律：封禁/警告会通知当事人（站内信），申诉 accept 联动解封；
自助解封每人一次（`self_unban_cooldown_hours` 开启即生效）。

## 什么时候升级到人工深查

四件套是探测器，不是判决书。出现以下信号再上人工：

- 同一种子做种时长/流量在多个账号间完全同步（共享账号/盒子群）；
- `leak_scan` 命中（站内内容外流）——这是最重的信号，直接进人工流程；
- 做种速度与上传量长期不匹配（伪造汇报）——对照 tracker 快照
  （后台「peers」面板，staff 档可见完整 IP）。
