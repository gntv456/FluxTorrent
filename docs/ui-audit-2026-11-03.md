## 1. 整体判断

**这套 UI 已经过了「能看」阶段，处在「设计系统基本成型、落地执行仍有系统性缺口」的阶段。**

- 视觉语言（Aurora 蓝 / 潮汐 / 山海经岩彩）完成度高，三套主题不是换色滤镜，而是有独立的令牌层、字体栈、圆角与阴影节奏。
- 令牌层非常扎实：`--text-*` 五阶、`--focus-ring` 归口、`--tap-min` 44px、`--compat-*` 兼容层、`--mood-*` 画布色，都有注释与单一真源意识。
- 但**「令牌定义正确」与「消费点用对」之间存在系统裂缝**：同一枚 `--sky-deep` 在亮色主题里当深底白字用（11.1:1），到山海经变成亮底白字（2.01:1）；`base.css` 里一条无 layer 的 `a{}` 直接压过 Tailwind 的 `text-white`，让标签、CTA 的最终颜色不可控；`--tap-min` 只有认证页和提交按钮消费，其余移动控件大量 24–36px。

粗略打分（10 分制）：

| 维度 | 分 | 说明 |
|---|---|---|
| 视觉语言与品牌感 | 8.0 | 三主题辨识度强，山海经尤其完整 |
| 令牌层与设计系统 | 7.5 | 结构好，但缺少「语义层 → 组件类」的收口 |
| 跨主题一致性 | 5.5 | 暗主题成片低对比；亮主题次级文字过淡 |
| 移动可用性 | 5.5 | 触摸目标系统性不足；375 后台横向溢出 |
| 表单与反馈 | 5.0 | 主提交按钮无外观；必填校验锚在 1×1 隐藏控件 |
| 可访问性基础 | 6.5 | 焦点环/skip link/ESC/焦点陷阱做到，但对比与触控拖后腿 |

### 最该先动的三件事

1. **打通匿名申诉通道**（P0）：全局 401 跳转把封禁用户唯一的自救路径直接弹回登录页。
2. **修复表单提交链路**（P0）：注册/发布的主提交按钮 CSS 类根本不存在，视觉上就是一行粗体文字；上传必填校验反馈落在不可见控件上。
3. **统一「暗底配色」与「链接色级联」**（P1）：山海经主按钮/Hero/分组标题的可读性，与 `base.css` 的 `a{}` 越权，是同一个问题的两面——颜色定义对了，但组件没有消费正确的语义令牌。

## 2. P0（2 项）

### P0-1 匿名封禁申诉被全局 401 跳转拦截，申诉入口不可达

**现象**：未登录访问 `/appeals`、`/ban-log`，页面在几百毫秒内被重定向到 `/login?next=%2Fappeals&expired=1`，申诉表单永远看不到。

**代价**：被封禁用户本来就不能登录，站内申诉是他们唯一的申诉通道；现在整条通道被客户端全局 401 处理短路，等于「申诉功能不存在」。

**证据**
- [api-client.ts](file:///d:/FluxTorrent/apps/web/lib/api-client.ts#L181-L195)：任意 `code === 2001`（401）→ `window.location.assign('/login?next=…&expired=1')`，只豁免 `/api/v1/auth/*`，无页面级例外清单。
- [appeals/page.tsx](file:///d:/FluxTorrent/apps/web/app/appeals/page.tsx#L22-L26)：注释明确「未登录（含被封禁用户）可凭用户名 + 验证码提交封禁申诉（P0 修复）」，与运行时行为相反。
- 采集终址：`brand|appeals|1440 → /login?next=%2Fappeals&expired=1`；`brand|ban-log|1440 → /login?next=%2Fban-log&expired=1`（`audit-metrics.json`）。
- 截图：`audit-brand-appeals-1440.png`、`audit-brand-ban-log-1440.png`（两张文件大小完全相同，都是登录页）。

**修复方向**
- 在 `api-client.ts` 的 401 分支加「匿名可访问路径白名单」：`/appeals`、`/ban-log`、`/login`、`/register`、`/forgot`、`/rules`、`/faq` 不跳转，交由调用方 `catch` 渲染「需要登录」空态。
- 更稳的做法：401 跳转只在 `Authorization` 头存在时触发（匿名请求本就不该被判为「会话过期」）。

**工作量**：小（1 个例外表 + 2 处 `catch` 文案）。

### P0-2 注册/发布的主提交按钮没有按钮外观（`ui-submit--brand` 无样式）

**现象**：注册页的「注册并登录」、发布页的「提交发布」在视觉上只是一行深色粗体文字；computed 背景 `rgba(0,0,0,0)`、边框 `0px`、无阴影，没有可点击暗示。

**代价**：这是注册与发布的**唯一主操作**。用户找不到「提交」，直接损失注册转化与资源供给；键盘用户可以盲按 Enter，手机用户会去找按钮并找不到。

**证据**
- [submit-button.tsx](file:///d:/FluxTorrent/apps/web/components/ui/submit-button.tsx#L22-L39)：`tone = "brand"` → 输出 `ui-submit ui-submit--brand`。
- [ui.css](file:///d:/FluxTorrent/apps/web/app/styles/ui.css#L981-L1005)：只有 `.ui-submit` 基类（`display:inline-flex`、`min-height`、`border-radius`），**全仓搜索 `ui-submit--brand` 零命中**；只定义了 `--compat` / `--danger` 两个变体。
- 实测：注册页 `.ui-submit` = `452×44`（1440）/ `343×44`（375），`background: rgba(0,0,0,0)`，`color: rgb(14,27,42)`；发布页 = `104×44`，同样透明。
- 截图：`audit-brand-register-btn-1440.png`、`audit-brand-upload-1440.png`。

**修复方向**
- 在 `ui.css` 补 `.ui-submit--brand { background: var(--tone-brand); color: var(--tone-on-accent); }` 及 hover/active/disabled 三态（与 `.ui-submit--danger` 同构）。
- 更彻底：把 `brand | danger` 改成 `tone` 枚举映射到 `--tone-*`，避免再出现「类名有、样式无」。

**工作量**：小（约 15 行 CSS + 一次视觉回归）。

### P1-2 `base.css` 的 `a{}` 越权覆盖 Tailwind 文字色，标签/CTA 最终颜色失控

**现象**：`<a class="… bg-sky text-white">` 的最终文字色不是白，而是 `--compat-orange-dark`。直接后果：
- 个人中心激活标签：brand `1.88:1`、shan `1.61:1`（深蓝压亮蓝 / 浅绿压石绿）；
- 「发布资源」空态 CTA：brand `2.04:1`（深蓝压红）、shan `1.45:1`（浅绿压朱），基本不可读；
- 任何拿 `<a>` 当按钮/胶囊的组件，都不再受 Tailwind 颜色类控制。

**代价**：这类「看起来有按钮、文字却糊成一团」的控件散布在个人中心、资源库、论坛、空态里；且它是**跨主题**的，亮色主题同样中招。更麻烦的是它让后续所有颜色改动的可预测性归零。

**证据**
- [base.css](file:///d:/FluxTorrent/apps/web/app/styles/base.css#L701-L708)：`a { color: var(--compat-orange-dark); }` 写在 **无 `@layer`** 的位置；`@import "tailwindcss"` 的 utilities 在 layer 内，**无 layer 的规则优先级更高**，因此 `.text-white` 必输。
- 消费点：[users/[id]/page.tsx](file:///d:/FluxTorrent/apps/web/app/(main)/users/[id]/page.tsx#L201-L203)：`border-sky bg-sky text-white`。
- 实测：active tab brand `rgb(10,61,107) on rgb(15,98,196)`；shan `rgb(143,212,189) on rgb(63,174,143)`。
- 截图：`audit-brand-tab-active-1440.png`、`audit-shanhaijing-tab-active-1440.png`、`audit-brand-empty-torrents-1440.png`（CTA「发布资源」深蓝压红）。

**修复方向**
- 把全局链接色放进 `@layer base`（`@layer base { a { color: … } }`），或降特异性为 `:where(a):not([class])`；组件内显式颜色类即可重新生效。
- 同步清理用 `text-white` 当按钮文字的写法，统一走 `--accent-on`。

**工作量**：中（改 1 处级联位置，但全站链接颜色需视觉回归，约 40+ 页面）。

### P1-4 上传页必填文件校验：原生气泡锚在 1×1 隐藏控件，页面无可见提示

**现象**：空表单点「提交发布」时，`<input type="file" required class="sr-only">` 触发浏览器原生校验，提交事件根本不进入 React 的 `submit()`；于是 `setMsg('请先选择 .torrent 文件')` 这段代码不可达。焦点落到 1×1 的 `sr-only` 输入，焦点环不可见；页面上没有任何 `role=alert` / `[aria-invalid]`。

**代价**：用户点完提交，页面毫无变化（或只在角落闪一个浏览器气泡），以为按钮坏了。

**证据**
- [upload-form-files.tsx](file:///d:/FluxTorrent/apps/web/components/upload-form-files.tsx#L110-L118)：`type="file" required class="sr-only"`。
- [upload-form.tsx](file:///d:/FluxTorrent/apps/web/components/upload-form.tsx#L154-L160)：`if (!file) { setMsg(dict.upload.chooseFile); return; }` —— 这段在有原生 `required` 时进不来。
- 实测：点击后 `[role=status]` 可见元素 0 个；file input 为 `1×1 @ (785,293)` / `(187,290)`；`document.activeElement` = 该 `sr-only` input。
- 截图：`audit-brand-upload-error-1440.png`、`audit-brand-upload-error-375.png`、`audit-brand-upload-validate-1440.png`。

**修复方向**
- 表单加 `noValidate`，把「文件缺失」纳入自有校验：顶部/文件块附近插入可见错误条 + `aria-invalid`，滚动并聚焦到可视化 dropzone 容器（`tabIndex=-1`）。
- 或保留原生校验但把 `required` 移到可见 dropzone 的 `<button>`/label 上，并让浏览器气泡锚点对准可见区域。

**工作量**：小（2 处 JSX + 1 个错误条样式）。

### P1-5 管理后台审核队列在 375 下页面级横向溢出（402 / 400px）

### P1-6 亮色主题次级文字成规模 2.17–2.29：10–11.5px 的「说明/单位/时间」几乎读不清

**现象**：`--text-fainter #a3b1c6` 被用在 10–11.5px 的说明文字上，白底/浅蓝底实测 **2.17–2.29:1**；H&R 角标「44H」**2.09:1**；「魔力值奖励」灰字压灰底 **1.86:1**。这些不是装饰线，而是携带信息的文字（单位、日期、状态、剩余时间）。

**代价**：用户需要凑近或系统放大才能读；在高 DPI 小屏上基本放弃阅读，等于信息丢失。

**证据**（`audit-metrics.json`，brand，ratio < 3.1，去重）
- `2.29` `11.5px`「上传量」×12、`11.5px`「免单券/通用券/卡牌」、`10px`「3,000 /GB」、`11px`「截至当前/不含今天/资源」、`10.5px`「未签」——统一 `rgb(154,167,186)` on `rgb(246,248,252)`
- `2.09` `10px`「44H」`rgb(107,78,0)` on `rgb(180,121,10)`
- `1.86` `12px`「魔力值奖励」`rgb(90,107,133)` on `rgb(146,152,159)`
- 令牌：[base.css](file:///d:/FluxTorrent/apps/web/app/styles/base.css#L71-L72) `--text-faint: #8493ad`、`--text-fainter: #a3b1c6`（注释标「辅助角标底线」，但白底 2.17 连大字号都不达标）。
- 截图：`audit-brand-shop-375-full.png`、`audit-brand-my-375-full.png`、`audit-brand-home-375-full.png`。

**修复方向**
- 10–12px 区间禁止使用 `--text-faint/fainter`，改用 `--text-muted`（白底约 4.0–4.5）；或把 `--text-fainter` 加深到 `#6f7f98`。
- H&R / 促销角标改为「深字压浅底」并单独定令牌。

**工作量**：小（改 2 个令牌 + 少量组件改类名）。

### P1-7 管理后台 403 只显示一行 11px 灰字「加载失败」，同时继续渲染完整数据面板

**现象**：模拟 `/api/v1/admin/staffpanel` 403 后，页面标题下出现一行几乎看不见的灰字「加载失败」，而「待办队列 / 站点数据 / 最近操作」仍照常渲染（去掉了错误信息，用户无法判断是加载失败还是没权限）。

**代价**：无权限用户会以为自己在看真实数据；真正的故障也无法区分。管理后台的权限态是安全语义，不能靠一条小灰字表达。

**证据**
- 截图：`audit-brand-admin-403-1440.png`（标题下小灰字 + 完整面板 + 「待办队列 14」）。
- 复跑：`audit-interactions.mjs` 第 169–178 行，拦截 `**/api/v1/admin/staffpanel**` 返回 403。
- i18n 文案：`zh-CN.ts` 中 `loadFail` 系列多处「加载失败或无权限」，是「把两种语义混成一句」的根源。

**修复方向**
- 403/401 走专用空态：图标 + 「需要 staff 权限」+ 「申请权限 / 返回首页」，并**不渲染**数据面板。
- 500/网络失败才显示「加载失败，重试」。

**工作量**：小。

### P1-8 搜索无结果复用「发布第一颗种子」空态，引导方向错误

**现象**：搜「zzzzzzzz」得到 0 条，主文案仍是「这里还空空的，去种下第一颗种子吧」，CTA 是红色「发布资源」。用户明明是在搜索，却被建议去发布。

**代价**：错误的下一步指引，用户会以为「站里没有这个资源」→「我要自己传一个」，而不是「换个关键词 / 清空筛选」。同时红色（危险语义）用于「发布」主 CTA，语义也不对。

**证据**

- 实测：`?search=zzzzzzzz&alive=0` 时 `h2 = 这里还空空的，去种下第一颗种子吧`，链接 `发布资源` = `96×36`，brand `深蓝压红 2.04`、shan `浅绿压朱 1.45`。
- 截图：`audit-brand-empty-torrents-1440.png`、`audit-brand-empty-torrents-375-full.png`、`audit-shanhaijing-empty-torrents-1440.png`。

**修复方向**
- 新增 `emptySearchTitle/Desc`（「没有找到与「{q}」相关的资源」）+「清空搜索」按钮；保留「发布」作为次要链接。
- 主 CTA 改 `--tone-brand`，不要用 `--coral`。

**工作量**：小。
